# 695 1人あたりの処理件数を、出勤した日数で割るか働いた時間で割るかで、担当者の順位はどれだけ入れ替わるのか（実務の型）

「1人あたりの処理件数」は、何で割るかで意味が変わります。出勤した日で割ると、勤務時間の短い人は少なく見えます。時間で割っても、難しい案件を多く受け持つ人は少なく見えます。**ここでは、架空の窓口の担当者40人（うち短時間勤務12人）の3か月分の日ごとの処理件数と勤務時間で、出勤日あたり・時間あたり・難しさで重みを付けた時間あたりの3通りで順位を出し、入れ替わりと、置いた実力の順位との一致を比べました。** DuckDB の SQL と Python で同じ値になることを確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A695 | 割り方で担当者の順位はどれだけ入れ替わるか | 架空の40人×60営業日。8時間勤務28人（残業で8〜10時間）、短時間勤務12人（4〜6時間）。人ごとに実力（重み付きの1時間あたり件数、平均3.0）と難しい案件（重み2）の割合（5〜40%）を置き、件数はポアソン分布。3通りの割り方で順位を出し、スピアマンの順位相関と10位以上の移動を数える。seed 695 | `src/a695_productivity.py`、`src/02_productivity_duckdb.sql`、`src/01_productivity_tsql.sql`（T-SQL：未検証） |

## 主な結果（40人）
| 割り方 | 置いた実力の順位との順位相関 | 重み付きの時間あたりとの比較で10位以上動いた人 | 短時間勤務12人の平均の順位 |
|---|---|---|---|
| 出勤日あたり | **0.38** | 23人 | **34.5位** |
| 時間あたり | 0.72 | 10人 | 18.9位 |
| 難しさで重みを付けた時間あたり | **0.95** | — | 18.0位 |

- 出勤日あたりで並べると、短時間勤務の12人のうち10人が下位10人に入った。重み付きの時間あたりで並べると、下位10人に入ったのは1人だった
- 出勤日あたりと重み付きの時間あたりで、順位が最大31位動いた人がいた
- 時間で割っても、難しい案件の多い人は下に見え、置いた実力との順位相関は0.72にとどまった

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data が一致した
- 3通りの値と順位が、DuckDB の SQL と Python で一致すること（assert）
- 重み付きの時間あたりの順位が、置いた実力の順位とほぼ一致すること（順位相関0.95）

## データ
- `data/daily_work.csv`：架空の担当者・日付・勤務時間・件数・難しさ（1日2行：ふつうの案件と難しい案件。勤務時間はふつうの案件の行に入れ、難しい案件の行は0）。作成者が乱数で作ったもの（seed 695）

## 注意（言えないこと）
- 架空のデータです。勤務時間・難しさ・実力の分布は作成者が置いたもので、入れ替わりの大きさはこれで決まります
- 人事の評価の方法についての助言はしません。割り方で数字の意味が変わることを見たものです
- 難しさの重み（2倍）は作成者が置いたもので、実際には重みの決め方自体が問題になります
- 品質（やり直しや苦情）は扱っていません

## 出典
架空の担当者の勤務と処理件数（作成者が乱数で作成、seed 695）
