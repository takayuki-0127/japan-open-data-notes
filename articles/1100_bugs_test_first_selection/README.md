# 1100 テストを先に書いた機能にバグが少ないのは、書き方の効果か、機能の選ばれ方か？（テストとバグ）

開発の記録を見ると、「テストを先に書いた機能は、書かなかった機能より公開後のバグが少ない」と出ることがあります。けれども、どの機能でテストを先に書くかは、チームが選んでいます。仕様のはっきりした易しい機能ほど先に書きやすく、書き方に慣れた年の後半ほど先に書くことが増えるなら、書き方に効果がなくても、先に書いた機能のバグは少なく見えます。易しい機能は小さく、後半に公開した機能は公開から日が浅いので、まだ見つかっていないバグも多いからです。**ここでは、作成者が乱数で作った架空の開発チームの1年の機能300件（難しさ・大きさ・公開した日と、どの機能で先に書くかの選ばれ方を作成者が置き、先に書くことの効果は基本では「なし」と置いたもの）で、先に書いた機能と書かなかった機能のバグの数を5つの比べ方で比べ、何倍に見えるかを数えました。選ばれ方の強さ・見積もりの誤差・置いた効果を変えた48通りも確かめました。**

この記事は、テストを先に書くことの良し悪しを言うものではありません。置いた効果が同じでも、機能の選ばれ方と数え方で見え方がどれだけ変わるかを数えたものです。例のチームと機能は架空のもので、実在の会社・開発の道具の名前は使っていません。比べているのは作成者が置いた機能の性質で、人や属性の比べではありません。

関連する記事：同じ形の「選ばれ方による見かけの効果」は、タグを付けた投稿の選ばれ方を扱う 846「ハッシュタグの「効果」は、付けた投稿の選ばれ方で決まるのか？」、混む時間帯を避ける人の選ばれ方を扱う 1034「混む時間帯を避けると、どれだけ早く着くのか？」、まわりと同じことをしているのが影響かもとから似ていたからかを扱う 1082「似た人どうしがつながっているのは、影響しあったからか、もとから似ていたからか？」で扱っています。同じ企画の1096「変更の多いファイルほどバグが多いのは、変更のせいか、ファイルの大きさのせいか？」は、ファイルの大きさという別の原因が変更とバグの見かけの関係に混ざる話です。この記事は、開発の記録に固有の「機能の大きさ」と「公開からの日数」による見え方の違いに絞ります。

## 主な結果

### 比べ方ごとの「先に書いた÷書かなかった」（効果なしと置いた、1,000回、`results/ratio_by_method.csv`）
| 比べ方 | 中央値 | 10〜90%の範囲 | 0.8倍より小さく出た年 |
|---|---|---|---|
| ①そのまま（1機能あたり、今までの分） | **0.3546倍** | 0.2765〜0.4577倍 | 100% |
| ②公開後90日の分（1機能あたり） | 0.4155倍 | 0.3086〜0.5619倍 | 99.8% |
| ③②を千行あたり | 0.6143倍 | 0.4957〜0.7633倍 | 94.5% |
| ④③を見積もりの難しさの帯ごとにそろえる | **0.7931倍** | 0.6619〜0.9493倍 | 52% |
| ⑤でたらめに選んだとき（③と同じ数え方） | 0.9991倍 | 0.827〜1.2301倍 | 6.9% |

- **先に書くことの効果を「なし」と置いても、そのまま比べると、先に書いた機能のバグは書かなかった機能の0.3546倍に見えた**。1,000回すべてで0.8倍より小さかった
- 公開後の日数をそろえる（②）、千行あたりにする（③）、見積もりの難しさの帯をそろえる（④）と1倍に近づいたが、④でも0.7931倍が残った。見積もりの難しさは置いた難しさと相関0.8197で、帯の中にも難しさの差が残るため
- 先に書く機能をでたらめに選ぶと（⑤）、0.9991倍と置いた効果に戻った（作りどおり）。それでも1チーム1年の300件では0.827〜1.2301倍と振れた

### 先に書いた機能と書かなかった機能の違い（1,000回を合わせた、`results/a1100_main.json` の profile）
| | 先に書いた機能 | 書かなかった機能 |
|---|---|---|
| 置いた難しさの平均 | −0.4188 | 0.2791 |
| 行数の中央値 | 325行 | 460行 |
| 公開した日の平均 | 233.53日目 | 144.96日目 |
| 持っているバグのうち、年の終わりまでに見つかった割合 | 69.05% | 87.71% |
| 年の終わりまでに見つかったバグ（1機能あたり） | 1.991件 | 5.586件 |

- 先に書いた機能は、易しく、小さく、公開から日が浅い機能に寄っていた（作成者がそう置いた）。日が浅いぶん、まだ見つかっていないバグが多かった

### 効果を0.8倍と置いたとき（1,000回の中央値）
| ① | ② | ③ | ④ | ⑤ |
|---|---|---|---|---|
| 0.287倍 | 0.3311倍 | 0.4894倍 | 0.6337倍 | **0.7965倍** |

- 本当に効果があると置いても、①〜④は置いた0.8倍より大きな効果に見えた。⑤だけが0.8倍に近かった

### 確かめ：置き方を変えると（48通り、各300回の中央値、`results/grid.csv`）
| 置いた効果 | ①そのまま | ②日数をそろえる | ③千行あたり | ④難しさの帯もそろえる | ⑤でたらめに選ぶ |
|---|---|---|---|---|---|
| 1倍（効果なし、24通り） | 0.2255〜1.0054倍 | 0.2402〜1.0218倍 | 0.4508〜1.0138倍 | 0.5441〜0.9993倍 | 0.969〜1.018倍 |
| 0.8倍（24通り） | 0.1829〜0.8077倍 | 0.1949〜0.7958倍 | 0.3634〜0.7916倍 | 0.4339〜0.798倍 | 0.7813〜0.818倍 |

- **そのまま比べた値は、選ばれ方の強さで0.2255〜1.0054倍と大きく動いた**。難しさでも時期でも選ばない置き方では、どの比べ方もほぼ1倍だった
- 効果なしのとき、④は難しさで選ぶ強さが0なら0.9838〜0.9993倍、2なら0.5441〜0.7936倍。見積もりの誤差が0.35・0.7・1.4のとき、④はそれぞれ0.7919〜0.9979倍・0.6511〜0.9911倍・0.5441〜0.9993倍で、誤差が大きいほど1倍から離れた。効果なしの24通り中16通りで、④は0.9倍より小さかった
- 年の時期で選ばない置き方では、①と②の差は最大0.0093倍で、①と②の差はほぼすべて公開からの日数の違いから来ていた。年の時期で選ぶ置き方では、12通りすべてで①が②より小さかった
- 効果0.8倍の24通りすべてで、④は0.8倍以下（0.4339〜0.798倍）だった。④までそろえても、選ばれ方の分だけ効果は大きく見えた
- 図3は、効果なし・年の時期で選ぶ強さ2のときの④を、難しさで選ぶ強さと見積もりの誤差ごとに並べたもの。基本の置き方の値（0.7987倍）は、主な結果（0.7931倍）とは別の乱数（各300回）で作ったので少し違う

- `results/grid.csv`：48通りの確かめ（各300回の中央値）

## 注意（言えないこと）
- 架空のデータです。どの機能で先に書くかの選ばれ方、難しさと大きさとバグの関係、バグが見つかるまでの日数、置いた効果は作成者が置いたもので、結果はこれで決まります。そのまま比べた値は、選ばれ方の強さで0.2255〜1.0054倍と動きました
- テストを先に書くことに効果があるかどうか、どの機能で先に書くべきかは、この記事では言えません。置いた効果を「なし」「0.8倍」としたのは、見え方を数えるための作成者の置き方です
- 先に書いた機能は、テストが多いぶん公開前に見つかるバグが多い、といった、公開後のバグの数え方そのものへの影響は入れていません
- 見積もりの難しさの帯をそろえる④は、置いた難しさの一部しか表さない見積もりでそろえたものです。選ばれ方を決めているもの（仕様のはっきりさなど）が記録に残っていなければ、そろえようがありません（推測）
- 実在の会社・チームの開発を表すものではありません
