# 541 郵便番号から都道府県・市区町村を引くと、古い番号や事業所の個別番号のせいで何件が引けないのか（実務の型・データの照合）

郵便番号から住所を補う処理は、日本郵便の「住所の郵便番号」の表だけで組まれていることがあります。**ここでは、日本郵便の郵便番号データ（2026年10月末時点）と、2023年7月〜2026年10月の削除データを使い、(1) 削除された番号が今どう引けるか、(2) 1桁の打ち間違い・隣り合う数字の入れ替えを全通り試すとどうなるかを数えました。そのうえで (3) 架空の注文20,000件（混ぜる割合は仮定）で、引き方4通りの「引けない」「黙って違う場所になる」「照合で止まる」件数を比べました。** (1)(2) は実データを全件数えた結果、(3) の合計は置いた割合で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A541 | 引き方で、引けない件数・違う都道府県になる件数・照合で見つかる件数はどう変わるか | A 住所の番号だけ／B 事業所の個別番号も／C B＋入力された都道府県と照合／D C＋市区町村名とも照合。打ち間違いは全通り（1桁違い 7,605,423通り、入れ替え 617,905通り）。架空の注文は seed 541 | `src/a541_zip_lookup.py`（表の準備は `src/a541_prepare.py`） |

## 主な結果
- **番号の数**：住所の番号 120,721、事業所の個別番号 22,196。両方にある番号は 0。住所の番号のうち 134 は複数の市区町村に、3 は2つの都道府県にまたがる（498-0000、618-0000、871-0000。どれも「以下に掲載がない場合」）
- **削除された番号（2023年7月〜2026年10月）**：住所の番号は 846行のうち、今は引けないのが 23行（2.7%）、同じ市区町村で引けるのが 421行、市区町村名が変わったのが 401行。市区町村名が変わった行は、99.4%（事業所の行も合わせて）が浜松市の区の再編（2024年1月）によるもの。事業所の番号は 1,577行のうち 387行（24.5%）が今は引けない
- **1桁の打ち間違い（全通り）**：71.2% は引けない（どの番号にもない）。17.6% は同じ市区町村の別の番号、5.7% は同じ都道府県の別の市区町村、5.4% は別の都道府県に当たる（住所＋事業所の番号で引いた場合）
- **隣り合う数字の入れ替え（全通り）**：80.6% は引けない。9.7% は同じ市区町村、3.7% は別の市区町村、6.1% は別の都道府県
- **架空の注文 20,000件**：住所の番号だけで引くと 2,467件（12.3%）が引けない（うち 1,643件は事業所の個別番号）。事業所の番号も足すと 613件（3.1%）。黙って別の都道府県になるのは 37件（すべて打ち間違い）、別の市区町村名になるのは 123件（打ち間違い 36件、削除された番号 87件）
- **照合**：入力された都道府県と照合すると 37件がすべて止まる。市区町村名とも照合すると 160件が止まるが、うち 87件は削除された番号で、86件は浜松市の旧区名で入力された、番号自体は今も使える注文。打ち間違いのうち 164件は同じ市区町村の別の番号に当たり、どの照合もすり抜ける

## 動かし方
```
pip install -r requirements.txt
cd src && python a541_zip_lookup.py      # data/zip_current.csv.gz と data/zip_deleted.csv.gz を読む（20秒ほど）
```
表を元データから作り直すときは、下の「データ」の4つを `data/raw/` に置いて `python a541_prepare.py` を先に動かします。

## 確かめたこと
- 空のフォルダで、元データから `a541_prepare.py` → `a541_zip_lookup.py` を流し直し、data・results・figures がバイト単位で一致した（gzip の時刻は 0 に固定）
- 打ち間違いの全通りは、住所の番号 120,721 個 × 7桁 × 9通り ＝ 7,605,423通り。入れ替えは、隣り合う数字が同じ所を除いた 617,905通り
- 削除データの行が、今のデータでも同じ都道府県・市区町村で引けるかを1行ずつ確かめた

## データ
- `data/zip_current.csv.gz`：今の番号の表（番号・全国地方公共団体コード・都道府県・市区町村・住所か事業所か）。日本郵便の「住所の郵便番号（1レコード1行、UTF-8形式）」utf_ken_all.zip（2026年10月末時点）と「事業所の個別郵便番号」jigyosyo.zip から作成
- `data/zip_deleted.csv.gz`：2023年7月〜2026年10月の削除データ（utf_del_YYMM.zip、jdelYYMM.zip）から作成。事業所の名前と番地は使わず、番号・都道府県・市区町村だけを残した
- 元データ（data/raw/、リポジトリには置いていない）：https://www.post.japanpost.jp/zipcode/download.html から取得。md5：utf_ken_all.zip `330f458a26a2146b9aa213b9c19b6f82`、jigyosyo.zip `85a5a555a6c7a018098cf31252b7aada`
- 架空の注文：住所の番号 86%・事業所の個別番号 8%・削除された番号 2%・1桁違い 3%・入れ替え 1% と置いた（仮定）。番号は表から一様に選んだ（人口や注文の多さの重みは付けていない）

## 注意（言えないこと）
- 架空の注文の合計（2,467件・613件など）は、置いた割合で決まる。種類ごとの割合（打ち間違いの71.2%が引けない、など）は実データを全通り数えたもの
- 都道府県・市区町村までを見た。町域（番号の下の地名）が合っているかは見ていない
- 事業所の番号が、同じ市区町村の別の会社に振り直されていても、この方法では分からない
- 削除データは2023年7月以降の分だけを使った。それより古い番号は数えていない
- 地域の順位づけはしていない。浜松市の例は、市区町村名が変わった行の大部分を占めるので書いたもの
- 実際の配送や、特定のシステムの動きを確かめたものではない
