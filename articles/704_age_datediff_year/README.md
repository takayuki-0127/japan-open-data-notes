# 704 年齢を「年の差」だけで出すと、誕生日前の会員は何%が1歳多く数えられるのか（実務の型・SQL の日付計算）

年齢を `基準日の年 − 生まれた年` で出すと、その年の誕生日がまだ来ていない人は1歳多くなります。SQL Server の `DATEDIFF(year, 生年月日, 基準日)` も「年の境目をまたいだ回数」を返すので同じことが起きます。**ここでは、架空の会員2万人（1950〜2006年生まれ）で、年の差だけの年齢と、誕生日を考えた年齢を比べました。** 生年月日の分布は作成者が置いたもので、数字はその置き方と基準日で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A704 | 年の差だけの年齢は、何%の人を1歳多く数え、年代別の人数をどれだけ動かすか | 年の差（DuckDB の date_diff('year')）、誕生日を考えた年齢（月日の比較で1を引く）。基準日を2025年の毎月1日と12月31日で変える。DuckDB（1スレッド）と pandas で一致を確認。seed 704 | `src/a704_age.py`、`src/02_age_duckdb.sql`、`src/01_age_tsql.sql`（未検証） |

## 主な結果
- **基準日 2025-10-01**：2万人のうち **5,015人（25.1%）** が1歳多い。ずれは最大1歳
- **基準日で大きく変わる**：1月1日なら99.7%、4月1日74.9%、7月1日50.2%、12月1日8.1%、12月31日0%。基準日より後に誕生日がある人の割合そのもの
- **年代別の人数**：10月1日基準で、20代は−2.9%、60代は+2.7%、70代は+4.2%（人数の少ない10代は−24.2%）
- **線の上下**：65歳以上は本当は1,142人のところ1,203人（+61人、+5.3%）。30歳以上は+72人

## 動かし方
```
pip install -r requirements.txt
cd src && python a704_age.py
```
数秒で終わります。`data/members.csv` に会員の生年月日を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- DuckDB の date_diff('year') と月日の比較による年齢が、pandas の計算と一致した。10歳ごとの人数も一致した
- T-SQL 版（`01_age_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）
- 2月29日生まれ（13人）は、うるう年でない年は3月1日に1つ上がる扱い（月日の比較による）。DuckDB の date_sub('year') は2月28日に上がる扱いで、ここだけ答えが違う

## データ
- `data/members.csv`：member_id・birth_date
- 仮定：生まれた年は1980年ごろを山にした形（作成者が置いた）。誕生日の月日は一様

## 注意（言えないこと）
- 架空のデータ。1歳多い人の割合は、ほぼ「基準日より後に誕生日が来る人の割合」で決まる
- 法律や制度で年齢の数え方が決まっている場面（誕生日の前日に1つ上がる、など）は扱っていない。数え方はそれぞれの決まりに従う
- 実在の会員の数字ではない
