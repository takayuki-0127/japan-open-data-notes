# 693 月数を「月の境目をまたいだ回数」で数えると、契約の経過月数は何件ずれるのか（実務の型）

SQL Server の DATEDIFF(month, 開始日, 終了日) は、日にちを見ずに「月の境目を何回またいだか」を返します。1月31日から2月1日までは1日しかたっていなくても1か月です。**ここでは、架空の契約3万件（2023〜2025年開始、長さ1日〜3年、月末に始まる契約を多め）で、経過月数を「境目の回数」「満了した月数」「日数÷30」の3通りで数え、食い違う件数と「6か月以上」などの区分の取り違えを数えました。** DuckDB の datediff('month')（境目の回数）と date_sub('month')（満了した月数）で、Python と一致することを確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A693 | 月数の数え方で、経過月数はどれだけずれるか | 境目の回数＝(年の差)×12＋(月の差)。満了した月数＝境目の回数から、終了日の日が開始日の日より小さければ1を引く（終了日が月末なら引かない）。日数÷30 の切り捨て。DuckDB の SQL と assert で一致を確認。seed 693 | `src/a693_month_count.py`、`src/02_month_count_duckdb.sql`、`src/01_month_count_tsql.sql`（T-SQL：未検証） |

## 主な結果（3万件）
| 項目 | 境目の回数（DATEDIFF 型） | 日数÷30 |
|---|---|---|
| 満了した月数と違う契約 | **16,565件（55.2%）**、すべて1か月多い | 5,575件（18.6%）、ほとんど1か月多い |
| 「1か月以上か」の取り違え | 842件 | 35件 |
| 「6か月以上か」の取り違え | 849件 | 139件 |
| 「12か月以上か」の取り違え | 880件 | 294件 |

- 例：2025-01-31 → 2025-02-01 は、境目の回数で1、満了した月数で0、日数÷30 で0。2025-01-15 → 2025-07-14 は、6・5・6
- 境目の回数は、1日に始まった契約では一度も食い違わず、月末に始まった契約では96%が1か月多かった
- 日数÷30 は、短い契約では合うが、長い契約ほど多く数えた（24か月以上の契約の43%が1か月多い）。1年は365日なので、30で割ると12.2か月になるため

## 注意（言えないこと）
- 架空のデータです。月末に始まる契約の多さと契約の長さは作成者が置いたもので、件数はこれで決まります
- 「満了した月数」の決め方（月末どうしを満了とみなすか）は、契約や社内の決まりによって違います。ここでは DuckDB の date_sub に合わせました
- 料金や解約の条件の助言はしません。数え方の違いを見たものです
- SQL Server では動かしていません（T-SQL 版は未検証）
