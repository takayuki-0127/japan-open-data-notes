# 673 1つの注文を、使ったクーポンそれぞれに全額付けると、クーポン別の売上の合計は実際の何倍になるのか（実務の型）

クーポンを何枚も併用できる通販では、「クーポン別の売上」をどう数えるかで数字が大きく変わります。使ったクーポンそれぞれに注文の全額を付けると、併用された注文は何回も数えられ、クーポン別の売上を足すと実際の売上より大きくなります。**ここでは、架空の注文3万件（クーポンを使った注文16,629件、うち37.9%が2枚以上の併用）で、全額を付ける・値引き額で按分する・最初の1つに付けるの3通りでクーポン別の売上を出し、合計と順位を比べました。** 数字は置いた併用の起き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A673 | 全額を付けると、クーポン別の売上の合計は実際の何倍になるか | 注文3万件、クーポン8種類（値引き200〜1,000円）。45%はクーポンなし、残りは1〜3枚を併用。送料無料の G・H は併用されやすい。全額・値引き額で按分・最初の1つの3通りで帰属させる。併用の割合を0〜80%で変えた場合も。seed 673。全額と按分は DuckDB の SQL でも出して一致を確認 | `src/a673_coupon.py`、`src/02_attribution_duckdb.sql`、`src/01_attribution_tsql.sql` |

## 主な結果
- **全額を付けると、クーポン別の売上の合計は1億7,709万円で、クーポンを使った注文の実際の売上1億1,956万円の1.48倍**。倍率は「クーポンを使った注文1件あたりの枚数の平均」（1.48枚）と同じになる
- 按分と最初の1つに付ける方法では、合計は実際の売上と一致する
- **併用が多いほど倍率は大きくなる**：併用の割合が20%で1.25倍、38%で1.48倍、60%で1.80倍、80%で2.16倍
- クーポン別に見ると、全額は按分の1.23〜1.80倍。値引き額の小さい D（200円）は、按分では取り分が小さいので差が最も大きい（1.80倍）
- **順位も入れ替わる**：送料無料の G は、全額・按分では3位、最初の1つに付けると7位。8つのうち4つで、全額と按分の順位が違った

## 動かし方
```
pip install -r requirements.txt
cd src && python a673_coupon.py
```
十数秒で終わります。`data/orders.csv`・`data/order_coupons.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 全額と按分のクーポン別の売上が、Python と DuckDB の SQL で一致すること
- 按分と最初の1つに付ける方法の合計が、クーポンを使った注文の実際の売上と一致すること

## データ
- `data/orders.csv`：架空の注文（order_id・amount）
- `data/order_coupons.csv`：注文で使ったクーポン（order_id・coupon・entry_order＝入れた順・discount＝値引き額）

## 注意（言えないこと）
- 架空のデータ。併用の起き方は作成者が置いたもので、結果はこれで決まる
- どの帰属のしかたが「正しい」かは決まらない。クーポンがなければ注文がなかったのか（効果）は、帰属のしかたでは分からず、配る・配らないを比べる実験が要る
- 値引きの会計上の扱いの助言ではない。T-SQL 版は未検証
