# 462 2つの期間が重なるかどうかの条件を書き間違えると、何件が漏れ、何件が余分に入るのか（実務の型）

架空の契約期間（2万件）とキャンペーン期間（12本）の24万組で、「期間が重なる」条件の正しい書き方と、よくある書き間違い6通りを比べたフォルダです。314（在籍件数）・386（以上と超）とは別に、2つの期間の重なりの判定だけを扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A462 | 書き間違いごとに、何組が漏れ、何組が余分に入るか。どの並び方の組で外れるか。端の値だけのテストで見つかるか | 24万組すべてに7通りの条件を当てて比べる（DuckDB）。正しい条件は pandas と、1日ずつ並べる方法（契約500件）でも確かめる。テストは手作りの12組と、本番の組からのくじ（2,000回） | `src/a462_overlap.py`、`src/01_overlap_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
24万組のうち、本当に重なるのは85,699組。期間は両端を含む。終了日が空（続行中）の契約は1,628件

| 書き方 | 漏れ | 余分 | 手作り12組で外れた組 | くじ100組で見つかる割合 |
|---|---|---|---|---|
| ① 開始日が期間の中かだけを見る | 76,075（88.8%） | 0 | 4 | 100% |
| ② 開始日か終了日が期間の中 | 69,329（80.9%） | 0 | 2 | 100% |
| ③ 端を含めない（< と >） | 991（1.2%） | 0 | 3 | 32.1% |
| ④ 終了日の空を考えない | 12,270（14.3%） | 0 | 1 | 99.4% |
| ⑤ AND を OR にする | 0 | 154,301（180.0%） | 3 | 100% |
| ⑥ 開始の時点で有効かだけを見る | 6,817（8.0%） | 0 | 3 | 94.5% |

- %は、本当に重なる85,699組に対する割合
- **どの並び方で外れるか**：①は「前からまたぐ」「すっぽり含む」を全部落とす。②は「契約がキャンペーンをすっぽり含む」57,837組を全部落とす。③は「端が同じ日」の771組を全部と、1日だけの期間どうしを落とす。④は終了日が空の契約の12,270組を全部落とす。⑥は期間の途中で始まった契約を落とす
- **1日だけのキャンペーン**（2本、正しくは4,030件と7,600件）：③は3,732件と7,287件。①は295件と294件
- **キャンペーンごとの件数のずれ**：③は−0.2〜−7.4%、④は−7.9〜−20.7%、⑥は0〜−28.3%
- **テスト**：端の値を並べた手作りの12組は、6通りの書き間違いをすべて見つけた。本番の組からくじで選ぶと、③は20組で8.0%、100組で32.1%、1,000組で98.6%

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- 正しい条件の結果は、pandas で出した数と一致する。契約500件×12本は、日を1日ずつ並べて「同じ日が1日でもあるか」で確かめた（コード内の assert）

## データ
- `data/contracts.csv`（架空の契約2万件）、`data/campaigns.csv`（架空のキャンペーン12本）。seed 462

## 注意（言えないこと）
- 架空のデータ。漏れと余分の件数は、契約の長さ・始まる日の寄り方・キャンペーンの置き方で決まる
- 期間は「両端を含む」と決めた。終了日を含まない決まり（半開区間）のデータでは、正しい条件は < と > になる。③が誤りになるのは、両端を含む決まりのデータに当てた場合
- 日付だけを扱った。時刻つきの期間は扱っていない
- 手作りの12組は、書き間違いを知ったうえで作った。見つかる割合は有利な数字
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
