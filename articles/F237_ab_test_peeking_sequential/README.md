# F237 A/B テストを途中で見ると、何がまずいのか

シリーズ「実務に近い分析」（F231〜F245）の7本目。A/B テストを始めたあと、結果を毎日（あるいは毎時間）見て「有意になったら止める」と何が起きるかを、シミュレーションで確かめた。あわせて、途中で見ても誤検出を5%に保つ方法（α 消費関数による群逐次検定、mSPRT）を同じ条件で比べ、テストの運用ルールの表にまとめた。前提（基準の購入率5%、見つけたい差 +10%、1日5,000人）は F236「A/B テストは、何人集めれば差が分かるのか」の設計表と同じ。テストのデータはすべてシミュレーションで、架空のECサイト「みどりモール」を想定している。

## 問い

- 結果を途中で何度も見て、そのたびに「|z| ≥ 1.96 なら止める」と、差がないのに「有意」と判定する割合はどれだけ増えるのか
- 途中で見ても誤検出を5%に保つには、どんな境界（止める基準）を使えばよいのか。止めるのは早くなるのか
- 「いつ見てもよい p 値」（mSPRT）は、決めた日だけ見る方法と比べてどうか
- 途中で止めたときの「差の大きさ」は信じてよいのか

## データ

テストのデータはすべてシミュレーション（`src/common.py`）。

| 前提 | 値 | 理由 |
|---|---|---|
| いまの購入率（基準） | 5% | F236 の基準と同じ |
| 見つけたい差 | 相対 +10%（5% → 5.5%） | F236 と同じ |
| 訪問者 | 1日5,000人（2群に半分ずつ、1時間ごとに均等） | F236 の設計表の行 |
| 固定の判定日 | 14日目（1群35,000人） | F236 の式で +10% に必要な人数（31,234人）を週単位に切り上げ |
| 連続で見る方法の上限 | 28日 | mSPRT の比べ |

各条件2万回（頑健性は1万回）。乱数の種は固定。

## 手法

- **調整なしで途中を見る**：決めた回数（1〜672回）だけ累積の z（2つの割合の差、併合した割合で標準誤差）を計算し、どこかで |z| ≥ 1.96 になったら止める
- **群逐次検定（α 消費関数）**：見る日の「情報の割合」t（その日までの人数÷最大の人数）で、使ってよい α を O'Brien-Fleming 型（α(t) = 2 − 2Φ(1.96/√t)）か Pocock 型（α(t) = 0.05·ln(1+(e−1)t)）で割り振り、各回の境界をブラウン運動のシミュレーション（40万本）で決めた（Lan-DeMets の方法）。最大の人数は固定の判定日と同じにした（人数を増やす調整はしていない）
- **mSPRT**：差 θ に正規分布の混合（平均0、標準偏差 τ）を置いた尤度比 Λ から、いつ見てもよい p 値 p_n = min(p_{n−1}, 1/Λ_n) を1時間ごとに計算し、0.05 を下回ったら止める。τ は見つけたい差（0.005＝5%×10%）を主に使った
- 評価：誤検出（差がないときに止める割合）、検出力（+10% のときに止める割合）、終わるまでの平均日数、止めたときの差 ÷ 本当の差

## 結果

### 1. 途中で見る回数と誤検出（差がないとき、14日間）

| 見る回数 | 誤検出 |
|---|---|
| 1回（14日目だけ） | 4.8% |
| 2回（7・14日目） | 8.2% |
| 4回（4・7・11・14日目） | 12.2% |
| 7回（2日ごと） | 16.5% |
| 14回（毎日） | 21.9% |
| 336回（1時間ごと） | 46.0% |
| 28回（毎日・28日間） | 27.8% |
| 672回（1時間ごと・28日間） | 50.3% |

毎日見たときの誤検出のうち24%は1日目に、半分は3日目までに起きた。人数が少ない最初のうちは、z が大きく振れるため。

### 2. 境界（誤検出を5%に保つ値）

| 見る日 | O'Brien-Fleming | Pocock |
|---|---|---|
| 4日目 | 3.67 | 2.32 |
| 7日目 | 2.77 | 2.38 |
| 11日目 | 2.24 | 2.34 |
| 14日目 | 2.05 | 2.36 |

毎日（14回）見る O'Brien-Fleming の境界は 7.33（1日目）→ 2.14（14日目）。

### 3. ルールの比べ（基準5%・+10%・1日5,000人、各2万回）

| ルール | 誤検出 | 検出力 | 平均日数（+10%のとき） | 止めたときの差÷本当の差（中央値） |
|---|---|---|---|---|
| 固定（14日目に1回） | 4.8% | 84.6% | 14.0 | 1.07 |
| 毎日見て1.96で止める | 21.9% | 90.7% | 6.2 | 1.34 |
| 4回・O'Brien-Fleming | 5.0% | 83.7% | 11.0 | 1.13 |
| 4回・Pocock | 5.1% | 77.8% | 9.7 | 1.28 |
| 毎日・O'Brien-Fleming | 4.9% | 82.9% | 10.0 | 1.19 |
| mSPRT（1時間ごと・14日まで） | 1.8% | 59.8% | 10.4 | 1.42 |
| mSPRT（1時間ごと・28日まで） | 2.5% | 92.3% | 13.2 | 1.18 |

- O'Brien-Fleming は、誤検出5%と検出力（84%）をほぼ保ったまま、差があるときは平均3日早く終わった
- Pocock は早く止まりやすいが、最大の人数を増やさないと検出力が下がる（78%）
- mSPRT は誤検出が5%より低め（2〜3%、保守的）。上限が14日だと検出力が60%しかなく、28日まで延ばすと92%になるが、平均日数は固定とほぼ同じ（13.2日）
- 途中で止める方法はどれも、止めたときの差が本当の差より大きめに出る（1.13〜1.42倍）。毎日1.96で止めると1.34倍

### 4. mSPRT の τ の選び方（28日まで、各1万回）

| τ（購入率の差） | 誤検出 | 検出力 | 平均日数 |
|---|---|---|---|
| 0.0025（見つけたい差の半分） | 1.4% | 90.7% | 15.5 |
| 0.005（見つけたい差） | 2.7% | 91.5% | 13.4 |
| 0.01（2倍） | 3.5% | 89.3% | 13.5 |
| 0.02（4倍） | 3.4% | 85.7% | 14.6 |

τ を見つけたい差の近くに置くと、いちばん早く終わった。

### 5. SQL とダッシュボード

- `sql/01_日ごとの累積とzと止める判定_tsql.sql`：日別の訪問者・購入数から、ウィンドウ関数で累積の購入率と z を出し、「毎日1.96で判定」と「決めた日に境界で判定」を並べる（SQL Server / T-SQL）。DuckDB で動かして（FLOAT を DOUBLE に読み替え）、2つの例（各14日）で Python と照合した。z の差は最大 4.4e-16、止める判定は全日一致。SQL Server では動かしていない
- `dashboard/index.html`：途中経過を見るダッシュボード（静的な HTML 1枚、架空の社内向け）。例1（本当は差がない）は、毎日1.96で判定すると3日目に「有意」になるが、決めた日の境界は一度も越えず、14日目の差は +2.7%（95%区間 −3.9〜+9.3%）だった

## 頑健性

| 確かめたこと | 毎日1.96 | 4回・O'Brien-Fleming | mSPRT（28日） |
|---|---|---|---|
| 基準の購入率2%（誤検出／検出力） | 22.0%／61.5% | 5.1%／43.5% | 1.8%／45.8% |
| 基準の購入率20% | 21.8%／100% | 4.9%／100% | 3.3%／100% |
| 曜日のパターンあり（週末は訪問者1.6倍・購入率0.85倍） | 22.2%／91.0% | 5.2%／83.8% | 2.4%／92.5% |
| 乱数の種を3通り（誤検出） | 22.2〜23.1% | 4.8〜5.1% | — |

- **見る日が予定とずれた**（5・9・12・14日目に見た）：実際の情報の割合で境界を計算し直すと誤検出5.0%、予定の境界のまま使っても4.7%
- **決めた4回に加えて、毎日1.96でも判定した**：誤検出20.4%。決めたルールの外で判定すると、境界を使った意味がなくなる
- **片側（良くなったときだけ止める、1.645）**：1回だけなら5.4%、毎日見ると19.6%
- 曜日のパターンがあっても、固定の判定（14日目）の誤検出は5.0%で変わらなかった

## 言えないこと

- **すべてシミュレーション**：実際のテストでは、目新しさの効果（最初だけ反応が良い）、同じ人が何度も来る、群の割り当ての不具合などがあり、ここより悪くなりうる
- **人数は増やしていない**：群逐次検定では、検出力を保つために最大の人数を少し増やすのがふつう（O'Brien-Fleming で数%、Pocock で約2割）。ここでは固定と同じ最大の人数で比べたので、Pocock の検出力は低めに出ている
- **mSPRT は正規近似**：1時間ごとの購入率から分散を出す簡単な形にした。購入数が少ない最初の数時間は近似が粗い。実際の製品（実験基盤）の実装とは細部が違う
- **止めたときの差の補正はしていない**：途中で止めた推定は大きめに出る。補正した推定（中央値不偏推定など）や、止めた後の区間の出し方は扱っていない
- **指標は購入率1つ**：金額の指標や、複数の指標を同時に見る場合（多重比較）は扱っていない
- **差の大きさを小さくする方法（前の期間のデータを使う CUPED など）**は F238 で扱う
