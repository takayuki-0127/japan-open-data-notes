# 385 図には、軸の名前・単位・出典がそろっているか（④ 振り返り R115）

GitHub に置いた記事637本の、図を作るコード2,520枚分を読み、軸の名前・題名・凡例・単位・出典を書き込む命令があるかを数えた

## 問い

- 図に、題名・軸の名前・単位・凡例・出典はどれだけ入っているか
- 記事のまとまりで違いはあるか
- 出典は、記事の中でそろっているか

## 手法

| 手順 | 中身 |
|---|---|
| 拾う（`src/a385_extract.py`） | `articles/*/` の .py から、図を保存する所（`.savefig(` の行と、savefig を中に持つ自作の関数を呼ぶ行）を探す。前の保存の次の行からそこまでを図1枚分とみなす（コミット 00b426f） |
| 要素 | 軸の名前（set_xlabel・set_ylabel など）、題名、凡例、出典を、文字の並びで探す。出典は「文字を書く命令と出典の文が同じ行にある」「出典を書く自作の関数を呼ぶ」「保存の関数に出典の文を渡す」「保存の関数が出典を書き込む」のどれか。架空・合成のデータであることの注記も出典に数える |
| 数の軸 | 横向きの棒グラフ（barh）なら横軸、それ以外は縦軸。表・模式図（軸を消した図）と色のマスの図（imshow など）は軸の集計から外す |
| 単位 | 軸の名前の文字に、かっこ書きか % がある |
| まとめ方（`src/a385.py`） | 要素ごと・まとまりごとの割合、記事ごとの出典のそろい方 |

240（縦軸の0）・F164（図の数と読まれ方）とは別で、要素があるかどうかだけを数える

## 主な結果（`results/summary.json`、`results/elements_axis_figures.csv`）

- 図2,520枚分（637本、1本あたり中央値3枚）。置いてある PNG は2,605枚で、枚数が同じ記事は91%
- 表・模式図90枚、色のマスの図75枚を除いた軸のある図は2,355枚
- 軸のある図：題名98%、数の軸の名前83%、軸の名前に単位74%（軸の名前が1つでもある図では81%）、凡例66%、出典50%

- 保存の関数を通した図の78%に出典があり、savefig を直接書いた図は36%
- 記事ごと：全部の図に出典359本（56%）、一部だけ39本、どの図にもなし239本（38%）

## 確かめたこと

- 図の枚数：コードから数えた2,520枚と、figures フォルダの PNG 2,605枚を記事ごとに比べた（同じ91%、差が1枚以内97%）
- 画像を18枚（まとまりごとに無作為に2〜3枚）目で見た。出典ありと判定した5枚は全部あり。なしと判定した13枚のうち1枚に、架空のデータであることの注記があった（別の書き方で、判定が拾えなかった）。最初の版で拾えなかった「保存の関数に出典の文を渡す」形は、判定に足した
- `src/a385_extract.py` と `src/a385.py` を空のフォルダで流し直し、data・results・figures が一致することを確かめた

## 注意（言えないこと）

- 読んだのはコードで、画像そのものは見ていない。出典の割合は、実際より少し低く出ている可能性がある
- 図1枚分のコードは「前の保存から次の保存まで」。関数の中で描いて何回も呼ぶ図は1枚に数えている
- 単位は軸の名前の文字だけで判定した。題名や注記に単位を書いた図は「単位なし」になる
- 要素があるかどうかだけを数えた。名前が分かりやすいか、単位が正しいかは見ていない
