# F110 予測モデルの設定は、どう選ぶのが効率的か？ ベイズ最適化とグリッド・ランダム探索を比べる

看板記事シリーズの110本目です。LightGBM の6つの設定（ハイパーパラメータ）を、グリッド探索・ランダム探索・ベイズ最適化（TPE とガウス過程）の4つの方法で選び、「何回試せば、どれだけよい設定に届くか」と「検証で選んだ設定は、テストでも本当によいか」を比べます。題材は、これまでの記事で使った2つの予測（東京の日次電力需要＝F22・F67、地価公示＝F03）です。新しいデータは取っていません。

## 問い

- 試せる回数が限られているとき、ベイズ最適化はグリッドやランダムより早くよい設定に届くか
- 見つけた「よい設定」は、選ぶのに使っていないデータ（その後の期間・別の地域）でもよいか。既定値と比べてどれだけ得か

## データ

| データ | 内容 | 分け方 |
|---|---|---|
| 電力需要（`data/power_daily_tokyo.csv`） | F67 で作った東京エリアの日次需要（2016/4〜2026/8、3,834日）と東京の気温・湿度・降水量・祝日など。目的変数は log(日量) | 時間の順に、学習 2016/4〜2022/3（2,190日）、検証 2022/4〜2024/3（731日）、テスト 2024/4〜（913日） |
| 地価公示（`data/land_features.csv`） | F03 で作った2026年の25,565地点の価格と30個の特徴量。目的変数は log(価格) | 20km 四方のブロック単位で、学習60%（15,116地点）・検証20%（5,249）・テスト20%（5,200）。同じブロックの地点は同じ側に入る |

元データは、電力が 東京電力パワーグリッド「エリア需給実績」と気象庁「過去の気象データ」（東京の日別値。F22・F67 の README）、地価が国土交通省「国土数値情報」の地価公示・駅別乗降客数と総務省「令和2年国勢調査」（F03 の README）です。

## 手法

| 項目 | 内容 |
|---|---|
| モデル | LightGBM（回帰、1スレッド）。検証データで早期打ち切り（50回改善なしで止める、最大 電力1,000・地価800本） |
| 選ぶ設定（6つ） | 学習率 0.02〜0.3、葉の数 4〜256、葉の最小件数 2〜200、使う特徴量の割合 0.3〜1、使う行の割合 0.3〜1、L2 正則化 0.001〜30（学習率・葉・最小件数・L2 は対数の目盛り） |
| 目的 | 検証データの RMSE（log）を小さくする |
| 方法 | ① グリッド：学習率3×葉3×最小件数2×特徴量の割合2＝36通り（残りは既定値）を乱数の順に ② ランダム ③ TPE（Optuna、多変量、最初の10回はランダム） ④ ガウス過程のベイズ最適化（Optuna の GPSampler、最初の10回はランダム） |
| 予算 | 1回の探索で40回（グリッドは36回で打ち止め）。電力は乱数5つ、地価は3つ |
| 評価 | ① その回までの最良の検証誤差 ② 既定値（学習率0.1・葉31・最小件数20、行と特徴量は全部・L2 なし）から「全探索で見つかった最良」までの改善幅の5割・8割・9割に届いた回数 ③ 検証で選んだ設定のテスト誤差 ④ 選んだ設定を、学習の乱数5つで作り直したテスト誤差（地価はデータの分け方を2つ変えても） |

## 主な結果

### 1. 何回試せば、よい設定に届くか（40回、乱数の平均）

| 題材 | 方法 | 最良の検証誤差（10回） | （20回） | （40回） | 改善幅の8割に届いた回数（中央値） | 40回で届かなかった探索 |
|---|---|---|---|---|---|---|
| 電力 | グリッド | 0.0310 | 0.0309 | 0.0308 | — | 5/5 |
| 電力 | ランダム | 0.0315 | 0.0299 | 0.0296 | 26 | 3/5 |
| 電力 | TPE | 0.0315 | 0.0299 | **0.0283** | 23 | 0/5 |
| 電力 | ガウス過程 | 0.0315 | 0.0297 | 0.0285 | 21 | 0/5 |
| 地価 | グリッド | 0.3554 | 0.3491 | 0.3491 | — | 3/3 |
| 地価 | ランダム | 0.3485 | 0.3469 | 0.3456 | 26.5 | 1/3 |
| 地価 | TPE | 0.3485 | 0.3469 | **0.3443** | 34 | 0/3 |
| 地価 | ガウス過程 | 0.3485 | 0.3466 | 0.3466 | 11 | 2/3 |

既定値の検証誤差は電力 0.0369、地価 0.3584。全探索で見つかった最良は電力 0.0278、地価 0.3430。

- **電力**：既定値から最良までの改善は約25%と大きく、ベイズ最適化の2つは5回とも40回以内に改善幅の8割に届いた。ランダムは5回中3回届かず、グリッドは届かなかった。改善幅の9割には TPE が5回中4回届き（中央値21.5回）、ガウス過程は3回、ランダムとグリッドは0回
- **地価**：改善は約4%と小さく、最初の数回で改善幅の半分に届く（グリッド以外は中央値2回）。そこから先は手法の差より乱数の差が大きい。ガウス過程は1回目の探索が11回で届いた一方、2回は40回で届かなかった
- グリッドは、どちらの題材でも最後まで最良に届かない。よい設定が、グリッドの点（葉8・32・128 など）と行の割合・L2 の既定値の外にあったため
- 地価で40回の学習にかかった時間（1スレッド）は、グリッド52秒、ランダム79秒、TPE 93秒、ガウス過程100秒。ベイズ最適化は学習率の小さい（＝本数の多い）設定を選びがちで、1回あたりが重くなった（選ぶ計算そのものの時間は含まない）

### 2. 検証でよかった設定は、テストでもよいか

| 題材 | 既定値のテスト誤差 | 各方法の最良設定のテスト誤差（乱数の平均） |
|---|---|---|
| 電力 | 0.0457 | グリッド 0.0400、ランダム 0.0373、TPE 0.0360、ガウス過程 0.0369 |
| 地価 | 0.3288 | グリッド 0.3184、ランダム 0.3223、TPE 0.3193、ガウス過程 0.3209 |

- 電力は、どの方法で選んでもテスト誤差が既定値より12〜21%小さい（log RMSE 0.046→0.036、おおよそ外れ方4.6%→3.6%）。最良の設定は葉8・特徴量の割合0.38・行の割合0.3 と、既定値よりずっと小さく、ばらつきを入れた木
- 地価は、テストでの差が2〜3%。しかも検証で最も悪かったグリッドの設定が、テストではいちばんよかった
- 試した全設定で、検証誤差とテスト誤差の相関は電力0.98・地価0.86と高い。ところが検証誤差の上位5%（電力39個・地価23個）の中だけで見ると、相関は0.22・0.11。**よい設定どうしの細かい順位は、テストでは当てにならない**

### 3. 学習の乱数とデータの分け方を変えて作り直すと（図4）

- 電力：選んだ設定（各方法の乱数0の回）は、学習の乱数を5つ変えても、テスト誤差が既定値より平均12.5〜15.7%小さい。方法どうしの差（平均で最大3ポイント）は、学習の乱数によるばらつき（同じ設定で最大12ポイントの幅）より小さい
- 地価：選んだ分け方では既定値より2.2〜2.9%よいが、ブロックの分け方を変えて作り直すと、既定値との差は −3.2%〜+3.4%（方法ごとの平均）に散らばった。TPE の設定は一方の分け方で+1.7%、もう一方で−1.7%、ガウス過程の設定は+0.8%・+3.4% と、既定値より悪くなる分け方もある

## 頑健性

| 確かめたこと | 結果 |
|---|---|
| 探索範囲を既定値のまわりに狭める（電力、学習率0.05〜0.2・葉16〜64 など、乱数5つ） | 40回の最良は TPE 0.0299・ガウス過程 0.0298・グリッド 0.0303・ランダム 0.0318。どれも広い範囲の TPE（0.0283）に届かない。よい設定（小さい木）が狭い範囲の外にあるため。ベイズ最適化がランダムより早いのは同じ |
| 回数を100回に増やす（電力、別の乱数3つ） | 100回の最良は TPE 0.0278・ガウス過程 0.0283・ランダム 0.0288。テスト誤差は 0.0347・0.0350・0.0366。順位は40回と同じで、差は少し縮む |
| 乱数（探索の乱数 電力5・地価3、学習の乱数5） | 電力の「ベイズ最適化が早い」は5回とも同じ。地価は乱数で順位が入れ替わる |
| データの分け方（地価のブロックの分け方を3通り） | 上の3。既定値との差は分け方で符号が変わる |
| 題材（電力と地価） | 既定値から改善の余地が大きい電力ではベイズ最適化の得が見え、余地の小さい地価では見えない |

## 動かし方

```
pip install -r requirements.txt
cd src
python3 01_取得.py      # F03・F67 の表を data/ にコピー（リポジトリ全体があるとき）
python3 02_整形.py      # 学習・検証・テストの件数を確かめる
bash zz_f110_run_all.sh  # 探索（電力→地価→狭い範囲→100回）と作り直し。1スレッドで合計30〜40分ほど
python3 04_図.py        # 集計と図
```

- `03_探索.py` は「題材 範囲 回数 乱数 方法 出力名」を引数に取り、1回の探索ごとに `results/trials_*.csv` に追記する（止まっても続きから再開できる）
- `03b_ばらつき.py` は各方法の最良設定（乱数0の回）と既定値を、学習の乱数・データの分け方を変えて作り直す
- Optuna 4 以上（GPSampler に PyTorch と SciPy が必要）。ランダム・TPE・ガウス過程は最初の10回が同じ乱数の列になる（同じシードの RandomSampler を使うため）

## 言えないこと

- 比べたのは LightGBM の6つの設定と、2つの題材（数千〜2万件の表データ）だけです。設定の数が多いモデル（ニューラルネットなど）や、1回の学習が重い題材では、ベイズ最適化の得はもっと大きくなりえます
- 「早い・遅い」は試した回数で比べています。選ぶ計算の時間（特にガウス過程）や、選んだ設定の学習の重さは揃えていません
- 検証は1つの分け方（電力は1つの期間、地価は1つのブロックの分け方）です。交差検証で選べば、地価で見えた「分け方による入れ替わり」は小さくなるはずですが、その分の計算は増えます（推測）
- 乱数の数（電力5、地価3）が少ないので、方法どうしの差の区間は出していません。地価での方法の順位は、乱数を増やせば変わりえます
- グリッドの点の置き方を変えれば、グリッドの成績は変わります。ここでは36点の粗いグリッドです
