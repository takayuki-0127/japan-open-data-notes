# 664 平均単価の前年比を、品目の構成の変化と単価の変化に分けると、それぞれどれだけになるのか（実務の型・売上の分解）

平均単価（売上÷数量）は、1つ1つの品目の値段が変わらなくても、高い品目がよく売れるようになるだけで上がります。そこで、平均単価の変化を「単価の効果」と「構成（ミックス）の効果」に分けることがよくあります。ただし、分け方の順番と、どの単位（品目か分類か）で分けるかで、取り分が変わります。**ここでは、架空の店の12品目（飲み物・総菜・弁当の3分類×4品目）の2024年と2025年の数量と単価で、分け方ごとの違いを比べました。** 数量と単価の変わり方は作成者が置いたもので、数字はその仮定で決まります。

## 主な結果
- **平均単価は340.3円から378.2円へ、+11.15%**（数量の合計は+2.2%）
- **品目の単位で、両方の平均で分けると、単価の効果は+4.82ポイント、構成の効果は+6.32ポイント**。変化の57%が構成の変化から来ていた
- **分け方の順番**：価格を先にすると単価+4.51・構成+6.63、構成を先にすると単価+5.13・構成+6.02。差は0.62ポイントで、これは単価と構成が一緒に動いた分（交差の項）にあたる。高い品目ほど数量も値上げも増えたので、交差の項はプラスになる
- **分類の単位（3つ）で分けると、構成の効果は+2.23ポイントに縮み**、単価の効果は+8.92ポイントに増えた。分類の中で高い品目に移った分が、「単価」に入るため

## 動かし方
```
pip install -r requirements.txt
cd src && python a664_mix.py
```
数秒で終わります。`data/items.csv`（item・category・year・qty・price）を書き出し、`results/` に品目ごと・分類ごとの割合と単価を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 品目の単位と分類の単位の分解が、DuckDB と pandas で一致した。単価の効果と構成の効果の合計は、平均単価の変化と一致する
- T-SQL 版（`01_mix_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 仮定：品目の単価は120〜980円。2024年の数量は単価が高いほど少ない
- 2025年は、分類の中で高い品目ほど数量が増え（いちばん安い品目は約12%減、いちばん高い品目は約18%増）、値上げも大きい（おおむね1%〜9%）。弁当の数量は、さらに8%増やした

## 注意（言えないこと）
- 架空のデータ。実際の店の数字ではない
- どの分け方が正しい、というものはない。順番と単位を決めて、同じ方法で毎年出すのが大事。報告には、どの方法で分けたかを書いておく
- 値上げで数量が減った、といった因果は、この分解からは言えない。分解は、起きた変化を足し算で分けているだけ
