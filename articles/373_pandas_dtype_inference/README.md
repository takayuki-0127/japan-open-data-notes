# 373 pandas で型を指定せずに読むと、何列が意図と違う型になるのか（実務の型）

`pd.read_csv(ファイル)` とだけ書いて読んだとき、列の型がどれだけ意図と違うかを数えたフォルダです。公的統計の CSV 10本（これまでの記事で使った手元の写し）と、正解の型を決めた架空の CSV（24列×3,000行）の2つで確かめました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A373 | 型を指定せずに読むと、数字のはずの列は何列が数字で読めるか。値が変わるセルはあるか | 公的統計：各ファイルを文字のまま読み、空でないセルの半分以上が数字・記号の行を「データの行」、その8割以上が数字・記号の列を「数字のはずの列」と決める（機械的な判定）。指定を1つずつ足して読み、数字で読めた列を数える。架空：正解の型と読み込み後の型を比べ、文字に戻して元と違うセルを数える | `src/a373_dtype_inference.py` |

## 主な結果
- **公的統計の CSV 10本を何も指定しないで読む**：5本はエラー（文字コード2本、列の数がそろわない3本）、1本は全体が1列として読まれ、表の形で読めたのは4本。数字のはずの431列のうち、数字で読めたのは3列（0.7%）
- 表の形で読めた4本でも、147列は見出しや注の行が混ざって文字になり、9列は欠測の記号（「-」）で文字になった。地域コード1列は数字で読まれ、58セルで先頭の0が落ちた
- **指定を足していく**：文字コードだけ 3列（0.7%）→ 見出しの行を飛ばす 186列（43%）→ 欠測の記号を指定 302列（70%）→ 桁区切りを指定 302列（70%、この10本にコンマつきの数字はなかった）→ 表の途中と末尾の文字の行を除く 430列（99.8%）
- **架空の24列**：意図どおりは9列。型が意図と違うのは14列。うち9列は文字のまま残り（「-」「…」、桁区切り、%、▲、日付、空欄のある真偽、全角の数字）、1列は整数が小数になった（空欄があるため、値は同じ）
- **値が黙って変わった列は5列・4,742セル**：市区町村コード1,001、店舗コード291、郵便番号321、電話番号3,000（先頭の0が落ちる）、国コード129（「NA」が欠測になる）。国コードは型が文字のままなので、型だけを見ても気づけない
- 型と欠測の記号を指定して読むと、24列すべてが意図どおりになった

## 動かし方
```
pip install -r requirements.txt
cd src && python a373_dtype_inference.py
```
乱数の種を固定してあるので、実行のたびに同じ `data/fake_customers.csv`・`results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダ（`data/public/` だけを置いた状態）で流し直し、data・results・figures が一致した
- 架空の CSV は、すべて文字で読み直すと作ったときの値と一致した（コード内の assert）
- pandas 2.3.3 で実行した。型の推定の決まりは版で変わることがある

## データ
- `data/public/`：公的統計の CSV 10本（下の出典）。これまでの記事のフォルダにあった写しで、01 は記事211で整えたあとの表、02〜10 は公表されたファイル（公表された Excel を CSV に直したものを含む）
- `data/fake_customers.csv`：架空の CSV（seed 373）
- `results/public_files.csv`：ファイルごとの結果。`results/public_columns_by_cause.csv`：文字になった原因。`results/fake_columns.csv`：架空の24列

## 注意（言えないこと）
- 公的統計の10本は、手元にあったものから選びました。公的統計の CSV 全体の割合ではありません
- 「数字のはずの列」は機械的に決めました。見出しが何行もある表では、人が見て決めた列と1〜2列ずれることがあります
- 公的統計の CSV は、人が読む表をそのまま CSV にしたものが多く、型の推定の前に、表の形を取り出す作業が要ります。0.7%という数字は、pandas の型の推定が弱いという意味ではありません
- 「-」を0と読むか欠測と読むかは、統計ごとの決まりによります（F69 で扱いました）。ここでは欠測として読みました
- 架空の24列は、起きやすい場面を集めたものです。14列という数は、列の選び方で決まります
