# 753 1年が53週ある年に「第N週」で前年同週比を出すと、何週の前年比が本当の伸びから外れるのか（実務の型・週次の前年比）

週次の前年比は「今年の第N週」と「去年の第N週」を比べて出すことが多いです。ところが週番号の決め方によっては、年の最初と最後の週が短くなり、日数の違う週どうしを比べてしまいます。ISO 週（月曜始まり、どの週も7日）では、5〜6年に1度、1年が53週になる年があり、その第53週には去年の相手がありません。**ここでは、毎年ちょうど3%伸びる架空のチェーンの日次売上（2024年1月〜2027年1月、2026年は ISO で53週ある年）で、週番号の決め方を3つ変えて前年同週比を出し、本当の伸びから5ポイント以上ずれた週を数えました。** 曜日の波や年末年始・連休の大きさは作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A753 | 週番号で前年同週比を出すと、何週が本当の伸びから外れるか | A 1月1日から7日ずつ、B 日曜始まり・1月1日を含む週が第1週（SQL Server の DATEPART(week) の既定と同じ数え方）、C ISO 週。同じ週番号どうしで前年比。DuckDB（1スレッド）と pandas で一致を確認。seed 753 | `src/a753_week53.py`、`src/02_week_duckdb.sql`、`src/01_week_tsql.sql`（未検証） |

## 主な結果
- **B（日曜始まり）は年の端が大きくずれる**：2026年の第1週は−37.4%、第53週は+26.4%（本当は+3%）。第1週は3日と4日、第53週は5日と4日を比べている。5ポイント以上ずれた週は2025年2週、2026年4週
- **A（7日ずつ）は第53週だけ**：第53週は1日か2日しかなく、2025年の第53週（12月31日の1日）は前年の2日と比べて−48.7%
- **C（ISO 週）は短い週がない**：5ポイント以上ずれたのは2025年1週、2026年2週（どちらも最大で10ポイント未満）。ただし2026年の第53週（2026年12月28日〜2027年1月3日）は、2025年に第53週がなく前年比が出ない
- **第53週の相手で答えが変わる**：364日前の7日間と比べると+3.7%、2025年の第52週と比べると−25.8%、2025年の第1週と比べると+9.4%

## 動かし方
```
pip install -r requirements.txt
cd src && python a753_week53.py
```
数秒で終わります。`data/daily.csv` に日次売上を、`results/weekly_yoy.csv` に3つの決め方の週ごとの前年同週比を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 3つの週番号での週の売上・日数と前年同週比が、DuckDB と pandas で一致した
- T-SQL 版（`01_week_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。DATEPART(week) は SET DATEFIRST で週の始まりが変わる

## データ
- `data/daily.csv`：d・sales（円）
- 仮定：毎年ちょうど3%伸びる。曜日の波（土日が高い）、12月20〜31日は1.35倍、1月1〜3日は0.55倍、4月29日〜5月5日は1.3倍、8月13〜16日は1.25倍、ゆるい季節の波と3%の揺れ

## 注意（言えないこと）
- 架空のデータ。ずれの大きさは、年末年始や連休の置き方で決まる
- 連休や祝日は日付で置いたので、曜日でそろえる比べ方（ISO 週・364日前）では、そのぶん少しずれる。どれが「正しい」前年比かは、何を比べたいかで決まる
- 実在の店の数字ではない
