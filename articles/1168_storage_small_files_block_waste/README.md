# 1168 小さなファイルがたくさんあると、大きさの合計と実際に使う量はどれだけ違うのか？（データ量の見込み）

ファイルの大きさを足し合わせた量と、保存の場所で実際に使う量は、同じではありません。保存の場所は決まった大きさの区画（ブロック）単位で使うことが多く、100バイトのファイルでも区画1つ分を使います。区画より小さいファイルがたくさんあると、大きさの合計より使う量がふくらみます。**ここでは、作成者が置いた架空のアプリの保存ファイル100万件（大きさの分布を置き、乱数で作ったもの）で、1件ごとに大きさを区画の大きさに切り上げた量を足し、大きさの合計と比べました。よく使われる目安「大きさの合計＋件数×区画の半分」とも比べ、ファイルの大きさの中央値・区画の大きさ・大きさの散らばりを変えた48通りで確かめました。**

使う量は、1件ごとに区画に切り上げた量の合計で、置いた大きさから式どおりに決まります（乱数で決まるのは大きさだけ）。また、中央値と区画を同じ倍率で変えても切り上げの割合は変わらないので、結果はおもに「中央値÷区画の大きさ」と散らばりで決まります（作りどおり）。この記事で数えたのは、小さなファイルが件数・大きさ・使う量のそれぞれで占める割合と、半分の目安がどの置き方で外れるかです。

関連する記事：631「発注をケース単位に切り上げると、在庫は平均で何日分多く持つことになるのか」は、決まった単位への切り上げで余りが出る同じ形を、発注と在庫で扱っています。1124「ダメージの小数を毎回切り捨てて計算すると、小さな強化はどれだけ消えるのか？」は、小さな値ほど丸めの影響を大きく受ける形を、切り捨てで扱っています。1162「ファイルごとの圧縮率を平均すると、全体の縮み方とどれだけ違うのか？」は、1件ごとの決まった上乗せで小さなファイルほど縮みにくくなる形を扱っています。この記事は、区画への切り上げで使う量がふくらむ点に絞ります。同じ企画の 1161「1件あたりの大きさの平均に件数を掛けた見込みは、とても大きい件が少しまざるとどれだけ外れるのか？」は、件数で0.1%のとても大きいファイルが量の大半を占める場面を、平均×件数の見込みで扱っています。この記事は逆に、件数の多い小さなファイルが使う量で効く場面です。1172「1行に項目を1つ足すと、表全体の量は足した項目の大きさの分だけ増えるのか？」は、同じ切り上げの仕組みを、表の行に項目を1つ足したときの増え方に当てています。

## 主な結果

### 基本の置き方（100万件、区画4,096バイト、`results/a1168_main.json` の `base`）
- 大きさの合計は14.8442GB、実際に使う量は17.5206GBで、**使う量は大きさの合計の1.1803倍（18.03%多い）**だった
- 区画より小さいファイルは**件数で63.98%**あったが、大きさの合計では5.01%だった。それが使う量では14.96%を占めた
- 1件あたりの使い残し（使う量−大きさ）は平均で区画の0.6534個分で、目安の「区画の半分」より大きかった。このため「大きさの合計＋件数×区画の半分」の目安は、実際の使う量の0.9641倍と低く出た

### 大きさの帯ごと（`results/base_by_band.csv`）
| 大きさ（バイト） | 件数の割合 | 大きさの合計に占める割合 | 使う量に占める割合 | 使う量÷大きさ |
|---|---|---|---|---|
| 512未満 | 24.81% | 0.37% | 5.8% | **18.738倍** |
| 512〜4,096 | 39.17% | 4.64% | 9.16% | 2.329倍 |
| 4,096〜65,536 | 31.94% | 34.73% | 33.5% | 1.139倍 |
| 65,536〜約100万 | 3.99% | 47.43% | 40.65% | 1.012倍 |
| 約100万以上 | 0.09% | 12.84% | 10.89% | 1.001倍 |

（約100万は1,048,576バイト）

- 512バイト未満のファイルは、大きさでは0.37%なのに、使う量では5.8%を占めた
- 量の大半を占める大きいファイルでは、使う量は大きさとほぼ同じだった

### 同じ100万件で区画の大きさを変える（`results/base_by_block.csv`）
| 区画 | 区画より小さいファイル（件数） | 使う量÷大きさの合計 | 半分の目安÷実際の使う量 |
|---|---|---|---|
| 1,024バイト | 36.92% | 1.0385倍 | 0.9961倍 |
| 4,096バイト（基本） | 63.98% | 1.1803倍 | 0.9641倍 |
| 16,384バイト | 85.34% | 1.862倍 | 0.8334倍 |
| 65,536バイト | 95.92% | **4.9429倍** | 0.6489倍 |

- 同じファイルでも、区画を65,536バイトにすると使う量は大きさの合計の4.9429倍になった。区画より小さいファイルの割合が増えるほど、半分の目安は低く出た

### 確かめ：48通り（各20万件、`results/grid.csv`）
| 中央値÷区画の大きさ | 置き方の数 | 使う量÷大きさの合計 | 半分の目安÷実際の使う量 |
|---|---|---|---|
| 0.5未満 | 20通り | **1.1806〜79.7526倍** | 0.5125〜0.9642倍 |
| 0.5〜4 | 8通り | 1.0377〜1.1557倍 | 0.9961〜1.0002倍 |
| 4以上 | 20通り | 1.0001〜1.039倍 | 0.9997〜1.0001倍 |

- **使う量÷大きさの合計は、48通りで1.0001〜79.7526倍と大きく動いた**。中央値が区画の半分より小さい20通りで1.1806倍以上になり、中央値が区画の4倍以上の20通りでは1.039倍以下だった
- 半分の目安は、48通りのうち32通りで実際の使う量の±5%に入ったが、中央値が区画の半分より小さい20通りでは0.5125〜0.9642倍と低く出た。小さなファイルでは使い残しが区画の半分より大きい（区画の大きさ−ファイルの大きさ）ためである
- 同じ中央値・区画なら、散らばりの大きい（対数の標準偏差2.0）ほうが、24組すべてで使う量÷大きさの合計が小さかった。散らばりが大きいと、量の多くを大きいファイルが占めるからである

## 注意（言えないこと）
- 架空のデータです。ファイルの大きさの分布と区画の大きさは作成者が置いたもので、使う量のふくらみ方はこれで決まります（使う量は置いた大きさから式どおりに決まります）。実在のアプリや保存の仕組みを表すものではありません
- 1件ごとに区画へ切り上げるだけの単純な形にしました。ファイルごとの管理の記録の量、とても小さいファイルを管理の記録の中にしまう仕組み、圧縮、同じ中身のまとめ、控えは入れていません。これらがあると使う量は変わります
- 大きさ0のファイルは入れていません
- 区画の大きさ（1,024〜65,536バイト）と大きさの帯の区切り（512・4,096・65,536・1,048,576バイト）は2を掛け合わせた数で置きましたが、量の合計は1GB＝10億バイトで数えました。この企画のほかの記事も、1KB＝1,000バイトの数え方でそろえています
- 区画の大きさをどう決めるべきかや、容量の費用は扱っていません
