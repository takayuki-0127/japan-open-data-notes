# 761 長さの足りない列に名前を入れると、後ろが切れて別の商品が同じ名前になるのは何件か（実務の型・文字列の長さ）

商品名は「シリーズ名＋種類＋香り・味＋容量」のように、先頭がそろい、違いが後ろにあることが多いです。名前の列の長さが足りずに後ろが切れると、別の商品が同じ名前になり、名前で集計したときに売上が合わさります。SQL Server の `varchar(20)` は「20バイト」で、日本語の照合順序なら全角1文字は2バイト（約10文字）、UTF-8 の照合順序なら3バイト（約6文字）しか入りません。**ここでは、架空の日用品261品目の名前を、20文字・Shift_JIS の20バイト・UTF-8 の20バイトで切る場合を Python で再現し、同じ名前になる品目と合わさる売上を数えました。** 商品名の作りは作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A761 | 名前が切れると、何品目が同じ名前になり、どれだけの売上が合わさるか | A 20文字で切る（nvarchar(20) に CAST）、B 20バイト・Shift_JIS（日本語の照合順序の varchar(20)）、C 20バイト・UTF-8（UTF-8 の照合順序の varchar(20)）。切り方は Python で再現（文字の途中では切らない）。A を DuckDB（1スレッド）の LEFT で確認。seed 761 | `src/a761_truncate.py`、`src/02_truncate_duckdb.sql`、`src/01_truncate_tsql.sql`（未検証） |

## 主な結果
- **名前の長さ**：中央値27文字、99.6%が20文字を超える
- **A 20文字で切る**：261品目が121の名前になり、79.7%の品目がほかの品目と同じ名前になった。名前で集計すると売上の76.6%が別の品目と合わさる。1つの名前に最大9品目
- **B Shift_JIS の20バイト**（約10文字）：261品目が14の名前（シリーズ名だけ）になり、全品目が重なった
- **C UTF-8 の20バイト**（約6文字）：10の名前になった
- **SQL Server での扱い**：長すぎる値を INSERT すると、ふつうはエラーで止まる。黙って切れるのは CAST・CONVERT で短い型に変えたときなど（未検証）

## 動かし方
```
pip install -r requirements.txt
cd src && python a761_truncate.py
```
数秒で終わります。`data/products.csv` に商品名と売上を、`results/truncated_names.csv` に3つの切り方の名前と長さ（文字・バイト）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 20文字で切ったときの名前の数と、20文字を超える名前の数が、DuckDB の LEFT・length と一致した
- バイトで切るときは、全角文字の途中で切らないようにした（SQL Server の実際の切り方は**未検証**）
- T-SQL 版（`01_truncate_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/products.csv`：product_id・name・sales
- 仮定：10シリーズ×種類×香り・味×容量の組み合わせで261品目（組み合わせは架空）。売上は対数正規分布

## 注意（言えないこと）

- 実際に切れるかどうか、どう切れるかは、道具・型・照合順序・設定で変わる。ここでは切り方を Python で再現しただけ
