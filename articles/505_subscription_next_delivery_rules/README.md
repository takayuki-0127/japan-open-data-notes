# 505 定期便の次回のお届け日を「30日後」と「毎月同じ日」で決めると、1年の出荷回数と月の出荷数はどれだけ違うのか（実務の型）

2025年に申し込んだ架空の定期便の会員5,000人（29〜31日の申込969人を含む）について、次回のお届け日の決め方4通りで2026年の1年分のお届け日を作り、1人あたりの回数・月ごとの出荷数・日ごとの山・日にちのずれを数えたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A505 | 次回のお届け日の決め方で、1年の回数と月の出荷数はどれだけ違うか | ①30日後 ②毎月同じ日（申込日の日にち、その日がない月は月末）③前回のお届け日に1か月足す（31日→2月28日→3月28日…と戻らない）④4週ごと（28日後）で2026年のお届け日を作る。予定の10%はスキップ（どの決め方でも同じ回をスキップ） | `src/a505_delivery.py`、`src/02_add_month_duckdb.sql`、`src/01_next_delivery_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **1人あたりの予定の回数（2026年）**：②③は全員12回。①30日後は平均12.15回（15.1%の754人が13回）。④4週ごとは平均13.03回（13回が4,831人、14回が169人）
- **出荷の合計（スキップを除く）**：②③53,995、①54,658（②より1.2%多い）、④58,667（8.7%多い）
- **月ごとの出荷数**：②③は4,477〜4,536でほぼ平ら（変動係数0.35%）。①は4,191〜4,656（2.87%）で、2月が少ない。④は4,487〜5,032（3.16%）
- **同じ月に2回届く**：①で930人（のべ1,087か月）、④で5,000人全員（のべ5,169か月）。②③では0
- **日にちのずれ**：③では、29〜31日に申し込んだ969人全員の12月のお届け日が28日になっていた。②では0人
- **日ごとの山**：②は29〜31日に出る数が9,594、1日の最大は2月28日の990。③は28日に11,088が集まり、1日の最大は1,004（11月28日）。①④は1日の最大が267・188で、山が立たない
- DuckDB で `DATE '2025-01-31' + INTERVAL 1 MONTH` をくり返すと 2月28日→3月28日→…12月28日 となり、③と同じになった

## 動かし方
```
pip install -r requirements.txt
cd src && python a505_delivery.py
```

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の再帰クエリで1か月ずつ足した日付が、Python の③の日付と一致すること（コード内の assert）

## データ
- `data/fictional_subscribers.csv`：架空の会員5,000人の申込日（seed 505）。29〜31日の申込を3倍の重みで多めにした
- `results/deliveries_2026.csv.gz`：決め方ごとの2026年のお届け日（スキップの印つき）

## 注意（言えないこと）
- 架空のデータ。差の大きさは、申込日の散らばりと月末の申込の割合で決まる
- 土日・祝日・配送の休み・お届け日の変更・解約は入れていない
- どの決め方が良いかは、出荷の平らさ・料金の数え方・お客の分かりやすさで変わる。ここでは回数と山の違いを数えただけ。料金や会計の扱いを言うものではない
- T-SQL 版（DATEADD と EOMONTH）は SQL Server 本体では動かしていない（未検証）
