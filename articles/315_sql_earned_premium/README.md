# 315 1年分の保険料を、月ごとの売上にどう分けるか（実務の型）

1年契約の保険料は、もらった月の売上にまるごと入れず、保険期間が過ぎた分だけを売上にします（経過保険料）。架空の保険契約で、日割り・12分の1・24分の1 の3つの分け方を SQL で書き、月の売上と、年度末にまだ売上にしていない分（未経過保険料）を比べたフォルダです。SQL は T-SQL の書き方で `sql/earned.sql` に置き、DuckDB で実行して確かめました。**SQL Server 本体では試していません（未検証）**。

- 日割り：その月に保険期間に入っていた日数 ÷ 保険期間の日数
- 12分の1：始期の月から12か月、毎月12分の1ずつ（始期の月をまるごと1か月と数える）
- 24分の1：始期は月の真ん中と考え、始期の月と13か月目は24分の1、あいだの11か月は24分の2ずつ

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A315 | 月割りと日割りで、月の売上と年度末の未経過保険料はどれだけ違うか | 架空の1年契約7.8万件・保険料の合計48.1億円（2024年1月〜2026年3月始期、seed 315）。3つの分け方で2025年度（2025年4月〜2026年3月）の月の売上と、2026年3月末の未経過保険料を出す。始期が月のどこに集まるかを5通りに変える | `src/a315_run.py`・`a315_figs.py`、`sql/earned.sql` |

## 主な結果
- 3つの分け方とも、全期間で足すと、もらった保険料の合計に1円未満の差で一致した
- 2025年度の売上：日割り 21.741億円、12分の1 21.827億円（+0.39%）、24分の1 21.745億円（+0.02%）
- 月の売上は、12分の1も24分の1も、**2月に約9%多く**（+9.1%・+8.7%）、31日の月に1.4〜1.9%少なく、30日の月に1.2〜1.9%多く出た。月割りはどの月も同じ長さとして分けるため
- **2026年3月末の未経過保険料**：日割り 11.056億円に対し、12分の1は 10.108億円（**−8.6%**）、24分の1は 11.053億円（−0.02%）
- 始期が月のどこに集まるかを変えると（未経過保険料の、日割りとの差）

| 置き方 | 12分の1 | 24分の1 |
|---|---|---|
| ばらばら（基本） | −8.6% | −0.02% |
| 月初に集まる（1日始期が約半分） | −4.7% | +4.2% |
| 月末に集まる（最後の3日で約半分） | −11.8% | −3.5% |
| 3月の契約が2倍 | −8.0% | 0.0% |
| 月末に集まる＋3月が2倍 | −11.0% | −3.3% |

## 確かめたこと
- 空のフォルダで流し直し、results と figures の7ファイルがバイト単位で一致した
- SQL で出した日割りの月の売上は、pandas で別に計算した値と一致する（コード内の assert）

## 注意（言えないこと）
- 契約の件数、保険料、始期の集まり方は架空の置き方です。特定の会社や商品の数字ではありません
- 途中解約と、そのときの返す保険料は入れていません。保険期間は1年だけです
- 「どの分け方を使うべきか」は、会計の決まりと会社の方針で決まります。ここでは「分け方で数字がどれだけ変わるか」だけを見ました。会計や税の助言ではありません
- 日割りを正解として比べましたが、事故の起きやすさが季節で変わる商品では、日数に比例させるのが実態に合うとは限りません
- 12分の1・24分の1 の呼び方と中身は、一般に説明されている範囲で書きました。細かい決まり（端数の扱いなど）は会社ごとに違います（推測）
