# 716 交差検証でハイパーパラメータを選び、同じ交差検証の成績を報告すると、本当の成績よりどれだけよく見えるのか（手法の解説・正解の分かるデータで試す）

交差検証でいくつもの候補（ハイパーパラメータや変数の組）を比べ、いちばんよい候補を選んだあと、その交差検証の成績をそのまま「このモデルの成績」として報告すると、たまたまよく出た分だけ甘くなります。選ぶことまで含めて評価するのが入れ子の交差検証です。**ここでは、変数50個（効くのは3個）の2クラス分類で、「5個の変数の組」を候補として1〜100個用意し、選んだ候補の交差検証の成績・入れ子の交差検証の成績・別の大きなテストデータでの本当の成績を、件数100・400、各200回で比べました。** 数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A716 | 選んだ候補の交差検証の成績は、本当の成績よりどれだけ甘いか | 最近傍重心法（クラスの平均に近いほうに分ける）、候補＝5個の変数の組（1・5・20・100個）。5-fold の交差検証、入れ子（外5・内5）、テスト5,000件。件数100・400、各200回。seed 716 | `src/a716_nested_cv.py` |

## 主な結果
- **100件**：候補1個なら甘さ−0.2ポイント（甘くない）。候補5個で+4.1、20個で+6.5、**100個で+8.7ポイント**（報告69.3%、本当60.6%）
- **400件**：候補100個で+1.9ポイント（66.8%、64.9%）。件数が多いと甘さは小さい
- **入れ子の交差検証**：どの組み合わせでも−1.2〜−0.1ポイント（わずかに辛い。学習に使う件数が8割になるため）
- **選ぶこと自体は役に立つ**：候補が多いほど、選んだ候補に効く変数が入る割合が上がり（100件で候補1個30.5%→100個92.5%）、本当の成績も上がった（53.2%→60.6%）。問題は選んだあとの成績の報告の仕方

## 動かし方
```
pip install -r requirements.txt
cd src && python a716_nested_cv.py
```
20秒ほどで終わります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures がバイト単位で一致した
- 候補1個のとき、交差検証の成績と本当の成績がほぼ同じ（差−0.2・0.0ポイント）になることを確かめた
- 本当の成績は、選んだ候補を学習データ全部で作り直し、別に作った5,000件で測った

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 716）
- 仮定：変数50個は標準正規。最初の3個だけ、クラス0で−0.3、クラス1で+0.3ずらした。クラスは半々

## 注意（言えないこと）
- シミュレーションの結果。甘さの大きさは、候補の数・候補どうしの似かた・件数で決まる。ハイパーパラメータの候補どうしが似ている（正則化の強さを少しずつ変えるなど）と、甘さはもっと小さくなる
- 入れ子の交差検証は「選び方」の成績で、最後に選ぶ1つの候補の成績そのものではない
- 1種類の単純なモデルだけで試した
