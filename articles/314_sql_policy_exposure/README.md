# 314 契約の「在籍件数」を、SQL でどう数えるか（実務の型）

架空の保険契約（始期・終期・中途解約）で、在籍の量を日数で数えた「経過契約年」と、件数で代える7つの数え方を比べたフォルダです。事故は在籍した日数に比例して起きるように作ってあるので、分母を変えたときの事故率のずれも分かります。SQL は T-SQL の書き方で `sql/exposure.sql` に置き、DuckDB で実行して確かめました。**SQL Server 本体では試していません（未検証）**。

経過契約年（エクスポージャ）＝契約が保険期間の中にいた日数を足して365で割ったもの。1年まるごと在籍した契約が1、半年で解約した契約が0.5です。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A314 | 在籍の量を件数で代えると、何%ずれるか。事故率はどれだけ変わるか | 架空の1年契約15.0万件（2023〜2026年始期、新しい契約は毎年15%増、25%が4月始期、8%が途中解約、seed 314）。事故は1契約年あたり0.06件。2025年の在籍を8つの数え方で出す。増え方を −20%〜+50% に変える | `src/a314_run.py`・`a314_figs.py`、`sql/exposure.sql` |

## 主な結果
- 2025年の経過契約年（日数で数えた正解）は 35,838.7。事故は2,145件で、事故率は 5.99%（作るときに置いた値は 6.0%）

| 数え方 | 正解との差 | この分母での事故率 |
|---|---|---|
| A 日数で数える（経過契約年） | — | 5.99% |
| B 年初の在籍件数 | **−8.0%** | 6.51% |
| C 年末の在籍件数 | +5.8% | 5.66% |
| D 年初と年末の平均 | −1.1% | 6.05% |
| E 月初の在籍件数の12か月平均 | −0.57% | 6.02% |
| F 月初と月末の平均の12か月平均 | **−0.04%** | 5.99% |
| G その年に始まった契約の件数 | +10.7% | 5.41% |
| H その年に1日でも在籍した契約の件数 | **+102.5%** | 2.96% |

- 新しい契約が増えも減りもしないとき（0%）は、B〜F の差は0.02%以内。G は +4.7%（途中解約の分）、H は +104%
- 毎年50%増えるときは、B −21.9%、C +17.0%、D −2.5%、E −1.6%、F −0.10%
- 月ごとに見ると、始期が集まる4月は、月初の件数が −2.2%、月末の件数が +2.3%、2つの平均は +0.03%。ほかの月は ±0.2〜0.7%
- 置き方を変えても向きは同じ：4月への集中をなくすと D は −0.01%、解約を2倍にすると G は +15.3%

## 動かし方
```
pip install -r requirements.txt
cd src && python a314_run.py && python a314_figs.py
```

## 確かめたこと
- 空のフォルダで流し直し、results と figures の7ファイルがバイト単位で一致した
- SQL で出した経過契約年は、pandas で別に計算した値と一致する（コード内の assert）

## 注意（言えないこと）
- 契約の増え方、4月への集中、解約の割合、事故の起き方は架空の置き方です。特定の会社や商品の数字ではありません
- 事故は在籍した日数に比例して起きると置いています。季節で事故の起きやすさが変わる商品では、日数で数えても足りません
- 保険期間は1年、終期の日は在籍に含めない、と決めて数えました。時刻（午後4時始期など）は扱っていません
- 1年を365日で割っています。うるう年の扱いは見ていません
- 保険料率を決める話や、会計上の扱いには触れていません。「分母の数え方で率がどれだけ変わるか」だけを見た記事です
