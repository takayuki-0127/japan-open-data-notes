# 691 同じ顧客の重複行から「最初」と「最新」のどちらを残すかで、属性の集計はどれだけ変わるのか（実務の型）

会員ランクの変更や引っ越しのたびに、元の行を上書きせず新しい行を足していく顧客表はよくあります。この表から「1顧客1行」にするとき、どの行を残すかで集計は大きく変わります。**ここでは、架空の顧客表（2万人・66,572行、8割の顧客に複数の行）で、重複を除かない・最初の行を残す・最新の行を残す・2024年末時点の最新を残す、の4通りで会員ランク別と地域別の人数を数えました。** DuckDB の SQL と Python の結果が一致することを確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A691 | 残す行で集計はどれだけ変わるか | 架空の顧客2万人。登録時のランクは一般7割・シルバー2割など、その後おおむね420日ごとにランクの変更（上がることが多い）か引っ越しで行を足す（2021-01〜2026-10）。ROW_NUMBER() OVER (PARTITION BY 顧客 ORDER BY 更新日時) で最初・最新を、2024-12-31 以前の行に絞って時点の最新を選ぶ。seed 691 | `src/a691_dedup_keep.py`、`src/02_dedup_duckdb.sql`、`src/01_dedup_tsql.sql`（T-SQL：未検証） |

## 主な結果
| 会員ランク | 重複を除かない（行数） | 最初の行 | **最新の行（いま）** | 2024年末時点 |
|---|---|---|---|---|
| 一般 | 23,012 | 13,915 | 5,541 | 4,909 |
| シルバー | 19,213 | 4,062 | 5,524 | 4,145 |
| ゴールド | 12,989 | 1,619 | 4,305 | 2,756 |
| プラチナ | 11,358 | 404 | 4,630 | 2,084 |
| ゴールド以上の割合 | 36.6% | 10.1% | **44.7%** | 34.8% |

- いまのランク（最新の行）ではゴールド以上が44.7%なのに、最初の行を残すと10.1%と4分の1以下に出た。プラチナは4,630人が404人になった
- 最初と最新でランクが違う顧客は12,417人、地域が違う顧客は6,345人
- 2024年末時点を知りたいのに最新の行を使うと、そのときの顧客13,894人のゴールド以上の割合は55.3%で、正しい34.8%より20ポイント高く出た（その後に上がったランクが入り込むため）
- 重複を除かずに数えると、人数は66,572（本当は2万人）になり、更新の多い上位ランクほど多く数えた
