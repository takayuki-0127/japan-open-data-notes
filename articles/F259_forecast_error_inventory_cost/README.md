# F259 需要予測の外れは、在庫と欠品のどちらに効かせるべきか？

公開データ（商業動態統計の業態別販売額）を、架空の小売チェーン「あおばストア（架空）」の需要に見立て、F231 で作った需要予測を使って2か月ごとに発注する在庫を回した。予測の外れを「安全在庫（余分に持つ在庫）」としてどう積むと、在庫の費用と売り逃しの損の合計が小さくなるか、どの精度の指標がお金と合うかを調べた。

- 計画は結果を計算する前に書いて先に置いた：[PLAN.md](PLAN.md)（コミット f197dd4、メッセージ "plan"）
- 費用の比（在庫1単位1か月=1、売り逃し1単位=p）は**例として置いた比で、実在の費用ではない**。実在の会社のデータは使っていない

## 問い（どこから来たか・誰が知りたいか）
- データアナリストの求人の業務内容によく出てくる「需要予測」。予測の精度（MAPE など）は報告できても、それが在庫や欠品のお金にどうつながるかは説明しにくい。
- 知りたい人：発注や在庫の担当者（安全在庫をどう決めるか）、予測モデルを作る人（どの指標でモデルを選ぶか）、月次報告で予測の精度を KPI にしている人。
- F205（電力の外れの値段）と F235（1か月先・繰り越しなしのニュースベンダー）とは違い、ここでは**繰り越しのある在庫・リードタイム（発注から届くまでの期間）・2か月ごとの発注**を扱う。

## データ
- 経済産業省「商業動態統計調査」業態別の月次販売額（百貨店・スーパー・コンビニ・ドラッグストア・ホームセンター・家電大型専門店、2014年1月〜2026年8月）。業態ごとに 2017〜2019年の月平均＝100 に換算して、架空の会社の6つの売り場の需要とみなした。
- 予測：F231（[articles/F231_sales_forecast_horizon](../F231_sales_forecast_horizon)、コミット 613a8c7）の予測結果をそのまま使った（5モデル：季節ナイーブ・季節ナイーブ＋伸び・ETS・SARIMA・LightGBM、起点は2016年12月〜2024年8月の2か月ごと47回、1〜24か月先）。新しい予測は作っていない。手元のファイルが 613a8c7 の GitHub 上のものと同じ（SHA-256 の先頭が一致）ことを確かめた。

## 手法
- 発注：2か月ごと（R=2）。リードタイム L＝0・1・2・3か月。発注のたびに「次の発注が届くまでの L+R か月の予測の合計＋安全在庫」まで補充する（発注点補充方式）。売れ残りは翌月に繰り越す。足りない分は売り逃し（主）。
- 費用：在庫1単位を1か月持つと h=1、売り逃し1単位で p（主は p=9、ほかに 4・19）。月末の在庫に h をかけ、売り逃しに p をかけて足す。頑健性のバックオーダーでは、月末に残っている不足分に毎月 p をかける。数字は「需要の月平均＝100 の売り場の、月あたりの費用」。
- 期間：コロナ期（2020年3月〜2021年12月）を挟むので、コロナ前（2018年9月〜2020年2月）とコロナ後（2022年1月〜2024年10月）の2区間で回した。始めの状態は「ふだんの回り方」（直前の発注がまだ届いていない分を途中に置く）にそろえた。
- 安全在庫の決め方：
  1. なし（予測の合計そのまま）
  2. ルートの式：1か月先の外れの RMSE × √(L+R) × z（計画では「標準偏差」と書いたが、実装は偏りを含む RMSE）（z は目標 α=p/(p+h) の正規分布の点、p=9 で 1.28）
  3. 合計の外れの分位点：過去の起点の「L+R か月の合計の外れ（実績の合計−予測の合計）」の α 分位点をそのまま積む
  4. 後から見た最良の倍率：ルートの式の倍率を −2〜8 から後で選んだ目安（実際には使えない）
  - 2・3 は、その起点より前に結果が出そろった外れだけを使う（先読みしない）。外れはコロナ期にかかる窓を除いてため、8個たまってから使う。
- 指標と費用の合い方：業態×L の24組それぞれで5モデルを並べ、指標（1か月先の MAPE・1か月先の RMSE・L+R か月の合計の外れの RMSE・合計の外れの偏り・ピンボール損失）と費用の順位相関（スピアマン）を出した。
- SQL：`sql/f259_check.sql`（SQL Server で動く書き方）で、在庫の推移の記録から費用を集計し、予測と実績から合計の外れの RMSE 倍率を出した。DuckDB で流して Python と照合（600組の費用の差は最大 8.5e-07、180組の倍率の差は最大 4.8e-07）。在庫の動きそのもの（前の月の在庫に次の月が依存する計算）は Python で回し、SQL では集計の部分を確かめた。
- 判断用の表：`dashboard/index.html`（L と p を選ぶと、決め方ごとの費用・売り逃し率・カバー率、モデル別の費用が出る。架空の会社の社内向けの例）

## 結果（主：p=9・売り逃し・業態ごと）
| 決め方 | L=0 | L=1 | L=2 | L=3 |
|---|---|---|---|---|
| なし | 69.8 | 70.6 | 72.7 | 75.8 |
| ルートの式 | 64.1 | 68.4 | 69.4 | 74.2 |
| 合計の外れの分位点 | 63.2 | 67.8 | 67.9 | 73.7 |
| 後から見た最良の倍率（目安） | 62.0 | 65.7 | 66.5 | 70.9 |

（月あたりの費用。6業態×5モデルの平均。L=2 の内訳は、在庫費 54.7〜63.2、売り逃しの損 5.9〜17.9。費用の大半は「2か月分を一度に入れるので持つ在庫」で、安全在庫の決め方で動くのは数%）

1. **守る期間が3か月を超えると、要る安全在庫は √ の式より速く増えた**（図1）。実際に要った量（合計の外れの90%点）を「1か月先の外れ（RMSE）×z」で割った倍率の中央値は、L+R=1〜5 で 0.74・1.30・2.09・2.70・3.59。√(L+R) は 1.00・1.41・1.73・2.00・2.24 なので、2か月以下では √ の式はむしろ多め、3か月以上では足りない。
   - 理由は2つ。**偏り**（予測が実績より毎月少しずつ低い。1か月あたり平均で約 +1、需要の約1%）が期間に比例して積み上がることと、**続く月の外れが同じ向きに出やすい**こと。同じ起点の外れどうしの相関の中央値は h1-h2 0.01 だが、h2-h3 0.40、h4-h5 0.44、h2-h5 0.33 とプラス（`results/G_review_checks.json`）。
   - 合計の外れの RMSE は5か月で1か月先の 3.22 倍、偏りを差し引いた標準偏差でも 2.62 倍（√5＝2.24）。おおまかに、2.24→2.62 が主に月どうしの相関（と先の月ほど外れが少し大きいこと）、2.62→3.22 が偏りの分。偏りの小さい SARIMA も 3か月 1.72（√3＝1.73）だが、4か月 2.48・5か月 3.60 で √ を超え、5か月の偏りは +1.21。
   - （最初の版の「理由は相関ではなく偏り」は、h1-h2 の相関だけを見た誤りで、レビューで直した）
2. **目標の90%に届いたかは、数え方で変わる**（図2）。
   - シミュレーションを使わない「覆えた割合」（発注の窓の需要を予測の合計＋安全在庫で覆えた発注の割合）：ルートの式 83%・79%・74%・71%（L=0〜3）、合計の外れの分位点 80%・81%・76%・75%。届かない。たまった外れが8〜30個ほどと少なく、少ない外れから取った90%点は小さくなりやすい（8個なら同じ分布でも覆える割合はおよそ8割、推測）。コロナ前と後に分けても、分位点は 73〜77% と 76〜83%。
   - シミュレーションで**売り逃しが出なかった月**の割合：ルートの式 91.5%・91.7%・89.4%・89.6%、分位点 89.8%・92.5%・90.0%・91.0%。ほぼ目標どおり。
   - **2か月の発注の周期**ごと：ルートの式 82.9%・83.3%・78.8%・79.2%、分位点 79.6%・85.0%・80.1%・82.1%。届かない。
   - 6業態の外れをまとめて分位点を作ると、覆えた割合は 86〜87% で L によらずほぼ一定。
3. **お金と合う指標は「L+R か月の合計の外れ」**（図4）。費用との順位相関の平均は、安全在庫なしのとき 合計の外れの RMSE 0.71・偏り 0.55・1か月先の RMSE 0.45・1か月先の MAPE 0.38。分位点で安全在庫を置いたとき 合計の外れの RMSE 0.48・ピンボール損失 0.48・1か月先の MAPE 0.29。安全在庫で偏りを直すと、偏りの指標は費用と合わなくなる（−0.17）。
   - 合計の外れの RMSE − 1か月先の MAPE の差（24組）のブートストラップ95%区間：分位点あり 0.06〜0.34、なし 0.20〜0.47。ただし24組は同じ業態のリードタイム違いを含み独立ではない。業態でまとめると、分位点ありのスーパーは −0.15 と逆。費用は合計の外れから直接決まるので、合う方が自然とも言える。
4. **モデルの違いの方が、安全在庫の決め方の違いより大きく出た**（図5）。同じモデルで決め方（なし・ルートの式・分位点）を変えた幅は平均 6.5、同じ決め方でモデルを変えた幅は 10.4。決め方の幅の方が大きかったのは24組中1組。
   - ただしこの比べ方は、5モデルの最大−最小と3つの決め方の最大−最小を比べるので、モデルの側に幅が出やすい。飛び抜けた組（LightGBM、安全在庫なしの季節ナイーブ 80.4）も効く。ルートの式と分位点の2つに絞り LightGBM を除いても、決め方の幅 2.4 に対してモデルの幅 5.2（3つの決め方で LightGBM を除くと 6.8 対 8.7）。
   - モデルの順位は1か月先の当たり具合と違う。分位点で安全在庫を置いたときの費用（L=0〜3 の平均）は、季節ナイーブ＋伸び 66.4、季節ナイーブ 66.7、ETS 67.9、SARIMA 68.2、LightGBM 71.6。F231 で1か月先の MAPE がいちばん小さかった SARIMA（2.5%、季節ナイーブは3.9%）は4位。順位は決め方で変わり、SARIMA はルートの式で3位、安全在庫なしで2位。季節ナイーブ＋伸びはどの決め方でも1位。
   - 季節ナイーブは4か月の合計の外れの平均が +8.5 と大きいが、起点ごとのばらつき（標準偏差 8.1）はほかのモデル（6.7〜9.4）と同程度で、偏りを安全在庫で差し引けば残る外れは小さい。偏りが時期によって安定しているかは確かめていない（推測）。
   - 季節ナイーブを安全在庫なしで使うと 80.4 と飛び抜けて悪い（偏りがそのまま売り逃しになる）。
5. ルートの式と分位点の差は、L=2 で 1.5（約2%）と小さい。業態×モデル×L（0〜3）の120組のうち分位点の方が安かったのは44%。平均の差は、偏りの大きい組での大きな差（最大15）から来ている。

## 計画とのずれ
- H1（√ より速く増える・ルートの式は目標に届かない）：
  - 前半は L+R が3か月以上で当たり、2か月以下では逆（1か月 0.74、2か月 1.30 で √ より小さい）。
  - 後半は**数え方で変わる**。計画の基準は「L=2・3 でルートの式の欠品なしの割合が目標から3ポイント以内なら外れ」だったが、単位（月か周期か）を決めていなかった。月ごとに数えると 89.4%・89.6% で**外れ**、2か月の周期ごとなら 78.8%・79.2% で**当たり**。最初の版は、シミュレーションを使わない「覆えた割合」（74%・71%）にすり替えて「当たり」としていた（レビューで指摘され、直した）。
  - 理由も、計画の「外れが同じ向きに続く（相関）」は h2 以降の多くの組で当たり（h2-h3 0.40・h4-h5 0.44、h3-h4 は 0.10）で、それに偏りが加わる。最初の版の「相関ではなく偏り」は誤り。
- ルートの式の分母：計画は1か月先の外れの「標準偏差」、実装は偏りを含む RMSE。
- H2（1か月先の MAPE より合計の外れの方が費用と合う）：当たり（0.48 対 0.29、安全在庫なしでは 0.71 対 0.38）。ただし組どうしは独立でなく、業態によっては逆。
- H3（決め方の差の方がモデルの差より大きい）：**外れ**（モデルの幅 10.4 対 決め方の幅 6.5、24組中1組だけ逆）。比べ方はモデルの側に幅が出やすい（上の結果4）。
- 計画になかったこと：後から見た最良の倍率は中央値 0.95（四分位 0.5〜1.4）で、z=1.28 より小さめ。安全在庫は次の発注まで2か月持つので在庫の費用が2か月分かかる、という説明（α=p/(p+2h)）は結果を見た後に考えたもの（推測、下の「問いの立て直し」の2）。
- 計画では始めの状態を決めていなかった。最初は全部を手元在庫で始めていたが、L が大きいほど始めの在庫が多すぎて費用がふくらむ（L=3 で月 +31）ことに気づき、「ふだんの回り方」（直前の発注がまだ届いていない分を途中に置く）で始めるように直した。

## 頑健性（L=2 の費用：ルートの式 → 合計の外れの分位点、覆えた割合）
| 条件 | ルートの式 | 分位点 | 覆えた割合（ルート/分位点） | モデルの幅 > 決め方の幅 |
|---|---|---|---|---|
| 主（p=9） | 69.4 | 67.9 | 74% / 76% | 23/24 |
| p=4 | 64.0 | 63.3 | 66% / 68% | 21/24 |
| p=19 | 75.8 | 74.2 | 82% / 82% | 17/24 |
| バックオーダー（翌月に回す） | 71.8 | 69.7 | 74% / 76% | 23/24 |
| 6業態まとめて分位点 | 70.3 | 70.1 | 83% / 87% | 23/24 |
| コロナ期も含めて1本 | 78.6 | 80.3 | 80% / 80% | 23/24 |
| 外れが12個たまってから | 71.0 | 69.3 | 74% / 75% | 21/24 |

- 偏りが積み上がって √ の式が足りなくなること、目標に届かないこと、モデルの差の方が大きいことは、どの条件でも同じ向き。
- p=4（売り逃しの損が小さい）では、L=1〜3 で「安全在庫なし」（62.2・62.7・65.7）の方がルートの式（63.4・64.0・67.4）より安い。安全在庫が割に合うのは、売り逃しの損が在庫の費用に比べて十分大きいとき。
- 6業態まとめて分位点を作ると、分位点の覆えた割合は 86〜87% に上がるが、費用はやや悪化する（業態ごとの分位点に比べ L=2 で 67.9→70.1、L=3 で 73.7→75.9、+2前後）。
- バックオーダーは、月末に残っている不足分に毎月 p をかけている。
- コロナ期も含めると、分位点はルートの式より悪くなる（コロナ期の大きな外れが、そのあとの安全在庫を積みすぎにする）。

## 問いの立て直し（最初の結果を見た後に足した問い）
1. **偏りを直すだけで、どれだけ減るか**：安全在庫を「過去の合計の外れの平均」（偏りの分だけ）にすると、L=2 で 72.7 → 69.5。安全在庫なしから分位点までの減り（4.8）の約3分の2が偏りを直すだけで取れる（L=0 では約半分）。ただし覆えた割合は 48% 前後で、欠品は残る。
2. **目標を「2か月持つ前提」にすると**：分位点の目標を α=p/(p+2h)（p=9 で 0.82）にすると、業態ごとの分位点に比べ L=1 で −0.75、L=2 で −0.20、L=3 で −0.59 と小さく下がり、L=0 では +0.09 とわずかに悪化（63.15→63.24）。覆えた割合は 68〜73%。結果を見た後に足した目標で、確かな改善とは言えない。

## 言えないこと
- 業界全体の合計の需要で、1店・1品目の需要は外れがずっと大きく、偏りより、ばらつきの方が大きくなりうる。結果の大きさ（特に「モデルの差の方が大きい」）は単位によって変わりうる。
- 費用の比（h=1、p=4・9・19）は例として置いたもの。実在の費用ではない。品切れで客が他の店に流れる損、廃棄、発注の手間、置き場所の上限は入れていない。
- 名目の販売額で、物価・店舗数・休日の並びは調整していない。偏り（実績が予測より高い）の一部は物価の上昇によるかもしれない（推測、分けていない）。
- 指標と費用の順位相関は、5モデルを並べた24組（業態×L）の平均で、組どうしは独立ではない。差の区間（ブートストラップ）は組を独立とみなした目安。
- 評価できる期間は52か月（コロナ前18か月、コロナ後34か月）と短く、たまった外れも少ない。
- 予測は F231 のもの（2か月ごとの起点）で、予測の作り方を変えれば順位は変わりうる。LightGBM は単純な設定。
