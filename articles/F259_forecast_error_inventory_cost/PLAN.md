# F259 計画（事前登録）：需要予測の誤差は、在庫と欠品のどちらに効かせるべきか？

この計画は、結果を計算する前に書いて GitHub に先に置く（コミットメッセージ "plan"）。結果がこの計画とずれたら、README と記事にずれを書く。

## 問いの出どころ
- データアナリストの求人票によくある業務「需要予測」。予測の精度（MAPE など）を報告しても、在庫や欠品のお金にどうつながるのかは、求人側も応募側も説明しにくい。
- F205（電力の外れの値段）と F235（1か月先・繰り越しなしのニュースベンダー）では扱っていない、**繰り越しのある在庫・リードタイム（発注から届くまでの期間）・どの精度指標がお金と合うか**を扱う。

## 設定
- 需要：経済産業省「商業動態統計」の6業態の月次販売額を、架空の小売チェーン「あおばストア（架空）」の需要とみなす。業態ごとに 2017〜2019年の月平均＝100 に換算。
- 予測：F231（articles/F231_sales_forecast_horizon、コミット 613a8c7）の予測結果をそのまま使う。起点は2か月ごと（47回）、1〜24か月先、5モデル（季節ナイーブ・季節ナイーブ＋伸び・ETS・SARIMA・LightGBM）。新しい予測は作らない。
- 発注：2か月ごとに発注（R=2）、リードタイム L＝0・1・2・3か月。発注点は「次の発注が届くまでの L+R か月の需要の予測の合計＋安全在庫」まで補充する（発注点補充方式）。売れ残りは翌月に繰り越す。足りない分は売り逃し（失注）。
- 費用（例として置く比。実在の費用ではない）：在庫1単位を1か月持つ費用 h=1、売り逃し1単位の損 p＝4・9・19。主は p=9。
- 期間：コロナ期（2020-03〜2021-12）を挟むため、コロナ前（2017〜2020-02）とコロナ後（2022-01〜）の2区間で別々に回し、合わせて評価する。

## 安全在庫の決め方（比べる）
1. なし（予測の合計そのまま）
2. ルートの式：1か月先の外れの標準偏差 × √(L+R) × z（よく使われる式。外れが月ごとに独立と仮定）
3. 合計の外れから直接：過去の起点での「L+R か月の合計の外れ」の分位点（目標 α＝p/(p+h)）
4. 後から見た最良の一定倍率（比べるための目安。実際には使えない）
- 2・3 は、その起点より前に結果が出そろった外れだけを使う（先読みしない）。外れが8個たまるまでは評価に入れない。

## 仮説と「外れ」の基準
- **H1（リードタイム）**：必要な安全在庫は √(L+R) より速く増える（月ごとの外れが同じ向きに続くため）。ルートの式は目標のサービス率に届かない。
  - 外れ：L=2・3 でルートの式の欠品なしの割合が、目標から3ポイント以内に届いていたら H1 は外れ。
- **H2（どの指標がお金と合うか）**：1か月先の MAPE より、「L+R か月の合計の外れ」の大きさ（RMSE）や偏り（平均の外れ）の方が、費用の順位と合う。
  - 外れ：業態×L の組の中でモデルを並べた順位相関（費用との相関）で、1か月先の MAPE が合計の外れの指標と同じかそれ以上なら H2 は外れ。
- **H3（予測の良さのお金の価値）**：予測が良いほど費用は下がるが、安全在庫の決め方の違い（1→3）の方が、モデルの違いより費用への効き目が大きい。
  - 外れ：同じ決め方の中でのモデル間の費用の差の方が、決め方の差より大きければ H3 は外れ。

## 頑健性（3つ以上）
- p=4・19 に変える
- 売り逃しではなく、翌月に回す（バックオーダー）にする
- 外れを6業態でまとめて分位点を作る
- コロナ期も含めて1本で回す
- 外れのため方（最小8個→12個）
