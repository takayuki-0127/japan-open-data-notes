# 453 数字が文字として入った列を並べ替えると、何件が違う順番になるのか（実務の型）

架空の伝票5万件（伝票番号・枝番・金額が文字列で入っている）で、文字のままの ORDER BY・MAX・MIN・BETWEEN の結果を、数に直した場合と比べたフォルダです。372（CSV を Excel で開く）・373（pandas の型）・375（表記のゆれ）は読み込みと結合を扱いました。ここでは、並べ替えと大小の比較だけを扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A453 | 数字が文字の列のままだと、並び順・MAX・MIN・BETWEEN はどれだけ違うか | DuckDB に全列を文字として読み込み、文字のままの結果と CAST した結果を比べる。桁数の混ざり方を5通りに変える。直し方（数に直す・ゼロ埋め）を、負の数・カンマ入り・小数が混ざった列でも試す | `src/a453_text_numbers.py`、`src/01_text_numbers_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
| 列 | 2件を選んだとき大小が逆になる割合 | 順位が違う行 | 順位のずれの中央値 |
|---|---|---|---|
| 伝票番号（1〜50,000、桁をそろえていない） | 25.3% | 100.0% | 8,221 |
| 伝票番号（6桁にゼロ埋め） | 0% | 0% | 0 |
| 枝番（1〜15） | 45.7% | 93.3% | 20,128 |
| 金額（2桁〜7桁） | 41.4% | 100.0% | 13,232 |

- **金額の大きい順の先頭**：文字のままだと「9999」「9999」「99978」「9997」…、数に直すと「1405993」「962204」「898433」…
- **MAX・MIN**：全体の MAX は文字で「9999」、数で 1,405,993。MIN は文字で「100」、数で 16。顧客2,000人ごとに出すと、MAX が違う顧客は94.1%、MIN が違う顧客は95.9%。違ったとき、文字の MAX は本当の MAX の10%（中央値）
- **BETWEEN**：

| 範囲 | 下限と上限の桁 | 本当の件数 | 文字の結果 | 漏れ | 余分 |
|---|---|---|---|---|---|
| 1,000〜5,000円 | 4桁〜4桁 | 18,725 | 34,822 | 0 | 16,097 |
| 5,000〜20,000円 | 4桁〜5桁 | 18,517 | 0 | 18,517 | 0 |
| 10,000〜99,999円 | 5桁〜5桁 | 15,496 | 49,989 | 0 | 34,493 |
| 800〜12,000円 | 3桁〜5桁 | 32,852 | 0 | 32,852 | 0 |
| 30,000〜100,000円 | 5桁〜6桁 | 4,221 | 0 | 4,221 | 0 |
| 99〜1,000円 | 2桁〜4桁 | 4,747 | 0 | 4,747 | 0 |

  下限と上限の桁数が違う4つは、文字では下限のほうが「大きい」ので0件になる。桁数が同じ2つは、別の桁数の金額が余分に入る
- **桁数の混ざり方（2万件・800グループ、桁ごとにほぼ同じ件数）**：4桁だけなら逆転0%・MAX の誤り0%。3〜4桁で逆転24.9%・MAX の誤り48.1%、3〜5桁で33.6%・69.5%、1〜5桁で38.0%・78.6%、1〜7桁で41.1%・85.8%
- **直し方**：整数だけの列なら、数に直しても、7桁にゼロ埋めして文字で比べても逆転は0%。負の数・カンマ入り・小数を1,000件ずつ混ぜると、ゼロ埋めでは3.3%が逆転したまま。DuckDB の TRY_CAST AS BIGINT は、カンマ入り912件を数に直せず、小数1,000件を黙って整数に丸めた。カンマを取ってから小数に直すと、直せない行も変わった行も0

## データ
- `data/slips.csv`：架空の伝票5万件（行番号・顧客・伝票番号・ゼロ埋めした伝票番号・枝番・金額）。作成者が乱数で作成（seed 453）。金額は対数正規の乱数で、2桁48件・3桁4,735件・4桁29,085件・5桁15,496件・6桁635件・7桁1件

## 注意（言えないこと）
- 架空のデータ。割合は、桁数の混ざり方（私が置いた分布）で決まる
- 「大小が逆になる割合」は、20万組を乱数で選んで数えたもの（数が同じ組は除く）
- 文字の大小は、DuckDB の既定の比べ方（文字コードの順）での結果。SQL Server の照合順序では試していない（未検証）
- TRY_CAST が小数の文字を整数に丸めるのは DuckDB での動き。ほかのデータベースでは違うことがある（未検証）
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
