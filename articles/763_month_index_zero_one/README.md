# 763 継続月数を0から数えるか1から数えるかで、継続率の表はどれだけずれて読まれるのか（実務の型・コホートの表）

定期購入の継続率は、加入した月ごとに「何か月目に何%残っているか」を並べた表で見ることが多いです。このとき加入した月を「0か月目」とする表と「1か月目」とする表があり、同じ「3か月目」でも指している月が1つずれます。**ここでは、架空の定期購入（2024年1月〜2025年6月に毎月400人加入、2025年12月まで観察）で、0始まりと1始まりの継続率の表を作り、同じ見出しの数字がどれだけ違うか、目標「3か月目の継続率60%以上」の判定がどう変わるかを数えました。** 解約のしかたは作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A763 | 0始まりと1始まりで、同じ「Nか月目」の継続率はどれだけ違うか | 在籍した月を展開し、`date_diff('month', 加入月, 在籍月)`（0始まり）と、それに1を足した値（1始まり）で集計。DuckDB（1スレッド）と pandas で一致を確認。seed 763 | `src/a763_month_index.py`、`src/02_retention_duckdb.sql`、`src/01_retention_tsql.sql`（未検証） |

## 主な結果
- **同じ「1か月目」が78%と100%**：0始まりの1か月目（加入の翌月）は77.8%、1始まりの1か月目（加入した月）は100%。差は22.2ポイント
- **ずれは最初の数か月ほど大きい**：同じ見出しでの差は、2か月目9.9、3か月目6.0、6か月目3.2、12か月目2.4ポイント
- **目標の判定が変わる**：「3か月目の継続率60%以上」を加入月ごとに判定すると、0始まりの表では18か月中13か月、1始まりの表では18か月すべてが達成
- **1始まり＝満Nか月**：1始まりの「Nか月目」は「Nか月分在籍した人の割合」と同じ。0始まりの「Nか月目」は「N+1か月分在籍した人」になる

## 動かし方
```
pip install -r requirements.txt
cd src && python a763_month_index.py
```
数秒で終わります。`data/subs.csv` に加入月と最後に在籍した月を、`results/cohort_table_0based.csv` に0始まりの継続率の表を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 加入月×月数ごとの在籍人数が、DuckDB と pandas で一致した
- T-SQL 版（`01_retention_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/subs.csv`：customer_id・signup_month・last_month（最後に在籍した月。2025年12月時点で継続中なら空）
- 仮定：解約の確率は、加入した月のうちに22%、翌月14%、その次9%、その後6%、7か月目以降4.5%。加入月ごとに±12%ほど揺らした

## 注意（言えないこと）
- 架空のデータ。ずれの大きさは、最初の数か月の解約の多さで決まる
- 全体の継続率は、その月数まで観察できる加入月だけで平均した。12か月目は2024年12月までに加入した12か月分だけ
- どちらの数え方が正しいということはない。表の見出しにどちらかを書いておくことが大事（推測）
- 実在のサービスの数字ではない
