# 852 余裕を作業ごとに持つのと、最後にまとめて持つのでは、どちらが間に合いやすいか？（見積もりと締め切り）

プロジェクトの予定に余裕（予備の日数）を入れるとき、作業ごとに少しずつ足す方法と、作業は「最もありそうな日数」で並べて最後にまとめて置く方法があります。全体の日数が同じでも、早く終わった作業の残りの日数が次の作業に渡されないと、作業ごとの余裕は使い切られて消え、遅れだけが次へ渡ります。**ここでは、作成者が置いた架空のプロジェクト（10個の作業を順に行う）で、同じ全体の日数を作業ごとに割り振る（A）か最後にまとめる（B）かで、全体の期限に間に合う割合を乱数で数えました。早く終わった分を次へ渡す割合を0・50・100%と変え、結果がこの置き方でどう動くかも確かめました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A852 | 同じ全体の日数のとき、余裕を作業ごとに持つ（A）のと最後にまとめて持つ（B）のでは、期限に間に合う割合はどれだけ違うか。90%間に合わせるための余裕は、作業ごとに積むとまとめるのとで何倍違うか | 架空のプロジェクト。10個の作業を順に行い、作業ごとの日数の中央値を 3・5・4・6・2・8・5・4・3・6日（合計46日）と置く。実際の日数は中央値×対数正規のぶれ（対数の標準偏差0.5、右に長い分布）。A は全体の日数を中央値に比例して作業ごとに割り振る。B は作業ごとの目標を中央値にして、残りを最後にまとめて置く。作業が目標より早く終わったとき、余った日数のうち f だけを次に渡す（f=0：目標の日まで次に渡さない、f=1：全部渡す）。基本は全体の日数55.2日（中央値の合計の1.2倍）・f=0。各10万回。確かめとして、ぶれ（0.3・0.5・0.7）・作業の数（5・10・20）・f（0・0.5・1）を変えて各4万回数えた。seed 852 | `src/a852_buffer.py` |

## 主な結果

### 同じ全体の日数（55.2日）での比較（10万回）
| 早く終わった分を次に渡す割合 f | A 作業ごとに余裕：期限内 | B 最後にまとめて：期限内 | A の終わる日（平均） | B の終わる日（平均） |
|---|---|---|---|---|
| 0（渡さない） | **1.2%** | **35.0%** | 64.3日 | 59.1日 |
| 0.5 | 39.7% | 53.5% | 58.2日 | 55.6日 |
| 1（全部渡す） | 66.3% | 66.3% | 52.1日 | 52.1日 |

- 早く終わっても次に渡さない（f=0）と置くと、同じ55.2日でも A は1.2%、B は35.0%しか間に合わなかった。A では、どれか1つの作業でも割り当てを超えると、全体は必ず期限を超える
- **早く終わった分を全部渡す（f=1）と置くと、A と B は同じになった**。差を生んだのは余裕の置き場所そのものではなく、「早く終わった分が次へ渡らない」ことだった

### 90%の余裕：作業ごとに積むか、全体でまとめるか
| | 中央値の合計に足す日数 | 全体の日数 |
|---|---|---|
| 作業ごとに90%の日数を積む | +41.3日 | 87.3日 |
| 全体の90%の日数（早く終わった分を全部渡すとき） | +18.4日 | 64.4日 |

- 作業ごとに「9割はこれで終わる」日数を積むと、余裕は全体でまとめたときの約2.2倍になった。どの作業も同時に悪いほうへ振れることはまれなので、全体では余裕が少なくて済む
- それでも f=0 と置くと、作業ごとに90%の日数を割り当てた A が全体の期限（87.3日）に間に合ったのは34.8%だった（式では 0.9 の10乗＝34.9%）。f=1 なら99.8%
- 全体の期限内90%に必要な全体の日数は、f=1 では中央値の合計の1.4倍、f=0 の B では1.55倍。f=0 の A は2倍にしても42.1%だった

### 確かめ：置き方を変えると（全体の日数は中央値の合計の1.2倍、各4万回）
- ぶれ0.3〜0.7・作業の数5〜20の9通りで、f=0 の期限内は A が0.01〜20.4%、B が6.6〜83.7%。f=0 と f=0.5 のどの置き方でも B が A を上回った
- f=1 では、どの置き方でも A と B は同じだった（差0）
- 作業ごとに90%の日数を積んだ余裕は、全体でまとめた余裕の1.64〜3.24倍だった（作業の数が多く、ぶれが小さいほど倍率が大きい）
- 間に合う割合そのもの（35.0%など）は、ぶれ・作業の数・全体の日数の置き方で大きく動く。言えるのは「A は B 以下で、f=1 で同じになる」という向きまで

## 注意（言えないこと）
- 架空のプロジェクトです。作業の日数の分布（対数正規・ぶれ0.5）、作業の数、全体の日数は作成者が置いたもので、間に合う割合の大きさはこれで決まります
- 「早く終わっても割り当ての日まで次に渡さない」（f）は作成者の置いた仮定です。実際のチームでどれくらい渡されるかは、ここからは言えません。f=1 なら A と B の差はなくなります
- B でも、作業ごとの目標（中央値）より早く終わった分は同じ f で扱いました。目標を厳しくすると人の働き方が変わる効果（急ぐ・品質が下がる）は入れていません
- 作業は1列に順に行うと置きました。並行する作業の合流による遅れは関連する記事 851、作業ごとの見積もりを足したときのずれは関連する記事 849 で扱っています。849 は余裕を持たずに見積もりを足したときの不足を、この記事は同じ日数の余裕をどこに置くかを数えています
