# 355 README の8つの節は、どれだけそろっているか（④ 振り返り R110）

GitHub に置いた記事の README の見出しを読み、問い・データ・手法・結果・頑健性・再現手順・言えないこと・出典の8つの節があるかを数えた

## 問い

- 看板記事で決めた8つの節は、どれだけそろっているか
- 記事のグループで、どの節が欠けやすいか
- 節の名前は、決めたとおりか

## 手法

| 手順 | 中身 |
|---|---|
| 拾う（`src/a355_extract.py`） | `articles/*/README.md` 607本のうち、初期の記事で同じ本文を共有しているものを1本にまとめた542本（2026年11月12日、コミット 0ee78ff）。`##` 以下の見出しを取り出す |
| 節の判定 | 決めた名前そのもの（問い・データ・手法・結果・頑健性・再現手順・言えないこと・出典）と、同じ役目の別の名前（動かし方・注意・確かめたこと・結論など）の両方で数える |
| 表で書いたもの | 通常の記事は、問いと手法を見出しではなく表の列（`| 問い | 手法 |`）で書いている。これも「ある」に数えた集計を主にした |
| まとめ方（`src/a355.py`） | 節ごと・記事のグループごとの割合、8つのうちそろっている数 |

F165（再現できる形）はコードを流し直して確かめた。ここでは節があるかどうかだけを数える

## 言えないこと

- 数えたのは節があるかどうかだけ。中身が足りているかは見ていない
- 見出しの名前で判定した。節を作らずに本文の中で書いた場合は「ない」になる（通常の記事の問いと手法は、表の列で拾った）
- 「同じ役目の別の名前」の決め方で割合は変わる。決めた名前そのものだけの集計は `results/sections_strict_names.csv`
- 8つの節は看板記事の決まりで、通常の記事は6つの形（問いと手法の表・主な結果・動かし方・データ・注意・出典）で作っていた。通常の記事で頑健性が0%なのは、決まりになかったため
- グループは番号のまとまりで、作った順とは少しずれる
