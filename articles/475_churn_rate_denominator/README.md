# 475 解約率の分母を変えると、月次と年率はどれだけ変わるのか（実務の型）

架空の会員データ（約14.8万人、36か月）で、月次の解約率を分母4通り（期首人数／期首と期末の平均／その月に1日でも在籍した人数／在籍日数）で出し、差と、年率への直し方による違いを測ったフォルダです。344（アクティブな顧客の定義）・388・314 とは別に、「同じ解約の数を何で割るか」だけを扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A475 | 分母で月次の解約率はどれだけ違うか。差は何で決まるか。前月比の向きは変わるか。年率にすると、直し方でどれだけ違うか | 入会からの日数で解約のしやすさが違う会員を作り、入会が増える年・横ばいの年・減る年を並べる／4つの分母で月次を出す／12倍・複利・実際に1年追った割合を比べる。SQL は DuckDB で実行し、pandas の値と一致を確かめる | `src/a475_churn.py`、`src/01_churn_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
基本の場面：最初の会員4万人＋36か月の入会108,036人。30日あたりの解約の確率は、入会30日まで12%、31〜90日6%、91日以降2.5%。キャンペーンの月（4回）は入会が2.2倍

- **月次の平均（36か月）**：①期首人数 3.35%、②期首と期末の平均 3.32%、③1日でも在籍した人数 3.18%、④在籍日数 3.31%。4つの幅は平均0.17pt、最大0.67pt（2023年10月：①4.53%、②4.26%、③3.87%、④4.24%。①は③の1.17倍）
- **差は入会の多さで決まる**：①と③の差と「その月の入会数÷期首の会員数」の相関は0.99。年ごとの①と③の差は、入会が増える2023年0.30pt、横ばいの2024年0.13pt、減る2025年0.07pt
- 解約のうち、その月に入会した人の解約は8.8%。これを除いて期首人数で割ると平均3.03%（①より0.32pt低い）
- **前月比の向き**：4つの分母で向きが分かれたのは、35か月のうち1か月だけ。いちばん高い月は①②④が2023年10月、③が2023年5月。いちばん低い月は4つとも2025年11月
- **入会の多さだけを変えると**（解約のしやすさは同じ）：毎月の入会が期首の0%なら4つとも2.55〜2.58%。8%で①3.71%・③3.44%、21%で①5.38%・③4.46%（1.21倍）
- **年率**（2023年／2024年／2025年）

| 出し方 | 2023年 | 2024年 | 2025年 |
|---|---|---|---|
| ①の月平均を12倍 | 45.7% | 39.0% | 35.7% |
| ①の月平均を複利で1年分 | 37.3% | 32.8% | 30.4% |
| ③の月平均を12倍 | 42.1% | 37.5% | 34.9% |
| ③の月平均を複利で1年分 | 34.9% | 31.7% | 29.8% |
| 年間の解約数 ÷ 年初の会員 | 58.9% | 41.0% | 35.6% |
| 年初にいた会員のうち、年末までに解約した割合 | 26.5% | 27.4% | 26.9% |

- 年率は、分母の違い（①と③で1〜4pt）より、直し方の違い（12倍と複利で5〜8pt）と、誰を追うかの違い（最大32pt）のほうが大きかった

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- SQL（DuckDB）で出した期首・期末・入会・解約の人数、在籍日数、4つの解約率が、pandas で出した値と36か月すべて一致する（コード内の assert）

## データ
- `data/members_sample.csv`：架空の会員（入会日・最後に在籍した日）から2,000人（全体はコードで作り直す。seed 475）

## 注意（言えないこと）
- 架空のデータ。差の大きさは、入会の多さと、入会直後の解約のしやすさの置き方で決まる。入会直後に解約しやすいと置いたので、入会が多い月はどの分母でも解約率が上がる
- どの分母が正しいかは決めていない。分子（解約の数）と分母（誰を数えるか）が同じ集まりを指しているかを確かめるための比べ
- 休会、再入会、月の途中での料金の変更、解約の申し出と実際の解約の日のずれは扱っていない
- 年率の比べは、この会員の作り方での結果。入会からの日数で解約のしやすさが変わらないなら、複利の年率は「年初にいた会員を追った割合」に近づく（推測。ここでは確かめていない）
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
