# 665 会員カードを出した客だけで客単価を見ると、店全体の客単価よりどれだけ高く出るのか（実務の型・顧客の指標）

会員カードを出したレシート（ID付きの購買データ）は、誰が何を買ったかが分かるので、客単価の分析によく使われます。ところが、カードを出すかどうかは客が決めます。まとめ買いのときほどポイントが多くつくので、金額の大きいレシートほどカードが出されやすくなります。**ここでは、架空の店の1年分のレシート6万枚で、金額が大きいほどカードを出すように置き、会員だけの客単価が本当の客単価からどれだけずれるか、金額帯で重みづけるとどこまで戻るかを比べました。** カードの出され方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A665 | 会員だけの客単価はどれだけ高く出るか。金額帯で補正するとどこまで戻るか | C1 会員カードを出したレシートだけの平均、C2 全レシートの平均（本当の客単価）、C3 金額帯ごとの会員の平均を全レシートの帯ごとの枚数で重みづけ（帯の数3・5・10）。カードを出す割合を全体で変えて比べる。DuckDB（1スレッド）と pandas で一致を確認。seed 665 | `src/a665_card.py`、`src/02_card_duckdb.sql`、`src/01_card_tsql.sql`（未検証） |

## 主な結果
- **本当の客単価は2,065円、会員カードを出したレシートだけでは2,690円（+30.2%）**。カードを出さなかったレシートは1,610円。中央値でも1,500円と2,010円
- **カードを出した割合は全体で42%**。300円未満のレシートでは10%、8,000円以上では79%
- **金額帯で重みづけると戻る**：帯が3つで+5.0%、5つで+2.3%、10で+0.7%。帯を細かくするほど、帯の中の偏りが小さくなる
- **カードを出す人が少ないほど、ずれは大きい**：全体のカードの割合が9%なら+59%、50%なら+25%、86%なら+6%。金額帯5つの補正では、どの割合でも+0.4〜+5.3%

## 動かし方
```
pip install -r requirements.txt
cd src && python a665_card.py
```
数秒で終わります。`data/receipts.csv`（receipt_id・amount・card・金額帯 b3・b5・b10）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 会員だけ・全体・金額帯5つの補正の客単価が、DuckDB と pandas で一致した
- T-SQL 版（`01_card_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 仮定：レシートの金額は対数正規（中央値1,500円）。カードを出す確率は、金額の対数に比例して上がるロジスティック（金額が2.7倍になるとオッズが2.5倍）
- カードを出すかどうかは、金額だけで決まるように置いた。補正が効くのはこのため

## 注意（言えないこと）
- 架空のデータ。実際の店の数字ではない
- 実際には、時間帯・年齢・買う品目など、金額以外の理由でもカードの出し方が変わる。金額帯で重みづけても、それらの偏りは残る
- 補正には、全レシートの金額帯ごとの枚数（POS の集計）が要る。会員データだけでは補正できない
