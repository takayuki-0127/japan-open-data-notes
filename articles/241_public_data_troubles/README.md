# 241 公的データを使って困ったことは何だったか（④ 振り返り R012）

このシリーズの記事501本の README に書き残した「困ったこと」（定義の変更・秘匿・転記・取れないデータなど）を、言葉で拾って数えたフォルダです。看板記事 F01〜F120 の作業ログから「設計から変えたこと」を数えた [F122](../F122_pitfalls_from_logs) を、全記事の README に広げ、公的データに特有の困りごとに絞りました。

## 問い

- 公的データを使っていて、どんな種類のことで困ったか
- 困ったことを書き残していたのは、どの記事のまとまりか
- 困ったときに、どう扱ったか

## 手法

| 手順 | 中身 |
|---|---|
| 拾う（`src/a241_01_extract.py`） | README を1行ずつ読み、8つの種類ごとの言葉の一覧（正規表現）に合う行を拾う。リンク（http）を含む行と見出しは数えない |
| 当たりを確かめる | 種類ごとに乱数（seed 7）で1記事1行を9〜10本選び、作成者が目で「困りごとの記述か」を判定（`data/precision_check.csv`） |
| 集計（`src/a241_02_analyze.py`） | 種類ごとに「1回でも出た記事の数」。記事のまとまり（000–099・100–226・F01–F99・F100–F199・F200–F255・F256–F295（精選）・227以降とT）ごとに、1つ以上出た記事の割合と、1万字あたりの種類の数 |

## 主な結果

| 種類 | 記事 | 501本に占める割合 | 目で確かめた当たり |
|---|---|---|---|
| 定義・分類・数え方の変更 | 70 | 14.0% | 8/10 |
| 欠測・秘匿・非公表 | 59 | 11.8% | 7/10 |
| 取れない・代わりのデータ | 35 | 7.0% | 8/10 |
| 改訂（速報と確報・遡及） | 19 | 3.8% | 7/10 |
| 丸め・桁 | 14 | 2.8% | 7/10 |
| 暦年と年度・時点のずれ | 10 | 2.0% | 8/10 |
| 市町村合併・境界の変更 | 10 | 2.0% | 8/10 |
| PDFや資料からの手での転記 | 9 | 1.8% | 7/9 |

- 1つ以上の種類が出た記事は176本（35.1%）
- まとまりごと：000–099 29%、100–226 33%、F01–F99 31%、F100–F199 44%、F200–F255 19%、精選 60%、227以降・T 22%
- README の平均の長さは精選が約7,300字でいちばん長い。1万字あたりの種類の数では 100–226（1.86）がいちばん多く、精選は 1.36
- 実際の例は `data/cases.csv`（図3）

## データ

| ファイル | 中身 |
|---|---|
| data/readme_index.csv | README ごとのまとまりと文字数 |
| data/trouble_lines.csv | 拾った行（記事・まとまり・種類・行の先頭240字） |
| data/precision_check.csv | 目で確かめた本数と当たりの本数（作成者の判定） |
| data/cases.csv | 図3の例（README から作成者が選んだ） |

## 注意（言えないこと）

- README に書き残したことだけを数えている。困ったのに書かなかったことは入らない。書く習慣はまとまりで違うので、まとまりの差が困りごとの多さの差とは限らない
- 言葉で拾ったので、外れ（2〜3割）と取りこぼしがある。目で確かめたのは種類ごとに9〜10本だけ
- どの統計が使いにくいかの評価ではない
