# 495 会員ランクを「暦年」と「直近12か月」で判定すると、何人のランクが変わるのか（実務の型）

架空の会員2万人の月ごとの購入額（2024〜2025年）から、会員ランクを2つの決め方で出し、2025年の各月にランクが違う会員の割合、上下の向き、年の途中でランクが変わる回数を数えたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A495 | 暦年で決めるランクと、直近12か月で毎月決め直すランクは、どれだけ食い違うか | 暦年：2024年の購入額で2025年の1年間のランク。直近12か月：2025年の毎月1日に、前の月までの12か月で決め直す。ゴールド（10万円以上）・シルバー（3万円以上）・ブロンズ。直近12か月の額は DuckDB のウィンドウ関数でも出して一致を確認。会員ごとの伸び縮みのばらつきを変えてくり返す | `src/a495_member_rank.py`、`src/01_rank_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **ランクの割合**（暦年）：ゴールド8.2%、シルバー26.8%、ブロンズ65.0%。直近12か月（2025年12月1日）も8.7%・26.7%・64.6%で、全体の割合はほとんど変わらない
- **ランクが違う会員**：1月1日は同じ（どちらも2024年1〜12月）。そこから毎月増え、2月3.7%、6月11.1%、12月18.5%。12月は、直近12か月のほうが上が9.7%、下が8.8%で、上下はほぼ半々
- **入れ替わり**（2025年12月1日）：暦年でゴールドの1,643人のうち、直近12か月でもゴールドは1,121人（68%）。シルバーの23%はブロンズになる
- **2025年のどこかで2つが食い違った会員**：26.1%
- **年の途中でランクが変わる回数**（直近12か月、購入のある会員）：0回が73.5%、1回以上が26.5%、2回以上が12.4%。暦年なら年の途中では0回
- **伸び縮みのばらつきを変えても**（各8,000人）：12月に食い違う割合は18.0%（伸び縮みなし）〜20.5%。食い違いの多くは、毎月の購入額の揺れから来ている

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- 直近12か月の購入額が、DuckDB のウィンドウ関数の結果と一致すること（コード内の assert）

## データ
- `data/fictional_monthly_spend.csv`：架空の会員2万人の月ごとの購入額（2024〜2025年、seed 495）

## 注意（言えないこと）
- 架空の購入額。食い違う割合は、置いたランクの線（10万円・3万円）と購入額の揺れで決まる
- ランクが変わったことで会員の買い方が変わる、という動きは入れていない
- どちらの決め方がよいかを言うものではない。暦年は1年間変わらず分かりやすい代わりに、最近の買い方が反映されるのは翌年。直近12か月は早く反映される代わりに、年の途中で上下する
- 商品の ABC 分析は 410、アクティブな顧客の定義は 344 で扱った
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
