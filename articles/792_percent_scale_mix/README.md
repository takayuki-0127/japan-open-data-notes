# 792 率の列に「0.05」と「5」が混ざっていると、平均はどれだけずれるのか（実務の型）

割引率や達成率のような「率」の列には、5% を「0.05」（割合）で入れる仕組みと、「5」（百分率の数）で入れる仕組みがまざることがあります。そのまま平均すると、5 は 500% として数えられます。「1より大きい値は百分率だろう」と考えて100で割る直し方もありますが、0.5% や 1% を手で「0.5」「1」と入れた行は、割合の 0.5（50%）・1（100%）と見分けがつきません。**ここでは、作成者が乱数で作った架空の割引の記録2,000件で、3通りの平均を本当の平均と比べました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A792 | 割合と百分率の数がまざった列の平均は、どれだけずれるか | 架空の割引2,000件。本当の割引率は0.5〜30%の9段階。6割はシステムからの入力（割合）、4割は手入力（百分率の数）。そのまま平均・1より大きい値だけ100で割る・入力元で直す、を DuckDB（1スレッド）で出し、pandas の値と一致を確認。手入力の割合を0〜100%に変えた試しも。seed 792 | `src/a792_percent.py`、`src/02_rate_duckdb.sql`、`src/01_rate_tsql.sql` |

## 主な結果

| 平均の出し方 | 割引率の平均 |
|---|---|
| そのまま平均 | **308%**（本当の41倍） |
| 1より大きい値だけ100で割る | **12.9%**（＋5.3ポイント） |
| 入力元で直す | 7.55% |
| 本当の平均 | 7.55% |

- 手入力は2,000件のうち807件。そのまま平均すると308%になった
- 「1より大きい値だけ100で割る」直し方では、手入力の 0.5%・1% の135件（手入力の17%）が 50%・100% のまま残り、平均は12.9%と本当（7.55%）より5.3ポイント高かった
- 手入力が1割まざるだけで、そのままの平均は85%になった。「1より大きい値だけ直す」は、手入力が1割で8.7%、6割で15.5%と、手入力が多いほど外れた
- 入力元（source の列）が分かれば、正しく直せた

## 注意（言えないこと）
- 架空のデータです。ずれの大きさは、手入力の割合と、0.5%・1% のような小さい率の多さで決まります
- 実際の表に入力元の列があるとは限りません。ないときは、入力画面や取り込みの仕組みをたどって確かめる必要があります
