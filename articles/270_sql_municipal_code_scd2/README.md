# 270 市区町村の合併を、SQL でどう扱うか（実務の型）

期間つきのマスタ（SCD2：Slowly Changing Dimension Type 2）と再帰 CTE で、2000年の市町村コードを今のコードへたどる SQL の型。総務省「廃置分合等情報」の実際の記録（2001〜2018年の700件）で動かし、結果を F94 の対応表と総務省の公表値に照らした。

| 番号 | 問い | 手法 | ファイル |
|---|---|---|---|
| A270 | 合併でコードが変わった市町村を、SQL でどう結合するか。そのまま結合すると何が起きるか | 期間つきマスタ（valid_from／valid_to と代理キー）、ある日に有効な版の結合、再帰 CTE、件数と合計の照合 | `sql/00〜05_*.sql`、`src/a270_scd2.py` |

F94（市町村合併の扱いで20年の推移の分析がどう変わるか）は「分析の結論への影響」を見た記事。この記事は同じ記録を使い、**SQL での持ち方と照合の手順**に絞った。

## 主な結果

- **そのまま結合すると**：2000年10月1日の3,252単位（東京23区は区ごと、政令市は市全体）のコードを2020年の1,741単位のマスタに結合すると、1,823単位（2000年の人口の20%）は結合で落ちた。294単位（人口の24%）は**同じコードのまま区域が広がっていて、エラーも件数の不一致も出ずにつながった**
  - その294単位で2000→2020年の人口の増減を素朴に出すと中央値 +14.6%。編入された町村を足した2000年の人口と比べると中央値 −13.0%。216単位が「増えた」に見えたが、正しく比べて増えていたのは38単位。178単位は増減の向きが逆になった
- **期間つきマスタ**：3,568コード・3,928版（2つ以上の版があるコード313）。同じコードの版どうしの期間の重なりは0
- **再帰 CTE**：3,252単位すべてが、2020年のマスタにある1,741単位のどれか1つにたどり着いた（0回1,429・1回1,770・2回53）。F94 の対応表と3,252/3,252一致。2000年の人口の合計 126,925,843人は、たどった先で足しても同じ
- **ある日の数**：期間つきマスタで「その日に有効だった版」を数えると（23区を除く）、2006年3月31日 1,821、2010年3月31日 1,727、2014年4月5日 1,718、2018年10月1日 1,718。総務省の公表値と4時点とも一致
- **つまずいた2点**（直さないと合わなかったもの）
  1. **同じ日の「編入→市制」**：6件。町に村が編入した同じ日に、その町が市になってコードが変わる（例：08308 御前山村 → 08344 大宮町 → 08225 常陸大宮市、2004年10月16日）。日付を「より後」でたどると途中で止まり、9単位が2020年のマスタにないコードで終わった。「同じ日以降」にし、期間つきマスタでは長さ0の版（6件）を落とした
  2. **政令市の区への編入**：4件（例：蒲原町 → 静岡市清水区 22103）。この記事の単位は政令市を市全体で数えるので、区のコードを市のコード（22100）にそろえた（`sql/00_ward_to_city.sql`）。そろえないと、区のコードが「市町村」として数えられ、ある日の数が公表値より3多くなった

## 動かし方

```
pip install -r requirements.txt
cd src && python a270_scd2.py
```

`results/checks.json` に照合の数字、`results/muni_scd2.csv` に期間つきマスタ、`results/crosswalk_sql.csv` に2000年→今の対応、`results/counts_by_date.csv` に月初ごとの数、`results/grew_codes.csv` に「同じコードで区域が広がった」294単位を書き出す。

## SQL（T-SQL）

| ファイル | 中身 | DuckDB での確かめ |
|---|---|---|
| `01_create_load.sql` | 表の定義と BULK INSERT | 表の定義は read_csv で同じ表を作って代用。**BULK INSERT は未検証** |
| `00_ward_to_city.sql` | 区への編入を市のコードにそろえる（UPDATE … FROM） | **T-SQL の UPDATE … FROM は未検証**。同じ中身を DuckDB の UPDATE … SET … WHERE で実行 |
| `02_scd2.sql` | 期間つきマスタ（LEAD で次の版の前日を valid_to に） | 実行済み（DATEADD(day, …) と SELECT … INTO を書き換え） |
| `03_as_of.sql` | ある日に有効な版の数 | 実行済み |
| `04_roll_forward.sql` | 再帰 CTE で今のコードまでたどる | 実行済み（T-SQL は WITH、DuckDB は WITH RECURSIVE） |
| `05_checks.sql` | 件数・行き先・人口の合計の照合 | 実行済み |

## データ

- `data/merger_events.csv`：総務省「廃置分合等情報」（e-Stat 市区町村名・コード）の 2000年10月2日〜2020年10月1日の記録のうち、区域・コードが変わるもの700件（F94 の写し）
- `data/events_x.csv`：上を「旧コード1つ」ずつの行（2,007行）にばらしたもの（`a270_scd2.py` が作る）
- `data/old_units_2000.csv`：2000年国勢調査 第1次基本集計の市町村ごとの人口（3,252単位、F94 の写し）
- `data/units_2020.csv`：社会・人口統計体系 市区町村データの2020年の総人口（今の境域、1,741単位、F94 の写し）
- `data/crosswalk_2000_2020.csv`：F94 の対応表（照合用）
- 公表値：総務省「広域行政・市町村合併」の市町村数の推移（平成18年3月31日 1,821、平成22年3月31日 1,727、平成26年4月5日 1,718、平成30年10月1日 1,718）

## 言えないこと・注意

- **境界変更と分割は細かく追っていない**。市町村の一部が隣に移る「境界変更」は記録に入れていない。上九一色村（2006年）は2つの町・市に分かれて編入したが、記録の上で1つの行き先（富士河口湖町）にまとめた（F94 と同じ）。人口を面積や地区で割り振る必要がある問いには、この対応表だけでは足りない
- **SQL Server では動かしていない**。T-SQL で書き、DuckDB で同じ中身を動かして確かめた。BULK INSERT と UPDATE … FROM は未検証
- **2020年10月以降の変更は入っていない**（記録の最後は2018年10月1日の那珂川市の市制）
- 「ある日の数」が公表値と合ったのは4時点。月ごとの数すべてを公表値と照らしたわけではない
