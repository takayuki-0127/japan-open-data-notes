# 287 頑健性チェックは、いくつやれば十分か（④ 振り返り R014）

このシリーズで記事ごとに書いてきた頑健性チェック（期間・対象・定義・モデルなどを変えて結論を確かめること）の数を数え、「いくつやれば、結論を動かすチェックに当たったか」を計算したフォルダです。

[F163](https://github.com/takayuki-0127/japan-open-data-notes/tree/main/articles/F163_robustness_checks_review) は、看板記事 F01〜F125 について「どの種類のチェックがよく効いたか」を手作業で判定しました。ここでは F163 の判定をそのまま使い、数のほうに絞ります。

## 問い

- 1本あたり、いくつの頑健性チェックをしてきたか。記事のグループで違うか
- チェックを k 個だけにしていたら、結論を動かした種類のチェックを含んでいた割合はどれくらいか

## 手法

| 手順 | 中身 |
|---|---|
| A. 数える | README の「頑健性」「ロバスト」の見出しの節から、表の行と箇条書きを1件ずつ数えた（表の見出し行と「基本」の行を除く）。共有している README は1本に数えて480本 |
| B. 何個で当たるか | F163 の手作業の判定（`data/f163_hand_labels.csv`：113本の「結論が動いたか」の3段階と「いちばん動かしたチェックの種類」）と、F163 が取り出したチェックの一覧（`data/f163_items.json`、コミット 8090888 時点）を使った。チェックの種類は F163 と同じ辞書で付けた |
| 当たる確率 | 記事のチェック n 個のうち、動かした種類のチェックが m 個あるとき、ランダムに k 個選んで1つ以上含む確率 1 − C(n−m, k)/C(n, k)。種類を1つずつ選ぶ場合は、記事にある種類の数を d として k/d |

## 主な結果

- 頑健性の節がある記事は480本中293本。000〜226 の通常の記事にはなく、看板記事は92〜100%、1000本計画（227〜・T）は55%（`results/checks_by_group.csv`）
- 1本あたりのチェックの数（中央値）：F01〜F99 で8、F100〜F199 で8、F200〜F255 で6、精選（F256〜F295）で8、1000本計画で4（図1）。精選では PLAN に「3つ以上」と決めていて、40本中39本が3つ以上だった
- F163 で結論が動いた（一部で弱まる・変わった）78本のうち、表の行か箇条書きでチェックを書いた75本を数えた。1本のチェックは中央値8個、そのうち動かした種類のチェックは中央値2個
- チェックを k 個にしていたら動かした種類を含んでいた割合：1個で31%、3個で66%、5個で81%、7個で88%、それ以上はほとんど増えず、上限は91%（図2、`results/coverage_curve.csv`）。残り9%（7本）は、手作業で選んだ種類が辞書の種類と合わなかった
- 結論が変わった・逆になった22本に限ると、3個で61%、5個で78%、7個で85%
- 種類を1つずつ選んでも、少ない数では早く当たらなかった（3個で53%）。動かした種類のチェックは、記事の中で2個以上あることが多かったため（推測）

## データ

- `data/f163_hand_labels.csv`・`data/f163_items.json`：F163 の手作業の判定とチェックの一覧（F163 のフォルダの写し）
- `data/f163_articles_coverage.csv`：記事ごとの n・m と、k 個で当たる確率

## 言えないこと

- 「動かした種類のチェックを含んでいれば、結論が動いたはず」と仮定した。同じ種類でも中身が違えば動かないことがあるので、割合は上限に近い見方（推測）
- 「結論が動いたか」は F163 の手作業の判定で、F01〜F125 だけ。F126 以降は数えた数だけで、動いたかは判定していない
- チェックの数は README に書いた分だけ。試して書かなかったチェックは数えていない
- 種類は辞書で付けたので、1つのチェックが複数の種類に入ることがある
