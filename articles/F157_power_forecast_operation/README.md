# F157 電力需要の予測を、1年通して運用したらどうなるか？（再学習のタイミングと、外れ方の推移）

看板記事 F157。F22 で作った「翌日24時間の電力需要」の予測を、**毎日実際に運用したつもりで1年分くり返し**、外れ方の推移と、モデルを学習し直すタイミングの効き方を確かめる。F92（ピークの上振れ）・F104（気温と需要）・F119（答え合わせ）の続編。

## 問い

- 予測モデルを一度作ったら、1年間そのまま使っても大丈夫か。毎月・毎週学習し直すと、どれだけ良くなるか
- 外れ方が悪くなったときだけ学習し直す「監視ルール」は、決まった間隔の再学習より効率がよいか
- 古いモデル（1〜3年前に学習したもの）を使い続けると、どれだけ外れるか
- 翌日ピークの「95%の上限」は、1年の運用で狙いどおり収まるか。幅をどう更新するとよいか

## データ

新しく取得したものはない。F22 で取得・整形したデータをそのまま使う（`src/01_データ.md`）。

| データ | 出典 | 期間 |
|---|---|---|
| 東京エリアの1時間ごとの需要 | 東京電力パワーグリッド「エリア需給実績データ」 | 2016年4月〜2026年9月 |
| 関西エリアの1時間ごとの需要（頑健性） | 関西電力送配電「エリアの需給実績」 | 2024年4月〜2026年9月 |
| 気温・湿度・降水量（東京・大阪） | 気象庁「過去の気象データ」 | 同上 |

## 手法

1. **運用の再現**：予測する日 D の前日 D−1 の夜に、D の24時間を予測する（特徴量は F22 と同じ：時刻・曜日・祝日・季節・気温・24時間前と1週間前の需要など）。これを **2025年10月1日〜2026年9月30日の365日** くり返す。学習に使うのは、その時点までに分かっている実績すべて（拡張ウィンドウ）
2. **再学習のしかた**（LightGBM）：
   - 固定：運用開始の前日までのデータで1回だけ学習
   - 四半期ごと（4回）・毎月（12回）・毎週（53回）
   - 監視ルール：直近14日の MAPE が 2.0% を超えるか、直近7日のずれの平均が ±1.0% を超えたら、その夜に学習し直す（前回から14日以上あける）。厳しめ（1.5%・0.75%）・ゆるめ（2.5%・1.5%）も
   - 古いモデル：運用開始の1・2・3年前までのデータで学習したモデルを、そのまま1年使う
3. **比べる相手**：1週間前の同じ時刻（そのまま）、線形回帰（Ridge、固定と毎日学習し直し）
4. **評価**：MAPE（1時間ごとの誤差率の平均）、ピークの MAPE、ずれの向き、日ごとの MAPE の95%点。差の区間は、日ごとの差を1週間ずつまとめて引き直すブロック・ブートストラップ（2,000回）
5. **ピークの95%上限**：毎月学習し直すモデルの翌日ピーク予測 ×（1＋q）。q は「1年前のモデルの1年分の外れ（実績÷予測−1）の95%点」を(a)1年で1つ、(b)季節ごと、(c)運用中の直近90日の外れで毎日更新、の3通り

LightGBM は F22 と同じ設定から、木の数を900→300・学習率を0.04→0.1にした軽い版を使った（何十回も学習し直すため）。固定のモデルで比べると、F22 と同じ設定は MAPE 2.22%、軽い版は 2.27% で、差は 0.05ポイント。

## 結果

### 1. 学習し直しても、東京ではほとんど変わらない

東京・2025年10月〜2026年9月（365日・8,760時間）

| 再学習 | 学習の回数 | MAPE | 固定との差（95%区間） | ピークの MAPE | ずれの平均 |
|---|---|---|---|---|---|
| 固定（開始前に1回） | 1 | 2.27% | — | 2.29% | −0.19% |
| 四半期ごと | 4 | 2.28% | +0.01（−0.03〜+0.04） | 2.33% | −0.27% |
| 毎月 | 12 | 2.25% | −0.02（−0.07〜+0.03） | 2.32% | −0.16% |
| 毎週 | 53 | **2.23%** | −0.04（−0.09〜+0.01） | 2.24% | −0.01% |
| 監視ルール | 23 | 2.26% | −0.01（−0.06〜+0.03） | 2.27% | −0.06% |
| 1週間前の同じ時刻 | — | 8.13% | | 9.34% | |
| 線形回帰・固定／毎日 | 1／365 | 3.59%／3.57% | | | |

- 毎週学習し直しても、MAPE は 2.27% → 2.23% で、区間は0をまたぐ。月ごとに見ても、どの再学習も固定とほぼ同じ線を描いた（図1）
- 1年の中で外れが大きかったのは8月（3.1〜3.4%）と12〜2月（2.5〜2.8%）。これは再学習の間隔では変わらなかった
- いちばん外れた日は、2026年9月9日（日降水量34mm、8.7%）、8月10〜12日（山の日の前後、予測が7〜8%上に外れた）、12月26日（年末に入る日、7.7%）。休みの取り方や天気の急変が原因と考えられる（推測）。毎週の再学習でも、これらの日はほとんど直らなかった

### 2. 監視ルールは、2週間ごとの定期再学習とほぼ同じになった

- 2.0%という水準は、東京の運用中の MAPE（年 2.27%）より低く、14日あけるたびにほぼ毎回ルールにかかった（23回）。結果として「2週間ごとの再学習」に近くなり、MAPE も毎月・毎週と同じ程度だった
- 厳しめ（26回）は 2.23%、ゆるめ（12回）は 2.28%。どれも固定との差は ±0.04 ポイント以内
- ずれ（予測−実績）の7日平均が ±1% を超えた期間は、8月のお盆の前後や2月など、再学習しても戻らない一時的なものが多かった（図4）

### 3. 効いたのは「古いモデルを使い続けない」こと

| 学習した時点 | MAPE（2025年10月〜） | 固定との差 | MAPE（2024年10月〜、頑健性） |
|---|---|---|---|
| 運用開始の直前 | 2.27% | — | 2.17% |
| 1年前 | 2.32% | +0.05（+0.00〜+0.10） | 2.42%（+0.26） |
| 2年前 | 2.63% | +0.37（+0.29〜+0.45） | 2.58%（+0.41） |
| 3年前 | 2.70% | +0.44（+0.33〜+0.54） | 2.58% |

- 2年前のモデルは、どの月も予測が低めにずれ（年平均 −0.97%）、3年前のモデルは高めにずれた（+1.15%）。古いモデルは「需要の水準」がずれていく（図3）
- 1年の中での再学習の間隔より、**1〜2年に一度は必ず学習し直すこと**のほうが、外れ方への効き目が大きい

### 4. 学習データが短い関西では、再学習が効いた

| | 固定 | 四半期 | 毎月 | 毎週 | 監視ルール |
|---|---|---|---|---|---|
| 関西（2024年4月〜のデータで開始） | 2.89% | 2.77% | 2.70% | **2.64%** | 2.65% |

- 関西は運用開始の時点で1年半分のデータしかなく、固定のモデルは1年を通して低めにずれていた（−1.19%）。毎週学習し直すと 2.64%（固定との差 −0.25、区間 −0.39〜−0.11）、ずれも +0.03% まで戻った
- 東京（9年半分のデータで開始）とは違い、**学習データが少ないうちは、再学習で新しい季節を覚えさせる効果が大きい**

### 5. ピークの「95%の上限」は、1年で9割しか収まらなかった

| 上限の幅の決め方 | 1年で収まった割合 | 平均の上乗せ | いちばん低かった月 |
|---|---|---|---|
| 1年分で1つの幅 | 90.1% | +5.0% | 1月 80.6% |
| 季節ごとの幅 | 89.6% | +4.6% | 1月 80.6% |
| 直近90日で毎日更新 | **93.4%** | +5.9% | 1月 83.9% |

- 前の年の外れから決めた幅（+5.0%）は、運用の年には狭すぎた（95%のはずが 90.1%）。直近90日の外れで幅を毎日更新すると 93.4% まで近づいたが、1月は 84% にとどまった（図5）
- F119 では「10月は幅が広すぎる」と書いたが、1年で見ると冬と夏に狭すぎる月があり、平均では足りなかった

## 頑健性

| 確かめたこと | 結果 |
|---|---|
| 運用する年を1年前（2024年10月〜2025年9月）にする | 固定 2.17%・毎月 2.13%・毎週 2.09%（差 −0.07、−0.12〜−0.03）。再学習の効果は小さく、古いモデルの悪化（1年前 +0.26、2年前 +0.41）は大きい、という形は同じ |
| 地域を関西にする | 上の4。データの短い関西では再学習が効いた |
| 気温に予報の誤差（日ごとに標準偏差1.5℃）を足す | 固定 2.97%・毎月 2.87%。誤差を足すだけで +0.70 ポイント悪化し、再学習の効果（−0.10）より大きい |
| 直近3年だけで学習（スライド） | 毎月 2.47%。全期間で学習する 2.25% より悪い（+0.20） |
| 線形回帰で毎日学習し直す | 3.59% → 3.57%（−0.02）。モデルを変えても再学習の効果は小さい |
| 監視ルールのしきい値（厳しめ・ゆるめ） | 2.23%〜2.28%。固定との差は ±0.04 以内 |
| F22 と同じ設定（木900本） | 固定で 2.22%（軽い版より −0.05）。軽い版で比べても結論は変わらないと考えられる |

## 言えないこと

- 気温は実測値で代用しており、実際の運用（前日の予報を使う）より良く出ている。予報の誤差を足すと 0.7 ポイント悪くなり、その影響は再学習の効果より大きい
- 運用したのは2地域・2年分だけ。需要の構造が大きく変わる年（新しい大口需要、料金制度の変更、感染症など）では、再学習の効き方は違う可能性がある
- 監視ルールのしきい値は私が決めたもので、最適化はしていない。ルールの作り方（例えばモデル自身のふだんの誤差に対する比で決める）しだいで結果は変わる
- 再学習にかかる手間や計算の費用は数えていない。「0.04ポイントのために毎週学習し直す価値があるか」は、使う場面しだい
- ピークの上限は1年分（365日）の結果で、月ごとの割合は30日前後から計算しているので、ぶれが大きい

## 再現手順

```bash
pip install -r requirements.txt
cd src
# F22 のデータ（../F22_power_demand_forecast/data）を使う
python 03_運用の再現.py tokyo 2025-10-01 2026-09-30 main fixed full quarter month week trigger trigger_alt slide age ridge noise
python 03_運用の再現.py kansai 2025-10-01 2026-09-30 kansai fixed quarter month week trigger
python 03_運用の再現.py tokyo 2024-10-01 2025-09-30 prev fixed quarter month week trigger age
python 04_集計と図.py
```

学習の締め日ごとの予測は `../../f157_cache/` に残し、止まってもやり直せるようにしている（リポジトリには入れていない）。乱数の種は 42。2コアの環境で、全部で約3時間。
