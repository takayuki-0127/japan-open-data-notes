# 512 割合を小数1桁で表示すると、前月比の増減が「0.0」や逆の向きに見える月は何か月あるのか？（実務の型）

架空の月次の率（KPI）300本×37か月を作り、表示の桁（整数・小数1桁・小数2桁）で丸めた値どうしの差と、丸める前の差を比べたフォルダです。千人単位に丸めた分子と分母から率を計算し直す場合と、構成比の表の合計が100にならない割合も数えました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A512 | 表示を丸めると、前月比が0に見える月・逆向きに見える月・表示どうしの差と「前月差」の表示が食い違う月はどれだけあるか | 率の水準0.5〜15%、月の動き0.02〜0.5ポイントの架空の KPI を作り、四捨五入（10進）で表示して前月差を比べる。千人単位に丸めた分子・分母から率を出す場合、区分の数2〜20の構成比の表（各1万枚）も数える | `src/a512_rounded_display.py`、`src/02_round_duckdb.sql`、`src/01_round_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（前月比10,800か月）
- **表示の差が0に見える月**：整数で87.8%、小数1桁で40.7%、小数2桁で6.4%
- **向きが逆に見える月**：値をそのまま丸めて表示するだけなら、どの桁でも0件。四捨五入は大小の順を崩さないので、増えたものが減って見えることはない
- **表示どうしの差と、丸める前の差を丸めた「前月差」の表示が食い違う月**：整数10.7%、小数1桁24.2%、小数2桁25.5%（例：3.24%→3.36%は表示が3.2→3.4で差0.2に見えるが、前月差の欄は+0.1）
- **小数1桁のとき、本当の差の大きさごとの「0.0に見える」割合**：0.025ポイント未満88.0%、0.025〜0.05で63.6%、0.05〜0.075で36.5%、0.075〜0.1で14.8%、0.1以上は0%
- **千人単位に丸めた分子と分母から率を計算し直し、小数1桁で表示すると**：向きが逆に見える月が6.5%、0.0に見える月が60.9%。逆に見えた月の本当の差は中央値0.034ポイントと小さいが、分子が小さい KPI では表示の差が最大1.3ポイント開いた
- **構成比の表で、丸めた値の合計が100.0にならない割合（小数1桁）**：3区分24.7%、5区分40.9%、10区分57.3%、20区分69.5%。整数で表示してもほぼ同じ割合
- **DuckDB の ROUND**：小数（DECIMAL）の1.005は1.01、浮動小数点（DOUBLE）の1.005は1.00 に丸まった

## 動かし方
```
pip install -r requirements.txt
cd src && python a512_rounded_display.py
```

## データ
- `data/fictional_kpi_rates.csv`：架空の月次の率（%）300本×37か月（seed 512）

## 注意（言えないこと）
- 架空のデータ。割合は、置いた率の水準と月の動きの大きさで決まる。月の動きが表示の1単位よりずっと大きい KPI では、ほとんど起きない
- 公的統計の率の例は使っていない（ストックの案から変えた点。丸める前の値が公表されていないため、本当の差と比べられない）
- 千人単位の分子・分母は、分母2万〜50万人・率0.5〜15%で置いた。分子が数百人だと丸めの影響が大きい
- 四捨五入は10進で行った。Excel や BI ツールの表示の丸めは試していない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
