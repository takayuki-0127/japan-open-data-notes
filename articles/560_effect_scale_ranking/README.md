# 560 効果を「差」で見るか「比」で見るかで、効果の大きい層が入れ替わるのはなぜか（手法の解説・正解の分かるデータで試す）

施策の効果を層（顧客のグループ）ごとに比べるとき、「率の差（何ポイント上がったか）」で見るか、「率の比（何倍になったか）」や「オッズ比」で見るかで、どの層がいちばん効いたかが入れ替わることがあります。もとの率が層で違うと、同じ効き方でも尺度によって大きさの並びが変わるからです。**ここでは、クーポンなしの購入率が2%〜60%の6つの層からなる架空の顧客で、本当の効き方を「オッズ比一定」「率の比一定」「率の差一定」の3通りに置き、尺度ごとの順位と、層で効き方が違うかの検定を比べました（各層・各群3,000人×1,000回）。** 数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A560 | 効果を差で見るか比で見るかで、層の順位や「効き方の違い」の答えはどう変わるか | 6つの層（クーポンなしの購入率 2・5・10・20・40・60%）。本当の効き方をオッズ比1.8一定・率の比1.3一定・率の差+4ポイント一定の3通りに置き、率の差・率の比・オッズ比と順位を計算。各層・各群3,000人を1,000回引き、最も効く層を当てた割合と、層で効き方が違うかの検定（重み付きの均一性の検定、率の差と対数オッズ比で）が p<0.05 になった割合を数えた。SQL は DuckDB（1スレッド）で例の1回を確かめた。seed 560 | `src/a560_effect_scale.py`、`src/a560_effect_scale.sql`、`src/a560_effect_scale_tsql.sql` |

## 主な結果
- **本当の効き方がオッズ比1.8で一定のとき**：率の差は S5（40%）が 14.5ポイントで1位、S1（2%）が 1.5ポイントで6位。率の比は逆に S1 が 1.77倍で1位、S6（60%）が 1.22倍で6位。率の比の順位は、もとの率の低い順とまったく同じ
- **クーポン1万枚あたりに増える購入**（オッズ比一定）：S1 154件、S5 1,455件
- **率の比で一定のとき**：率の差とオッズ比は、もとの率が高い層ほど大きい（率の差 S1 0.6ポイント→S6 18ポイント）。**率の差で一定のとき**：率の比は S1 3.0倍→S6 1.07倍
- **層で効き方が違うかの検定**（p<0.05 になった割合）：オッズ比一定なら、率の差で検定すると 100%、オッズ比で検定すると 5.1%。率の差で一定なら、率の差で 4.9%、オッズ比で 100%。率の比で一定なら、どちらも 100%
- **最も効く層を当てた割合**（オッズ比一定）：率の差では 81%（本当の1位 S5 と2位 S6 は 14.5 と 13.0 で近い）、率の比では 50%（S1 1.77 と S2 1.73 が近く、S1 の購入が少ないためぶれる）
- **例の1回**（オッズ比一定）：オッズ比は本当は全層 1.80 だが、推定は 1.57〜1.84 にばらつき、順位も付いてしまう

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 560）。例の1回の人数は `results/example_counts_OR.csv`

## 注意（言えないこと）
- 架空のデータ。層のもとの率と本当の効き方は作成者が置いたもので、結果はこれで決まる。実際のクーポンがどの尺度で一定に近いかは分からない
- どの尺度が「正しい」かという話ではない。増える件数を知りたいなら率の差、相対的な効き方を比べたいなら比、というように、目的で尺度を選ぶ
- 「層で効き方が違うか」の答えは、どの尺度で聞くかで変わる。尺度を書かずに「効き方に違いがあった／なかった」とは言えない
- 層の中の人はみな同じ確率と置いた。層の中のばらつきや、層の分け方そのものの影響は扱っていない
