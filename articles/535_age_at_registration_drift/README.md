# 535 顧客の年齢を「登録したときの年齢」のまま集計すると、年代別の構成は何年でどれだけずれるのか？（実務の型）

架空の会員30,000人（2012〜2025年に登録、生年月日つき）と2025年の購入の記録を作り、年代別の構成を、登録時の年齢（登録したときに保存した値）・基準日（2026-03-31）の年齢・購入した日の年齢の3通りで出して比べたフォルダです。ずれが登録からの年数とどう関係するかも見ました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A535 | 保存した年齢のまま集計すると、年代別の構成は何ポイントずれるか。登録からの年数とどう関係するか | 生年月日から満年齢（誕生日の当日に1つ加わる）を3通りの日で出し、10歳ごとの年代に分ける。同じ計算を SQL（DuckDB）でも行い、Python と一致するか確かめる | `src/a535_age_drift.py`、`src/02_age_bases_duckdb.sql`、`src/01_age_bases_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（会員30,000人、2025年の購入58,099件・購入した会員13,854人）
- **会員の平均年齢**：登録時の年齢のまま 36.3歳、基準日の年齢 42.6歳
- **会員の年代別構成（登録時 → 基準日）**：10代 8.5% → 1.9%（−6.5ポイント）、20代 20.8% → 13.5%（−7.3）、30代 31.9% → 25.8%（−6.1）、40代 25.8% → 30.4%（+4.6）、50代 10.5% → 19.5%（+9.0）、60代 2.2% → 7.3%（+5.1）、70代以上 0.3% → 1.6%（+1.3）
- 会員の59.1%は、保存した年齢と今の年齢で年代が違う。構成のずれ（構成比の差の絶対値の和の半分）は20.0ポイント
- **登録からの年数別**：年代が変わった人の割合は、1年 14.0%、3年 34.9%、5年 57.1%、8年 85.8%、10年以上 ほぼ100%。構成のずれは 1年 4.6、5年 17.4、10年 32.8ポイント
- **2025年の購入（登録時 → 購入した日の年齢）**：構成のずれは12.2ポイント、年代が違う購入は39.7%。会員全体より小さいのは、登録から間もない会員ほどよく買うように作ったため
- SQL（DuckDB）の満年齢は、Python と全件一致

```
pip install -r requirements.txt

```

## データ
- `data/fictional_members.csv`：架空の会員（seed 535）。列は member_id・birth_date・registered_on・age_at_registration（登録時に保存した年齢）
- `data/fictional_purchases_2025.csv`：架空の購入。列は purchase_id・member_id・purchased_on

## 注意（言えないこと）
- 架空のデータ。登録の年ごとの人数、登録時の年齢の分布、買う頻度の落ち方は作成者が置いたもので、実際の会社の値ではない。古い会員が多いほど、ずれは大きくなる
- 退会や亡くなった会員は入れていない。生年月日の入力の誤りもない
- 年齢は誕生日の当日に1つ加わる扱いで数えた。2月29日生まれの扱いは、この計算では平年の3月1日に1つ加わる
- どの年齢で集計すべきかは、何を知りたいか（登録したときの客層か、今の客層か、買ったときの客層か）で決まる。この記事はずれの大きさを見ただけ
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
