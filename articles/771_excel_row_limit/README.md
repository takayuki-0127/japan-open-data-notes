# 771 104万行を超える CSV を Excel で開くと、どれだけの行と売上が消えるのか（実務の型）

Excel の1つのシートに入るのは1,048,576行までです。見出しに1行使うので、明細は1,048,575行まで。それを超える CSV を開くと、後ろの行は読み込まれません。開いたときに注意の表示は出ますが（推測。Excel では未検証）、見落とすと、そのまま合計やピボットを作ってしまいます。**ここでは、作成者が乱数で作った架空の売上明細120万行で、Excel に入らない行と売上を、日付順に並んだファイルとばらばらの順のファイルの2通りで数えました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A771 | 上限を超えた分は、どの月から、どれだけ消えるか | 架空の売上明細120万行（2025年1〜12月、後の月ほど件数が多い）。先頭の1,048,575行だけを残す切り方を Python で再現（Excel では未検証）。全件の月別集計を DuckDB（1スレッド）で出し、pandas と一致を確認。seed 771 | `src/a771_row_limit.py`、`src/02_monthly_duckdb.sql`、`src/01_monthly_tsql.sql` |

## 主な結果

| | 日付順に並んだファイル | ばらばらの順のファイル |
|---|---|---|
| Excel に入らない行 | 151,425行（12.6%） | 151,425行（12.6%） |
| 入らない売上 | 4.17億円（12.6%） | 4.15億円（12.6%） |
| 12月 | **すべて消える（123,599行）** | 87%が残る |
| 11月 | 77%が残る（11月22日まで） | 87%が残る |
| 1〜10月 | すべて残る | 87%が残る |

- 120万行のうち151,425行（12.6%）が Excel に入らなかった
- 日付順のファイルでは、11月22日より後がまるごと消え、12月の売上は0になった。月別のグラフでは「12月に売上がなかった」ように見える
- ばらばらの順のファイルでは、どの月も87%ずつ残った。月ごとの形は保たれるが、合計は12.6%少ない
- どちらでも、全件の集計は SQL で先に出しておけば確かめられる


## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- DuckDB の月別の件数・合計が、pandas の集計と全月で一致すること（assert）

## データ
- データファイルは置いていない（120万行で大きいため）。データはコードの中で乱数から作る（seed 771）

## 注意（言えないこと）
- 架空のデータです。月ごとの件数の増え方は作成者が置いたもので、どの月が消えるかはこれで決まります
- Excel の動き（先頭の1,048,576行だけを読み込むこと、注意の表示）は Python で再現したもので、Excel では未検証です。Excel の版や開き方（データの取り込み機能など）で動きが違うことがあります
- T-SQL 版は未検証です
