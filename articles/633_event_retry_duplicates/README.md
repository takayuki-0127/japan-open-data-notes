# 633 送り直しで二重に届いたイベントを除かずに数えると、申込みの数は何%多くなるのか（実務の型）

アプリやサイトから送られるイベントは、返事が来ないと同じ内容をもう一度送る作りがよくあります。受け取る側には、同じイベントが二重・三重に届きます。**ここでは、架空の申込みイベント30日分（1日約2,000件、返事が来ない確率は時間帯の混み具合に比例し、平均1・3・6%、送り直しは最大3回）で、5通りの数え方（そのまま、全部の列が同じ行を除く、受け取り時刻と試行回数以外が同じ行を除く、event_id で1行にする、同じ人の10分以内を1件にする）を、本当の申込み数（event_id の数）と比べました。** 本当に2回申し込んだもの（別の event_id）も0.5%混ぜています。平均3%の場面は SQL（DuckDB）でも出し、Python と一致することを確かめています。数字は置いた送り直しの多さで決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A633 | 数え方で、申込みの数は本当の数とどれだけ違うか | 時間帯で多さの変わる申込み、送り直し（試行回数＋1、受け取り時刻が5〜30秒後）、30日分、seed 633 | `src/a633_retry_dups.py` |
| SQL | 4通りの数え方 | DuckDB 版（1スレッドで実行）、T-SQL 版（未検証） | `src/02_dedup_duckdb.sql`・`src/01_dedup_tsql.sql` |

## 主な結果
- **そのまま数えると**：返事が来ない確率が平均1%で +1.4%、**3%で +4.5%**、6%で +9.5%
- **全部の列が同じ行を除いても**：そのままと同じ（+1.4%・+4.5%・+9.5%）。送り直した行は受け取り時刻と試行回数が違うので、1行も除けない
- **受け取り時刻と試行回数を除いた列で同じ行を除く・event_id で1行にする**：本当の数とぴったり一致
- **同じ人の10分以内を1件にまとめる**：本当の数より 0.5〜0.6% 少ない。本当に2回申し込んだ人もまとめてしまうため
- **混む時間ほど多い（平均3%）**：深夜0時台は +0.6%、昼12時台 +4.9%、夜21時台 +7.8%。日ごとでは +3.6〜5.7%
