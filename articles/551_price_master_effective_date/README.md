# 551 月の途中で単価が変わったとき、適用開始日を見ずに今の単価で集計すると、金額はどれだけずれるのか（実務の型・期間つきマスタの結合）

単価マスタに「適用開始日」があるのに、明細に単価を付けるとき今の単価や月初の単価で結んでしまうと、売上の集計がずれます。**ここでは、架空の単価マスタ（80品目、2025年中に73品目で計124回、月の途中で単価が変わる）と2025年の売上明細6万行を作り、単価の結び方4通りで金額を比べました。** 単価の変わり方と売れ方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A551 | 結び方で、ずれる明細の行数・年間合計・月別・品目別の金額がどれだけ違うか | J0 正しい（valid_from ≦ 日付 ＜ valid_to）、J1 今の単価（valid_to が空の行）、J2 月初の単価（明細の月の1日に有効な単価）、J3 BETWEEN（両端を含める）。Python と SQL（DuckDB、1スレッド）で4通りの行数と合計が一致することを確認。seed 551 | `src/a551_price_master.py`、`src/02_price_join_duckdb.sql`、`src/01_price_join_tsql.sql`（未検証） |

## 主な結果
- **正しい結び方（J0）**：6万行、年間合計 88,328,440円
- **今の単価で結ぶ（J1）**：29,786行（49.6%）の金額がずれ、年間合計は +2,801,720円（+3.17%）。月別では1月 +6.2% から12月 +0.3% まで、年の前半ほど大きい。品目別の差の中央値は、変更1回 +4.0%、2回 +8.1%、3回 +10.2%（値下げのあった品目はマイナス）。80品目のうち43品目で売上の順位が変わった（上位10品目の顔ぶれは同じ）
- **月初の単価で結ぶ（J2）**：3,723行（6.2%）がずれ、年間合計は −235,080円（−0.27%）。月別では −1.1%〜+1.0%で、単価が変わった月だけずれる
- **BETWEEN で両端を含める（J3）**：切り替え日に売れた217行が2行ずつになり（行数 60,217）、年間合計は +337,300円（+0.38%）。行数を数えると気づける

## 動かし方
```
pip install -r requirements.txt
cd src && python a551_price_master.py
```
数秒で終わります。`data/` に単価マスタと明細（price_master.csv・sales_lines.csv）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- J0〜J3 の行数と年間合計が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_price_join_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/price_master.csv`：item_id・price・valid_from・valid_to（次の単価の開始日。その日は含まない。今の単価は空）
- `data/sales_lines.csv`：line_id・item_id・sold_on・qty
- 仮定：品目ごとに2025年中の変更 0〜3回、変更日は2〜28日、変わり幅は −10%・+5%・+8%・+10%・+15%（上げが多め）。売れやすさは品目でばらつき、数量は1〜5

## 注意（言えないこと）
- 架空のデータ。実際の店や会社の数字ではない
- ずれの大きさは、置いた変更の回数・時期・変わり幅で決まる。値上げが多いので「今の単価」は多めに出たが、値下げが多ければ逆になる
- valid_to を「最後の日（その日を含む）」で持つ作りなら、BETWEEN が正しい結び方になる。マスタの持ち方を確かめてから結ぶ、という話
- 価格の決め方や会計処理についての助言ではない
