# 1316 容量の大きい台と小さい台がまざるとき、件数で均等に振り分けると、全体の何割が埋まった時点で最初の1台がいっぱいになるのか？（データの振り分け）

データを何台かに分けて置くとき、台の容量がそろっていないことがあります。あとから足した台だけ容量が大きい、といった場合です。そこへ「どの台にも同じ件数ずつ」振り分けると、小さい台は大きい台と同じ量を受け取るので、全体にはまだ空きがあるのに、小さい台から先にいっぱいになります。**ここでは、作成者が置いた架空のアプリの保存データ（容量200GBの台5台と100GBの台5台に、平均10MBのデータを1件ずつ置いていくもの）で、最初の1台がいっぱいになった時点で全体の容量の何%が埋まっているかを、①件数で均等（でたらめ）②件数で均等（順番に回す）③容量に比例（参考）の3つの振り分け方で300回ずつ数えました。容量の比・大きい台の数・台の容量を変えた36通りでも確かめました。実機では測らず、すべてシミュレーションです。**

例のアプリ・データ・台は架空のもので、実在のデータベース・ストレージや機械の振り分け方を表すものではありません。容量の費用・台数の購入の助言はしていません。

関連する記事：1170「空きが何%を切ったら足すと決めるとき、増え方のばらつきで、足りなくなる日の何日前に気づけるのか？」は、1か所の保存の量の増え方のばらつきで、空き10%を切ってから満杯までの日数がどれだけ散らばるかを扱っています。1305「1万件のデータを乱数で10台に振り分けると、いちばん多い1台の件数は平均の何倍になるのか？」は、乱数で振り分けたときのいちばん多い1台の件数の倍率を扱っています。1315「写しを3台ずつに置いても、3台が同時に止まったときに読めなくなるデータの割合は、写しの置き方でどれだけ違うのか？」は、写しを3台ずつに置いたとき、3台が同時に止まると読めなくなるデータの割合が、写しの置き方でどう違うかを扱っています。この記事は、1か所の増え方ではなく、容量の違う台に件数で均等に分けたとき、全体のどこまで埋まった時点で最初の1台がいっぱいになるかに絞ります。

## 主な結果

### 基本（200GB×5台＋100GB×5台、各300回、`results/base_methods.csv`）
| 振り分け方 | 最初の1台が満杯の時点の全体の埋まり具合（平均） | 5%点 | 95%点 | いちばん早かった回 | 最初に満杯になったのが小さい台だった割合 |
|---|---|---|---|---|---|
| ①件数で均等（でたらめ） | **65.44%** | 64.39% | 66.38% | 62.81% | 100.0% |
| ②件数で均等（順番） | 65.65% | 64.61% | 66.42% | 64.1% | 100.0% |
| ③容量に比例（参考） | **97.84%** | 96.26% | 98.93% | 94.7% | 65.0% |

（式どおりの見込みは、件数で均等のとき66.67%）

- **件数で均等に振り分けると、全体の65.44%が埋まった時点で最初の1台（いつも小さい台）がいっぱいになった**。式どおりの見込み66.67%より1.23ポイント早かった（`a1316_main.json` の base の rand_equal_minus_formula_pt）。小さい台5台のうち、使った量がたまたま多くなった台が先に満杯になる分と考えられる（推測）
- 件数を順番に回してぴったりそろえても65.65%で、でたらめのときとほぼ同じだった。件数がそろっても、1件の大きさがばらつくので、台ごとの使った量はそろわなかった
- 容量に比例して振り分けると、97.84%まで埋まってから最初の1台がいっぱいになった
- 1回目（①）では、全体の65.51%の時点で台5（小さい台）が満杯になった。このとき大きい台の埋まり具合は平均49.39%、小さい台は平均97.76%だった（`data/rep1_nodes_at_first_full.csv`、図1）

### 確かめ：36通り（`results/grid.csv`）
- **容量がまざる27通りでは、①件数で均等（でたらめ）の埋まり具合の平均は28.65〜90.28%だった**。式どおりの見込み（29.41〜90.91%）とほぼ同じ並びで、容量の比が大きいほど、大きい台が多いほど早く満杯になった（図3）。容量の比4倍・大きい台8台・小さい台10GBでは、全体の28.65%で満杯になった
- ①の埋まり具合は、36通りすべてで式どおりの見込みより早かった（差は−8.31〜−0.12ポイント）。差は台の容量が小さい（1台に入る件数が少ない）ほど大きく、小さい台10GBで−8.31〜−0.76ポイント、100GBで−2.67〜−0.26ポイント、1,000GBで−0.81〜−0.12ポイントだった
- ②件数で均等（順番）は、容量がまざる27通りで28.67〜90.52%で、①とほぼ同じだった（式との差は36通りで−6.41〜−0.1ポイント）
- ③容量に比例は、36通りで91.54〜99.32%だった（小さい台10GBで91.54〜94.4%、1,000GBで99.17〜99.32%）
- 容量がそろっている（比1倍）9通りでは、①は91.69〜99.27%で、③と同じ程度だった

## 注意（言えないこと）
- 架空のデータです。台の容量、1件の大きさの分布、増え方は作成者が置いたもので、結果はこれで決まります。とくに、件数で均等のときの埋まり具合は、ほぼ容量の比と大きい台の数の式で決まりました
- データは消さず、足すだけと置きました。台を途中で足す・データを台の間で動かすことは数えていません
- 「いっぱい」は次の1件が入らない時点としました。実際には満杯の手前で足すなどの決まりがあるのがふつうで、その時点はもっと早くなります
- どの振り分け方を使うべきか、容量や台数をどう用意するかを言うものではありません。費用の見込み・購入の助言はしていません
