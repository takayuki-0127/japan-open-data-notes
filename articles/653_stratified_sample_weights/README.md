# 653 層ごとに抽出率の違うサンプルを、重みを付けずに平均すると、全体の値はどれだけずれるのか（実務の型・抜き出しの集計）

全体に効く大きな店を多めの割合で抜き出す（層ごとに抽出率を変える）と、少ない数で精度よく調べられます。ただし、抜き出した店をそのまま平均すると、大きい店の割合が実際より高くなるので、全体の値はずれます。**ここでは、架空の店2,000店（小1,500・中400・大100）から、小2%・中10%・大50%の割合で120店を抜き出し、全体の「1店あたりの月の売上」と「キャッシュレスの割合」を、重みなしと重みありで出すことを2,000回くり返しました。** 店の大きさごとの売上・割合は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A653 | 重みなしの平均はどれだけずれ、抽出率の逆数で重みを付けるとどれだけ戻るか | W0 重みなし、W1 抽出率の逆数で重み、W2 層ごとの平均を店数の割合で合わせる（この設計では W1 と同じ値）。区間はふつうの標準誤差と層別の標準誤差。1回分の SQL を DuckDB（1スレッド）と pandas で一致を確認。seed 653 | `src/a653_strat_weights.py`、`src/02_weighted_duckdb.sql`、`src/01_weighted_tsql.sql`（未検証） |

## 主な結果
- **抜き出した120店のうち大きい店は41.7%**（全体では5%）
- **重みなしの平均**：1店あたりの売上は本当の593万円に対して平均1,711万円（**+189%、約2.9倍**）。キャッシュレスの割合は本当の39.9%に対して54.4%（+36%）
- **抽出率の逆数で重みを付けると**：売上 592.7万円（−0.05%）、キャッシュレス 39.9%。偏りはほぼなくなる
- **95%区間の当たり方**：重みなしの平均にふつうの区間を付けると、2,000回で一度も本当の値を含まない（0%）。層別の区間は 93.8%（売上）・94.1%（キャッシュレス）

## 動かし方
```
pip install -r requirements.txt
cd src && python a653_strat_weights.py
```
十数秒で終わります。`data/stores_population.csv` に2,000店、`data/sample_stores.csv` に1回分の抜き出しを書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 1回分の重みなし・重みありの平均が、DuckDB と pandas で一致した。W1 と W2 が同じ値になることも確かめた
- T-SQL 版（`01_weighted_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/stores_population.csv`・`data/sample_stores.csv`：store_id・size_class・sales（万円）・cashless_rate・sample_rate
- 仮定：売上は対数正規（中心 小300・中900・大3,000万円）、キャッシュレスの割合は正規（中心 35%・50%・70%）

## 注意（言えないこと）
- 架空のデータ。実際の店の数字ではない
- 重みは「どの店がどの確率で選ばれたか」が分かっているときに使える。答えてくれた店だけが残る場合（回答の偏り）は、別の補正が要る
- 層の数が少なく抜き出しが多い層では、区間がやや狭めに出た（93.8%）
