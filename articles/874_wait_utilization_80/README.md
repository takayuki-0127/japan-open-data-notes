# 874 利用が8割を超えると、待ち時間はなぜ急に伸びるのか？（待ち時間と混雑）

窓口やレジが「8割ほど埋まっている」状態を超えると、待ち時間が急に伸びるとよく言われます。ここでいう「利用率」は、窓口が人を処理している時間の割合（来る人数×1人の処理時間÷窓口の数）です。**ここでは、作成者が乱数で作った架空の窓口（客の来方・処理時間・窓口の数を作成者が置いたもの）で、利用率を30〜97%に変えて平均の待ち時間を数え、待ち行列の理論の式と比べました。あわせて、窓口の数・処理時間のばらつき・1日で閉まる窓口かどうかで、伸び方がどう変わるかを数えました。**

平均の待ち時間が同じ店で長く待つ人の割合は関連する記事 873、店の混み具合と「混んでいる」と感じる人の割合は 875 で扱っています。利用率を同じにして処理時間のばらつきだけを変えたとき（来方や長く待つ人の割合まで）は 880、窓口を1人ずつ増やしたときの減り方は 882 で扱っています。この記事は「利用率が上がると、平均の待ち時間がどう伸びるか、なぜか」に絞ります。

## 主な結果

### 利用率と平均の待ち時間（窓口1つ・処理2分・指数分布、5回の平均）
| 利用率 | 乱数で数えた値 | 5回の幅 | 式の値 | 処理時間の何倍か（式） |
|---|---|---|---|---|
| 30% | 0.86分 | 0.85〜0.88 | 0.86分 | 0.43倍 |
| 50% | 2.01分 | 1.98〜2.04 | 2.00分 | 1倍 |
| 70% | 4.71分 | 4.64〜4.83 | 4.67分 | 2.3倍 |
| 80% | **8.02分** | 7.79〜8.39 | 8.00分 | **4倍** |
| 85% | 11.30分 | 10.99〜11.52 | 11.33分 | 5.7倍 |
| 90% | **18.27分** | 16.85〜19.37 | 18.00分 | **9倍** |
| 95% | 39.70分 | 34.19〜48.62 | 38.00分 | 19倍 |
| 97% | 65.82分 | 59.04〜76.11 | 64.67分 | 32倍 |

- **乱数で数えた値は、式の値とほぼ一致した**（利用率90%以下で差は最大0.27分）。この記事の中心の結果は、式どおりの値
- 式では、平均の待ち時間は「利用率÷空き時間の割合（1−利用率）」に比例する。空き時間の割合が20%（利用率80%）から10%（90%）に半分になると、待ちは倍より大きく（8.0分→18.0分）伸びる
- 利用率が同じだけ上がったときの待ちの増え方（式の傾き＝1÷(1−利用率)²）は、50%で4、80%で25、90%で100だった。80%では50%のときの6倍あまり、90%では25倍の速さで伸びる。曲線はなめらかで、8割にだけ折れ目があるわけではない
- 利用率が高いほど、同じ置き方でも5回の平均の幅が広がった（95%で34.19〜48.62分）

### 客が1割増えると（式の値、窓口1つ）
| 元の利用率 | 増えた後 | 待ち時間 | 増えた分 | 何倍か |
|---|---|---|---|---|
| 50% | 55% | 2.00→2.44分 | +0.44分 | 1.22倍 |
| 70% | 77% | 4.67→6.70分 | +2.03分 | 1.43倍 |
| 80% | 88% | 8.00→14.67分 | **+6.67分** | 1.83倍 |
| 85% | 93.5% | 11.33→28.77分 | +17.44分 | 2.54倍 |

### 窓口の数と処理時間のばらつき（ずっと開いている窓口、5回の平均）
| | 利用率80% | 利用率90% |
|---|---|---|
| 窓口1つ | 8.02分 | 18.27分 |
| 窓口3つ（1つの列） | 2.13分 | 5.49分 |
| 窓口10（1つの列） | 0.41分 | 1.25分 |
| 窓口1つ・処理時間が毎回同じ | 3.96分 | 9.07分 |
| 窓口1つ・処理時間のばらつき大 | 19.36分 | 48.87分 |

- 窓口が多いと、同じ利用率でも待ちは短く、伸び始めは右（高い利用率）にずれた。窓口10なら、利用率90%でも平均1.25分だった
- 処理時間のばらつきは、どの利用率でも待ちをほぼ同じ倍率で上下させた（毎回同じなら指数分布の半分、変動係数2なら2.5倍、式の(1＋変動係数²)÷2）

### 1日600分で毎朝空から始まる窓口（窓口1つ・指数分布、400日）
| 利用率 | 日ごとの平均の待ちの平均 | 少ない日〜多い日（10〜90%） | いちばん長かった日 |
|---|---|---|---|
| 50% | 1.93分 | 1.09〜2.92分 | 7.74分 |
| 80% | 7.09分 | 3.43〜11.79分 | 40.09分 |
| 90% | 13.02分 | 5.27〜24.31分 | 65.05分 |
| 95% | 18.48分 | 6.86〜35.08分 | 77.75分 |
| 100% | 24.55分 | 8.61〜48.01分 | 130.86分 |
| 110% | 42.50分 | 16.26〜74.17分 | 165.24分 |

- 毎朝空から始まる窓口では、利用率90%の平均は13.02分と、ずっと開いている窓口（18.27分）より短かった。列が育ちきる前に1日が終わるため
- 利用率100%以上でも、1日で区切られるので待ちは有限の値になった。ただし日ごとの振れが大きく、利用率80%でもいちばん長い日は40.09分だった
- 同じ客の並びで客の来る多さだけを変えたある1日（図3）では、平均の待ちは利用率50%で1.19分、80%で5.03分、90%で7.37分だった

## 動かし方
```
pip install -r requirements.txt
cd src && python a874_utilization.py
```
10秒ほどで終わります。`data/one_day_trace.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダ（/tmp）に src と requirements.txt を写して流し直し、results・figures・data の8ファイルがバイト単位で一致した（cmp、約7秒）
- 乱数で数えた平均の待ちは、窓口1つ（3つの処理時間の形）・窓口3・10のどれでも式の値に近かった。利用率90%以下での差は、窓口1つ・指数分布で最大0.27分。この記事の中心の数字は、乱数ではなく式でも出せる値
- 窓口の数を1・3・10、処理時間の形を3通り、営業時間の区切りあり・なしに変えても、「利用率が上がるほど加速して伸びる」向きは同じだった。どの利用率から急に見えるかは、窓口の数で大きく変わった

## データ
- `data/one_day_trace.csv`：図3のある1日（同じ客の並びで利用率だけを50%・80%・90%に変えた3通り）の客。rho（利用率）・arrival（開店からの来た時刻、分）・wait（待ち時間、分）

## 注意（言えないこと）
- 架空のデータです。客の来方（でたらめな間隔）、処理時間の分布、窓口の数は作成者が置いたもので、結果はこれで決まります。結果のほとんどは待ち行列の理論の式どおりで、乱数はその確かめです
- 客は来たら必ず並び、列を離れないと置きました。長い列を見て帰る人がいれば、高い利用率での待ちは短く出ます（推測）
- 1日の中で客の来る多さは一定と置きました。昼などに山がある店では、山の時間帯の利用率で待ちが決まります（時間帯の山は関連する記事 873）
- 「8割」に決まった境目はありません。窓口が多い、処理時間がそろっている店では、もっと高い利用率まで待ちは短いままでした
- 窓口を1人増やしたときの待ちの減り方は関連する記事 882、処理時間のばらつきの影響は 880 で詳しく扱っています
