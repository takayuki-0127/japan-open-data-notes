# 405 「合計は変わらない」「件数は減らない」という決まりだけで、処理の誤りはどこまで見つかるか（実務の型）

データの処理を試験するとき、期待する答えを1件ずつ書く代わりに、「どんな入力でも成り立つはずの決まり」を乱数の入力で確かめる方法があります（性質にもとづくテスト）。架空のデータ処理（つなぐ・絞る・集計・按分・出力の5段）に誤りを20個入れ、決まりを確かめる試験と、期待する答えを書いた試験が、それぞれいくつ見つけるかを数えたフォルダです。303（E2E テストの考え方）に対し、ここでは決まり（不変条件）で確かめる方法に絞ります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A405 | 決まりだけで、20個の誤りのうちいくつ見つかるか。期待する答えを書く試験と比べてどうか | 決まりは9つ（件数・金額の合計・按分の合計・按分の大小・利益の式・並びを変えても同じ・金額を2倍・キーが重ならない・分けて流して足す）。入力は乱数で300個（ふつうの入力だけ／端の入力も混ぜる）。期待する答えを書いた例は、ふつうの3件と、端の入力を1つずつ足した8件 | `src/a405_property_tests.py`、`src/pipeline.py` |

## 主な結果（20個のうち見つけた数）
| 試験 | 見つけた数 |
|---|---|
| 期待する答えを書いた例3件（ふつうの入力） | 7 |
| 期待する答えを書いた例11件（端の入力も） | 18 |
| 決まり9つ（ふつうの入力だけ300個） | 8 |
| 決まり9つ（端の入力も混ぜて300個） | 18 |
| 決まり9つ＋この処理だけの決まり1つ | 20 |
| 決まり9つ＋例3件 | 18 |
| 決まり9つ＋例11件 | 20 |

- **決まり9つで見つからなかった2個**：マスタの重複で後の行を使う誤り、キーの空白を除かない誤り。どちらも、件数も合計も按分も変えず、地域の名前だけが変わる。「『不明』の件数＝マスタにない顧客の注文の件数」という、この処理だけの決まりを足すと見つかった
- **例11件で見つからなかった2個**：区分ごとに四捨五入して端数を合わせない誤り（例の数字ではたまたま合った）、先頭50行で切る誤り（例は行が少ない）。どちらも決まりの試験は見つけた
- **入力の作り方が効く**：ふつうの入力だけだと、決まりの試験は8個。マスタにない顧客・空の状態・大文字・返品・重複・全部0を混ぜると18個
- **決まり1つずつ**：件数8個、金額の合計8個、按分の合計5個、按分の大小4個、分けて足す3個、並びを変える2個、利益の式1個。金額を2倍・キーが重ならない、の2つは1個も見つけなかった
- **入力1つで見つかる割合**：見つかった18個のうち14個は36〜73%。マスタの重複で行が増える誤りは23%、マイナスの費用を配る誤りは12%。全部0のとき費用を配らない誤りは2%、先頭50行で切る誤りは3%（最初に見つけたのは16個目と54個目）
- 乱数の種を変えた20回：入力10個で中央値16個（14〜17）、30個で17個、100個と300個で18個

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- 正しい処理は、端の入力も混ぜた2,000個の入力で、決まり10個を1つも破らない（コード内の assert）

## データ
- すべて架空。処理は `src/pipeline.py`（仕様は先頭のコメント）、入力は乱数（seed 405）。`data/example_cases.json` に、期待する答えを書いた例11件の入力と答え

## 注意（言えないこと）
- 20個の誤りは作成者が選んで入れました。「20個中いくつ」は、選び方で変わります。合計を変えない誤りを多く入れれば、決まりの試験の数字は下がります
- 例11件は、仕様の端の場面を知ったうえで作りました。誤りの中身を見て作ってはいませんが、仕様を書いた人と同じ人が作っています
- 決まりは、処理の仕様から作成者が選びました。決まりそのものが間違っていれば、試験は役に立ちません
- 入力の作り方（端の入力の混ぜ方）も作成者が決めました。混ぜていない場面の誤りは見つかりません
- 専用のライブラリ（Hypothesis など）は使っていません。入力を小さくして見せる機能（縮小）は試していません
