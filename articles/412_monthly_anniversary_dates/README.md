# 412 月末に始まった契約の「1か月後」は、いつになるのか。応当日の決め方で、何件の日付がずれるか（実務の型）

架空の契約5万件で、月ごとの応当日を4つの決め方で12回分出し、日付が違う契約を数えたフォルダです。315（1年分の保険料を月に分ける）は金額の按分を扱いました。ここでは、日付の出し方だけを比べます。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A412 | 応当日の出し方で、何件の日付がずれるか | ①始期に月数を足す、②前の応当日に1か月ずつ足す、③月末合わせ、④30日ごと。①を基準に、日付が違う契約を数える。①〜③は DuckDB の SQL でも出して一致を確かめる | `src/a412_anniversary.py`、`src/01_anniversary_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **1回でも①と日付が違う契約**（始期が散らばる／月末に集まる）：②7.8%／40.3%、③1.3%／16.8%、④100%／100%
- **12か月後の日付が①と違う契約**：②7.8%／40.3%、③0%／0%、④100%／100%（④は5日早い）
- **ずれの最大**：②3日、③3日、④7日
- **2025-01-31 始期の12か月後**：①2026-01-31、②2026-01-28、③2026-01-31、④2026-01-26。2024-01-31 始期（うるう年）では②は2025-01-29
- **請求が立つ日**（始期が月末に集まる5万件、12回分60万件）：28日は①46,868件・②167,728件、30日は①128,335件・②94,267件、31日は①86,737件・②3,532件
- **月の最終日に立つ請求**：①187,327件、②58,072件、③252,620件、④46,313件
- 始期が29〜31日の契約の割合：散らばる場合7.8%、月末に集まる場合40.3%

## 動かし方
```
pip install -r requirements.txt
cd src && python a412_anniversary.py     # 10秒ほど
```

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の SQL で出した①②③の応当日が、Python の計算と5万件×12回すべてで一致する（コード内の assert）

## データ
- `data/contracts.csv`：架空の契約5万件（契約ID、始期が散らばる場合の始期、月末に集まる場合の始期）。作成者が乱数で作成（seed 412）

## 注意（言えないこと）
- 架空のデータ。ずれる割合は、始期が29〜31日の契約の割合でほぼ決まる
- どの決め方が正しいかは、契約の決まりで決まる。①を基準にしたのは比べるため
- 始期は2025年だけ。うるう年に始まる契約は、1月の4日分の例だけ
- 金額への影響、休日に当たる応当日をずらす決まりは扱っていない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL Server の DATEADD・EOMONTH が DuckDB と同じ日を返すことは確かめていない
