# 350 まだ報告されていない事故の件数は、報告の遅れからどこまで当てられるのか

事故は、起きてから報告されるまでに時間がかかります。月末の時点で「起きているがまだ報告されていない事故」が何件あるかを、過去の報告の遅れ方から見積もるとどこまで当たるか、遅れが途中で伸びると何が起きるかを、正解が分かる架空の事故で測ったフォルダです。316（支払いの進み方からの見積もり）の件数版です。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A350 | 未報告の件数の見積もりは、遅れが変わらないときにどこまで当たるか。遅れが伸びるとどれだけ外れ、伸びたことに何か月で気づけるか | 発生月×報告までの遅れ の件数表を作り、報告の進み方（チェインラダー）で最終件数を見積もる。遅れの平均を2.5か月から3.0・4.0か月に伸ばす場面と、2つの見張りを試す。各1,000回 | `src/a350_ibnr_counts.py` |

## データの作り方（架空）
- 事故は月200件（ポアソン分布）。報告までの遅れは負の二項分布で、平均2.5か月（発生した月のうちに報告されるのは20%、3か月後までに74%、6か月後までに93%）
- 遅れが伸びる場面では、49か月目に起きた事故から、遅れの平均が3.0か月または4.0か月になる
- 乱数の種は350。実在の会社・事故の数字ではありません

## 主な結果
### 遅れが変わらないとき（60か月目の終わりに見積もる。本当の未報告は平均499件）
- **未報告の件数の合計の誤差（RMSE）は8%、10回のうち8回は−9〜+11%に収まった**。偏りは+0.7%
- **新しい月ほど当たらない**。当月に起きた事故の最終件数の誤差は15%（まだ20%しか報告されていない）、1か月前は9%、3か月前は4%、6か月前は2%
- 進み方を直近12か月だけから出しても、誤差は8.5%でほとんど同じ

### 途中で遅れが伸びたとき（未報告の件数の見積もりのずれ、平均）
| 伸び始めてから | 2.5→3.0か月：全期間の進み方 | 同：直近12か月 | 2.5→4.0か月：全期間 | 同：直近12か月 |
|---|---|---|---|---|
| 1か月 | −7% | −7% | −17% | −17% |
| 3か月 | −17% | −17% | −39% | −38% |
| 6か月 | −24% | −22% | −51% | −49% |
| 12か月 | −25% | −15% | −54% | −38% |
| 24か月 | −21% | −1% | −48% | −3% |

- **遅れが1.5か月伸びると、半年後には未報告の件数を半分に見積もっていた**。0.5か月の伸びでも−24%
- **進み方を直近12か月だけから出す形は、2年たつと元に戻った**（−1〜−3%）。全期間の進み方を使い続けると、2年たっても−21%・−48%のまま

### 伸びたことに気づくまで（2か月続けて下側2.5%を外れたら知らせる）
| 場面 | 見張りA（当月に起きて当月に報告された件数）：6か月以内／12か月以内 | 見張りB（遅れ2か月までの報告のうち当月報告の割合）：6か月以内／12か月以内 |
|---|---|---|
| 遅れ 2.5→4.0か月 | 96%／99% | 38%／72% |
| 遅れ 2.5→3.0か月 | 13%／20% | 10%／27% |
| 変化なし（空振り） | 0.2%／0.5% | 2.9%／6.5% |
| 遅れは同じで、事故が2割減った | 16%／24% | 3.3%／6.7% |

- **1.5か月の伸びは、当月の報告件数を見ていれば8割が3か月以内に気づけた**。ただしこの見張りは、遅れが同じで事故が減っただけでも鳴る（12か月以内に24%）
- **割合で見る見張りBは、事故の増減では鳴らない**（空振りと同じ7%）が、気づくのが遅い（1.5か月の伸びで12か月以内に72%）
- **0.5か月の伸びは、どちらの見張りでも1年以内に気づけたのは2〜3割**。その間、未報告の件数は2割以上少なく見積もられていた

## 動かし方
```
pip install -r requirements.txt
cd src && python a350_ibnr_counts.py
```
`data/example_triangle_60m.csv`（60か月分の発生月×遅れの件数の例）、`results/main.json`、`results/stable_ibnr_error.csv`、`results/stable_by_month.csv`、`results/after_change_ibnr_error.csv`、`results/detection.csv`、`figures/` の3枚ができます（約15秒）。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した

## 注意（言えないこと）
- すべて架空のデータです。誤差の大きさは、置いた件数（月200件）と遅れの分布で決まります。件数が少なければ誤差はもっと大きくなります
- 遅れは「ある月に起きた事故から」伸びる形にしました。処理の滞りのように、ある月から報告そのものが止まる形（暦の月で効く形）は試していません
- 見張りは2つだけで、しきい値（下側2.5%が2か月続く）も1通りです。しきい値を変えれば、気づく早さと空振りの数は入れ替わります
- 件数だけを扱いました。支払う金額の見積もり（316〜318）や、報告されたあとに取り下げられる事故は入れていません
- 備金の積み方について助言するものではありません
