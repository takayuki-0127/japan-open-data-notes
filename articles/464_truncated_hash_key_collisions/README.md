# 464 短くしたハッシュをキーにすると、何行から衝突が起き、何行がまちがってつながるのか（実務の型）

架空のキー（文字列）1,000万件の SHA-256 を、先頭32・48・64ビットに切ってキーにしたとき、別のキーが同じハッシュになる（衝突する）件数と、そのキーで表をつないだときに余分にできる行を数えたフォルダです。326（移行の照合で列ごとのハッシュを使う）とは別に、ハッシュをキーとして使うときの衝突だけを扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A464 | ビット数ごとに、何行から衝突が起きるか。衝突の件数は式と合うか。衝突したキーでつなぐと何行が余分にできるか。照合で気づけるか | SHA-256（Python の hashlib）の先頭を切り出す。衝突の組の数を、誕生日の問題の近似式 n(n−1)/2÷2^ビット と比べる。結合は DuckDB | `src/a464_hash.py`、`src/01_hash_key_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **使ったハッシュ**：SHA-256。キーの文字列（`BR123-C000000001` の形）を UTF-8 にして hashlib.sha256 に通し、先頭8バイトを整数にして、上から32・48ビットを切り出した（64ビットは8バイト全部）

| ビット | 1万行 | 10万行 | 100万行 | 1,000万行 |
|---|---|---|---|---|
| 32（実際に数えた組の数／式） | 0／0.01 | 1／1.16 | 121／116 | 11,579／11,642 |
| 48 | 0／0.00 | 0／0.00 | 0／0.00 | 0／0.18 |
| 64 | 0 | 0 | 0 | 0／0.000003 |

- **何行から起きるか（式）**：衝突が1件以上ある確率が50%になる行数は、32ビットで約7.7万行、48ビットで約1,980万行、64ビットで約51億行。1%になる行数は、約9,300行、約238万行、約6.1億行
- **32ビットの最初の衝突**（キーの並びを変えて300回）：中央値74,797行目、10%点26,391行目、90%点134,317行目、最小5,990行目。10万行までに起きたのは73%（式は69%）
- **結合で余分にできる行**（取引の表はマスタの3倍の行）：

| マスタのキー | ビット | 同じハッシュの組 | 余分な行 | 金額の合計のずれ | まちがってつながった顧客 |
|---|---|---|---|---|---|
| 10万 | 32 | 1 | 7 | +0.0012% | 2 |
| 100万 | 32 | 121 | 742 | +0.0235% | 228 |
| 500万 | 32 | 2,932 | 17,628 | +0.1171% | 5,602 |
| 500万 | 48 | 0 | 0 | 0 | 0 |

- **照合**：500万キー・32ビットで、余分な行は取引の0.12%、金額の合計のずれは+0.12%。「合計が0.5%以内なら通す」照合は通る。行数をぴったり比べる照合と、マスタの中で同じハッシュのキーを数える照合は見つける
- **式の確かめ**：一様な乱数のハッシュ（100〜200回）でも、組の数の平均は式と合った（32ビット100万行で118.5対116.4）

## 注意（言えないこと）
- 架空のキー。ただし、衝突の数はキーの中身にほとんどよらない（SHA-256 の出力がほぼ一様なため）。ほかのハッシュ関数（質の低いもの）では、衝突はこれより増えることがある
- 「先頭を切り出す」切り方だけを試した。後ろを切り出す、足し合わせるなどの切り方は試していない
- わざと衝突を作る攻撃は扱っていない。偶然の衝突だけ
- 余分な行の数は、取引の表が顧客ごとに何行あるかで変わる（ここでは平均3行）
- T-SQL 版（HASHBYTES）は SQL Server 本体では動かしていない（未検証）。結合の数は DuckDB で実行した
