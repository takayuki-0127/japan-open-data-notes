# 1056 A のあとに B を測る順番を固定すると、何が差にまざるのか？（処理の速さ）

2つの処理 A と B のどちらが速いかを測るとき、「A を何回か測ってから B を測る」「A と B を交互に測る」のように順番を決めて測ることがよくあります。けれども、測っているあいだに機械がだんだん遅くなったり、前に動いた処理の後片付けが次の回にまわったりすると、その分が A と B の差にまざります。**ここでは、作成者が置いた架空のアプリの処理時間（B が本当は3ms速い）を乱数で作り、A・B を50回ずつ測る4つの並べ方（①ブロック、②交互、③でたらめ、④往復）で、測った差が本当の差からどれだけずれるか、そのずれが何から来るかをしくみを1つずつ入れて分けました。実機の計測はしていません。**

同じ企画の関連する記事 1053 は1回ずつ測った時間で速い方を選ぶとまちがえる割合、1054 は温まる前の最初の数回を入れて平均すると遅く出ること、1061 は同じ設定のつもりの2台で速さがどれだけ違うか、1062 は短い時間の計測で、動かすほどだんだん遅くなる処理が見つかるかを扱っています。この記事は、だんだん遅くなることや後片付けの持ちこしがあるとき、測る順番の決め方で A と B の差にどれだけまざるかに絞ります。

## 主な結果

### 並べ方ごとの測った差（基本、1万回の平均、`results/designs_base.csv`）
| 並べ方 | 測った差（B−A） | 本当の差（−3ms）からのずれ | 測った差の散らばり（標準偏差） | 「B が速い」と出た割合 |
|---|---|---|---|---|
| ①ブロック（A50回→B50回） | −0.91ms | +2.09ms | 1.88ms | **68.42%** |
| ②交互（ABAB…、いつも A が先） | +1.0ms | +4.0ms | 0.79ms | **10.2%** |
| ③全体をでたらめに並べる | −1.01ms | +1.99ms | 0.92ms | 86.64% |
| ④往復（A25回→B50回→A25回） | −2.92ms | +0.08ms | 1.55ms | 96.88% |

- 交互に測ると、本当は B が3ms速いのに、測った差の平均は B が1.0ms遅く、「B が速い」と出たのは10.2%だった
- ブロックで測ると差が−0.91msまで縮み、「B が速い」と出たのは68.42%だった

### ずれの中身（しくみを1つずつ入れる、1万回の平均、`results/components.csv`）
| 並べ方 | だんだん遅くなる分 | 後片付けの持ちこし | 混み具合の揺れ（ずれ／散らばり） | 全部 | 式の値（遅くなる分＋持ちこし） |
|---|---|---|---|---|---|
| ①ブロック | **+2.02ms** | +0.06ms | −0.0ms／1.9ms | +2.06ms | 2.02＋0.04＝2.06ms |
| ②交互 | +0.05ms | **+3.96ms** | −0.01ms／0.79ms | +3.99ms | 0.04＋3.96＝4.0ms |
| ③でたらめ | +0.01ms | **+1.99ms** | 0.0ms／0.86ms | +1.99ms | 0＋2.02＝2.02ms |
| ④往復 | −0.0ms | +0.07ms | +0.03ms／1.56ms | +0.06ms | 0＋0.08＝0.08ms |

- **ブロックには、だんだん遅くなる分がまざった**。B は平均で50回あとに測られるので、100回で4msの遅くなり方なら 4÷99×50＝2.02ms、B が遅く出る（式どおり）
- **交互には、後片付けの持ちこしが2倍でまざった**。いつも A のあとに B が来るので、B は A の後片付け（4ms）を払い、A は B の後片付け（2ms）を払う。差は本当の差より 2×(4−2)＝4ms 近く大きく出る（式どおり、3.96ms）
- でたらめに並べると、持ちこしは半分（ほぼ 4−2＝2ms）まざった。前の回が A か B かがほぼ半々になるため（式どおり）
- 往復は、直線のだんだん遅くなる分を打ち消し（A と B の平均の位置がそろう）、持ちこしも並べ方が切りかわる2回だけになった。ただし、混み具合のゆっくりした揺れでは散らばりが1.56msと、交互（0.79ms）の約2倍だった
- 混み具合の揺れは、どの並べ方でも平均のずれにはならなかったが、ブロックと往復では散らばりを大きくした（ブロック1.9ms）

### A と B が同じ処理のとき（本当の差0、`results/a1056_main.json` の `same_code`）
- ブロックでは、測った差は平均+2.01msで、70.17%の計測で「B が1ms以上遅い」と出た。同じ処理でも、あとに測った B が遅く見える
- 交互・でたらめ・往復では、平均のずれは±0.03ms以内だった（A と B の後片付けを同じにしたので持ちこしはまざらない）

### 置き方を変えると（27通り、`results/grid.csv`）
- 「B が速い」と出た割合は、①ブロックで8.13〜100%、②交互で0〜100%、③でたらめで11.63〜100%、④往復で83.77〜100%だった
- ずれは、ブロックではだんだん遅くなる量でほぼ決まり（0ms・4ms・8ms で約0・2・4ms）、交互では後片付けの差でほぼ決まった（最大+8.02ms）。どちらも式どおり
- 後片付けの差がない9通りでは、交互のずれは−0.011〜+0.089msで、「B が速い」と出た割合は99.97〜100%といちばんよかった。交互が弱いのは、前の回の影響が次に持ちこされるときだけだった
- 往復は27通りすべてで83.77%以上だったが、混み具合の揺れが4msの9通りでは83.77〜87.13%に下がった（測った差の散らばりは平均2.786ms、交互は0.798ms）

- 空のフォルダ（/tmp に `src` と `requirements.txt` だけを写したもの）で流し直し、results・figures・data の8ファイルがバイト単位で一致した（cmp、約9秒）

- 振れだけを入れたときは、どの並べ方でもずれが±0.02ms以内だった

## 注意（言えないこと）
- 架空のデータです。処理時間、後片付けの大きさ、だんだん遅くなる量、混み具合の揺れは作成者が置いたもので、結果はこれで決まります。「B が速い」と出た割合は、置き方で交互なら0〜100%と動きました。実在のソフトや機械を測った値ではありません
- 主なずれ（ブロックの+2.02ms、交互の+3.96ms、でたらめの+1.99ms）は、置いた決まりからの式どおりの値です。新しいのは、同じ「順番を決めて測る」でも、並べ方によってまざるものが入れかわる点です
- だんだん遅くなる分は直線と置きました。往復が打ち消せるのは直線の分だけで、途中で急に遅くなるような動きは打ち消せないと考えています（推測）
- 本当の速さは「その処理だけをくり返し動かしたとき」の時間と置きました。実際に使うときに A と B がどんな順で動くかによって、どちらの速さを本当とみるかは変わります
