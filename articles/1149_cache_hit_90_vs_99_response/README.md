# 1149 当たり率90%と99%の差は、平均の応答時間で何倍の差になるのか？（キャッシュの当たり率）

よく使うデータを手元の置き場所（キャッシュ）に置いておくと、置き場所に当たった問い合わせは速く返り、外れた問い合わせは元のデータを取りに行くので遅くなります。当たり率90%と99%は、数字の上では9ポイントの差、比べて1割ほどの差に見えます。けれども、外れる割合は10%と1%で10倍違います。平均の応答時間は「外れの遅さ×外れる割合」でほぼ決まるので、当たり率の数字の差よりずっと大きく動きます。**ここでは、作成者が置いた架空のアプリへの問い合わせ（当たったときの時間は中央値2ms、外れたときは中央値80ms、どちらも乱数）で、当たり率90%と99%の平均・中央値・90%点・95%点・99%点と、元のデータへの問い合わせの件数を比べ、平均が何倍違うかを式と乱数100万件で数えました。外れたときの遅さと元のデータの混み具合を変えた24通りの確かめも行いました。処理時間はすべて作成者が置いた分布からの乱数で、実機の計測はしていません。**

パーセンタイル（速い順に並べて何%の位置の値か）の言葉は、99%点なら「100件のうち99件はそれより速く終わる時間」のことです。

関連する記事：897「「10%から12%」は、2%増か20%増か？」は、割合の差（ポイント）と割合の比の言い方の違いを扱っています。この記事は、当たり率では小さく見える差が、外れ率の比では大きくなる場面に当てたものです。906「割合の差と割合の比、どちらで比べると順位が変わるのか？」も同じ形です。1060「平均が速くなっても、遅い側の数%は遅くなっていることはあるのか？」は、手元に結果を置く変更で平均と遅い側が逆に動く場合を、1055「平均・中央値・最小値のどれで比べるかで、速い方は入れかわるのか？」は物差しの選び方を扱っています。同じ企画の 1150「置き場所の大きさを2倍にすると、当たり率はどれだけ上がるのか？」は当たり率そのものの上がり方、1151「当たり率を件数で数えるかデータの量で数えるかで、良し悪しはどう入れかわるのか？」は当たり率の数え方を扱っています。1156「当たり率が上がったのに、平均の応答が遅くなるのはどんなときか？」は、この記事の式で当たったとき・外れたときの時間も動く場合（当たり率が上がっても平均が遅くなる場合）を扱っています。1155「同じものを大勢が同時に取りに来ると、置き場所から消えた瞬間に、元のデータへ何件の問い合わせが流れるのか？」は、この記事で置かなかった「外れがまとまって起きる」場面を扱っています。この記事は、当たったとき・外れたときの時間を決めたまま、当たり率の差が応答時間の差としてどれだけになるかに絞ります。

## 主な結果

### 当たり率90%と99%（乱数100万件ずつ、`results/compare_90_99.csv`）
| 物差し | 当たり率90% | 当たり率99% | 90%÷99% |
|---|---|---|---|
| 当たり率 | 90% | 99% | 0.91倍 |
| 外れ率 | 10% | 1% | 10倍 |
| 元のデータへの問い合わせ（1,000件あたり） | 100.1件 | 10.16件 | 9.85倍 |
| 平均（式） | 10.948ms | 2.9777ms | **3.68倍** |
| 平均（乱数） | 10.9562ms | 2.989ms | 3.67倍 |
| 中央値 | 2.0861ms | 2.008ms | 1.04倍 |
| 90%点 | 16.9584ms | 2.9851ms | 5.68倍 |
| 95%点 | 80.213ms | 3.3801ms | **23.73倍** |
| 99%点 | 151.9155ms | 26.8485ms | 5.66倍 |

- **当たり率は9ポイントの差（比で0.91倍）なのに、平均の応答時間は3.68倍違った（式どおり）**。乱数100万件でも3.67倍で、式と合った
- 平均のうち外れの分が占める割合は、当たり率90%で82.8%、99%で30.44%だった（式どおり）。90%では、平均はほとんど外れた問い合わせの時間で決まっている
- 中央値は1.04倍でほとんど動かなかった。どちらの当たり率でも、真ん中の問い合わせは当たっているため
- 95%点は23.73倍違った。90%では95%点が外れの中に、99%では当たりの中にあるため
- 99%点は、当たり率99%では当たりと外れのちょうど境目にあり、26.8485msだった。当たり率を98%にすると80.5591ms、99.5%にすると4.3418msと大きく跳んだ（`results/by_hit_rate.csv`）。99%点より遅い問い合わせは100%が外れだった

### 当たり率を1ポイント上げたときの平均の縮み（式、`results/a1149_main.json` の one_point_steps）
| 当たり率 | 平均の前→後 | 何倍速くなるか |
|---|---|---|
| 90%→91% | 10.948ms→10.0624ms | 1.088倍 |
| 95%→96% | 6.52ms→5.6344ms | 1.1572倍 |
| 98%→99% | 3.8633ms→2.9777ms | 1.2974倍 |
| 99%→100% | 2.9777ms→2.0921ms | 1.4233倍 |

- 1ポイント上げて縮む時間（0.8856ms）はどこでも同じ（式どおり、当たり率に比例して減る直線）。けれども、もとの平均が小さいほど、同じ1ポイントの比は大きくなった

### 確かめ：外れの遅さと元のデータの混み具合を変えた24通り（式、`results/grid.csv`）
| 外れの平均÷当たりの平均 | 混み具合0 | 0.3 | 0.6 | 0.9 |
|---|---|---|---|---|
| 5倍 | 1.35倍 | 1.55倍 | 2.06倍 | 5.65倍 |
| 10倍 | 1.74倍 | 2.13倍 | 3.1倍 | 9.91倍 |
| 30倍 | 3.02倍 | 3.99倍 | 6.42倍 | 23.41倍 |
| 100倍 | 5.48倍 | 7.51倍 | 12.61倍 | 48.3倍 |
| 300倍 | 7.74倍 | 10.72倍 | 18.15倍 | 70.19倍 |
| 1,000倍 | 9.18倍 | 12.72倍 | 21.58倍 | 83.55倍 |

- 元のデータが混まないと置くと、平均の比は1.35〜9.18倍で、外れが遅いほど外れ率の比（10倍）に近づくが、10倍は超えない（式どおり）
- 外れが増えると元のデータが混んで遅くなると置くと、平均の比は外れ率の比の10倍を超え、24通りのうち9通りで10倍より大きくなった（最大83.55倍）
- つまり、何倍になるかは、作成者が置いた外れの遅さと混み具合でほぼ決まる。この記事が示せるのは、当たり率の差の見た目（9ポイント、0.91倍）と、平均の差（ここでは1.35〜83.55倍）が大きく離れること

## 注意（言えないこと）
- 架空のデータです。当たったとき・外れたときの時間の分布、混み具合で遅くなる置き方は作成者が置いたもので、何倍になるかはこれで決まります。主な値（平均の比）は置いた式どおりです。実在のソフトやサーバーの速さを表すものではありません
- 1件ごとの当たり外れは、ほかの問い合わせと関係なく決まると置きました。実際には、外れが続けて起きる時間帯（置き場所を空にした直後など）があります
- 当たり率をどうやって上げるかや、上げるのにかかる手間・費用は扱っていません。置き場所の大きさと当たり率の関係は 1150 で扱っています
- 混み具合で遅くなる置き方（1÷（1−混み具合））は、作成者がそう置いただけの目安です
