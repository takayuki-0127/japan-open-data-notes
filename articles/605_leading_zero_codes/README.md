# 605 先頭の0が落ちた商品コードや取引先コードで表をつなぐと、何件がつながらず、何件が別のコードにつながるのか（実務の型・コードの型）

「00123」のようなコードは、表計算ソフトで開いて保存したり、数として読み込んだりすると「123」になります。この明細をマスタにつなぐとき、文字のまま結ぶとつながらない行が出て、数にそろえて結ぶと、数として同じになる別のコード（「0123」と「00123」など）にもつながります。**ここでは、桁数の違うコードが混ざる架空のコードマスタ（3,057件）と明細5万行（4割が表計算ソフトを通って先頭の0が落ちた）で、つなぎ方3通りの結果を数えました。** コードの作り方とファイルの経路は作成者が置いたもので、数字はその仮定で決まります。

## 主な結果
- **マスタ**：4桁1,000件・5桁1,257件・6桁800件。先頭が0のコードは348件（11.4%）。数にすると同じになるコードが72組（古い4桁を5桁に付け替えた想定の60組を含む）
- **文字のまま結合（K1）**：2,257行（4.5%）がつながらない。さらに72行は、0が落ちて別の桁のコードと同じ文字になり（「01234」→「1234」）、**別の品目に黙ってつながった**。金額は −4.7%
- **整数にして結合（K2）**：つながらない行は0になるが、数として同じコードがある明細2,311行が2行に増えた（1行は正しい品目、1行は別の品目）。金額は **+4.9%**
- **6桁に0で埋めて結合（K3）**：K2 とまったく同じ結果。桁数の違うコードが混ざるマスタでは、0で埋めても数として同じコードは区別できない
- 正しく1行にだけつながった明細は、どの方法でも約95.4%。残りの4.6%は、つなぎ方を変えても直らない

## 動かし方
```
pip install -r requirements.txt
cd src && python a605_leading_zero.py
```
数秒で終わります。`data/` にマスタと明細（master.csv・lines.csv）を書き出します。lines.csv のコードは0が落ちたままです。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- K1〜K3 の結合後の行数とつながらない行数が、DuckDB の SQL と pandas で一致した
- T-SQL 版（`01_code_join_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/master.csv`：code（文字）・item_name・unit_price
- `data/lines.csv`：line_id・code_raw（4割の行で先頭の0が落ちている）・qty
- 仮定：コードは桁数ごとに一様な乱数、明細の品目は売れやすさがばらつく、表計算ソフトを通る確率は行ごとに40%

## 注意（言えないこと）
- 架空のデータ。実際の会社のコード体系ではない
- コードの桁数が1つに決まっている体系なら、0で埋めれば正しく戻せる。桁数の違うコードが混ざると戻せない、という話
- 直し方は、取り込みの時点で文字として読むこと（CSV の型を指定する、表計算ソフトで開かない）
