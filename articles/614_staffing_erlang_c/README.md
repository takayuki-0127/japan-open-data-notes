# 614 平均の問い合わせ件数から窓口の人数を決めると、待ち時間はどれだけ長くなるのか（実務の型・人員の見積もり）

窓口の人数を「1日の件数×対応時間÷営業時間」で決めると、仕事量に対して人数がちょうどになり、件数の山の時間帯には待ちが積み上がります。30分ごとの仕事量に合わせても、人が100%ふさがる前提では、電話がたまたま重なったときに待ちが出ます。**ここでは、架空の問い合わせ窓口（9〜18時、1日720件、対応は平均6分）の1日を300日分シミュレーションし、人数の決め方3つで、待ち時間と20秒以内に出られる割合を比べました。** 件数の山の形・対応時間は作成者が置いたもので、途中で電話を切る人は入れていません。数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A614 | 人数の決め方で、待ち時間と応答率がどれだけ変わるか | N1 1日の平均の仕事量で全時間8人、N2 30分ごとの仕事量（件数×6分÷30分）を切り上げ、N3 30分ごとにアーラン C の式で「20秒以内に80%」を満たす最小の人数。到着はポアソン、対応時間は指数分布、先着順。300日、seed 614 | `src/a614_staffing.py` |

## 主な結果
- **仕事量**：30分ごとに3.75〜12.75（平均8.0）。10時台の山は平均の1.6倍
- **1日の平均で8人（N1、延べ72人時）**：午前の山で待ちが積み上がり、夕方まで解消しない。平均の待ち時間 **41分**、20秒以内に出られたのは **7.7%**、待ちが5分を超えた電話が87.9%
- **30分ごとの仕事量を切り上げ（N2、75.5人時）**：平均の待ち 5.7分、20秒以内 29.1%、5分超 39.3%。人が常にふさがる前提なので、たまたまの重なりで待ちが伸びる
- **アーラン C で「20秒以内に80%」（N3、103人時）**：平均の待ち 19秒、20秒以内 **84.5%**、5分超 0.9%。人数は山の時間帯で17人（仕事量12.75の1.33倍）、少ない時間帯でも7人
- 区間ごとに見ると、N3 の20秒以内の割合は 78.8〜91.7%。アーラン C の式（区間ごとの定常の計算）とシミュレーションの差は、区間をまたいだ待ちの持ち越しによる

## 動かし方
```
pip install -r requirements.txt
cd src && python a614_staffing.py
```
十数秒で終わります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures がバイト単位で一致した
- アーラン C の式で出した区間ごとの20秒以内の割合（80.9〜91.4%）と、シミュレーションの値が近いこと

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 614）
- 仮定：30分ごとの件数の山の形は作成者が置いたもの（午前10時台と午後2時台に山）。到着はポアソン、対応時間は平均6分の指数分布。人数が減る時刻には、空いている人から抜ける

## 注意（言えないこと）
- 架空の窓口。実際の会社の数字ではない
- 途中で電話を切る人（放棄）を入れていないので、人が足りない決め方の待ち時間は、実際より大きく出る（実際には切った人の分だけ待ちが短くなり、そのかわり応答できない電話が出る）
- 休憩・後処理の時間・人ごとの対応の速さの違いは入れていない。実際の人数は、ここで出した人数より多く要る
