# 674 広告の成果を「最後の接点」に付けるか均等に分けるかで、広告ごとの成果はどれだけ違うのか（実務の型）

申し込みに至るまでに複数の広告に接した人がいるとき、その申し込みをどの広告の成果とするか（アトリビューション）で、広告ごとの評価は大きく変わります。よく使われるのは、最後に接した広告に付ける方法、最初の広告に付ける方法、均等に分ける方法、最初と最後を重くする方法です。どの方法も「付け方」であって、その広告がなければ申し込みがなかったのか（本当の効き目）は測っていません。**ここでは、本当の効き目を作成者が置いた架空の利用者5万人で、4つの付け方の広告ごとの成果を、本当の効き目と比べました。** 数字は置いた確率と接点の順番で決まります。

## 主な結果
- 申し込みは2,548件。うち広告に接した人の申し込み2,339件を、どの付け方も広告に配る。本当に広告で増えた分は期待値で950件（申し込みの37%）で、残りは広告がなくても申し込んだ分
- **最後の接点では検索広告の取り分が48%で最大**。本当の効き目では16%（3位）。申し込む直前に検索されやすいため
- **ディスプレイ広告は、最後の接点では19%、本当の効き目では51%で最大**。最初の接点では63%と大きく出すぎる
- 均等と位置で重みは、取り分の順番は本当の効き目に近いが、件数はどの広告も本当の効き目の1.9〜7.9倍（広告がなくても申し込んだ分を配るため）
- **メール**は主に常連に届くので、どの付け方でも本当の効き目（25件）の4〜9倍に見える（最後の接点で227件、8.9倍）

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 最後の接点と均等の広告ごとの成果が、Python と DuckDB の SQL で一致すること
- 4つの付け方の合計が、どれも広告に接した人の申し込みの数（2,339件）と一致すること

## データ
- `data/touches.csv`：架空の接点（user_id・seq＝接した順・channel）
- `data/users.csv`：架空の利用者（user_id・converted＝申し込んだか）
- 本当の効き目は、データを作るときの確率から計算した（実際のデータでは分からない）

## 注意（言えないこと）
- 架空のデータ。上乗せの確率と接点の順番は作成者が置いたもので、結果はこれで決まる
- どの付け方も、本当の効き目を測る方法ではない。本当の効き目は、広告を出す・出さないを無作為に分ける実験などで測る
- 本当の効き目は、作成者が置いた「上乗せがかけ算で重なる」形のもとでの値。広告の組み合わせで効き方が変わる場合は扱っていない
- 広告の出し方や予算の助言ではない。T-SQL 版は未検証
