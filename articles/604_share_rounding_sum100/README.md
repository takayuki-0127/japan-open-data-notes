# 604 構成比を四捨五入すると、合計が100%にならない表は何%あり、最大剰余法で直すと各項目はどれだけ動くのか（実務の型・構成比の丸め）

売上の内訳などの構成比を整数の%に四捨五入すると、合計が99%や101%になることがあります。報告の表で「合計が100にならない」と指摘されたとき、いちばん大きい項目で差を吸収する直し方がよく使われますが、項目によっては大きく動きます。**ここでは、項目数3〜12の架空の構成を2万表ずつ作り、四捨五入で合計が100にならない割合と、最大剰余法・いちばん大きい項目に寄せる方法で直したときのずれを数えました。** 構成の作り方（ディリクレ分布）は作成者が置いたもので、数字はその仮定で決まります。

|---|---|---|---|
| A604 | 四捨五入で合計が100にならない割合と、直し方ごとのずれ | R0 四捨五入（整数・小数1桁）、R1 最大剰余法（切り捨ての不足分を小数部分の大きい順に1ずつ足す）、R2 いちばん大きい項目に差をまとめる。項目数 3〜12、各2万表。最大剰余法は DuckDB（1スレッド）の SQL でも計算して一致を確認。seed 604 | `src/a604_share_rounding.py`、`src/02_largest_remainder_duckdb.sql`、`src/01_largest_remainder_tsql.sql`（未検証） |

## 主な結果
- **合計が100にならない表の割合（整数の%）**：3項目 24.5%、5項目 38.7%、10項目 **57.3%**、12項目 60.9%
- **小数1桁にしても減らない**：合計が100.0にならない割合は、10項目で 56.5%（整数とほぼ同じ）。桁を増やしても、ずれの幅が小さくなるだけ
- **10項目のときの合計**：97〜103。99か101が 48.9%、98か102が 8.2%、97か103が 0.3%
- **最大剰余法で直すと**：合計が合わない表で動く項目は平均1.0〜1.2個。もとの値からのずれは、どの表でも最大0.81ポイント以内（四捨五入だけなら0.5以内）
- **いちばん大きい項目に寄せると**：ずれは最大3.6ポイント（11項目）。合計が合わない表の99%点でも 2.3ポイント（10項目）。10項目の表の52.2%で、最大剰余法と違う値になった

## 確かめたこと
- 空のフォルダで流し直し、results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 10項目の先頭500表で、最大剰余法と四捨五入の結果が、DuckDB の SQL と Python で一致した
- 最大剰余法の結果は、すべての表で合計がちょうど100になった
- T-SQL 版（`01_largest_remainder_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 604）
- 仮定：構成はディリクレ分布（集中度 0.5・1.0・3.0 を表ごとにくじで選ぶ）。四捨五入は0.5を切り上げる形

## 注意（言えないこと）
- 架空のデータ。実際の会社の構成比ではない
- 最大剰余法でも、同じ値の項目が違う%に分かれることがある（小数部分の順で決まるため）。並びの決め方（同点のとき項目の順）を決めておく必要がある
- 会計・開示の決まりについての助言ではない。表の注に「四捨五入のため合計が100にならない」と書く方法もある
