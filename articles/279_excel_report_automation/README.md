# 279 手作業の月次 Excel レポートを、Python でどう自動にするか（実務の型）

POS の書き出し CSV（店×部門×日）から、毎月手で作っていた Excel の月次レポートを、pandas で集計して openpyxl でひな形に流し込む形に置き換えたフォルダです。出来上がった表は、pandas を使わない別の計算（`csv`＋`Decimal`）と1セルずつ照合し、手作業や素朴な自動化で起きやすい3つの「わな」を再現して、ずれの大きさを測りました。データはすべて架空です。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A279 | 月次 Excel レポートを自動にすると、何がなくなり、何に気をつけるか | pandas の集計、openpyxl でひな形に書き込み（行の差し込み・式の範囲の付け直し）、LibreOffice で計算し直して読み戻し、別の計算との1セルずつの照合、わなの再現 | `src/a279_make_data.py`・`a279_template.py`・`a279_fill.py`・`a279_check.py`・`a279_figs.py` |

## 主な結果
- 手で作る手順を書き出すと、9店×5部門の月で**約127回の操作**（CSV を店で絞る18、部門の合計45、ひな形に貼る54、月と店名10）。自動では `python a279_fill.py` の1回
- 出来上がった表の64セル（店×部門45・店の合計9・前月9・総合計1）を別の計算と照合し、**ずれは0**
- わな1：ひな形の表が8店ぶんで固定のまま、新しい9店目を下の行に足すと、総合計の式は9店目を飛ばす。総合計は **47.9百万円（12%）少なく**、エラーは出ない。自動化では、行を店の数だけ差し込み、式の範囲もそれに合わせて書き直す
- わな2：CSV の金額「1,234」を文字のまま貼ると、SUM はその列を飛ばす。食品の列で試すと、総合計は **226.4百万円（56%）少なく**、エラーは出ない。読み込むときに桁区切りを外して数値にする
- わな3：openpyxl で保存した式（26個）は、Excel などで開いて計算し直すまで値が空。pandas や一部のプレビューで読むと空欄に見える。確かめるときは LibreOffice で計算し直してから読む

## 動かし方
```
pip install -r requirements.txt
cd src && python a279_make_data.py && python a279_template.py && python a279_fill.py && python a279_check.py && python a279_figs.py
```
`a279_check.py`・`a279_figs.py` は LibreOffice（`soffice`）で式を計算し直します。

## データ
- `data/pos_2025-09.csv`・`pos_2025-10.csv`：架空のチェーンの POS の書き出し（店×部門×日、BOM つき UTF-8、金額は桁区切りつきの文字）。作成者が乱数で作成（seed 279）。S09 は2025年10月に開いた店
- `template/monthly_template.xlsx`：8店ぶんで作られたひな形（手で作ったひな形によくある形）
- `output/report_2025-10.xlsx`：自動で作った月次レポート
- `results/checks.json`：照合とわなの結果、手作業の手順の数え方

## 注意
- 「約127回」は手順書に書いた場合の操作の数で、実際にかかる時間やミスの起きやすさは測っていません
- わなのずれの大きさ（12%・56%）は、この架空のチェーンの店の大きさと部門の割合で決まります。言えるのは「エラーが出ずに合計が小さくなる」ことまでです
- 総合計の前月比（+15.8%）は新しい店 S09 の分を含みます。既存店だけの比べ方は、このレポートの範囲外です
- 既存の 244（月次レポートを書く順番）とは切り口を変え、Excel への流し込みと照合に絞りました
