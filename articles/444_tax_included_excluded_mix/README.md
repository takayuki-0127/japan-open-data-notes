# 444 税込みと税抜きの金額が混ざった表を足すと、売上はどれだけずれるのか（実務の型）

架空の取引2万件（2019年4月〜2020年3月。途中で税率が8%から10%に変わり、食品は8%のまま）で、税込みと税抜きが混ざった金額を集計したときのずれと、税抜きにそろえる3つの方法を比べたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A444 | 混ざった金額をそのまま足すとどれだけずれ、どこまで戻せるか | ①そのまま足す ②税の列が「込」の行だけ戻す ③列が空の行は端数から推し量る、の3つを税抜きの正解と比べる。②③は SQL（DuckDB）でも実行して全行の一致を確かめる。税込みの割合、列が空の割合、値付けの刻みを変えて比べる | `src/a444_tax.py`、`src/01_to_tax_excluded_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（税込み45%、税の列が空30%、10円単位の値付け）
| 方法 | 合計のずれ | 2019年4〜9月 | 2019年10月〜 | 行ごとに正解と一致 |
|---|---|---|---|---|
| ①そのまま足す | +3.85% | +3.52% | +4.19% | — |
| ②税の列で戻す（空は税抜きとみなす） | +1.13% | +1.01% | +1.25% | 86.5% |
| ③空の行は「10円の倍数でなければ税込み」 | +0.72% | +0.46% | +0.98% | 93.2% |
| ③' 「戻した額が50円の倍数なら税込み」も足す | +0.28% | — | — | 97.2% |

- **③の当たる割合**（列が空の6,012行）：77.3%。外れ1,363行はすべて、税込みを税抜きと判断。税率8%の時期83.0%、10%の時期71.7%。税込みの金額の51.0%は10円の倍数
- **③'の当たる割合**：90.6%（値付けの刻みを知っている場合）
- **月ごとの①のずれ**：3.42%（2019年9月）〜4.45%（2019年10月）
- **条件を変える**（12回の平均、`results/by_condition.csv`）：税込み20%で①1.7%・80%で6.9%。列が空10%で②0.4%・60%で2.3%・すべて空で3.9%。1円単位の値付けでは③の当たる割合45%、ずれ−1.1%
- **月によって税込みの割合が違う場合**（45%±10ポイント、200回）：①の前月比のずれは平均0.94ポイント、年の最大の中央値2.2ポイント。前月比の向きが逆になる月が1つ以上あった回は50%
- **税込みとして作れない額**：税率8%で7.4%、10%で9.1%（1〜10万円の整数のうち）
- 税込み（切り捨て）から税抜きへの戻しは、税込みの全行で正解と一致

## 動かし方
```
pip install -r requirements.txt
cd src && python a444_tax.py     # 2〜3分
```

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- ②③を SQL（DuckDB）で実行し、2万行すべてで Python の計算と一致する（コード内の assert）

## データ
- `data/transactions_mixed.csv`：架空の取引2万件（税込みと税抜きが混ざった金額、税の列は3割が空）
- `data/transactions_truth.csv`：正解（税抜きの金額、税込みだったかどうか、税率）
- すべて架空（作成者が乱数で作成、seed 444）

## 注意（言えないこと）
- 架空の取引での結果。ずれは、税込みの行の割合と、列が空の行の割合でほぼ決まる
- 税の端数は1円未満切り捨てだけ。四捨五入や、請求書単位の計算は試していない
- 端数から推し量る方法は、値付けの刻みに強く左右される
- 税の計算や申告についての助言ではない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
