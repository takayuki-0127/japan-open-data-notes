# 1263 商談の段階ごとの進んだ割合を掛けた見込みは、段階を飛ばす商談や戻る商談があるとどれだけずれるのか？（受注の見込み）

法人向けの商談を「初回の面談 → 提案 → 見積もり → 条件の詰め → 受注」のような段階に分け、過去の商談の記録から「段階ごとに次へ進んだ割合」を数え、いま途中の商談の段階から受注までの割合を掛けて見込みを出すことがあります。すべての商談が段階を1つずつ進むなら、この掛け算は合います。けれども、実際の商談の記録には、見積もりを飛ばして条件の詰めに進む商談や、条件の詰めから見積もりに戻る商談がまざります。段階ごとの割合を何で割って数えるかで、飛ばしと戻りの入り方が変わります。**ここでは、作成者が置いた架空の会社の商談（段階ごとに、次へ進む・1つ飛ばす・1つ戻る・失注する確率を作成者が置き、乱数で過去の商談800件の移り変わりと、いま途中の商談200件を作ったもの）で、①段階に来た商談の数で割って掛ける、②1つずつ進んだ回数で割って掛ける、③段階に来た商談のうち受注した割合を直接数える、の3つの見込みが、置いた確率から式で出した本当の受注の確率とどれだけずれるかを数えました。飛ばす割合・戻る割合・進む割合を変えた36通りでも確かめました。**

例の会社・商談・金額は架空のもので、実在の会社の商談や、商談の記録の仕組みの数え方を表すものではありません。売上の目標の立て方、値引き・価格の付け方、担当の評価の決め方の助言はしていません。

関連する記事：920「工程を2つつなぐと、全体の良品率はどうなるのか？」は、工程ごとの良品率を掛ける形が検査の見逃しや工程どうしの結びつきでずれることを、895「問い合わせから契約までの割合は、どこで落ちているのか？」は、段に分けた流れのどの段で落ちているかの読み方を扱っています。この記事は、同じ「段階ごとの割合を掛ける」形のうち、商談が段階を飛ばす・戻るときのずれに絞ります。

## 主な結果

### 基本の置き方（500回、`results/a1263_main.json` の `headline`）
| 見込みの出し方 | 見込みの合計÷本当の見込みの合計（平均） | 10〜90%の範囲 |
|---|---|---|
| ①来た数で割って掛ける | **1.2226倍** | 1.1285〜1.3168倍 |
| ②1つずつ進んだ数で割って掛ける | **0.6292倍** | 0.5664〜0.6879倍 |
| ③来た商談のうち受注した割合 | 1.0002倍 | 0.925〜1.0776倍 |

- **①は500回のうち99.8%で本当より多く、②は100%で本当より少なく出た**。③は平均で本当とほぼ同じだった（動きが前の動きによらないと置いたので、③が合うのは作りどおり）
- 本当の受注の確率は、いま初回の面談で0.1902、提案で0.314、見積もりで0.4732、条件の詰めで0.6284だった（置いた確率からの式どおり）

### いまの段階ごと（500回の平均、`results/by_stage.csv`）
| いまの段階 | ①÷本当 | ②÷本当 | ③÷本当 |
|---|---|---|---|
| 初回の面談 | 1.0 | 0.347 | 1.0 |
| 提案 | **1.362** | 0.478 | 0.998 |
| 見積もり | 1.207 | 0.66 | 1.0 |
| 条件の詰め | 1.302 | 0.956 | 1.002 |

- ①は「受注の数÷段階 k に来た数」と同じになる。受注の数には、段階 k を飛ばして受注した商談も入るので、飛ばされることのある段階（提案・見積もり・条件の詰め）で多く出た。初回の面談はどの商談も通るので、①は本当と合った（作りどおり）
- ②は、飛ばした動きも戻った動きも「次へ進まなかった」と数え、飛ばしてから受注する道と、戻ってからまた進んで受注する道が掛け算に入らない。そのため段階が前ほど掛ける数が増え、ずれが大きくなった（初回の面談で0.347）

### 対照：飛ばしと戻りを分けると（各200回、`results/controls.csv`）
| | ①÷本当 | ②÷本当 | ③÷本当 |
|---|---|---|---|
| 飛ばしも戻りもない | 0.996 | 0.996 | 0.996 |
| 戻りだけ（15%） | 0.996 | **0.922** | 0.996 |
| 飛ばしだけ（20%） | **1.23** | **0.672** | 0.993 |
| 両方（基本） | 1.228 | 0.629 | 1.004 |

- 飛ばしも戻りもないときは、3つの出し方は同じ式になり（作りどおり）、本当の0.996倍だった（1から少し外れるのは、800件から割合を数える揺れの分）
- **戻りだけなら①は合い、②だけが少なく出た。飛ばしがあると①は多く、②は少なく出た**。①は戻りには影響されず、飛ばしでずれる

### 確かめ：36通り（各40回、`results/grid.csv`）
- ①÷本当は0.9935〜1.4117倍。飛ばしがないと0.9935〜1.0155倍、飛ばす割合30%では1.275〜1.4117倍だった
- ②÷本当は0.4917〜1.0063倍。飛ばしも戻りもないと0.9981〜1.0063倍、飛ばし30%・戻り30%では0.4917〜0.4962倍だった
- ③÷本当は0.9796〜1.0217倍だった
- いま提案の段階の商談で、①÷本当は0.9947〜1.7487倍まで動いた。進む確率が低い組ほど、飛ばしによる上ずれが大きかった
- ①と②の差が0.2倍より大きかったのは36通りのうち27通りだった

### 1回分（`data/`、`results/a1263_main.json` の `one_set`）
- 過去の商談800件のうち、受注は140件、飛ばしのあった商談は160件、戻りのあった商談は38件だった
- いま途中の商談200件（金額の合計87,815万円）の見込みは、①35,380万円・②18,150万円・③28,381万円で、本当の見込みは29,929万円だった

## 注意（言えないこと）
- 架空のデータと、作成者が置いた段階の動き方です。とくに「動きは前の動きによらない」と置いたので、③が本当と合うのは作りどおりです。戻った商談がそのあと取りにくくなる、長く止まった商談ほど取りにくい、といった動きがあると、③もずれると考えられます（推測。この記事では数えていません）
- 飛ばしは「先へ進む分のうちの割合」、戻りは「失注しそうな分のうちの割合」と置きました。飛ばしや戻りの置き方を変えると、ずれの大きさは変わります
- 実際の商談の記録では、段階の付け直しが遅れる、段階の名前が途中で変わる、といったことがあります。それらは入れていません
- 1件ずつ取れるか取れないかの振れ、決まるまでの日数は扱っていません。見込みの合計と期の実績の外れは別の問いです
