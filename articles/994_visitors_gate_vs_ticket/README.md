# 994 入口のゲートで数えるか、チケットで数えるかで、人数は変わるのか？（来場者と集客）

イベントの来場者数は、売れたチケットの枚数、入口で読み取ったチケットの枚数、入口のゲートのセンサーが数えた通過の回数など、いくつかの数え方で出せます。同じ日でも、来なかった人、券のいらない子ども、外に出て入り直す人（再入場）、同じ入口を通るスタッフ、並んで通る人の見落としで、それぞれ別の向きにずれます。**ここでは、作成者が乱数で作った架空の3日間の展示会（チケットの枚数と、来なかった人・子ども・再入場・スタッフ・見落としの割合を作成者が置いたもの）で、3つの数え方を本当の人数と比べ、どちらが近いかが置き方でどう入れかわるか、日ごとの増減の向きがどう変わるかを数えました。**

展示会・会場・チケットはすべて架空のもので、実在のイベントの数字は使っていません。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A994 | 販売枚数・チケットの読み取り・ゲートのセンサーで、来場者数はどれだけ違うか。どれが本当の人数に近いかは置き方で変わるか | 架空の3日間の展示会。1日券を日ごとに5,000・8,000・7,000枚、3日通し券を1,500枚売った。1日券の8%は来ない。通し券の人は各日に70%の確率で来る。券を持つ人は、平均0.15人の子ども（券なし・無料、ポアソン分布）を連れる（通し券の人の子どもは毎日同じ子ども）。来た人（子どもも）は、その日に平均0.4回、外に出て入り直す（ポアソン分布）。スタッフ・出展者300人も同じ入口を1日に平均3回通る。**本当の人数**＝その日に来た人（子どもを含む、スタッフを含まない）。数え方は3つ：**販売枚数**（その日の1日券＋通し券）、**チケットの読み取り**（その日の最初の入場で券を読む。子どもは券がないので数えない）、**ゲートのセンサー**（入る向きの通過を数える。並んで通ると8%を見落とす）。3日間を作り直して200回の平均。各数え方の倍率は、置いた割合からの式の値とも比べた。確かめとして、再入場（0・0.2・0.4・0.8回）×見落とし（0・8・15%）×スタッフ（0・300・600人）×子ども（0・0.15・0.3人）の108通り（各20回）。3日目だけ再入場を0.4〜1.0回に変えたときの、2日目→3日目の比も200回ずつ数えた。seed 994 | `src/a994_gate_vs_ticket.py` |

## 主な結果

### 日ごとの数え方と本当の人数（200回の平均、`results/by_day_200reps.csv`）
| | 本当の人数 | 販売枚数 | チケットの読み取り | ゲートのセンサー |
|---|---|---|---|---|
| 1日目 | 6,497.505 | 6,500（1.0倍） | 5,652.33（0.87倍） | 9,199.265（**1.416倍**） |
| 2日目 | 9,675.63 | 9,500（0.982倍） | 8,412.91（0.869倍） | 13,289.975（1.374倍） |
| 3日目 | 8,611.84 | 8,500（0.987倍） | 7,492.36（0.87倍） | 11,919.075（1.384倍） |

- ゲートのセンサーは本当の人数の1.374〜1.416倍、チケットの読み取りは0.869〜0.87倍だった。ゲートは再入場とスタッフの通過で多く、読み取りは券のない子どもの分だけ少ない
- これらの倍率は、置いた割合からの式の値（ゲート1.415・1.374・1.384倍、読み取り0.87倍、販売枚数1.0・0.982・0.987倍）と同じだった（式どおり）。向きと大きさは作成者が置いた割合の写し
- 販売枚数が本当の人数に近かったのは、来なかった1日券の人（8%）・来なかった通し券の日（30%）と、券のない子ども（0.15人）がたまたま打ち消し合ったため。どちらかの置き方が変わると外れる

### 3日間の合計（200回の平均、`results/a994_main.json`）
| | 3日間の合計 | 本当の人数（日ごとの合計）に対して | 3日間の実人数に対して |
|---|---|---|---|
| 本当の人数（日ごとの合計） | 24,784.975 | 1 | 1.085倍 |
| 販売枚数 | 24,500 | 0.989倍 | 1.073倍 |
| チケットの読み取り | 21,557.6 | 0.87倍 | 0.944倍 |
| ゲートのセンサー | 34,408.315 | **1.388倍** | **1.507倍** |

- 3日間で来た実人数は22,834.56人。通し券の人を日ごとに数えるので、日ごとの本当の人数の合計でも実人数の1.085倍になる
- ゲートの3日間の合計を「来場者数」と読むと、実人数の1.507倍になった

### 確かめ：108通り（各20回、`results/sensitivity_grid.csv`）
| | 108通りの幅（本当の人数の日ごとの合計に対する倍率） |
|---|---|
| ゲートのセンサー | 0.85〜2.054倍 |
| チケットの読み取り | 0.768〜1.0倍 |
| 販売枚数 | 0.872〜1.138倍 |

- ゲートのほうが読み取りより本当の人数に近かったのは108通りのうち30通り。再入場の平均で分けると、0回で27通り中16通り、0.2回で11通り、0.4回で3通り、0.8回で0通りだった。どちらが近いかは、再入場の多さでほぼ決まった
- 再入場がないと、見落としでゲートが本当の人数を下回ることがあった（108通り中9通り、再入場0回の27通りでは0.85〜1.25倍）
- 読み取りは子どもの数だけで決まり（子ども0人で1.0倍）、ゲートの倍率は108通りすべてで式の値と0.004以内で合った
- 108通りは作成者が選んだ組み合わせなので、「30通り」という数は組み合わせの選び方で変わる。言えるのは、再入場が多いほどゲートが上に外れるという向き

### 3日目だけ再入場が多いと（200回ずつ、`results/day3_reentry.csv`）
| 3日目の再入場の平均 | 本当の人数 3日目÷2日目 | ゲート 3日目÷2日目 | ゲートが「増えた」と出た回の割合 |
|---|---|---|---|
| 0.4（2日目と同じ） | 0.891 | 0.898 | 0% |
| 0.6 | 0.891 | **1.017** | 96% |
| 0.8 | 0.891 | 1.136 | 100% |
| 1.0 | 0.891 | 1.257 | 100% |

- 本当の人数は3日目が2日目の0.891倍と少ないのに、3日目だけ再入場が0.6回になると、ゲートでは96%の回で3日目が増えて見えた。販売枚数（0.895）と読み取り（0.89〜0.891）は本当の人数とほぼ同じ向きだった
- 日による再入場の違いがゲートの比をそのまま動かすのは、式どおりの向き

## 動かし方
```
pip install -r requirements.txt
cd src && python a994_gate_vs_ticket.py
```
6秒ほどで終わります。`data/event_example.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダ（/tmp）に src と requirements.txt を写して流し直し、results・figures・data の8ファイルがバイト単位で一致した（cmp、約6秒）
- 3つの数え方の倍率は、置いた割合（来なかった人・子ども・再入場・スタッフ・見落とし）からの式どおりの値で、データから見つけたものではない。乱数の結果は式の値と0.004以内で合った
- 新しく数えたのは、どの数え方が本当の人数に近いかが置き方でどう入れかわるかと、日ごとの増減の向きがゲートだけ逆になる大きさ

## データ
- `data/event_example.csv`：基本の置き方の1回分の3日間。day・sold（販売枚数）・scanned（チケットの読み取り）・gate（ゲートのセンサー）・true_visitors（本当の人数）・holders（来た券の人）・kids（子ども）・passes_visitors（来た人の入る向きの通過）・passes_staff（スタッフの通過）

## 注意（言えないこと）
- 架空のデータです。来なかった人・子ども・再入場・スタッフ・見落としの割合は作成者が置いたもので、各数え方のずれはこれで決まります。実在のイベントや機械の数え方を表すものではありません
- センサーの見落としは、並んで通る人を一律8%と置きました。実際の機械の誤りの出方（重なり方、出る向きの数え違いなど）は扱っていません
- 招待券、当日券、券を持つ人が来た日に入れなかった場合は入れていません（招待券で増えた人が次の回も来るかは 1001 で扱っています）
- どの数え方を使うべきかは言えません。それぞれ別のもの（券の数・券を持って来た人・入口を通った回数）を数えています
- 関連する記事：848 は計測の仕様が途中で変わったときの前月比を、872 は質問文を変えた年との比較を扱っています。同じ企画の 993 は延べと実人数の違いを、995 は前年比の伸びを新しい人と来る回数に分けられるかを、1003 は人の手で数えるときの数え漏れを、1004 は数え方を変えた年のあとの「過去最高」を扱っています
