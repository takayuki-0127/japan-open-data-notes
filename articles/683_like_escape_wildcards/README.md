# 683 品名に「_」や「%」を含む行を LIKE で探すと、何件を取り違えるのか（実務の型）

SQL の LIKE では、「%」は任意の0文字以上、「_」は任意の1文字として読まれます。品名に「_」（型番の区切り）や「%」（果汁の割合など）が入っているとき、`LIKE '%_M%'` と書くと、「_M」ではなく「何か1文字＋M」を探すことになり、余分な行を拾います。文字として探すには、ESCAPE 句を使うか、SQL Server では角かっこ（`[_]`）で囲みます。**ここでは、作成者が乱数で作った架空の品名5,000件で、5つの文字列を3つの書き方で探し、余分に拾った件数を数えました。** 数字は置いた品名で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A683 | エスケープしない LIKE で、何件を取り違えるか | 品名5,000件（「_」を含むもの320件、「%」を含むもの140件）。「_M」「100%」「10%」「_」「%」を含む品名を、エスケープなし・ESCAPE 句・角かっこの3通りで探す。正解は Python の文字列の包含。LIKE の読み方を Python の正規表現で再現し、DuckDB の結果と一致を確認。角かっこの SQL Server での結果は Python で再現したもの。seed 683 | `src/a683_like.py`、`src/02_like_duckdb.sql`、`src/01_like_tsql.sql` |

## 主な結果

| 探した文字列 | 本当に含む | エスケープなし | ESCAPE 句 | 角かっこ（SQL Server の読み方） | 角かっこ（DuckDB） |
|---|---|---|---|---|---|
| 「_M」 | 218 | 1,052 | 218 | 218 | 0 |
| 「100%」 | 34 | 356 | 34 | 34 | 0 |
| 「10%」 | 37 | 615 | 37 | 37 | 0 |
| 「_」 | 320 | 5,000 | 320 | 320 | 0 |
| 「%」 | 140 | 5,000 | 140 | 140 | 0 |

- **エスケープなしでは、「_M」で834件、「10%」で578件を余分に拾った**。「_」「%」だけを探すと、全5,000件が当たる
- 「100%」は「100を含む」と読まれ、「1000枚」のような品名を拾った
- **ESCAPE 句は、DuckDB でも正しい件数**。SQL Server にも同じ書き方がある
- 角かっこは SQL Server の書き方で、DuckDB では「[」「]」がただの文字として読まれ、1件も拾わなかった。データベースを移すときに結果が変わる
