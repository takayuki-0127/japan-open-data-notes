# 374 VLOOKUP は、どんなときに黙って間違った値を返すのか（実務の型）

商品マスタから単価を引く VLOOKUP が、エラーにならずに違う値を返す場面を数えたフォルダです。VLOOKUP と XLOOKUP の決まりを Python で再現し、架空の商品マスタ（2,000商品）と売上表（20,000行）で6つの場面を試しました。pandas の結合（merge）と SQL の結合（DuckDB）とも比べています。**Excel 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A374 | 6つの場面で、エラーにならずに違う値が返る行は何行か。XLOOKUP や結合に替えるとどうなるか | VLOOKUP（完全一致は上から最初の行、第4引数を省略した近似一致は昇順を前提にした二分探索）と XLOOKUP（完全一致・最初の行・返す列は範囲で指定）を関数として書き、売上の全行に当てる。正しい単価と比べ、「正しい」「エラーにならずに違う値」「エラー（#N/A）」に分ける | `src/a374_vlookup.py` |

## 主な結果（売上20,000行）
| 場面 | VLOOKUP：黙って違う値 | VLOOKUP：#N/A | XLOOKUP：黙って違う値 | 結合（1対多を止める指定つき） |
|---|---|---|---|---|
| ① 第4引数を省略し、マスタがコード順でない | 18,818行（94.1%） | 1,152行 | 0 | 0 |
| ② 第4引数を省略し、マスタにないコードがある（3%） | 600行（3.0%） | 0 | 0（#N/A になる） | 0（欠測になる） |
| ③ 完全一致で、マスタに同じコードが2行ある（5%の商品） | 1,018行（5.1%） | 0 | 1,018行（5.1%） | エラーで止まる |
| ④ 完全一致で、コードの後ろに空白がある（3%） | 0 | 600行 | 0（#N/A） | 0（欠測） |
| ⑤ 完全一致で、マスタは数、売上は文字のコード | 0 | 20,000行 | 0（#N/A） | エラーで止まる |
| ⑥ 完全一致で、マスタに列を足した（列番号は3のまま） | 20,000行（100%） | 0 | 0 | 0 |

- **VLOOKUP がエラーにならずに違う値を返したのは、6場面のうち4場面**（①②③⑥）。空白（④）と型の違い（⑤）は #N/A になるので気づける
- 売上の合計のずれ：① +28.2%、② +2.9%、③ −0.6%、④ −2.8%、⑤ −100%、⑥ −40.2%（#N/A の行を0円として足した場合）
- ①は、マスタの並び方で結果が変わる。並びを100通りに変えると、黙って違う値は平均92%（57〜99.6%）、#N/A は平均7%、正しい値は平均0.3%だった
- XLOOKUP に替えると、黙って違う値が残るのは③（同じコードが2行）だけ。結合に「マスタ側は1行のはず」という指定をつけると、③もエラーで止まる。指定をつけない SQL の LEFT JOIN では、③は行が20,000から21,018に増える

## 注意（言えないこと）
- **Excel 本体では動かしていません**。公開されている決まりの再現です。とくに①（並んでいない表への近似一致）は、Excel の中の探し方しだいで、返る値と割合が変わります。94%という数字そのものではなく、「ほとんどの行が違う値になり、エラーはほとんど出ない」という点を見てください
- 割合は置いた数字で決まります（マスタにないコード3%、重複5%、空白3%）
- VLOOKUP が大文字と小文字を区別しないこと、「*」「?」を含むコードが別の意味になることは、試していません
- XLOOKUP の近似一致、INDEX と MATCH の組み合わせは試していません
- 手作業の Excel レポートを自動にする話は 279 で扱いました。この記事は、単価を引く1つの式に絞っています
