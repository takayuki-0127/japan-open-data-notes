# 602 平均単価を「明細の単価の平均」で出すか「金額の合計÷数量」で出すかで、品目の単価はどれだけ違うのか（実務の型・平均単価の定義）

平均単価は、明細の単価を平均する（1行を同じ重さで数える）か、金額の合計を数量の合計で割る（1個を同じ重さで数える）かで値が変わります。まとめ買いほど単価が下がる品目では、行の数は小口が多く、数量は大口が占めるので、前者が高く出ます。**ここでは、架空の80品目・2025年の明細4万行（数量値引きと大口の取引先あり）で、平均単価の出し方3通りを品目ごとに比べました。** 値引きの仕方は作成者が置いたもので、数字はその仮定で決まります。

| A602 | 出し方で品目の平均単価がどれだけ違い、「平均単価×数量」で売上を戻すとどれだけずれるか | U0 金額の合計÷数量の合計、U1 明細の単価の単純平均、U2 日ごとの平均単価の平均。DuckDB（1スレッド）と pandas で一致を確認。seed 602 | `src/a602_avg_unit_price.py`、`src/02_avg_price_duckdb.sql`、`src/01_avg_price_tsql.sql`（未検証） |

## 主な結果
- **明細の単価の平均（U1）は、金額÷数量（U0）より高く出る**：80品目の差の中央値 **+5.7%**、最大 +14.3%。5%を超える品目が58.8%、10%を超える品目が23.8%
- **差は大口の割合で決まる**：数量のうち20個以上の取引の割合と差の相関 0.68。大口のない9品目の差の中央値 +1.9%、大口が4割を超える42品目では +8.1%
- **日ごとの平均の平均（U2）**も中央値 +5.7%（最大 +14.6%）で、U1 とほぼ同じ
- **「平均単価×数量」で売上を戻すと**：U1 を使うと、全品目の合計が実際の売上より **+7.6%** 大きくなる。U0 を使えばぴったり戻る
- 同じ定価の品目どうしで単価の低い順に並べると、80品目のうち43品目の順位が U1 と U0 で入れ替わった（単価の差が小さい品目どうしの入れ替わりを含む）

## 動かし方
```
pip install -r requirements.txt
cd src && python a602_avg_unit_price.py
```
数秒で終わります。`data/sales_lines.csv` に明細を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- U0〜U2 の値が、DuckDB の SQL と pandas で一致した
- T-SQL 版（`01_avg_price_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。整数どうしの AVG・割り算は整数になるので 1.0 を掛けている

## データ
- `data/sales_lines.csv`：line_id・item_id・sold_on・qty・unit_price・amount
- 仮定：定価7種類、数量が多いほど単価が下がる（品目ごとに効き方が違う、最大25%）、大口（20〜60個）の取引は品目ごとに0〜12%の行で、さらに2〜8%低い

## 注意（言えないこと）
- 架空のデータ。実際の店や会社の数字ではない
- どちらが「正しい」かは目的で決まる。売上や粗利の計算に使うなら金額÷数量、「1回の取引でいくらで売っているか」を見るなら行の平均も意味がある。名前を分けて持つ、という話
- 価格の決め方についての助言ではない
