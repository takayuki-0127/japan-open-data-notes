# 601 外部結合（LEFT JOIN）のあと WHERE で右の表の列を絞ると、何件の行が黙って消えるのか（実務の型・外部結合の条件の置き場所）

「注文のない顧客も0円で残したい」ので LEFT JOIN を使ったのに、期間の条件を WHERE に書くと、右の表が NULL の行が条件で落ち、内部結合と同じ結果になります。エラーは出ず、合計金額も変わらないので気づきにくいずれです。**ここでは、架空の顧客5,000人と2025年の注文11,751件で「顧客ごとの下期の注文金額」を3通りの SQL で出し、消える顧客の数と1人あたり平均のずれを数えました。** 買い方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A601 | 条件の置き場所で、残る顧客の数と1人あたり平均がどれだけ変わるか | W0 期間の条件を ON に置く（正しい）、W1 WHERE に置く、W2 WHERE に `OR o.order_id IS NULL` を足す。期間の長さを1〜12か月で変えた比較。DuckDB（1スレッド）と pandas で一致を確認。seed 601 | `src/a601_left_join_where.py`、`src/02_left_join_duckdb.sql`、`src/01_left_join_tsql.sql`（未検証） |

## 主な結果
- **正しい書き方（W0）**：5,000人が残り、下期に注文のない2,534人は0円。1人あたり平均 5,758円
- **WHERE に置く（W1）**：2,466人しか残らず、**2,534人（50.7%）が消えた**。合計金額は同じ 28,789,270円のまま。1人あたり平均は 11,674円（**2.03倍**）
- **OR … IS NULL を足す（W2）**：2025年に注文が1件もない1,878人は戻るが、上期にだけ注文がある656人（13.1%）は消えたまま。1人あたり平均は 6,627円（1.15倍）
- **期間が短いほど消える**：12月末までの期間を1か月にすると W1 で84.1%、W2 で46.5%が消える。12か月では W1 37.6%（1年注文のない人）、W2 0%

## 動かし方
```
pip install -r requirements.txt
cd src && python a601_left_join_where.py
```
数秒で終わります。`data/` に顧客と注文（customers.csv・orders.csv）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- W0 の合計と行数、W1・W2 の行数が、pandas で数えた値と一致した
- T-SQL 版（`01_left_join_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/customers.csv`：customer_id・joined_on
- `data/orders.csv`：order_id・customer_id・order_date・amount（2025年）
- 仮定：顧客ごとの年間の注文回数は買う頻度のばらつきが大きいポアソン（ガンマ混合）、注文日は年内に一様、金額は対数正規

## 注意（言えないこと）
- 架空のデータ。実際の店や会社の数字ではない
- 消える人数は、注文のない顧客の割合と期間の長さで決まる。注文のない顧客がほとんどいないデータでは、ずれは小さい
- 合計金額は3通りとも同じ。合計の照合だけではこのずれは見つからない。行数（顧客数）を確かめるのが手がかり
