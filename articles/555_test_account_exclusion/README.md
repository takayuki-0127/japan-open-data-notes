# 555 社内のテスト用アカウントの行を外す条件を変えると、利用者数と売上はどれだけ動くのか（実務の型・テスト用の行の除外）

サービスの利用ログや注文には、社内の動作確認に使うテスト用アカウントの行が混ざります。外す条件を「メールの末尾」「ID の範囲」「テスト用フラグ」のどれにするかで、利用者数や売上の値が変わります。**ここでは、架空のサービス（2025年10〜12月、一般の利用者20,000人）の利用ログと注文に、テスト用アカウント240件の行を混ぜ、外す条件7通りで、利用者数・購入者数・売上・購入した人の割合と、外し漏れ・外しすぎの件数を比べました。** 目印の付き方やテスト用アカウントの使われ方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A555 | 外す条件で、利用者数・売上・転換率と外し漏れ・外しすぎがどれだけ違うか | 条件：外さない・E メール末尾（@corp.example、架空）・I ID の範囲（900000〜900999）・F フラグ・E か I・E か F・3つのどれか。正しい値は作成者が付けた「本当にテスト用か」で出す。「3つのどれか」を Python と SQL（DuckDB、1スレッド）で突き合わせ。seed 555 | `src/a555_test_accounts.py`、`src/02_exclude_duckdb.sql`、`src/01_exclude_tsql.sql`（未検証） |

## 主な結果
- **テスト用の行**：240件で、セッションの 19.8%、売上の 12.4% を占めた。目印は E 142件・I 150件・F 132件に付き、3つとも付くのは 48件、どれも付かないのは 16件
- **外さない**：正しい値と比べて、利用者数 +1.26%、売上 +14.20%、購入者数 +14.56%、注文件数 +40.38%、購入した人の割合 6.70%（正しい値 5.92%、+0.78ポイント）
- **1つの条件だけ**：売上は +5.52%（I）〜 +6.90%（F）。外し漏れは 90〜108件
- **2つの条件**：売上は +2.40%（E か I）・+2.94%（E か F）
- **3つのどれか**：売上 +0.96%、購入した人の割合 +0.06ポイント。外し漏れ 16件（目印なし）、外しすぎ 38件（社内メールで一般の利用者として使う 8件、ID の範囲に入っていた一般の利用者 30件）。利用者数は −0.12% と、正しい値より少なくなった

## 動かし方
```
pip install -r requirements.txt
cd src && python a555_test_accounts.py
```
数秒で終わります。`data/` に利用者・セッション・注文と、正しい値を出すための区分（users_true_label.csv）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 「3つのどれか」で外した利用者数・購入者数・売上・購入した人の割合が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_exclude_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/users.csv`（user_id・email・is_test_flag）、`data/users_true_label.csv`（true_test）、`data/sessions.csv`、`data/orders.csv`
- 仮定：テスト用アカウントの 150件は ID の範囲内、60% は社内のメール、55% にフラグ。テスト用は1件あたりセッション 5〜119回、65% が注文（1〜7件、1円〜4,980円）。一般の利用者はセッションが平均3回、6% が注文
- メールの末尾・ID の範囲・ドメイン名はすべて架空
