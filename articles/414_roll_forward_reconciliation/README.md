# 414 「期首＋増加−減少＝期末」の照合は、どんな誤りを見つけ、何を見逃すのか（実務の型）

架空の契約の異動の記録24か月分に、誤りを10種類入れ、件数の照合・保険料の照合・契約ごとの照合で見つかるかを数えたフォルダです。233（合計の照合）・326（移行の照合）は、表全体の合計やハッシュを比べました。ここでは、増減の内訳（期首・増加・減少・期末）の照合に絞ります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A414 | 増減の照合は、どんな誤りを見つけ、何を見逃すか | 月末の一覧と異動の記録を作り、誤りを10種類×200回入れて、3つの照合で見つかった割合を数える。件数と保険料の照合は DuckDB の SQL でも実行する | `src/a414_rollforward.py`、`src/01_roll_forward_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
| 誤り | 件数の照合 | 保険料の照合 | 契約ごとの照合 |
|---|---|---|---|
| E1 解約の記録が1件抜ける | 100% | 100% | 100% |
| E2 新規の記録が二重に入る | 100% | 100% | 100% |
| E3 新規の記録が翌月にずれる | 100% | 100% | 100% |
| E4 解約を満期と書く | 0% | 0% | 0% |
| E5 同じ月に解約1件と新規1件の記録が抜ける | 0% | 98.5% | 100% |
| E6 中途変更の増減の符号が逆 | 0% | 100% | 100% |
| E7 中途変更の記録が1件抜ける | 0% | 100% | 100% |
| E8 復活を新規と書く | 0% | 0% | 0% |
| E9 解約した契約が月末の一覧に残る | 100% | 100% | 100% |
| E10 月末の一覧で2件の保険料が入れ替わる | 0% | 0% | 98.5% |

- **必ず見つかった誤りの種類**：件数の照合だけ4、件数＋保険料6（ほかに一部の試行で1）、契約ごとの照合7（ほかに一部の試行で1）
- E5 の残り1.5%は、抜けた2件の保険料が同じだった試行。E10 の残り1.5%は、同じ保険料どうしの入れ替え（実際には何も変わらない）
- E3 と E9 は、件数の照合が2か月続けて合わない
- **例**：12か月目に E5 を入れると、件数の差は0、保険料の差は6,900円
- 誤りを入れる前の記録は、24か月すべてで3つの照合に合う

## 動かし方
```
pip install -r requirements.txt
cd src && python a414_rollforward.py     # 20秒ほど
```

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の SQL で出した月ごとの増減の表で、件数の差・保険料の差が24か月すべて0になる（コード内の assert）
- 契約ごとの照合の SQL（T-SQL 版と同じ形）を DuckDB で1〜2か月目に流し、誤りを入れる前の記録で0行になることを確かめた

## データ
- `data/movements.csv`：架空の異動の記録30,531件（月・契約ID・種類・金額）。作成者が乱数で作成（seed 414）
- `data/snapshots_sample_months.csv`：月末の一覧のうち、0・1・2・12・24か月目だけ（全部は大きいので置いていない。コードを流すと作られる）

## 注意（言えないこと）
- 架空のデータ。誤りは作成者が選んだ10種類だけで、「何種類見つかるか」は選び方で変わる
- 誤りは1回に1つだけ入れた
- 98.5%という割合は、保険料が同じ契約がどれだけあるかで変わる（保険料は100円単位）
- 種類の書き間違いを見つける別の照合（別の記録との突き合わせ）は試していない
- 契約ごとの照合にかかる時間は測っていない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
