# 563 千円単位と円単位の数字が混ざった表から、桁のずれた行をどう見つけるのか（実務の型・入力の点検）

部門から集めた月次の表に、千円単位で入れた行が混ざることがあります。そのまま足すと合計が少なく出ます。**ここでは、架空の部門別の月次経費表（60部門 × 2023年1月〜2025年12月、2,160行）に、千円単位の行150行（1か月だけ40行・数か月続けて38行・ある部門がずっと72行）を混ぜ、見つけ方4通り（M1 前月比・M2 中央値との倍率・M3 全社合計との照合・M2 で直してから M3）で、見つけた行・見逃した行・誤って見つけた行を数えました。** 本当に大きく動いた月（5〜20倍が18行、0.002〜0.1倍が12行）も混ぜています。混ぜ方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A563 | 見つけ方で、桁ずれの行をどれだけ見つけ、どれだけ誤るか | M1：前月の1/100以下。M2：部門の36か月の中央値の1/100以下。M3：別に分かっている全社の月合計との差を、×1000で埋める行の組（1〜3行）を探す。M2→M3：M2 の行を ×1000 で直してから、残りの差を M3 で探す。正解は作成者が付けた区分。M1・M2 は Python と SQL（DuckDB、1スレッド）で一致を確認。seed 563 | `src/a563_unit_mix.py`、`src/02_detect_duckdb.sql`、`src/01_detect_tsql.sql`（未検証） |

## 主な結果
- **直さずに足すと**：全社の月合計は36か月すべてで少なく出た（−0.77〜−16.96%、平均 −3.79%）
- **M1 前月比**：見つけた 46行（1か月だけ 38・続けて 8・ずっと 0）、見逃し 104行、誤り 4行。続けての行は、始まりの月しか引っかからない
- **M2 中央値との倍率**：見つけた 78行（1か月だけ 40・続けて 38・ずっと 0）、見逃し 72行、誤り 4行。ずっと千円単位の部門は、中央値も千円単位なので見つからない
- **M3 合計との照合（単独）**：見つけた 43行、見逃し 107行、誤り 0行。1か月に桁ずれが4行以上あると組が見つからず、36か月中21か月で解けなかった
- **M2→M3**：見つけた **142行**、見逃し 8行、誤り 4行。見逃した8行は、M2 が本当に小さかった月（0.002〜0.1倍）を誤って直した4つの月にあった。誤って直した分だけ合計の差がずれ、照合が合わなくなった
- 誤って見つけた4行は、どの方法でも「本当に小さかった月」だった

## 動かし方
```
pip install -r requirements.txt
cd src && python a563_unit_mix.py
```
数秒で終わります。`data/` に部門別の表（dept_monthly.csv）、全社の月合計（monthly_total.csv）、正解（dept_monthly_truth.csv）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- M1・M2 の判定が、Python と DuckDB の SQL で全2,160行一致した
- T-SQL 版（`01_detect_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。M3 は Python だけで書いた

## データ
- 部門の規模は30万〜8,000万円（対数一様）、季節の振れ ±12%、月ごとの揺れ（対数で標準偏差0.18）
- 千円単位の行は、正しい値を1,000で割って整数に丸めた。M3 は、丸めのずれ（1行あたり最大500円）を許して照合した
- 全社の月合計は、正しい値の合計が別に分かっているとした

## 注意（言えないこと）
- 架空のデータ。実際の会社の数字ではない
- 1/100 というしきい値や、M3 で探す組の大きさ（3行まで）を変えると、数字は変わる
- 実際には、全社の正しい合計が別に分かっているとは限らない。会計の数字との照合ができるときの話
- 会計や税務の判断についての助言ではない
