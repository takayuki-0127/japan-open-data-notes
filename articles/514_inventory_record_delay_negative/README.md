# 514 入庫と出庫の記録が遅れて届くと、在庫が一時的にマイナスになる日は何日あるのか？（実務の型）

架空の倉庫（200品目×180日、入出庫75万件）で、出荷（出庫）と入荷（入庫）の「起きた時刻」と「システムに記録された時刻」を作り、記録された時刻で積み上げた在庫が、本当の在庫からどれだけずれるかを数えたフォルダです。入庫の記録の遅れ（中央値0〜48時間）と、日次の締めの時刻（当日24時〜3日後）を変えました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A514 | 入庫の記録が遅れると、日次の在庫がマイナスになる品目・日、欠品と誤って見える品目・日、月末在庫のずれはどれだけか。締めを遅らせるとどこまで戻るか | 本当の在庫がマイナスにならない（物がなければ出荷できない）架空の入出庫を作り、入庫の記録に対数正規の遅れ、出庫の記録に平均12分の遅れを付ける。「d日目までに起きて、締めの時刻までに記録されたもの」を積み上げて本当の在庫と比べる | `src/a514_record_delay.py`、`src/02_stock_duckdb.sql`、`src/01_stock_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **入庫の記録の遅れが中央値6時間、締めが当日24時のとき**：日次の在庫がマイナスの品目・日は36,000のうち314（0.87%）、200品目のうち134品目が一度はマイナスになった。記録の順に在庫を動かす画面では、日中に一度でもマイナスになる品目・日が1.9%（184品目）
- **欠品と誤って見える（記録の在庫が0以下、本当は1個以上ある）品目・日**：同じ条件で360（1.0%）。締めを翌9時にすると205（0.57%）、翌日24時で104（0.29%）、3日後で16（0.04%）
- **月末在庫の合計のずれ**：締め当日24時で−4.7%、翌9時で−2.2%、翌日24時で−0.4%、3日後で−0.1%（入庫が記録されていない分、少なく出る）
- **遅れの大きさ別（締め当日24時、マイナスの品目・日の割合）**：遅れ0〜1時間で0%、3時間0.18%、6時間0.87%、12時間3.3%、24時間10.7%、48時間27.4%
- **記録された時刻で積み上げた在庫は、締めを当日24時にして起きた時刻で積み上げた在庫と同じになる**（記録は起きたあとにしか来ないため）。違いが出るのは、締めを遅らせて遅れて届く記録を待つときだけ
- 本当の在庫がマイナスの品目・日は0（作り方による）。DuckDB の SQL で出した日次の在庫は、Python の計算と全品目・全日で一致した（締め当日24時・翌9時）

## 動かし方
```
pip install -r requirements.txt
cd src && python a514_record_delay.py
```
`results/sweep.csv` に遅れ×締めの全組み合わせ、`results/a514_main.json` にまとめが出ます。入出庫の記録は毎回スクリプトで作り直すので、`data/` は置いていません。

## 注意（言えないこと）
- 架空のデータ。品目の出荷件数（1日4〜60件）、発注点（3日分）、発注量（7日分）、入荷の時刻（朝7〜8時半）、記録の遅れの分布は置いた値。実際の倉庫の割合とは違う
- 出庫の記録はほぼすぐ届く前提。出庫の記録も遅れると、逆に在庫が多く見える日が出る（ここでは試していない）
- 返品・棚卸の調整・移動・引当は入れていない
- 欠品と誤って見えた日に、実際に発注や販売停止が起きるかどうかは仕組みによる
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
