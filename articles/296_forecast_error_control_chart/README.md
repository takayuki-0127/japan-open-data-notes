# 296 需要予測の当たり外れを、毎週どう見張るか（実務の型）

週の予測誤差を管理図（平均±2σ・±3σの線）で見張り、鳴ったら予測を作り直す、という表計算と SQL でできる程度の仕組みを、正解の分かる架空の日別需要で試したフォルダです。見張りの SQL は T-SQL と DuckDB 版を `sql/` に置きました（T-SQL 版は **SQL Server 本体では試していません＝未検証**、DuckDB 版で実行）。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A296 | 需要の水準が変わったとき、週の誤差の管理図は何週で気づくか。変化がないのに何回鳴るか。鳴ったら作り直す決まりは効くか | 架空の日別需要156週（曜日の形＋ばらつき8%、80週目から水準が変わる）、予測は1〜52週の曜日ごとの平均（固定）、管理限界は53〜78週の26週で決める。決まり5つ（R1〜R3、その組み合わせ、CUSUM）を各2,000回、作り直しの決まり3つを各1,000回 | `src/a296_sim.py`・`a296_retrain.py`・`a296_sql_example.py`・`a296_figs.py`、`sql/01_weekly_error_chart_*.sql` |

決まり：R1＝1週でも±3σを超える、R2＝3週のうち2週が同じ側で±2σを超える、R3＝4週続けて同じ側で±1σを超える、CUSUM＝ずれを積み上げて閾値（k=0.5, h=4）を超える。

## 主な結果
- **8週以内に鳴った割合**：需要が+10%・−10%・+20%変わると、どの決まりでもほぼ100%（R1〜R3のどれかなら中央値1週）。+5%の小さい変化では R1 だけだと57%、R1〜R3のどれかで84%、CUSUM で94%
- **空振り（変化がないのに鳴る）**：1年あたり R1 0.36回・R3 0.15回・R1〜R3のどれか 0.86回・CUSUM 0.71回。R1 は教科書の0.14回（52週×0.27%）より多い。管理限界を26週だけで決めると、ばらつきを小さめに見積もるため（推測）
- **予測が年の季節（±5%）を取りこぼしていると**、変化がなくても1年に4.6〜21回鳴り、管理図は使えなくなった。管理図は「誤差が週ごとに独立」のときの道具で、先に予測の作り方を直す必要がある
- **作り直しの決まり**（+10%の変化）：作り直さないと変化の後の誤差は平均10%のまま。13週ごとに作り直すと77週の平均は3.8%だが、変化の直後8週は10%。鳴ったら作り直すと直後8週は6.6%、77週で3.1%。変化がないときは作り直しが平均1.2回あり、誤差は2.46%→2.52%とわずかに増えた
- SQL（DuckDB）で出した週の誤差と z は、Python の計算と一致した（差の最大 2×10⁻¹⁶）。例の1本では82週目に R1 が鳴った

## 注意（言えないこと）
- 需要は架空で、水準が一度に変わる形だけを試しました。ゆっくり変わる変化、季節の形が変わる変化、外れ値の週（祝日・欠品）は扱っていません
- 鳴ったら作り直す決まりの最初の作り直しは、変化の前の週を含む直近8週で行うため、続けて数回作り直しました（+10%で平均4.4回）。作り直す週の数の決め方で結果は変わります
- 「変化を見つけた週」は変化の後に最初に鳴った週です。変化の前の空振りは別に数えました
- 予測の見張りをもう少し本格的にする話（特徴量のずれ・再学習の自動化）は F205 で扱いました。この記事は表計算と SQL でできる範囲に絞りました
