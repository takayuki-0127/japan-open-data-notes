# 986 2つの出来事が同時に起きる確率は、掛け算でよいのか？（確率の直感）

「1日に1%で止まるサーバーを2台並べれば、同時に止まるのは 1%×1%＝0.01%」と考えることがあります。掛け算が使えるのは、2つの出来事が互いに関係なく起きる（独立）ときだけです。同じ更新作業や同じ設定の誤りのように、両方に効く「共通の原因」が少しでもあると、同時に起きる確率は掛け算から大きく離れます。**ここでは、作成者が乱数で作った架空の会社のサーバー2台（主と予備、どちらも1日1%で止まる）の停止の記録（共通の原因の日の割合を作成者が置いたもの）で、2台が同じ日に止まる割合が掛け算とどれだけずれるか、どれくらいの長さの記録ならそのずれが見えるかを数えました。**

## 主な結果

### 基本の置き方（1台1%、共通の原因の日0.1%、1,000万日、`results/a986_main.json`）
| | 値 |
|---|---|
| 1台ずつの止まった日の割合 | 1.0013%・1.0002% |
| 掛け算 | 0.0100% |
| 2台が同じ日に止まった割合 | **0.1079%**（式0.1081%） |
| 掛け算の何倍か | **10.77倍**（式10.811倍） |
| 2台の「止まった（1/0）」の相関 | 0.0988（式0.0991） |
| 同じ日に止まった日のうち、共通の原因の日 | 92.481% |
| 独立（共通の原因なし）のとき、同じ日に止まった割合 | 0.0100%（式0.0100%） |

- 共通の原因の日を0.1%置くだけで、2台が同じ日に止まる日は掛け算の10.77倍になった。**この倍率は置いた共通の原因の日の割合から式で決まる値（10.811倍）で、乱数はその確かめです**
- 2台の「止まった・止まらない」の相関は0.0988と小さかった。相関がこの程度でも、同時に止まる割合は掛け算の約10倍になる

### 確かめ：共通の原因の日 × 1台の確率（式、`results/grid_common_cause.csv`）
| 共通の原因の日 | 1台0.1% | 1台1% | 1台5% | 3台とも止まる（1台1%） |
|---|---|---|---|---|
| 0% | 1倍 | 1倍 | 1倍 | 1倍 |
| 0.01% | 100.81倍 | 1.98倍 | 1.036倍 | 101.0倍 |
| 0.05% | 500.25倍 | 5.903倍 | 1.181倍 | 500.9倍 |
| 0.1% | 1,000倍 | **10.811倍** | 1.361倍 | 1,000.7倍 |
| 0.2% | — | 20.641倍 | 1.723倍 | 2,000.5倍 |
| 0.5% | — | 50.251倍 | 2.814倍 | 5,000.1倍 |

（数字は、同時に止まる割合 ÷ 掛け算。1台0.1%で共通の原因0.1%は、止まる日がすべて共通の原因の日になる置き方。「—」は共通の原因の日が1台の確率を超えるので置けない）

- 共通の原因のある13通りで、掛け算からのずれは1.036〜1,000倍だった。**同じ共通の原因の割合でも、1台が止まるのがまれなほど、掛け算から大きく離れた**（共通の原因0.1%で、1台5%なら1.361倍、1%なら10.811倍、0.1%なら1,000倍）
- 3台にすると、掛け算（1%の3乗＝0.0001%）に対し、共通の原因0.1%で1,000.7倍になった。台を増やして掛け算で小さくした分は、共通の原因の割合でほぼ打ち消される
- 各200万日の乱数で、同時の日が見込み100日以上の15通りを数え、式との差は6%以内（乱数の振れの範囲）だった

### 確かめ：止まりやすさの相関（数値積分、`results/grid_latent_corr.csv`）
| 止まりやすさの相関 ρ | 1台10% | 1台1% | 1台0.1% |
|---|---|---|---|
| −0.3 | 0.3倍 | 0.055倍 | 0.009倍 |
| 0 | 1倍 | 1倍 | 1倍 |
| 0.1 | 1.334倍 | 1.927倍 | 2.834倍 |
| 0.3 | 2.162倍 | 5.563倍 | 14.902倍 |
| 0.5 | 3.24倍 | 12.939倍 | 54.259倍 |

- 共通の原因の代わりに止まりやすさの相関を置いても、同じ相関でまれな出来事ほど掛け算から離れた（ρ＝0.3で、1台10%なら2.162倍、0.1%なら14.902倍）。反対向きの相関（片方が止まりやすい日はもう片方が止まりにくい）では、掛け算より小さくなった
- ρ＝0.3・1台1%の数値積分（0.0556328%）は、500万日の乱数（0.0565%）と合った。**この表は置いた分布からの式の値です**

### 記録の長さ（各4,000通り、`results/record_length.csv`）
| 記録の長さ | 同時に止まった日が0日の記録（共通の原因0.1%） | 同じ（独立） | 同時の日の平均（共通の原因0.1%） | 1台ずつの割合の掛け算から見込んだ日数 |
|---|---|---|---|---|
| 1年（365日） | **66.85%** | 95.80% | 0.403日 | 0.037日 |
| 3年 | 31.77% | 90.18% | 1.158日 | 0.11日 |
| 10年（3,650日） | 1.85% | 69.17% | 3.932日 | 0.365日 |

- 掛け算の10倍を超えていても、1年の記録の66.85%では同時の停止が0回だった。0回の記録からは、掛け算でよいのか、共通の原因があるのかを見分けられない
- 10年の記録では、共通の原因0.1%なら0回は1.85%だけで、同時に止まった日の平均は3.932日（掛け算の見込みは0.365日）だった。0回の割合は式（(1−同時の確率)の日数乗）とほぼ同じだった
- 1回分の10年の記録（`data/days_10years.csv`）では、主38日・予備38日止まり、同じ日に止まったのは3日（うち共通の原因の日2日）、掛け算からの見込みは0.396日だった

## 注意（言えないこと）
- 架空のデータです。1台の止まる確率、共通の原因の日の割合と効き方（その日は必ず2台とも止まる）は作成者が置いたもので、倍率はこれで決まります。表の倍率はどれも式どおりで、乱数で新しく見つけた値ではありません。新しく数えたのは、まれさによる倍率の違いの大きさと、記録の長さで見え方がどう振れるかです
- 共通の原因は1種類、日ごとに関係なく起きると置きました。止まった日が続く、1台が止まるともう1台に負荷が移って止まりやすくなる、といった形は入れていません
- 実際のサーバーやシステムの止まりやすさ、組み方の良し悪しを表すものではありません
- 関連する記事：920「工程を2つつなぐと、全体の良品率はどうなるのか？」は、材料のロットが2つの工程の不良を結びつけるときの良品率の掛け算を扱っていて、同じ「共通の原因」の形です。920 はよく起きる出来事（良品）のずれが小さいことを、この記事はまれな出来事ほどずれが大きく、短い記録では見えないことを扱いました。851「並行する作業が増えると、全体の遅れはどれだけ増えるのか？」は、全部の作業が一緒に延びる共通の振れで、全部が間に合う確率が掛け算から離れることを扱っています。同じ企画の987「『少なくとも1回』の確率は、回数でどう増えるのか？」は、1回起きると続けて起きやすいときに「少なくとも1回」が独立の式より下がることを扱っています
