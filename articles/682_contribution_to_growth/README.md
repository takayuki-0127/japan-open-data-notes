# 682 店ごとの前年比を並べるのと、全体の伸びへの寄与度で並べるのでは、順位はどれだけ違うのか（実務の型）

店ごとの前年比（今年 ÷ 前の年 − 1）は、店の大きさを考えません。小さい店が20%伸びても、全体の売上はあまり増えません。全体の伸びにどれだけ効いたかは、寄与度（店の増えた額 ÷ 全店の前の年の合計）で見ます。寄与度は全店を足すと全体の前年比になり、寄与率（店の増えた額 ÷ 全店の増えた額）は足すと100%になります。**ここでは、作成者が乱数で作った架空の30店の売上2年分で、前年比と寄与度の順位の違いと、全体がほぼ横ばいのときの寄与率の振れを確かめました。** 数字は置いた売上と伸び率で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A682 | 前年比と寄与度で、順位はどれだけ違うか | 30店。前の年の売上は対数正規（平均 約2億円）。伸び率は平均+4%、小さい店ほど振れが大きい（標準偏差3〜18%）。場面A：そのまま（全体+2.5%）。場面B：伸び率を一律に下げて全体を+0.3%にしたもの。前年比・寄与度・寄与率を出し、順位を比べる。seed 682。DuckDB の SQL でも出して一致を確認 | `src/a682_contrib.py`、`src/02_contrib_duckdb.sql`、`src/01_contrib_tsql.sql` |

## 主な結果
- 場面A：全体の前年比は+2.53%。**寄与度を全店で足すと+2.53ポイント、寄与率を足すと100%**（定義どおり）
- **前年比の上位5店と寄与度の上位5店で、重なったのは1店（店02）**。前年比1位の店02（+19.9%）は寄与度4位、寄与度1位の店14（+11.9%、前の年の売上が最大級）は前年比7位
- 前年比2位の店06（+17.5%）は、前の年の売上が小さく、寄与度は12位
- 順位全体のつながり（スピアマンの順位相関）は0.90。順位が5以上動いた店は8店、いちばん動いたのは10
- 寄与度の上位5店（前の年の売上の25.1%）で、全体の伸びの96.2%を生んでいた（伸びた店の分を、減った店の分が打ち消すため）
- **場面B（全体+0.3%）：寄与率は1店で+205.4%から−171.2%まで振れ、±100%を超える店が6店**。寄与度は+0.63〜−0.52ポイントで、場面Aと同じ尺度で読める

## 動かし方
```
pip install -r requirements.txt
cd src && python a682_contrib.py
```
数秒で終わります。`data/store_sales.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 前年比・寄与度・寄与率が、Python と DuckDB の SQL で両方の場面とも一致すること
- 寄与度の合計が全体の前年比に、寄与率の合計が100%になること

## データ
- `data/store_sales.csv`：架空の店の売上（scene＝場面・store・year・sales＝万円）。店の名前は番号だけで、実在の店・地域ではない

## 注意（言えないこと）
- 架空のデータ。売上と伸び率は作成者が置いたもので、結果はこれで決まる
- 前年比と寄与度は、見たいものが違う指標。どちらの順位が正しいというものではない（店の勢いを見るなら前年比、全体への効き方を見るなら寄与度）
- 全体の伸びが0に近いと、寄与率は分母が0に近くなって大きく振れ、全体が減ったときは符号の読み方が逆になる。T-SQL 版は分母が0のとき NULL にしている（未検証）
- 店の評価や配分の助言ではない。要因分解（F127）は扱っていない
