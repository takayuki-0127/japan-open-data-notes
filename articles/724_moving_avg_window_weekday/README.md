# 724 日次の売上に7日以外の幅の移動平均をかけると、曜日の波はどれだけ残るのか（実務の型）

日次の売上には、土日が高く平日が低いといった曜日の波があります。移動平均の幅を7日（またはその倍数）にすると、どの日でも各曜日が1回ずつ入るので、曜日の波が消えます。3日や5日の幅では、入る曜日がずれていくので、波が残ります。**ここでは、曜日の波と水準の変化を置いた架空の店の2年分の日次売上で、幅3・5・7・14・28日の移動平均（その日までの k 日の平均）を出し、残った曜日の波の大きさ、本当の水準との誤差、水準の変化への遅れを比べました。** DuckDB の SQL（ROWS BETWEEN）と Python で同じ値になることを確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A724 | 移動平均の幅で、曜日の波はどれだけ残るか | 架空の店の730日（2024-01-01〜2025-12-30）。水準100万円から2年で+15%、曜日の波 月−12%〜土+25%（幅40ポイント）、2025-06-01 から水準+10%、ノイズ4%。後ろ向きの移動平均を5つの幅で。seed 724 | `src/a724_moving_avg.py`、`src/02_moving_avg_duckdb.sql`、`src/01_moving_avg_tsql.sql`（T-SQL：未検証） |

## 主な結果
| 移動平均の幅 | 残った曜日の波（最大−最小、水準に対する%） | 本当の水準との誤差（RMSE） | 水準の上がりを半分映すまで |
|---|---|---|---|
| 3日 | **27.3%** | 10.0% | 1日 |
| 5日 | **13.4%** | 5.2% | 2日 |
| 7日 | 0.0% | 1.6% | 3日 |
| 14日 | 0.0% | **1.2%** | 6日 |
| 28日 | 0.0% | 1.2% | 13日 |

- 元の曜日の波（最大−最小）は40ポイント。3日の移動平均には27.3ポイント、5日には13.4ポイントの波が残り、週ごとに山と谷ができた
- 7日・14日・28日（7の倍数）では、曜日の波はほぼ0になった
- 幅を広げるほど水準の変化に遅れ、2025-06-01 の+10%を半分映すのに7日で3日、28日で13日かかった

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data が一致した
- 5つの幅の移動平均が、DuckDB の SQL（`ROWS BETWEEN k−1 PRECEDING AND CURRENT ROW`）と Python で一致すること（assert）
- 曜日の波だけに7日の移動平均をかけると、ほぼ0になること

## データ
- `data/daily_sales.csv`：架空の日付・売上（万円）。作成者が乱数で作ったもの（seed 724）

## 注意（言えないこと）
- 架空のデータです。曜日の波・水準の変化・ノイズは作成者が置いたもので、残る波や遅れの大きさはこれで決まります
- ROWS で数える移動平均は、日付が抜けていない表が前提です。売上のない日の行がないと、7行が7日になりません
- 祝日や月末のように曜日以外の周期がある場合は、7日の移動平均でもその波は残ります
- 後ろ向きの移動平均は、水準の変化に (幅−1)÷2 日ほど遅れます。中心に置く移動平均なら遅れはなくなりますが、直近の日が出せません
