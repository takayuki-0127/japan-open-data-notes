# 1274 同時に動かして足し合わせた小数の合計は、足す順番が回ごとに変わると、どれだけ食い違うのか？（並列処理）

コンピューターの小数は、決まったけた数しか持てないので、足し算のたびに最後のけたで丸めが起きます。そのため、同じ値を足しても、足す順番が変わると合計が少し変わります。1つで先頭から順に足せば毎回同じ合計になりますが、同時に動かして部分の合計を「終わった順」に足したり、全部の値を1つの合計に来た順に足しこんだりすると、足す順番が回ごとに変わり、同じデータなのに合計が回ごとに違って見えます。**ここでは、作成者が乱数で作った架空のアプリの記録の値100万件（正の値だけのものと、増えた・減ったで打ち消し合うもの）を、足す順番の決まり5つで100回ずつ足し、回ごとの合計の食い違いを数えました。32ビットの小数（有効数字およそ7けた）と64ビットの小数（およそ16けた）で比べ、件数・分ける数を変えた72通りで確かめました。**

足す順番が変わる様子は、実機ではなく、順番を乱数で並べかえて作りました。実在のプログラミング言語やライブラリの仕組みを表すものではありません。この記事は、足す順番で回ごとに合計が食い違う点だけを扱い、金額の計算の決まりの助言はしません。

関連する記事：1048「途中の数字を1桁に丸めて計算すると、答えは何倍まで外れるのか？」は、概算で途中の数字を丸めたときの外れを扱っています。1124「ダメージの小数を毎回切り捨てて計算すると、小さな強化はどれだけ消えるのか？」は、計算のたびの切り捨てで小さな増えが消えることを扱っています。この記事は、丸めの量そのものではなく、足す順番が回ごとに変わることで、同じデータから違う合計が出ることに絞ります。

## 主な結果

### 100万件・100回で、違う合計が出た数と、最大と最小の差（`results/spread_by_method.csv`）
| 値の種類・小数 | 決まり | 違う合計の数 | 最大−最小 | 合計に対する割合 | 最後のけたの何個分 |
|---|---|---|---|---|---|
| 正の値・32ビット（本当の合計 49,902.15248） | ① 1つで先頭から順に | 1通り | 0 | 0% | 0 |
| | ② 8つ・番号順 | 1通り | 0 | 0% | 0 |
| | ③ 8つ・終わった順 | 3通り | 0.007812 | 0.00001566% | 2 |
| | ④ 1,000件ずつ・空いた所が取る | 20通り | 0.08984 | 0.00018% | 23 |
| | ⑤ 全部を来た順に | **92通り** | **3.258** | **0.006528%** | 834 |
| 正の値・64ビット | ⑤ 全部を来た順に | 89通り | 7.349e-09 | 1.473e-11% | 1,010 |
| 打ち消し合う値・32ビット（本当の合計 −35.32882974） | ③ 8つ・終わった順 | 5通り | 1.526e-05 | 0.00004319% | 4 |
| | ④ 1,000件ずつ・空いた所が取る | **87通り** | 0.002228 | 0.006306% | 584 |
| | ⑤ 全部を来た順に | 96通り | 0.005886 | **0.01666%** | 1,543 |
| 打ち消し合う値・64ビット | ⑤ 全部を来た順に | 92通り | 8.64e-12 | 2.446e-11% | 1,216 |

（「最後のけたの何個分」は、最大−最小を、本当の合計の大きさでの小数の最後のけた1つ分で割った値）
- **①②のように足す順番が決まっていれば、何回やっても合計は1通りだった（作りどおり）**。ただし本当の合計とは違い、正の値・32ビットの①は49,902.05859、②は49,902.22266だった。決まった順は、毎回同じになるだけで、本当の合計に近いとは限らない
- **⑤のように全部の値を来た順に足しこむと、100回で89〜96通りの合計が出た**。正の値・32ビットでは、最大と最小の差は3.258（合計の0.006528%）だった
- ③のように部分の合計（8つ）だけを終わった順に足すと、違う合計は3〜5通りで、差は最後のけたの2〜4個分だった。順番が変わるのが8つの足し算だけだから
- 64ビットの小数でも、違う合計の数は32ビットとほぼ同じだった（⑤で89・92通り）。差が小さくなるだけで、回ごとに違うことは変わらなかった。合計に対する割合は、32ビットよりけたちがいに小さかった
- 打ち消し合う値では、差の絶対の大きさは正の値より小さかった（32ビットの⑤で0.005886）が、合計そのものが0に近いため、合計に対する割合は大きかった（0.01666%）。④では違う合計の数が20通りから87通りに増えた

### 確かめ：72通り（③④、各50回、`results/grid.csv`）
- **32ビットでは、最大と最小の差は合計の0〜0.05978%、64ビットでは0〜5.045e-11%だった**
- 差が0（いつも同じ合計）だったのは72通りのうち12通りで、すべて「2つに分けて、部分の合計を終わった順に足す」だった。2つの数の足し算は、順番を入れかえても同じ答えになるため（作りどおり）
- 合計に対する差の割合は、同じ置き方どうしで比べると、打ち消し合う値のほうが正の値より大きく、中央値で6.886倍だった（正の値で差が0の組を除く）
- いちばん大きかったのは、打ち消し合う値・100万件・32ビット・④で2つに分けたときの0.05978%だった。④の打ち消し合う値・100万件・32ビットでは、分ける数2・8・64で0.05978%・0.01261%・0.00603%と、分ける数が多いほど小さかった

## 注意（言えないこと）
- 架空のデータで、実機での計測ではありません。値の分布、分ける数、かたまりの取り方は作成者が置いたもので、食い違いの大きさはこれで決まります
- 食い違いの大きさは、値の大きさのそろい方や、足す途中の合計の大きさで変わります。ここで置いた2種類の値以外の場合は扱っていません
- 打ち消し合う値で差の絶対の大きさが小さかったのは、足す途中の合計が0の近くにとどまり、丸めの大きさも小さく済むためと考えられます（仕組みからの説明で、途中の合計の大きさは数えていません）
- 丸めの誤差を減らす足し方（足す途中の誤差を持ち越すなど）は扱っていません
- 金額の計算の決まりや、どの足し方を使うべきかの助言ではありません
