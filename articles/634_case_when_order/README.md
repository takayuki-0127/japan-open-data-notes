# 634 CASE WHEN の条件の並べ方で、何件が別の区分に入るのか（実務の型）

顧客を「VIP」「常連」「新規」「休眠」のように区分するとき、SQL の CASE WHEN は上から順に条件を見て、最初に当てはまった区分を返します。条件が重なる顧客は、並べ方で入る区分が変わります。**ここでは、架空の顧客2万人を4つの条件（VIP：直近1年の金額10万円以上、常連：6回以上、新規：初めての購入から90日以内、休眠：最後の購入から180日超）で区分し、並べ方24通りすべてで区分ごとの人数を出しました。** よく使いそうな2つの並べ方は SQL（DuckDB）でも出し、Python と一致することを確かめています。数字は置いた顧客の分布で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A634 | 条件の並べ方で区分の人数はどれだけ変わるか | 顧客の購入の回数・金額・日数のシミュレーション、4条件の並べ方24通り、重なりの数、2つの並べ方のクロス表、seed 634 | `src/a634_case_order.py` |
| SQL | 2つの並べ方の CASE WHEN と、当てはまる条件の数 | DuckDB 版（1スレッドで実行）、T-SQL 版（未検証） | `src/02_case_order_duckdb.sql`・`src/01_case_order_tsql.sql` |

## 主な結果
- **条件ごとに当てはまる人数**：VIP 2,126人、常連 4,028人、新規 916人、休眠 8,182人
- **2つ以上の条件に当てはまる人**：2,066人（10.3%）。うち VIP かつ常連が 1,884人、常連かつ休眠 192人、VIP かつ休眠 102人
- **24通りの並べ方での人数の幅**：**VIP 196〜2,126人**（いちばん後ろに置くと91%減る）、常連 2,008〜4,028人、休眠 7,947〜8,182人、新規 908〜916人
- **並べ方A（VIP→常連→新規→休眠）と B（休眠→新規→常連→VIP）**：VIP 2,126人と 196人、常連 2,144人と 3,831人。区分が変わる人は 2,066人で、重なっている人全員
- 「その他」（どれにも当てはまらない）6,875人は並べ方で変わらない

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- 2つの並べ方の区分ごとの人数と、当てはまる条件の数ごとの人数が、SQL（DuckDB）と Python で一致すること
- 区分が変わる人数が、2つ以上の条件に当てはまる人数と同じになること
