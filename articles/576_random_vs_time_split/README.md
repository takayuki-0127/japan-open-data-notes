# 576 時系列のデータをランダムに分けて確かめると、時間の順に分けた場合より成績はどれだけ良く見えるのか（手法の解説・正解の分かるデータで試す）

予測モデルの成績を確かめるとき、行をランダムに分ける（ランダムなk分割）と、時系列では確かめ用の日の前後の日が学習側に入ります。**ここでは、トレンドと曜日の形と自己相関のある架空の日次データ（3年分＋その先の180日）で、ランダム5分割・時間順（最後の20%）・ずらした窓（30日ずつ5回）の3通りで誤差を見積もり、全期間で学習したモデルの「本当の先の180日」の誤差と比べました。モデルはランダムフォレストと線形回帰、自己相関は0・0.5・0.9、各60回。** 数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A576 | 時系列をランダムに分けて確かめると、成績はどれだけ良く見えるか | 架空の日次データ（年に+10のトレンド、曜日の形、AR(1)の誤差。全体の散らばりは自己相関によらず同じ）。特徴は日の番号・前日の値・7日前の値・曜日。誤差は平均絶対誤差（MAE）。3通りの確かめ方の MAE を、全期間で学習したモデルの次の180日の MAE で割った比を60回分求めた。SQL は DuckDB（1スレッド）で例の1回の MAE を数え直した。seed 576 | `src/a576_split.py`、`src/a576_mae.sql`、`src/a576_mae_tsql.sql` |

## 主な結果
- **ランダムフォレスト**：ランダム5分割の誤差は、本当の先の誤差の 0.90倍（自己相関0）・0.91倍（0.5）・0.83倍（0.9）（中央値）。60回のうち、先の誤差より小さく見積もった回は 97%・90%・92%
- **時間順（最後の20%）**：1.08倍・1.00倍・1.00倍。ずらした窓：0.92倍・0.94倍・0.93倍
- **線形回帰**：3通りとも 0.99〜1.01倍で、ランダム分割でも良く見えなかった
- 自己相関0.9・ランダムフォレストの MAE：ランダム5分割 2.37、時間順 2.87、ずらした窓 2.60、本当の先 2.92
- ランダムフォレストは日の番号の前後を覚えて「間」を当てるのは得意だが、学習した期間の外（先）にトレンドを伸ばせない。ランダム分割は「間」を当てる成績を測っている


## 確かめたこと
- 空のフォルダで流し直し、results が一致した
- 例の1回（自己相関0.5・ランダムフォレスト）の方法ごとの MAE が、Python と DuckDB の SQL で一致すること（T-SQL 版は SQL Server では動かしていない：**未検証**）

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 576）。例の1回の予測は `results/example_predictions.csv`

## 注意（言えないこと）
- 架空のデータ。トレンド・曜日の形・自己相関は作成者が置いたもので、結果はこれで決まる。トレンドのないデータや、特徴に日の番号を入れない場合は、差は小さくなると考えられる（推測）
- 回数は各60回。比の中央値は数%ぶれうる
- 線形回帰で差が出なかったのは、データを作った式と同じ形のモデルだから。どのモデルでもランダム分割が安全という意味ではない
- 「先の180日」の誤差を正解とした。先が180日より長い・短い場合や、途中で傾向が変わる場合は扱っていない
