# 722 整数の列を SQL Server の AVG で平均すると、小数の切り捨てで店ごとの平均はどれだけずれるのか（実務の型）

SQL Server の AVG は、整数（int）の列を平均すると結果も整数になり、小数が切り捨てられる、とされています（ここでは SQL Server では試していません。未検証）。DuckDB や Python では小数のまま返るので、同じ SQL でも結果が変わります。**ここでは、架空の30店のレシート約9,000枚で、店ごとの「1枚あたりの点数」と「会員の割合（0/1の列の平均）」を、小数のままの平均と、整数の AVG の切り捨てを再現した値で比べ、ずれ・同じ値にまとまる店・順位の変わり方を数えました。**

## 主な結果（30店）
| 指標 | 小数のままの平均 | 整数の AVG（切り捨ての再現） |
|---|---|---|
| 1枚あたりの点数の範囲 | 2.60〜4.81点 | 2・3・4点の3つの値だけ |
| 店ごとのずれ | — | 平均 **0.53点**（15.3%）、最大0.98点（32.9%）低い |
| 違う値の数 | 30 | **3**（2点：7店、3点：12店、4点：11店） |
| 会員の割合（0/1の列） | 25.6〜66.8% | **どの店も0** |

- 同じ「3点」にまとまった店の中には、小数では最大0.92点違う店があった。小数との順位相関は0.935
- 切り捨てた平均に枚数をかけて点数の合計を戻すと、28,756点で、本当の33,668点より14.6%少なかった
- 0/1 の列を整数のまま平均すると、全員が1でない限り0になる。会員の割合のような指標は必ず小数に直してから平均する

## 注意（言えないこと）
- 架空のデータです。点数と会員の割合の分布は作成者が置いたもので、ずれの大きさはこれで決まります
- SQL Server の AVG(int) の切り捨ては、ここでは SQL Server で試しておらず、Python と DuckDB の整数の割り算で再現したものです（未検証）
- 負の数を含む列では、切り捨ての向き（0に近づける）が床関数と違います。ここの点数はすべて正の数です
- 平均を取る値が大きい（客数が1日100人など）ときは、切り捨ての影響は相対的に小さくなります
