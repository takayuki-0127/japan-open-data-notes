# 564 注文を何回かに分けて出荷すると、「出荷済みの注文」の数え方でどれだけ違うのか（実務の型・分納の定義）

在庫が足りない品目があると、注文を何回かに分けて出荷します（分納）。そのとき「出荷済みの注文」を、1回でも出荷した注文と数えるか、全量を出荷し終えた注文と数えるかで、出荷率も出荷までの日数も変わります。**ここでは、架空の通販の注文（2025年1〜12月、20,000件・42,625品目）と出荷44,360回で、3つの定義（S1 1回でも出荷・S2 全量出荷・S3 数量の比）の月末時点の出荷率と、注文から出荷までの日数（最初の出荷まで・出荷し終えるまで）を比べました。** 在庫切れの起こり方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A564 | 定義で、月末の出荷率と出荷までの日数がどれだけ違うか | 月末時点で、その月に受けた注文について S1（出荷数量 > 0）・S2（出荷数量 ≧ 注文数量）・S3（出荷数量 ÷ 注文数量の平均）。注文ごとに最初の出荷までの日数と、出荷し終えるまでの日数。品目数（1〜6）で分ける。12か月の月末の出荷率を Python と SQL（DuckDB、1スレッド）で突き合わせ。seed 564 | `src/a564_partial_ship.py`、`src/02_ship_rate_duckdb.sql`、`src/01_ship_rate_tsql.sql`（未検証） |

## 主な結果
- **分納になった注文**：19.05%（3,811件）。全量を出し終えない注文（取り消し前で止まっている注文）は 0.74%
- **月末時点の出荷率（その月に受けた注文、12か月の平均）**：S1 1回でも出荷 **92.41%**、S3 数量の比 88.71%、S2 全量出荷 **80.53%**。S1 と S2 の差は月によって 10.27〜13.57ポイント
- **年末時点、1年分の注文全体**：S1 99.28%、S3 98.76%、S2 97.50%。古い注文ほど出し終えているので、差は小さくなる
- **注文から出荷までの日数（全注文）**：最初の出荷まで平均 2.39日（中央値2・90%点3）、出荷し終えるまで平均 6.47日（中央値2・90%点22）
- **分納のあった注文だけ**：最初の出荷まで平均 1.77日、出荷し終えるまで平均 **23.26日**（中央値18・90%点48）
- **品目数別**：分納の割合は1品目 4.5%・2品目 21.9%・6品目 52.0%。出荷し終えるまでの平均は1品目 4.19日から6品目 13.73日に延びた。最初の出荷までは1品目 3.24日・2品目以上 1.6〜1.8日で、1品目の注文のほうが長い（品目が1つだけだと、在庫切れのときに先に出せるものがない）

## 動かし方
```
pip install -r requirements.txt
cd src && python a564_partial_ship.py
```
数秒で終わります。`data/` に注文（orders.csv）、注文の品目（order_lines.csv）、出荷（shipments.csv）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 12か月の月末時点の注文数と3つの出荷率が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_ship_rate_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 注文日は2025年の中で一様。品目数は1〜6（45%・25%・14%・8%・5%・3%）、1品目の数量は1〜10
- ふだんの出荷は注文の1〜3日後。品目の12%は在庫が足りず、0〜80%を先に出し、残りを5〜49日後に出す。そのうち3%は残りが出ない
- 出荷日が2026年になる出荷も含む（日数の計算に使う）

## 注意（言えないこと）
- 架空のデータ。実際の通販の数字ではない
- 差の大きさは、在庫切れの割合と、残りを出すまでの日数で決まる
- どの定義が正しいということはない。お客さんへの約束（届いたか）を見るなら S2、倉庫の作業量を見るなら S1 や S3、というように目的で選ぶことになる（推測）
