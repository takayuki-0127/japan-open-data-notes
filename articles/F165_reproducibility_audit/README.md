# F165 データ分析の「再現できる形」は、どこまで作れたか？ 記事フォルダ40本を最初から動かし直す

看板記事 F165。note：「データ分析の『再現できる形』は、どこまで作れたか？…」（下書き）

## 問い
このリポジトリの記事フォルダは、別の人が README の手順どおりに動かしたとき、同じ数字を出せるのか。出せないなら、どこで止まり、何がずれるのか。

## データ
- このリポジトリ自身（コミット `de944aa`、2026年11月4日 8:55 時点）の `articles/` にある379フォルダ（看板記事160本・通常記事219本）。作業中だった F162・F164 と、この F165 は除いた。設計書で関連としていた F30 は、記事フォルダがない。
- 外部のデータは新しく取っていない。

## 手法
1. **動かさずに棚卸し（379本すべて）**：`src/01_棚卸し.py`。README の再現手順、requirements.txt、版の固定、コードの import と requirements の食い違い、ネット接続、ほかの記事フォルダの参照、乱数と種、絶対パス、大きなファイルを数えた。
2. **抽出（40本）**：`src/02_抽出.py`。看板の前半（F01〜F80）・後半（F81〜）、通常の前半（000〜109）・後半（110〜）の4層から10本ずつ、種165で無作為に選んだ。
3. **動かし直す**：`src/03_実行.py`。記事ごとに新しい仮想環境（uv）を作り、その記事の requirements.txt だけを入れる。版は記事を書いた環境と同じものに合わせた（`data/constraints_authoring_env.txt`）。results/ と figures/ を空にし、README のコードブロックの手順を上から実行。1本あたり上限600秒。
4. **比べる**：`src/04_比較.py`。作り直した results/ の CSV・JSON・テキストを、リポジトリにある元のファイルと比べた（相対誤差：完全一致／1e-6以内／1e-3以内／1e-2以内／ずれ／形が違う）。図（PNG）は比べていない。実行ログのファイルは除いた。
5. **集計と図**：`src/05_集計.py`、`src/06_図.py`。

判定（記事ごと）：
- **そのまま再現**：手順が全部動き、結果ファイルがすべて相対誤差1e-3以内
- **取得以外は再現**：最初のデータ取得だけが通信で止まり（この作業環境は政府サイトなどにつながらない）、リポジトリに入っているデータで残りの手順が動いて、数字が一致
- **手順が止まったが数字は一致**：取得以外の理由で止まった手順があるが、残りの結果は一致
- **数字がずれた**：1e-3 を超えて違う結果ファイルが1つ以上ある

- **看板記事は20本中9本（45%）だけがそのまま再現**、数字が一致したのは13本（65%）。

## 言えないこと
- **図は比べていない。** 数字が一致しても、図が同じとは限らない。
- **取得の手順は確かめていない。** 通信で止まった4本は、元のサイトから今も同じデータが取れるかが分からない。サイトの表の形が変われば、取得は動かない可能性がある。
- 40本の抽出で、379本全体の割合には±9ポイントくらいの幅がある。看板記事は20本なので、もっと幅が広い。
- 「新しい環境」でも、Python の版と OS はこの作業環境と同じ。別の OS・別の Python では、ずれがもっと増える可能性がある。
- ずれの原因は、F74（結果が古い・推測）と F113（並び順）以外は特定していない。
- 「数字が一致」は保存してある results/ との一致で、記事の本文の数字と照らし合わせてはいない。
