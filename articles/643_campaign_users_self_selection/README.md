# 643 キャンペーンを使った人と使わなかった人を比べると、効果が0でもどれだけ差が出るのか（実務の型）

キャンペーンの効果を「使った人」と「使わなかった人」の購入額の差で見ることがあります。ところが、もともとよく買う人ほどキャンペーンを使うので、効果がなくても差が出ます。**ここでは、架空の顧客2万人（前の6か月の購入額が多い人ほど使いやすく、翌月の購入額も前の購入額で決まる）で、本当の効果が0円と500円の場合に、単純な差・前の購入額の十分位でそろえた差・前の購入額を入れた回帰・くじで半分の人にだけ案内した比較の4通りで効果を推定しました。** 各200回です。数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A643 | 使った人と使わなかった人の差は、効果0でもどれだけ出るか | 架空の顧客2万人。前の6か月の購入額は対数正規（中央値1.2万円）。使う確率はロジスティック（前の購入額の標準化した対数に比例、利用率は約28%）。翌月の購入額＝0.17×前の購入額×振れ＋効果。比べ方：A 単純な差／B 前の購入額の十分位の中の差を使った人の数で平均（DuckDB の NTILE でも計算して一致を確認）／C 回帰（使ったか＋前の購入額の対数）／D くじで半分に案内し、案内した群としない群の差を利用率で割る。各200回、seed 643 | `src/a643_self_selection.py`、`src/02_compare_duckdb.sql`、`src/01_compare_tsql.sql` |

## 主な結果（200回の平均±標準偏差。翌月の購入額の平均は約3,200円）
| 比べ方 | 本当の効果 0円 | 本当の効果 500円 |
|---|---|---|
| A 単純な差 | +2,730円（±76） | +3,226円（±74） |
| B 十分位でそろえる | +432円（±86） | +934円（±84） |
| C 前の購入額を入れた回帰 | +348円（±51） | +848円（±50） |
| D くじで案内（差÷利用率） | +20円（±189） | +517円（±179） |

- 例の1回では、使った人の前の購入額の中央値は2.13万円、使わなかった人は0.98万円で、使った人はもともと2倍以上買っていた
- **前の購入額でそろえても、差は350〜430円残った**。十分位の中にも購入額の差が残ること（とくにいちばん上の十分位）と、回帰の式の形（対数で入れたが本当は比例）が合っていないため
- くじで案内した比較は、平均では本当の効果に近いが、ばらつきが大きい（標準偏差 約180円）。案内した群としない群の差そのもの（利用率28%で薄まった効果）は、効果500円のとき145円
- 前の購入額が使いやすさに効かない場合（強さ0）は、単純な差もほぼ0（−3円）。強さ0.5で1,580円、1で2,705円、1.5で3,302円と、選ばれ方が強いほど大きくなった

## 動かし方
```
pip install -r requirements.txt
cd src && python a643_self_selection.py
```

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data が一致した
- DuckDB の SQL（NTILE で十分位）で出した単純な差と十分位でそろえた差が、Python と一致すること
- 選ばれ方の強さが0のとき、単純な差がほぼ0になること

## データ
- `data/customers.csv`：例の1回（効果0）の架空の顧客2万人（customer_id・prev_spend・offered・used・next_spend）

## 注意（言えないこと）
- 架空のデータ。使いやすさと購入額の関係は作成者が置いたもので、見かけの差の大きさはこれで決まる
- 実際の使いやすさは、前の購入額以外の測っていない理由（関心・時期）にも左右されるので、そろえる方法で残る差はここより大きいこともある
- くじで案内を分けるのは、案内しない人が出ることを業務で受け入れられる場合だけ。可否の判断はしない
- T-SQL 版は SQL Server では動かしていない（未検証）
