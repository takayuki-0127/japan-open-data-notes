# 406 SQL の見直しの観点10個を、自分の記事の SQL に当てると何件引っかかるか（実務の型）

SQL の見直しでよく挙がる観点10個を、このシリーズの GitHub にある SQL ファイルに機械で当て、引っかかった行を読んで分けたフォルダです。体験談ではなく、件数だけを出しています。F244（集計の落とし穴）・F275（直しやすい SQL の書き方）は書き方を扱いました。ここでは、機械で引っかかった数と、読んで残った数の差を数えます。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A406 | 10個の観点を機械で当てると何件引っかかるか。そのうち、直すものは何件か | .sql ファイル148本（65記事・477文）に正規表現を当てる。割り算のほかの94件は、行と前後を読んで4つに分ける | `src/a406_scan.py`（探す）、`src/a406_count.py`（数える・図） |

## 主な結果
- **引っかかった数**：284件。1件以上引っかかったファイルは148本のうち71本
- **観点ごと**：割り算の分母を守っていない190、SELECT DISTINCT 26、SELECT * 25、日付に BETWEEN 24、ROW_NUMBER の並びが1列だけ 11、NOT IN (SELECT …) 5、カンマでつなぐ結合 2、UNION（ALL なし）1、TOP・LIMIT に ORDER BY がない 0、= NULL 0
- **割り算のほかの94件を読んだ分類**：問題なし61（65%）、わざと書いた悪い例19（20%）、誤検出4（4%）、直す候補10（11%）
- **直す候補10件**：SELECT * 5、ROW_NUMBER 3、カンマの結合2。いまのデータで結果が変わるものは0件（ROW_NUMBER の2件は、同じ時刻の行が0組であることを元のデータで確かめた。1件は確かめていない。残りの7件は書き方だけ）
- **割り算190件（機械の判定だけ）**：分母が列・変数130、集計した値27、かっこの式18、LAG 12、COUNT 3。同じ文の中に守り（NULLIF、0より大きい条件など）があるのは22件（12%）、ないのは168件
- **系列ごと**：看板記事（26記事・232文）は文100個あたり94.4件、実務の型など（39記事・245文）は26.5件。割り算を除くと23.7件と15.9件

## 動かし方
```
pip install -r requirements.txt
cd src && python a406_count.py            # data/ の結果から、数と図を作る（数秒）
# 探すところからやり直すとき（リポジトリの articles/ を渡す）
python a406_scan.py ../../
```

## 確かめたこと
- 空のフォルダで `a406_count.py` を流し直し、results・figures が一致した
- F247 の ROW_NUMBER の2件は、元のデータ（32,548行・235,950行）で、同じキーで同じ送信日時の行が0組であることを確かめた

## データ
- `data/sql_files.csv`：対象の .sql ファイル（記事・ファイル・行・文の数）。記事406を上げる前の状態で数えた
- `data/hits.csv`：引っかかった284件（記事・ファイル・行番号・観点・該当行。割り算は分母の形と守りの有無つき）
- `data/labels_manual.csv`：割り算のほかの94件に、読んで付けた分類と理由

## 注意（言えないこと）
- 自分の記事の SQL だけで、記事用に短く書いたものが多い。業務の SQL での数は分からない
- 正規表現で探している。見逃しは測っていない。Python の文字列に書いた SQL と、dbt が作る写し（target/）は対象外
- 分類は作成者1人が読んで決めた。問題なしと直す候補の境目は、読む人で動く
- 割り算は1件ずつは読んでいない。守りの有無は「同じ文の中にあるか」で、その分母を守っているとは限らない
- 10個の観点は作成者が選んだ。実行はしておらず、書き方だけを数えている
- T-SQL のファイルは SQL Server 本体では動かしていない（未検証）
