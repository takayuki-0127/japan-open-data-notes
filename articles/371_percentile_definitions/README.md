# 371 中央値や90%点は、計算の定義でどれだけ違うのか（実務の型）

「中央値」「90%点」（分位点）には、計算の定義が9つあります（Hyndman & Fan の型1〜9）。SQL の PERCENTILE_CONT と PERCENTILE_DISC、Excel の PERCENTILE.INC と PERCENTILE.EXC、NumPy の既定は、それぞれ別の型です。架空の処理時間と金額で、定義の間の差と、差が1%未満になる件数を数えたフォルダです。SQL は DuckDB で動かしました。T-SQL 版は `src/01_percentiles_tsql.sql` に置きましたが、**SQL Server 本体と Excel 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A371 | 9つの定義で値はどれだけ違うか。何件あれば差が1%未満になるか | 処理時間（対数正規、中央値30秒・σ=1.0）と金額（ガンマ、形2・平均5,000円）を、件数5〜1,000の8通りで2,000回ずつ作り、中央値・90%点・95%点・99%点を9つの定義で計算する。定義の幅（最大−最小）を値に対する%で出し、その中央値を見る。分布から決まる本当の値とのずれ（偏り・RMSE）も出す | `src/a371_percentiles.py`、`src/*.sql` |

## 主な結果
- **同じ10件の例**：90%点は、型1（PERCENTILE_DISC）92.6秒、型7（PERCENTILE_CONT・PERCENTILE.INC・NumPy の既定）96.2秒、型6（PERCENTILE.EXC）125.0秒。最小と最大で35%違う
- **9つの定義の幅（処理時間、2,000回の中央値）**：中央値は 5件31%・10件9.3%・20件4.3%・50件1.7%・100件0.9%。90%点は 10件37%・20件18%・50件7.1%・100件3.6%・200件1.8%・500件0.7%。95%点は 20件33%・100件6.4%・1,000件0.6%。99%点は 100件27%・500件5.3%・1,000件2.6%
- **幅が1%未満になる件数**：中央値100件、90%点500件、95%点1,000件。99%点は1,000件でも届かない（2.6%）。金額（ガンマ）では 100件・200件・500件・届かない（1.2%）
- 端の分位点は、件数が 1÷(1−p) のあたり（90%点なら10件、99%点なら100件）で幅がいちばん大きい。それより少ないと、どの定義もいちばん大きい値に張りついて、幅はかえって小さくなる
- **SQL の2つ**（PERCENTILE_CONT と PERCENTILE_DISC）：90%点の差の中央値は 10件4.9%・20件2.2%・100件0.4%。中央値は、件数が偶数のときだけ違う（10件で9.3%、100件で0.9%）
- **Excel の2つ**（PERCENTILE.INC と PERCENTILE.EXC）：90%点の差の中央値は 10件39%・20件17%・100件3.2%・1,000件0.3%
- **本当の値とのずれ（90%点）**：10件では、型1が−17%、型7が−10%、型6が+45%、型8が+26%と、偏りの向きが定義で分かれる。100件では−1.4%〜+3.9%。一方、標本の揺れを含めたずれ（RMSE）は100件でどの定義も17〜18%で、定義の差より標本の揺れのほうがずっと大きい

## 動かし方
```
pip install -r requirements.txt
cd src && python a371_percentiles.py     # 30秒ほど
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- DuckDB の PERCENTILE_CONT・PERCENTILE_DISC は、NumPy の `linear`（型7）・`inverted_cdf`（型1）と一致した（コード内の assert、`results/sql_check_duckdb.csv`）
- Excel の2つの関数の式（(n−1)p+1 番目、(n+1)p 番目を内分）を素朴に書いたものは、NumPy の `linear`・`weibull` と一致した（コード内の assert）。Excel 本体では動かしていない

## データ
- すべて架空（作成者が乱数で作成、seed 371）。`results/example_n10.csv` に10件の例、`results/spread_by_n.csv` に件数ごとの幅、`results/error_vs_truth.csv` に本当の値とのずれ

## 注意（言えないこと）
- 架空のデータです。幅の大きさは分布の形で変わります（裾の重い処理時間のほうが、金額より大きい）
- 同じ値がたくさんあるデータ（整数の件数、丸めた金額）では、定義の差はもっと小さくなることがあります。試していません
- PERCENTILE.EXC は、件数が少ないと値を返せず #NUM! になります（90%点はおよそ9件未満、99%点はおよそ99件未満）。この計算では NumPy に合わせて、いちばん大きい値を返したものとして数えました。境目の件数は Excel 本体で確かめていません
- どの定義が正しいかは決めていません。同じ数字を2つの道具で出すときに、定義をそろえる必要がある、というところまでです
- T-SQL 版は SQL Server 本体では動かしていません
