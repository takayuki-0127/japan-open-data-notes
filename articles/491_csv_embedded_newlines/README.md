# 491 セルの中に改行がある CSV を素朴に読むと、何行がずれるのか（実務の型）

本文に改行・カンマ・引用符が入る架空の問い合わせの記録1万件を、CSV の決まり（RFC 4180：引用符で囲んだ中の改行とカンマは中身の一部）どおりに書き出し、5通りの読み方で読み直して、正しく読めた記録・壊れた行・列の数が合わない行を数えたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A491 | 改行入りの CSV を、行で分ける読み方と決まりどおりの読み方で読むと、何件が壊れるか | 架空の問い合わせを pandas で書き出し（引用符は必要なときだけ）、①行で分けてカンマで分ける ②行で分けてから1行ずつ csv モジュールで読む ③csv モジュールで全体を読む ④pandas.read_csv ⑤DuckDB read_csv で読み直し、元の記録と1件ずつ照合。改行のある記録の割合を0〜30%に変えて同じことをくり返す | `src/a491_csv_newlines.py`、`src/01_bulk_insert_csv_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **ファイルの物理的な行**：記録1万件に対して14,135行（本文の11.6%＝1,156件に改行がある）。行を数えるだけで、件数を41%多く見誤る
- **①行で分けてカンマで分ける**：14,135行に割れ、元と同じ記録は6,035件（60.4%）。列の数が5でない行が7,125行。改行に加えて、本文のカンマ（24%の記録）でも崩れる
- **②行で分けてから1行ずつ CSV として読む**：引用符とカンマは読めるが、行をまたげない。元と同じ記録は8,844件で、壊れたのは改行のある1,156件とちょうど同じ。列の数が合わない行が5,291行
- **③〜⑤決まりどおりに読む**（csv モジュール、pandas、DuckDB）：1万件すべて元と一致
- **改行のある記録の割合を変えると**：②で正しく読める割合は、改行の割合とほぼ同じだけ下がる（1%で99.1%、10%で90.4%、30%で70.4%）。③〜⑤はどの割合でも100%
- **書き出す側**：引用符をつけずに書き出したファイルは、決まりどおりに読んでも6,708件しか元に戻らない。改行を空白に置き換えてから書けば行は1万行のままだが、本文の中身は変わる

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した

## データ
- `data/fictional_inquiries.csv`：架空の問い合わせ1万件（seed 491）。列は id, received, category, body, amount。改行は LF と CRLF が混ざる

## 注意（言えないこと）
- 架空の記録。壊れる件数は、置いた改行・カンマ・引用符の割合で決まる
- Excel で開いたときの見え方や、Excel から書き出した CSV は試していない（Excel は 372、型の推測は 373、文字コードは 428 で扱った）
- T-SQL 版（BULK INSERT の FORMAT = 'CSV'）は SQL Server 本体では動かしていない（未検証）
- 行で分ける読み方がいつも間違いという話ではない。改行が入らないと決まっているファイルなら速くて十分。決まりを確かめずに使うと危ない、という話
