# 573 会員の「休眠」を最終購入から90日で切るか180日で切るかで、休眠の人数と「復活」の割合はどれだけ変わるのか（実務の型・休眠の区切り日数）

「最終購入から○日買っていない会員を休眠とする」という決め方はよく使われますが、○日をいくつにするかで、休眠の人数も、休眠から戻った（復活した）割合も変わります。**ここでは、架空の会員3万人と3年分の購入履歴（338,487件）で、2025年6月30日を判定日として、区切りを30〜365日の7通りに変え、休眠の人数・休眠のうち180日以内に買った割合（復活率）・誤判定の人数を比べました。** 誤判定の正解には、作成者が置いた「離れた時点」（ふつうは見えない）を使っています。数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A573 | 区切りの日数で、休眠の人数・復活率・誤判定がどれだけ変わるか | 判定日までの最終購入日からの日数で休眠を判定（30・60・90・120・180・270・365日）。判定日のあと180日以内に買った割合を復活率とする。作成者が置いた「離れた時点」と比べて、まだ離れていないのに休眠に入った人・もう離れているのに休眠に入らなかった人を数える。買う間隔の違う3つのグループ別と、本人の買う間隔の中央値×3で切る方法も比べる。90日・180日の人数を Python と SQL（DuckDB、1スレッド）で突き合わせ。seed 573 | `src/a573_dormant.py`、`src/02_dormant_duckdb.sql`、`src/01_dormant_tsql.sql`（未検証） |

## 主な結果
- **休眠の人数**：90日で切ると 14,828人（49.4%）、180日で切ると 11,421人（38.1%）。90日のほうが1.3倍多い
- **復活率**：90日なら 14.2%、180日なら 4.6%。60日なら 22.0%、365日なら 0.4%。短く切るほど、休眠に「すぐ戻る人」が混ざる
- **誤判定**：まだ離れていないのに休眠に入った人は、90日で 2,397人、180日で 601人。もう離れているのに休眠に入らなかった人は、90日で 975人、180日で 2,586人。両方が釣り合うのは120日あたり
- **買う間隔の違い**：120日ごとに買う人では、まだ離れていない人の37.3%が90日で休眠に入る（180日でも13.1%）。30日ごとに買う人では1.2%
- **本人の買う間隔×3で切ると**：休眠 11,944人、復活率 6.1%、まだ離れていないのに休眠 787人、取りこぼし 2,249人。120日ごとに買う人の入れすぎは7.6%まで減るが、取りこぼしは増える。どの決め方でも、入れすぎと取りこぼしの両方をなくすことはできない

## 動かし方
```
pip install -r requirements.txt
cd src && python a573_dormant.py
```
数秒で終わります。`data/purchases.csv`（member_id・bought_on）と `data/members.csv`（member_id・cycle・joined_on）を書き出します。離れた時点は書き出していません。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 90日・180日の休眠人数が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_dormant_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 会員3万人。2023年1月〜2024年12月初めに入会。買う間隔の平均は 30日（35%）・60日（40%）・120日（25%）の3グループに、±30%のばらつき。間隔はガンマ分布
- 入会から離れるまでの日数は指数分布（平均900日）。離れたあとは買わない。判定日までに離れていた会員は13,406人
- 判定日は2025年6月30日、復活は判定日の翌日から180日以内に1回以上買ったこと

## 注意（言えないこと）
- 架空のデータ。実際の会員の数字ではない
- 「離れた時点」は実際のデータでは分からない。ここでは、区切りの日数による誤判定の大きさを見るために置いた
- 復活率は、判定日のあとの見る期間（ここでは180日）でも変わる
- 区切りの日数の決め方を勧めるものではない。目的（連絡の対象を選ぶのか、離脱の数を報告するのか）で、入れすぎと取りこぼしのどちらを避けたいかが変わる
