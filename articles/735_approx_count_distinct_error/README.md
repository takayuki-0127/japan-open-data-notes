# 735 ユニークな人数を近似の関数で数えると、件数の少ない区分でどれだけずれるのか（実務の型）

ユニークな人数（同じ人を1回と数えた人数）を正確に数える `COUNT(DISTINCT)` は、行が多いと重くなります。そこで、HyperLogLog という考え方で近似する関数（DuckDB の `approx_count_distinct`、SQL Server の `APPROX_COUNT_DISTINCT`）が使われます。**ここでは、作成者が乱数で作った架空のアクセスログ約194万行（40区分、区分のユニーク人数3人〜40,000人）で、正確な数と近似を区分ごとに比べました。** あわせて、HyperLogLog の考え方を Python で小さく作り、メモリの大きさ（レジスタの数 m）を変えたときの誤差を数えました。数字は置いたデータと DuckDB の版（2.0.0）で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A735 | 近似のユニーク人数は、区分の大きさでどれだけずれるか | 架空のアクセスログ1,940,735行。区分40個、区分の人数は3〜40,000人（等比で並べる）、1人のアクセス1〜20回。DuckDB（1スレッド）の COUNT(DISTINCT) と approx_count_distinct。自作の HyperLogLog（m＝16〜4,096、本当の人数30・1,000・30,000人、各200回）。seed 735 | `src/a735_approx_distinct.py`、`src/02_approx_duckdb.sql`、`src/01_approx_tsql.sql` |

## 主な結果

| 区分のユニーク人数 | 区分の数 | 近似のずれ（人、最大） | 近似のずれ（%、最大） |
|---|---|---|---|
| 100人未満 | 15 | 1人 | 7.7%（13人の区分で1人） |
| 1万人以上 | 6 | 1,193人 | 3.8% |
| 全40区分 | 40 | — | 中央値 1.2% |

- **100人未満の15区分では、近似のずれは0〜1人**（15区分のうち11区分はぴったり）。%では13人の区分の1人ずれが7.7%で、40区分の中でいちばん大きかった
- 1万人以上の区分では、%は3.8%以内だが、人数では最大1,193人ずれた
- 全体（142,082人）を近似で数え直すと140,951人（−0.8%）。区分の人数を足すと185,044人で、区分をまたぐ同じ人を重ねて数える（足し算はできない）
- 自作の HyperLogLog では、誤差の大きさは m を4倍にするとおよそ半分になり、目安の 1.04/√m に近かった（m＝4,096 で約1.1〜1.5%）

## 注意（言えないこと）
- 架空のデータです。ずれの大きさは、置いた人数と DuckDB の版・実装で変わります
- SQL Server の APPROX_COUNT_DISTINCT は試していません（T-SQL 版は未検証）。誤差の大きさが DuckDB と同じとは限りません
- 小さな区分でずれが小さかったのは、近似の関数が少ない人数のときに別の数え方へ切り替える作りになっているためと考えられます（推測。DuckDB の内部は確かめていない）
- 自作の HyperLogLog は考え方を見るための小さな実装で、DuckDB の実装とは同じではありません
