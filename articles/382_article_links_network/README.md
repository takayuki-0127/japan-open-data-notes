# 382 記事どうしは、どうつながっているか（④ 振り返り R112）

GitHub に置いた記事の README から、ほかの記事の番号が出てくる所を拾い、記事を点、言及を線にして数えた

## 問い

- ほかの記事に触れている README はどれだけあるか。1本あたり何本を引くか
- 多く引かれた記事はどれか。どこからも引かれていない記事はどれだけあるか
- どのまとまりが、どのまとまりを引いているか

## 手法

| 手順 | 中身 |
|---|---|
| 拾う（`src/a382_extract.py`） | `articles/*/README.md` 639本のうち、初期の記事で同じ本文を共有しているものを1本にまとめた574本（コミット 00b426f）。拾う形は4つ：`articles/<フォルダ名>`、F01〜F295 の形、T001 の形、「記事 141」と `141_wage_increase` の形 |
| 除くもの | 自分自身、存在しない番号、「F01〜F99」のような範囲の両端、数字だけの番号（「232」など） |
| まとめ方（`src/a382.py`） | 1組＝「A の README に B の番号が1回以上」。引いた数・引かれた数、まとまり×まとまりの表、つながりのまとまり（向きを無視） |

F124（データの系譜）・F200（手法とデータのネットワーク）は、同じデータ・手法を使った記事をつないだ。ここでは README に書いた言及だけを数える

## 主な結果（`results/summary.json`、`results/by_group.csv`、`results/group_matrix.csv`）

- 言及は707組（番号の出現は1,869回）。形の内訳は F の番号1,764回、リンク68回、「記事 NNN」など35回、T の番号2回
- ほかの記事を引いた README は253本（44%）。引いた README の中央値は2本、最大は F124 の27本
- 1回以上引かれた記事は639本のうち244本（38%）。上位20本で言及の28%
- 引かれた先の94%は看板記事（F01〜F295）。同じ系列の中の言及の97%は、番号の若い記事を向いている
- どこも引かず、どこからも引かれていない README は237本（41%）
- 向きを無視したいちばん大きなまとまりは316本。互いに引き合う組は13組

|---|---|---|---|---|---|
| 000–099 | 40 | 0% | 0.00 | 10% | 90% |
| 100–226 | 114 | 1% | 0.01 | 9% | 90% |
| F01–F99 | 97 | 59% | 1.16 | 86% | 5% |

- 多く引かれた記事：F01 17本、F03 16本、F22 16本、F209 14本、F12 14本、F231 13本、F18 13本、F246 10本
- 多く引いた記事：F124 27本、F165 16本、F200 15本、253 14本、F163 14本

## 確かめたこと

- 最初の版では F99・F100・F199・F255 が上位に入った。「F01〜F99」のようなまとまりの名前の両端だったので、範囲の形は除いた
- 「記事 NNN」と数字のかっこの形を目で見て、数字だけの形（「100（2019年=100）」など）は区別できないと確かめ、拾わないことにした
- `src/a382_extract.py` と `src/a382.py` を空のフォルダで流し直し、data・results・figures が一致することを確かめた

## 注意（言えないこと）

- 拾ったのは README に書いた番号だけ。番号を書かずにデータを使い回した場合や、note の本文だけで触れた場合は入っていない
- 通常の記事（000〜226）は数字だけの番号なので、引かれた回数を少なく数えている
- 番号が出てくる理由（データの使い回し、結果の比べ、「この記事とは別」という断り書き）は区別していない
- 多く引かれた記事がよい記事という意味ではない
