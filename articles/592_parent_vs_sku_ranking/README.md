# 592 同じ商品の色・サイズ違いを1品目と数えるか別々に数えるかで、売れ筋の順位はどれだけ変わるのか（実務の型・親品番と SKU）

服や雑貨のように、同じ商品に色やサイズの違いがあると、売上は「SKU（色・サイズまで分けた1つ1つ）」で記録されます。売れ筋の一覧を作るとき、SKU のまま並べるか、色・サイズをまとめた「親品番」で並べるかで、上位に出てくる商品が変わります。**ここでは、架空の150商品・2,613SKU・1年分の売上で、親品番での順位と SKU での順位を比べ、上位の重なりと売上の集中の度合いを数えました。** あわせて、親品番を商品マスタでひかずに「SKU コードの先頭6文字」で切り出したときに、桁数の違う商品がどう混ざるかも確かめました。色・サイズの数と売れ方は作成者が置いたもので、数字はその仮定で決まります。実在のブランド・商品名は使っていません。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A592 | 親品番と SKU のどちらで数えるかで、売れ筋の順位と集中度はどれだけ変わるか | 親品番ごと・SKU ごとに数量を足して順位を付け、①上位20の重なり、②各商品でいちばん売れた SKU の順位、③上位10%・20%の品目が売上に占める割合を比べる。さらに、親品番を商品マスタでひく方法と、SKU コードの先頭6文字で切る方法の上位20を比べる。集計と順位を DuckDB（1スレッド）の SQL と Python で突き合わせ。seed 592 | `src/a592_parent_sku.py`、`src/02_rank_duckdb.sql`、`src/01_rank_tsql.sql`（未検証） |

## 主な結果
- 150商品・2,613SKU。1商品あたりの SKU は中央値14、最大48（1色・フリーサイズだけの商品は7）。1年の数量は400,538個
- **上位20の重なり**：親品番の上位20商品のうち、SKU の上位20に1つでも SKU が入ったのは **7商品**。SKU の上位20は8商品の SKU だけでできていた
- 親品番の上位20商品のうち **6商品** は、いちばん売れた SKU でも100位より下（色・サイズの多い商品）。例：30SKU の商品は親品番で17位、いちばん売れた SKU は174位
- 親品番の順位と「いちばん売れた SKU の順位」の順位相関は 0.76
- **集中度**：上位10%の品目が売上に占める割合は、親品番 45.6%、SKU 64.6%。上位20%では 60.2% と 78.5%
- **先頭6文字で切る近道**：親品番が7文字の20商品が、6文字目までが同じ10商品ずつ2つにまとまり、順位で1位と3位に出てきた（どちらも実在しない商品）。上位20のうち正しい一覧と重なったのは16

## 動かし方
```
pip install -r requirements.txt
cd src && python a592_parent_sku.py
```
数秒で終わります。`data/sku_master.csv`（sku・parent・color・size）と `data/sales.csv`（sold_on・sku・qty）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 親品番ごとの数量（マスタでひく方法・先頭6文字で切る方法）が、Python と DuckDB の SQL（`02_rank_duckdb.sql`）で一致した
- T-SQL 版（`01_rank_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 親品番150。130商品は6文字（A00001〜）、後から入った20商品は7文字（A100010〜A100029）
- 色は1〜8色、サイズはフリー・4サイズ・6サイズのいずれか。商品の売れやすさは対数正規、色の売れ方はディリクレ分布、サイズは中央のサイズが売れやすい形で置いた
- 1年分の数量は SKU ごとにポアソン分布で作り、日別に散らした

## 注意（言えないこと）
- 架空のデータ。実際の会社の売上ではない
- 差の大きさは、1商品あたりの色・サイズの数と、売れ方の偏りで決まる
- どちらの単位で見るべきかは用途による（発注・在庫は SKU、品ぞろえや販促は親品番など）。どちらかが正しいという主張ではない
- 実在のブランド・商品は扱っていない
