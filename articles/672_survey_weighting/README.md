# 672 回答者の年代の偏りを重み付けで直すと、アンケートの結果はどれだけ動き、ばらつきはどれだけ増えるのか（実務の型）

アンケートは、答えやすい人に回答が偏ります。年代で回答率が違うと、回答者の年代の構成は対象の全体とずれ、満足度のような結果も年代の偏りの分だけずれます。年代ごとに「全体の構成÷回答者の構成」の重みを付けると、このずれは直せますが、そのかわりに結果のばらつきが増えます（有効な件数が減る）。**ここでは、架空の会員アンケート1,000件で、重みなし・年代の重み・重みに上限を付けた場合の満足の割合を、本当の値と比べました（各2,000回）。** 年代の中でも答える人に偏りがある場面も見ました。数字は置いた構成・回答率・満足の割合で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A672 | 年代の重みで、結果はどれだけ動き、ばらつきはどれだけ増えるか | 会員の構成（20代18%〜60代以上22%）、回答率（20代5%〜60代以上25%）、満足の割合（20代40%〜60代以上70%）を置き、回答1,000件を作る。重みなし・年代の重み（事後層化）・重みの上限2で比べる。有効な件数は Kish の式。場面 A（年代の中の偏りなし）と場面 B（満足している人ほど答えやすい）。各2,000回、seed 672。1回分の回答は data/ に置き、重み付きの割合を DuckDB の SQL でも出して一致を確認 | `src/a672_weighting.py`、`src/02_weighting_duckdb.sql`、`src/01_weighting_tsql.sql` |

## 主な結果
- **回答者の構成**：20代は会員の18%なのに回答の6.3%、60代以上は22%なのに38.7%。20代の重みは2.84、60代以上は0.57
- **重みなしでは満足の割合を5.4ポイント高く見る**（本当56.1%、重みなし61.5%）。満足しやすい年代が多く答えるため
- **年代の重みを付けると56.2%で本当の値に戻る**。そのかわり、推定の標準偏差は1.60ポイントから1.87ポイントに増え（1.16倍）、**有効な件数は1,000件から726件に減った**
- **重みの上限を2にすると**、有効な件数は820件に戻るが、57.3%と1.2ポイントのずれが残る
- **年代の中でも満足している人ほど答えやすい場合（場面 B）**、年代の重みを付けても64.1%で、8.0ポイントのずれが残った。重みで直せるのは、重みに使った項目（年代）の偏りだけ

## 動かし方
```
pip install -r requirements.txt
cd src && python a672_weighting.py
```
十数秒で終わります。`data/survey.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 1回分の回答で、重みなしと重み付きの満足の割合が、Python と DuckDB の SQL で一致すること
- 回答者の年代の構成の期待値が、会員の構成×回答率から計算した値と合うこと

## データ
- `data/survey.csv`：架空の回答1,000件（resp_id・age_group・satisfied）
- 会員全体の年代の構成はコードの中に置いた（POP）

## 注意（言えないこと）
- 架空のデータ。構成・回答率・満足の割合は作成者が置いたもので、結果はこれで決まる
- 重みで直せるのは、重みに使った項目の偏りだけ。答えた理由が結果そのものと関係していると（場面 B）、重みを付けても直らない
- 重みの上限の決め方に正解はない。ずれ（偏り）とばらつきの入れ替わりを見て決める
- T-SQL 版は SQL Server では確かめていない（未検証）
