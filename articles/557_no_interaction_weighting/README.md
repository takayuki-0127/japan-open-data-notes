# 557 効き方が層で違うのに、交互作用を入れずに回帰すると、全体の係数は何を表すのか（手法の解説・正解の分かるデータで試す）

施策の効き方が店の種類（層）で違うのに、回帰に「施策あり」と層のダミーだけを入れて、交互作用を入れないことがあります。このときの施策の係数は、層ごとの効果を店の割合で平均したものではありません。層ごとの「店数 × 施策した割合 ×（1 − 施策した割合）」を重みにした平均です。**ここでは、3つの層（駅前・住宅地・郊外）に分けた架空の600店（本当の効果は層ごとに2・5・10万円、施策した割合は50%・10%・5%）で、4つの方法の答えを2,000回くり返して比べました。** 数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A557 | 交互作用を入れない回帰の係数は、どの平均を表すか | 層ごとに効果と施策の割合が違う架空の600店を作り、単純な差・層のダミーだけの回帰・交互作用ありの回帰（店の割合で平均／施策した店で平均）を比較。駅前で施策した割合（5〜90%）と郊外の店の割合（20〜70%）を動かした。重みの式と回帰の係数の一致を確認。SQL は DuckDB（1スレッド）で例の1回を確かめた。seed 557 | `src/a557_no_interaction.py`、`src/a557_no_interaction.sql`、`src/a557_no_interaction_tsql.sql` |

## 主な結果
- **本当の効果**：店の割合で平均すると 5.67万円、施策した店で平均すると 3.07万円（施策した店は効きの小さい駅前に偏る）
- **2,000回の平均**：単純な差 11.94、層のダミーだけ（交互作用なし）3.68、交互作用あり→店の割合で平均 5.66、交互作用あり→施策した店で平均 3.10
- **交互作用なしの係数が使う重み**：駅前 65%・住宅地 23%・郊外 12%（店の割合はどれも33%）。重みの式で計算した値は回帰の係数と一致
- **95%信頼区間が「店の割合で平均した効果」を含んだ割合**：交互作用なし 19.5%、交互作用あり 95.8%
- **駅前で施策した割合を動かすと**（住宅地10%・郊外5%は固定）、交互作用なしの係数は 5%で 5.59、50%で 3.66、90%で 4.84。店の割合で平均した効果（5.67）とも、施策した店の効果（5.54→2.67）とも一致しない
- **施策した割合がどの層も同じ（20%）なら**、交互作用なしの係数 5.66 は店の割合で平均した効果 5.67 と一致
- **郊外の店の割合を 20%→70% に増やすと**、店の割合で平均した効果は 4.80→8.05、交互作用なしの係数は 3.25→5.62

## 確かめたこと
- 空のフォルダで流し直し、results が一致した
- 施策した割合が層で同じなら、交互作用なしの係数が店の割合で平均した効果と一致すること
- 例の1回で、交互作用なしの係数（3.2387）と、交互作用ありを店の割合で平均した値（5.1824）が、Python と DuckDB の SQL で一致すること（T-SQL 版は SQL Server では動かしていない：**未検証**）

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 557）。例の1回の600店は `results/example_stores.csv`

## 注意（言えないこと）
- 架空のデータ。層の数・効果・施策の割合・売上の振れは作成者が置いたもので、結果はこれで決まる
- 「交互作用を入れないと間違い」という話ではない。知りたいのが「どの平均か」を決めてから方法を選ぶ、という話
- 施策のしかたは層の中ではランダムと置いた。層の中でも効きそうな店を選んで施策していると、どの方法でも偏る
- 層が細かく、施策した店が少ない層があると、交互作用ありの推定はぶれが大きくなる
