# 1091 ときどき落ちるテストを再実行で通すと、本当の不具合を何%見逃すのか？（テストとバグ）

自動テストの中には、バグがなくても、ときどき落ちるテストがあります（待ち時間の取り方などで、同じコードでも結果が変わるもの）。落ちるたびにビルド（変更を取りこむたびにテストを流す1回分）が赤くなると困るので、「落ちたテストを1回か2回再実行し、1回でも通れば通ったことにする」という決まりがよく使われます。けれども、本当のバグの中にも、ときどきしかテストを落とさないものがあります。そうしたバグは、再実行すると通ってしまいます。**ここでは、作成者が乱数で作った架空のアプリの自動テスト1,500本（うち60本は、バグがなくてもときどき落ちるテスト）と本当のバグ（7割はいつもテストを落とし、3割はときどき落とす。落とす確率は作成者が置いたもの）で、再実行の回数（最大0〜3回）を変えたとき、本当のバグがあるのにビルドが通ってしまう割合（1回のビルド・リリースまでの10回のビルド）と、バグのないビルドが赤くなる割合を数えました。「再実行で通った」記録を数えると、ときどき落とすバグに気づけるかも数え、置き方を変えた27通りの確かめも行いました。**

例のアプリとテストは架空のもので、実在のテストの道具・開発のサービスの名前は使っていません。

関連する記事：同じ企画の 1089「見つかったバグが減ったのは、品質が上がったからか、テストが減ったからか？」は、テストの量と見つかる数の関係を、1090「カバレッジ80%のテストで、埋めこんだバグはどれだけ見つかるのか？」は、テストがバグの行を通っても見つからないことを扱います。911「検査で『不良』と出た品物は、本当に不良なのか？」は、工場の検査で「不良」と出た品物を測り直して当たりを上げる話で、この記事の再実行と同じ形です。ただし、911 の測り直しは誤検出を減らすほうを数えていて、この記事は、再実行でときどき落とす本当のバグも通ってしまうほうを数えます。914「全数検査なら、不良はゼロになるのか？」は、検査をくり返したとき見つけにくい不良が残ることを扱っています。

## 主な結果

### 再実行の回数ごとの見逃しと、バグのないビルドが赤くなる割合（`results/by_reruns.csv`）
| 再実行（最大） | 1回のビルドで見逃す（全部のバグ） | 1回のビルドで見逃す（ときどき落とすバグ） | 1回目に落ちたのに再実行で通った | 10回のビルドで一度も赤くならない（全部のバグ） | 同（ときどき落とすバグ） | バグのないビルドが赤くなる |
|---|---|---|---|---|---|---|
| 0回 | 17.81%（式 18%） | 60.26%（式 60%） | 0% | 1.94% | 6.58% | **95.53%** |
| **1回** | **24.12%**（式 24%） | **79.74%**（式 80%） | **49.17%**（式 50%） | **9.03%** | **29.86%** | **26.87%** |
| 2回 | 26.84%（式 26.57%） | 88.96%（式 88.57%） | 72.49%（式 71.43%） | 15.78% | 52.29% | 3.93% |
| 3回 | 28.02%（式 27.86%） | 92.58%（式 92.86%） | 81.37%（式 82.14%） | 20.16% | 66.64% | 0.6% |

- いつも落とすバグ（7割）は、再実行しても落ちるので見逃さない（作りどおり）。見逃しはすべて、ときどき落とすバグから来る
- **1回の再実行で、ときどき落とすバグが1回目に落としても、その49.17%は再実行で通った**。落とす確率 r のバグが再実行でも落ちる確率は r なので、通る割合は1−（r²の平均÷rの平均）＝50%（式どおり）。1回のビルドで見逃す割合（79.74%）も、式（1−r²の平均＝80%）どおり
- **リリースまでの10回のビルドで一度も赤くならなかったときどき落とすバグは、再実行なしで6.58%、1回で29.86%、2回で52.29%だった**。全部のバグのうちでは、1.94%・9.03%・15.78%。赤くなったビルドは、ときどき落とすバグで平均2.5717回目（再実行なし）、3.5167回目（1回）と遅くなった
- 一方、バグのないビルドが赤くなる割合は、再実行なしで95.53%（1回のビルドに平均2.9872本が落ちる）、1回で26.87%、2回で3.93%に下がった

### 落とす確率ごと（再実行1回、ときどき落とすバグ、`results/by_fail_prob_k1.csv`）
| 1回の実行で落とす確率 | 件数 | 1回のビルドで見逃す | 10回のビルドで一度も赤くならない | 10回で赤くならず、「再実行で通った」も2回未満 |
|---|---|---|---|---|
| 0〜0.2 | 1,047件 | 98.28% | **82.43%** | 59.6% |
| 0.2〜0.4 | 2,105件 | 89.5% | 38.15% | 12.3% |
| 0.4〜0.6 | 1,806件 | 75.97% | 7.53% | 1.16% |
| 0.6〜0.8 | 923件 | 54.39% | 0.54% | 0% |
| 0.8〜1 | 170件 | 22.35% | 0% | 0% |

- 落とす確率の低いバグほど通った。0.2以下のバグは、10回のビルドで82.43%が一度も赤くならなかった
- **10回で赤くならなかったときどき落とすバグのうち、49.97%は「再実行で通った」が同じテストで2回以上あった**。この記録まで見れば、ときどき落とすバグに気づけた割合は85.06%（再実行なしで赤くなった割合93.42%より低い）。ただし、バグのないときどき落ちるテストも、10回のビルドのうちに平均5.75本（60本のうち）が同じ記録を2回以上残した

### 確かめ：置き方27通り（`results/grid27.csv`）
| ときどき落とすバグの割合 | 落とす確率の平均 | 10回で一度も赤くならない（全部のバグ）：再実行なし | 1回 | 2回 |
|---|---|---|---|---|
| 10% | 0.6 | 0.15% | 0.85% | 2.38% |
| 30% | 0.4（基本） | 2.02% | 9.0% | 15.52% |
| 50% | 0.2 | 14.82% | 32.52% | 41.05% |

（表はときどき落ちるテスト60本の9通りのうち3通り。「30%・0.4」の行は基本の置き方と同じで、バグ6,000個の別の乱数で流したもの）

- **再実行1回で10回のビルドを通っても一度も赤くならないバグは、27通りで全部のバグの0.67〜33.58%**と、ときどき落とすバグの多さと落とす確率で大きく動いた。再実行なしとの差は+0.65〜+19.23ポイントで、27通りすべてで再実行のほうが見逃した
- バグのないビルドが赤くなる割合は、ときどき落ちるテストの本数で変わった。20本・60本・150本で、再実行なし64.13%・95.28%・99.92%、1回9.63%・25.05%・51.07%、2回1.24%・3.95%・9.49%（9通りずつの平均）
- 見逃しの割合は、ときどき落ちるテストの本数には左右されない（本当のバグのテストとは別に置いたため、作りどおり）

## 動かし方
```
pip install -r requirements.txt
cd src && python a1091_flaky_rerun.py
```
数秒で終わります。`data/bugs_k1_first2000.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダ（/tmp に `src` と `requirements.txt` だけを写したもの）でコードを流し直し、results・figures・data の8ファイルがバイト単位で一致した（cmp、約2秒）
- 1回のビルドで見逃す割合と、再実行で通った割合を、ベータ分布の式の値と並べた（`by_reruns.csv` の `_formula` 列）。差は最大1.06ポイントだった
- `data/bugs_k1_first2000.csv`（再実行1回のシミュレーションの最初の2,000個）の1回のビルドで見逃す割合（22.7%）が、20,000個の24.12%に近いことを確かめた
- 図3枚を開き、日本語・重なり・軸（棒は0から）を確かめた。図の値のラベルは results と同じ小数2けたにし、図3の縦軸の2行の見出しを1行に縮めた

## データ

## 注意（言えないこと）
- 架空のデータです。ときどき落とすバグの割合とその落とす確率、ときどき落ちるテストの本数と落ちる確率、リリースまでのビルドの回数は作成者が置いたもので、結果はこれで決まります。再実行1回で10回のビルドを通っても赤くならないバグは、置き方で全部のバグの0.67〜33.58%と動きました
- 1回のビルドの見逃しと、再実行で通る割合は、置いた分布の式どおりです。新しく数えたのは、10回のビルドを重ねたときと、記録を数えたときの値です
- 本当のバグは1本のテストだけを落とし、ほかのバグやときどき落ちるテストとは別々に置きました。ときどき落ちるテストの中に本当のバグが入ることは入れていません
- 赤くなったビルドを人が見て直すまでの時間、赤いビルドが多いと見なくなること（推測）は入れていません
- 再実行の決まりを使うべきかどうかは言えません。この記事は、再実行の回数で見逃しと赤いビルドがどう入れかわるかを数えただけです
