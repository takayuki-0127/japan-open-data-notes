# F22 明日の電力需要を当てる：予測コンペ形式でモデルを競わせる

note：明日の電力需要はどこまで当てられるか？ 東京エリアの1時間ごとの需要を6年半分予測すると、LightGBMの誤差は2.2%で「1週間前の同じ時刻」の4分の1。外れやすいのは天気より「お盆」だった（看板記事 F22）

## 問い

東京エリアの1時間ごとの電力需要を、前日の夜の時点で翌日24時間分予測するとき、どこまで当てられるか。単純な予測（1週間前・前日の同じ時刻）にどれだけ勝てるか。どんな日に外れるか。

## データ

| データ | 出典 | 使った範囲 |
|---|---|---|
| エリア需給実績（東京エリアの需要） | 東京電力パワーグリッド「でんき予報」 | 2016年4月〜2026年9月、1時間ごと（2024年1月までは1時間値の万kWh、2024年2月からは30分値の MW 平均を1時間に平均） |
| エリア需給実績（関西エリアの需要） | 関西電力送配電「でんき予報」 | 2024年4月〜2026年9月（頑健性チェック用） |
| 日ごとの気象（平均・最高・最低気温、平均湿度、降水量） | 気象庁「過去の気象データ検索」東京・大阪 | 2016年4月〜2026年9月 |
| 祝日 | Python の `holidays` パッケージ（内閣府の祝日に準拠） | |

`data/raw/` に 2026-10-27 に取得したファイル、`data/hourly_tokyo.csv`・`data/hourly_kansai.csv` は 02 で作る1時間ごとの表です。古い形式（2024年1月まで）と新しい形式（2024年2月から）のつなぎ目で、月平均の需要に段差がないことを確かめています（2024年1月 34.3GW、2月 34.4GW）。

## 予測の設定（使える情報）

- 予測を出すのは**予測する日 D の前日 D−1 の夜（24時）**。D の0〜23時の24時間分を一度に出す
- 需要は D−1 の23時まで分かっている → **24時間前・1週間前（168時間前）の同じ時刻**、前日の平均を使う
- 気温は **D の日平均・最高・最低気温**。本来は気象予報を使うところを、実測で代わりにしている（後述の頑健性チェックで、予報の誤差を足した場合も示す）
- 実際の電力市場（スポット市場）の入札は D−1 の午前10時なので、それよりも少し多くの情報を使っている

## 手法

| モデル | 中身 |
|---|---|
| 1週間前の同じ時刻 | 168時間前の需要をそのまま使う |
| 前日の同じ時刻 | 24時間前の需要をそのまま使う |
| 線形回帰（Ridge） | 時刻×曜日区分（平日・土曜・日祝）のダミー、時間帯ごとの冷房度日・暖房度日とその2乗、24時間前・1週間前の需要など |
| LightGBM | 時刻・曜日・祝日・年末年始/お盆/大型連休・季節・気温（平均・最高・最低、冷房度日・暖房度日、前日からの変化）・湿度・24時間前と1週間前の需要・前日の平均など23個。木900本・葉63 |

- **時系列の交差検証（拡張ウィンドウ）**：2020年度〜2025年度と2026年度上期の7つの期間について、それぞれ**その期間より前のデータだけで学習**して予測（学習は2016年4月から）
- **評価**：1時間ごとの平均絶対誤差率（MAPE）、1日のピーク（最大の1時間）の MAPE、平均絶対誤差（MW）、誤差が5%を超えた時間の割合
- **誤差分析**：日ごとの MAPE を出し、外れた日を種類（お盆の時期・年末年始・大型連休・祝日とその前後・猛暑・気温の急変・大雨）に分けて数える
- **SHAP**：2026年度上期のモデルで、4,000時間分の SHAP 値を計算

## 主な結果

| 2020年4月〜2026年9月 | MAPE | 平均絶対誤差 | ピークの MAPE | 誤差5%超の時間 |
|---|---|---|---|---|
| 1週間前の同じ時刻 | 8.17% | 2,698 MW | 9.43% | 55.0% |
| 前日の同じ時刻 | 6.66% | 2,196 MW | 7.73% | 46.9% |
| 線形回帰（Ridge） | 3.63% | 1,166 MW | 3.30% | 25.9% |
| **LightGBM** | **2.22%** | **725 MW** | **2.33%** | **8.8%** |

1. **LightGBM の誤差は2.2%で、「1週間前の同じ時刻」の約4分の1、線形回帰の約6割。** 年度ごとに見ても 2.06〜2.51% で、いちばん大きいのはコロナの2020年度。
2. **気温と需要は U 字。** 平日の日平均気温が16〜20℃のときに需要がいちばん少なく（日平均 28.6GW）、30〜32℃で 41.9GW、0℃以下で 44.1GW。同じ15〜20℃の平日でも、2016〜19年の 29.8GW から 2023〜26年は 27.7GW と7%下がっていて、長期の流れ（年）の特徴量も効いている。
3. **外れやすいのは天気より暦。** 日ごとの MAPE の中央値は 1.97%、5%を超えた日は 2,374日中74日。誤差の大きい100日のうち17日は「お盆の時期（8/10〜8/20）」で、全日数に占める割合（3.2%）の5倍。前日から日平均気温が5℃以上変わった日（2.1% → 9%）、年末年始（2.8% → 8%）も多い。猛暑の日（9.3% → 8%）や大雨の日は、ほかの日と同じくらいしか外れていない。
4. **いちばん外れた日は 2025年8月12日（火）。** 山の日（11日）の翌日で、実績の日平均 31.9GW に対して予測は 35.3GW（+10%）。多くの職場がお盆休みに入っていたが、モデルは「平日」として予測した。
5. **SHAP で効いていたのは「24時間前の需要」（平均 3,405MW）、次いで時刻・1週間前の需要・曜日区分・最高気温。** ただし気温を外すと誤差は 4.4% に倍増する。24時間前の需要が「昨日の気温」の情報も含んでいるため、SHAP では気温の寄与が小さく見える。

## 頑健性チェック（LightGBM の MAPE、東京は2020年4月〜2026年9月）

| 設定 | MAPE |
|---|---|
| 基本（2016年度から拡張ウィンドウ） | 2.22% |
| 学習を直近3年に限る | 2.37% |
| お盆・年末年始を広めにとり、休みの前後の特徴を足す | 2.21%（お盆・年末年始の日だけでは 3.19% → 3.13%） |
| 過去の需要（ラグ）を使わない | 2.91% |
| 気温・湿度を使わない | 4.39% |
| 予測に使う気温に誤差を足す σ=1℃ / 2℃ / 3℃（3回の平均） | 2.67% / 3.40% / 4.28% |
| 関西エリア（2024年4月〜2025年9月で学習、2025年10月〜2026年9月で評価） | LightGBM 2.69%、線形回帰 3.57%、1週間前 8.30% |
| 東京を関西と同じ短い学習期間にした場合 | LightGBM 2.72% |

- 学習期間を長くとるほうが良く、関西でも同じ順位・ほぼ同じ精度（短い学習期間の東京とほぼ同じ）になった
- 気温の予報の誤差は、翌日の最高気温でおよそ1〜2℃。実際の予報を使うと、誤差は 2.7〜3.4% 程度まで増えると考えられる
- 休みの前後の特徴を足しても、お盆の誤差はあまり減らない。「その年のお盆に何日休む職場が多いか」はカレンダーだけでは分からないため

## 言えないこと

- 気温は実測で代わりにしているので、実際の予報を使う運用での精度より良く出ている（予報の誤差を足すと 2.7〜4.3%）
- 予測する日の前日24時までの需要を使っている。実際の入札（前日10時）では、前日の午後以降の需要はまだ分からない
- 東京エリア全体の需要で、家庭・業務・産業の内訳や、太陽光の自家消費の影響は分けられない
- 気象は東京（大手町）1地点の日ごとの値。関東全体の気温や1時間ごとの気温を使えば、もっと当たる可能性がある

## 動かし方

```
pip install -r requirements.txt
cd src
python 01_取得.py        # data/raw/ を取り直す（置いてあるファイルを使うなら不要）
python 02_整形.py        # data/hourly_tokyo.csv・hourly_kansai.csv
python 03_分析.py        # results/metrics.csv・predictions.csv.gz・daily_errors.csv・error_by_category.csv・shap_importance.csv（約3分）
python 03b_頑健性.py     # results/robustness*.csv（約7分）
python 04_図.py          # figures/
```

乱数の種は 42 に固定しています。`results/_shap_values.npy`・`_shap_X.csv` は 03 で作り直せるので置いていません。
