# 675 DISTINCT で重複を消すと、本当に2回あった同じ内容の取引は何件消えるのか（実務の型）

売上明細を取り込むと、同じ行が2回入ることがあります。これを `SELECT DISTINCT` で消すと、取り込みの重複と一緒に、本当に2回あった同じ内容の取引（同じ店・同じ日・同じ品目・同じ数量・同じ金額）も1件にまとめてしまいます。消える量は、DISTINCT に入れる列、特に時刻をどこまで細かく持つかで変わります。**ここでは、作成者が乱数で作った架空の店10店・60日・約5.5万件の売上明細に、取り込みの重複を2%混ぜ、3通りの消し方で消えた本当の取引の数と売上の差を比べました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A675 | DISTINCT で、本当の取引はどれだけ消えるか | 架空の10店×60日、1日の取引はポアソン分布（平均80件）、品目30（実在の商品ではない）。安い品目ほど同じ人が90秒以内に同じものをもう一度買いやすい。取り込みの重複は取引の2%。消し方は D1＝DISTINCT（時刻は分まで）、D2＝DISTINCT（時刻は秒まで）、T＝取引番号で1行に。seed 675。3通りとも DuckDB の SQL でも出して一致を確認 | `src/a675_distinct.py`、`src/02_distinct_duckdb.sql`、`src/01_distinct_tsql.sql` |

## 主な結果
- 本当の取引は54,903件、売上は34,035,450円。そのうち直前と同じ内容の買い直しが6,947件（12.65%）。取り込みの重複は1,098件
- 重複を消さないと、売上は本当より **+1.99%**
- **DISTINCT（時刻は分まで）は、取り込みの重複1,098件と一緒に本当の取引2,363件も消し、売上は本当より −3.20%**。消えた2,363件のうち2,262件は買い直し、101件は別の人がたまたま同じ分に同じものを買ったもの
- 分までの DISTINCT で消えた本当の売上の割合（価格帯ごと）は、300円以下の品目で5.75%、301〜600円で3.71%、601〜1,200円で2.27%、1,201円以上で1.22%。安い品目ほど多く消える
- DISTINCT（時刻は秒まで）で消えた本当の取引は1件（−0.002%）。取引番号で消すと0件で、売上は本当と一致
- 買い直しのうち、前の取引と同じ分に入ったのは32.6%

## 動かし方
```
pip install -r requirements.txt
cd src && python a675_distinct.py
```
十数秒で終わります。`data/sales_lines.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 3通りの消し方の件数と売上が、Python と DuckDB の SQL で一致すること
- 取引番号で消した結果が、作ったときの本当の取引の件数・売上と一致すること

## データ
- `data/sales_lines.csv`：架空の売上明細（txn_id・store・date・minute・time・item_name・qty・amount）。取り込みの重複は同じ txn_id で2行ある
- 本当の取引と買い直しの区別は、データを作るときの情報から数えた（実際のデータでは分からない）

## 注意（言えないこと）
- 架空のデータ。買い直しの起きやすさと時間の間隔は作成者が置いたもので、消える量はこれで決まる
- 秒までの DISTINCT がほぼ正しかったのは、この設定で同じ秒に同じ内容の取引がほとんどないため。レジや取り込みの仕様によっては秒でも重なる
- 取引番号がない、または取り込みのたびに番号が振り直されるデータでは、T の方法は使えない
- T-SQL 版は未検証
