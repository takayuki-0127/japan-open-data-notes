# 641 整数どうしの割り算で割合を出すと、何%の行が0になるのか（実務の型）

SQL Server では、int の列どうしを割ると小数点以下が切り捨てられます（`3 / 40` は 0）。購入率や返品率のような割合をそのまま書くと、ほとんどが0になり、100を掛けてから割っても % の小数点以下が消えます。**ここでは、架空の300店の来店数・購入数・返品数で、購入率と返品率を「整数どうしの割り算」「100を掛けてから整数で割る」「100.0 を掛けて小数で割る（正しい）」の3通りで出し、0になる店・ずれの大きさ・順位の入れ替わりを数えました。** DuckDB では `//` で SQL Server の整数の割り算を再現しています。数字は置いた件数と率で決まります。

## 主な結果
- **整数どうしの割り算（r1）**：購入率は300店すべてが0（購入が来店より少ないので、割合は必ず1未満）
- **100を掛けてから整数で割る（r2）**：
  - 購入率（平均8%前後）では0になる店はなかったが、小数点以下が切り捨てられ、店の平均は8.28%から7.76%（−0.52ポイント、−7.2%）
  - 返品率（平均2.5%前後）では、本当は0でない275店のうち13.5%（37店）が0になった。店の平均は2.55%から2.12%（−17%）
  - 正しい返品率が1%未満の店はすべて0、1〜2%の店は平均27%、5%以上の店は6%小さく出た
- 切り捨てで同じ値の店が増え、購入率で298店、返品率で297店が、ほかの店と同じ値になった。購入率の上位10店を取ると、同点で15店が並んだ
- 全体の率を合計どうしで出しても、購入率 8.27% → 8、返品率 2.47% → 2 になった

## 注意（言えないこと）
- 架空のデータ。件数と率は作成者が置いたもので、0になる店の割合は率の大きさで決まる
- SQL Server の int / int の動きは、DuckDB の `//` で再現しただけで、SQL Server では動かしていない（T-SQL 版は未検証）
- 負の数の割り算（0に向かって切り捨てるか、小さい方へ切り捨てるか）は扱っていない
