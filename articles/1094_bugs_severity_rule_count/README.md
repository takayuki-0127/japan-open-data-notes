# 1094 深刻度の分け方で、「重大なバグ」の件数はどれだけ変わるのか？（テストとバグ）

見つかったバグには、深刻度（どれだけ困るか）を付けて、「重大なバグが今月◯件」と報告することがよくあります。けれども、「重大」の分け方は1つではありません。止まり方（機能が使えない・データが壊れる など）で分ける、影響を受ける利用者の割合で分ける、両方を組み合わせる、などがあり、同じバグでも分け方で「重大」に入ったり入らなかったりします。また、利用者の割合や止まり方は、バグを記録する人が見積もって付けるので、見積もりのぶれも入ります。**ここでは、作成者が乱数で作った架空のアプリの1か月分のバグ（平均400件。1件ずつの本当の利用者の割合と止まり方、記録する人の見積もりのぶれを作成者が置いたもの）で、4つの分け方で「重大」の件数と顔ぶれがどれだけ違うか、見積もった値で分けると本当の値で分けたときより何倍になるか、途中で分け方を変えると件数がどう動くかを数えました。利用者の割合の散らばり・止まり方の内わけ・見積もりのぶれを変えた27通りの確かめも行いました。**

例のアプリは架空のもので、4つの分け方も作成者が置いたものです。実在の会社や開発の現場の決まりを写したものではありません。

関連する記事：915「検査員によって合否が違うとき、何を数えればよいのか？」は、人の目で合否を付けるときの判定のそろい方を、809「星3.9と4.0の境目で、選ばれ方はどれだけ変わるのか？」は、境目のすぐ下とすぐ上で扱いが大きく変わることを扱います。この記事は、ソフトウェアのバグの深刻度で、分け方と見積もりのぶれが「重大」の件数をどれだけ動かすかに絞ります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A1094 | 「重大なバグ」の件数は、分け方でどれだけ違うか。記録する人の見積もりのぶれで、どれだけ増えるか（減るか）。途中で分け方を変えると、どう見えるか | 架空のアプリの1か月分のバグ（平均400件の件数の分布から引く）。1件ずつ、影響を受ける利用者の割合（中央1%、対数の標準偏差1.5、100%で打ち切り）と止まり方（見た目だけ35%・回り道できる35%・機能が使えない22%・データが壊れる8%）を置いた。「重大」の分け方は R1：止まり方が「機能が使えない」以上、R2：利用者の割合10%以上、R3：「機能が使えない」以上かつ利用者1%以上、R4：「データが壊れる」、または「機能が使えない」かつ利用者10%以上、の4つ。記録する人は、利用者の割合を本当の値×ぶれ（対数の標準偏差0.7）で見積もり、止まり方を15%の確率で1段上か下にずらす。同じバグを別々の2人が見積もったときに「重大」がそろった割合（どちらかが重大とした中で、両方が重大とした割合）も数えた。基本の置き方で400か月。12か月の例では、6か月目までR3、7か月目からR1で数えた。確かめに、利用者の割合の散らばり（1.0・1.5・2.0）×止まり方の内わけ（軽め・基本・重め）×見積もりのぶれ（なし・基本・大きい（対数の標準偏差1.2、ずらす確率30%））の27通りを各150か月。seed 1094 | `src/a1094_severity_rules.py` |

## 主な結果

### 同じ1か月400件（`data/bugs_one_month.csv`）
| 分け方 | 本当の値で分けた「重大」 | 見積もった値で分けた「重大」 |
|---|---|---|
| R1 止まり方が「機能が使えない」以上 | 117件 | 123件 |
| R2 利用者の割合10%以上 | 28件 | 29件 |
| R3 「機能が使えない」以上 かつ 利用者1%以上 | 56件 | 54件 |
| R4 「データが壊れる」、または「機能が使えない」かつ利用者10%以上 | 27件 | 32件 |

- **同じ400件でも、「重大」は分け方で27〜117件（最多÷最少4.33倍）だった**
- どれかの分け方で「重大」に入ったのは137件、4つすべてで「重大」だったのは8件（**5.84%**）だった
- 2つの分け方の顔ぶれの重なり（両方で重大÷どちらかで重大）は、6つの組でいちばん小さいのがR1とR2の0.0584、いちばん大きいのがR1とR3の0.4786だった（`results/overlap_one_month.csv`）
- R2の境目を動かすと、利用者の割合5%以上は57件、10%以上は28件、20%以上は6件だった。5〜20%の間に51件あり、境目の近くに多くのバグがあった

### 基本の置き方で400か月（`results/rules_base.csv`）
| 分け方 | 本当の値で分けた「重大」（平均） | 見積もった値で分けた「重大」（平均） | 見積もり÷本当 | 2人の「重大」がそろった割合 | 見積もりで「重大」としたうち本当に重大 |
|---|---|---|---|---|---|
| R1 | 119.81件 | 123.89件 | 1.03倍 | 77.39% | 91.44% |
| R2 | 24.85件 | 33.05件 | **1.33倍** | **39.22%** | 57.65% |
| R3 | 59.89件 | 61.86件 | 1.03倍 | 54.37% | 78.94% |
| R4 | 37.65件 | 43.5件 | 1.16倍 | 59.13% | 78.11% |

- R2（利用者の割合だけで分ける）では、見積もった値で分けると平均で本当の1.33倍に増えた。見積もりのぶれは上にも下にも同じ大きさに置いたが、境目（10%）のすぐ下には上よりずっと多くのバグがあるので、下から上がる件数のほうが多くなる
- R2では、同じバグを別々の2人が見積もると、どちらかが「重大」としたうち、両方が「重大」としたのは39.22%だった
- 4つすべてで「重大」だったのは、どれかで「重大」だったうちの平均5.39%だった

### 途中で分け方を変えると（12か月、本当のバグの出方は毎月同じ、`results/months_rule_change.csv`）
| | 値 |
|---|---|
| 1〜6か月目（R3）の平均 | 66件 |
| 7〜12か月目（R1）の平均 | 128件 |
| 後÷前 | **1.94倍** |
| R3のまま数えたときの月ごとの上下（400か月の10〜90%） | 52〜72件 |

- 本当のバグの出方は12か月とも同じに置いたが、分け方を変えた月から「重大」は1.94倍になった。R3のまま数えても、12か月の中の最多÷最少は1.7倍あった

### 確かめ：置き方27通り（各150か月、`results/grid.csv`）
- 4つの分け方の「重大」（本当の値で分けた平均）の最多÷最少は、**2.78〜42.19倍**だった。利用者の割合の散らばりを1.0にすると、利用者10%以上のバグがまれになり、R2の件数がとても小さくなって差が開いた
- 4つすべてで「重大」の割合は、どれかで「重大」のうち0.86〜10.88%だった
- 見積もりのぶれを置いた18通りすべてで、R2（1.1〜6.6倍）とR4（1.07〜1.45倍）の「重大」は本当より多く出た。R1・R3は、止まり方の内わけが重めのとき0.99〜1.01倍とほとんど動かず、軽めでは1.06〜1.15倍に増えた（軽めでは境目のすぐ下の「回り道できる」が境目の上より多く、1段ずらすと上がる件数のほうが多くなるため）
- 2人の「重大」がそろった割合は、見積もりのぶれを置いた18通りで、R1が56.62〜83.04%、R2が12.64〜54.61%、R3が29.81〜62.69%、R4が40.23〜65.63%だった

## 注意（言えないこと）
- 架空のデータです。利用者の割合と止まり方の分布、4つの分け方、見積もりのぶれは作成者が置いたもので、結果はこれで決まります。分け方による最多÷最少は、置き方で2.78〜42.19倍と大きく動きました
- 見積もりのぶれは、上にも下にも同じ大きさで、記録する人どうしで癖の違いはないと置きました。重く付けやすい人・軽く付けやすい人の違いは入れていません
- どの分け方が正しいかは、この記事からは言えません。4つの分け方は、どれも「重大」の決め方の例として作成者が置いたものです
- 実在の会社・開発の現場のバグの数や深刻度の決まりを表すものではありません
