# 754 欠品率を「欠品した SKU の数」で数えるか「売上の重み」で数えるかで、店の比べ方はどれだけ変わるのか（実務の型・SQL の集計）

欠品率は「欠品した SKU×日 ÷ 全 SKU×日」で出すことが多いです。この数え方では、1日に何十個も売れる売れ筋も、月に数個の死に筋も同じ1件です。売上で重みをつけると、売れ筋の欠品が大きく効きます。**ここでは、架空の20店×300SKU×90日の在庫（売れ方の偏った SKU、店によって売れ筋が欠けやすいか死に筋が欠けやすいかが違う）で、欠品率を3通りに出し、店の順位がどれだけ入れ替わるかを数えました。** 店ごとの欠けやすさは作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A754 | 欠品率の数え方で、店の順位はどれだけ変わるか | A 欠品した SKU×日 ÷ 全 SKU×日、B 欠品の日に売れたはずの数 ÷ 売れたはずの数の合計（売上の重み）、C 期間中に1日でも欠品した SKU の割合。DuckDB（1スレッド）と pandas で一致を確認。seed 754 | `src/a754_stockout.py`、`src/02_stockout_duckdb.sql`、`src/01_stockout_tsql.sql`（未検証） |

## 主な結果
- **売れ方の偏り**：上位10%の SKU で、売れたはずの数の45.8%を占める
- **全店ではあまり違わない**：A 6.30%、B 7.45%
- **店ごとでは大きく違う**：A は3.6〜9.8%、B は1.8〜22.4%。店の順位の相関（スピアマン）は0.38
- **順位の入れ替わり**：20店のうち9店が5位以上動き、いちばん動いた店は13位。欠品率の高い5店のうち、A と B で同じ店は2店だけ
- **例**：店03は A では高いほうから4位（8.8%）だが、B では17位（2.5%）。死に筋ばかり欠けていた。店09は A では20位（3.6%）、B では10位（5.7%）。数は少ないが売れ筋が欠けていた

## 動かし方
```
pip install -r requirements.txt
cd src && python a754_stockout.py
```
十秒ほどで終わります。`data/` に SKU の売れ方と店×SKU の欠品日数を、`results/store_rates.csv` に店ごとの3つの欠品率と順位を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 3つの欠品率が、DuckDB と pandas で一致した
- T-SQL 版（`01_stockout_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/skus.csv`：sku・daily_rate（1日に売れる数の見込み）。`data/stockout_days.csv`：store_id・sku・stockout_days（90日のうち欠品した日数）
- 仮定：売れ方は対数正規分布。欠品は「在庫あり→欠品」になる確率（店と SKU で違う）と、欠品から戻る確率（1日35%）で決まる。日次の在庫（54万行）はファイルに置かず、コードの中で作る

## 注意（言えないこと）
- 架空のデータ。順位の入れ替わりの大きさは、置いた店ごとの欠けやすさの違いで決まる
- B は「欠品の日も、いつもどおり売れたはず」とした。欠品の日の本当の需要はふつう見えないので、実際には見込みが要る（欠品の日の需要の見積もりは別の問題）
- どの数え方がよいかは目的による。棚の管理なら A、売上の取りこぼしなら B が近い（推測）
- 実在の店の数字ではない
