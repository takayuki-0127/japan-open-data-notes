# 473 注文全体への値引きを明細にどう割り振るかで、商品別の粗利はどれだけ変わるのか（実務の型）

架空の注文（6万件、明細168,128行）で、注文全体にかかった値引き（クーポン、送料の免除）を明細に割り振る方法を4通り試し、商品別・部門別の粗利と、端数の扱いによる合計のずれを測ったフォルダです。集計の置き方の比べであり、会計や税務の処理としてどれが正しいかは扱っていません。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A473 | 割り振り方で、赤字に見える商品の数や部門の粗利率はどれだけ変わるか。端数の扱いで、明細の合計は値引きの額と合うか | 金額の割合／数量の割合／いちばん高い明細に寄せる／割り振らない（別の行に置く）の4通り。端数は四捨五入・切り捨て・切り上げ・切り捨てて余りを戻す、の4通り。SQL は DuckDB で実行し、pandas の値と一致を確かめる | `src/a473_alloc.py`、`src/01_allocate_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
基本の場面：320商品・8部門、売上1.95億円、値引きは1,679万円（売上の8.6%。送料の免除を含む）、値引きのある注文は49.6%

| 割り振り方 | 赤字になった商品（320のうち） | 原価を下回った明細 |
|---|---|---|
| 金額の割合 | 19 | 14.4% |
| 数量の割合 | 71 | 25.9% |
| いちばん高い明細に寄せる | 8 | 7.0% |
| 割り振らない（別の行） | 0 | 0% |

- 粗利の合計は、割り振る3つの方法でまったく同じ（4,588万円）。変わるのは、どの商品・部門に付くかだけ
- 割り振る3つの方法のあいだで、黒字か赤字かが分かれた商品は63。金額の割合と比べた粗利率の差は、数量の割合で中央値3.8pt（上位1割は15.4pt以上、5pt超が122商品）、高い明細に寄せる方法で中央値2.5pt
- 部門の粗利率（金額／数量／高い明細／割り振らない）：飲料 9.3%／−3.8%／13.5%／17.5%、日用品 4.2%／−1.8%／7.1%／12.4%。部門ごとの幅は4.0〜17.3pt。4つの部門で順位が入れ替わる
- 数量の割合では、値引きが明細の金額を超えてマイナスになる明細が3,357行（高い明細に寄せる方法で767行、金額の割合で0行）
- **端数**（金額の割合で割り振るとき、値引きのある注文のうち明細の合計が値引きの額と合わない割合）：四捨五入18.2%（明細が2行以上の注文では21.9%）で差の合計+36円、切り捨て65.6%で−36,101円、切り上げ65.6%で+36,293円、切り捨てて余りを大きい順に戻すと0
- 値引きの大きさ（売上の5.6%／8.5%／13.2%）で、数量の割合での赤字の商品は30／72／124

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- SQL（DuckDB）で出した割り振りの額が、pandas で出した値と一致する（コード内の assert）
- 割り振る3つの方法で、粗利の合計が一致する

## データ
- `data/products.csv`：架空の商品（単価・原価・部門）
- `data/orders_sample.csv`、`data/order_lines_sample.csv`：架空の注文と明細の一部（全体はコードで作り直す。seed 473）

## 注意（言えないこと）
- 架空のデータ。数は、値引きの大きさ、単価と原価の置き方、1つの注文に入る商品の組み合わせで決まる
- どの割り振り方が正しいかは決めていない。値引きの目的（特定の商品のためか、注文全体のためか）によって合う方法が違う
- 会計や税務の処理は扱っていない。ここで比べたのは、分析用の粗利の表での置き方だけ
- 商品ごとの値引き（明細に最初から付いている値引き）は対象外
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
