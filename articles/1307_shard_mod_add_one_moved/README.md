# 1307 「番号を台数で割った余り」で置く台を決める振り分けで1台足すと、置き場所が変わるデータは全体の何割になるのか？（データの振り分け）

データを何台かに分けて置くとき、いちばん簡単な決め方は「番号を台数で割った余り」の台に置くことです。番号23のデータは、10台なら余り3の台に置きます。この決め方は台数が変わらないうちは均等に分かれますが、1台足すと割る数が変わるため、番号23は11台では余り1の台に移ります。新しい台に移す分だけ動かせば足りるのに、もとの台どうしのあいだでも大量の入れかえが起きます。**ここでは、作成者が置いた架空のアプリのデータ1万件（番号は1〜10億のでたらめな整数）で、10台から11台にしたときに置く台が変わる件数の割合と、その内訳（新しい台へ・もとの台どうしのあいだ）を数え、必要な最小の量（新しい台に入る分）と比べました。もとの台数を2〜100台に変えて1台足す・減らす場合、10台から何台か足す場合、1台ずつ20台まで足したときの延べの量でも確かめました。実機では測らず、すべてシミュレーションです。**

例のアプリ・データ・台は架空のもので、実在のデータベースや機械の振り分け方を表すものではありません。台数・費用の見込みの助言はしていません。

関連する記事：1305「1万件のデータを乱数で10台に振り分けると、いちばん多い1台の件数は平均の何倍になるのか？」は、置く台をでたらめに決めたときの1台ごとの件数の偏りを扱っています。1306「データの件数を変えずに、振り分ける台数を10台から100台に増やすと、いちばん多い1台と平均の比はどう広がるのか？」は、台数を増やしたときの偏りの広がりを扱っています。1308「動くデータを少なくする振り分け（番号を輪の上に並べて、時計回りに次の台へ置く形）で1台足すと、動く量は少なくなっても、台ごとの受け持ちの量はどれだけばらつくのか？」は、動くデータを少なくする「輪の上に並べる振り分け」で1台足したとき、動く量は少なくても、台ごとの受け持ちが大きくばらつくことを扱っています。この記事は、件数の偏りではなく、台数を変えたときに置き場所が変わるデータの量に絞ります。

## 主な結果

### 10台→11台（200回、`results/a1307_main.json` の base_10_to_11）
| 内訳 | 数えた割合（平均） | 式どおりの値 |
|---|---|---|
| 同じ台のまま | 9.12% | 9.09% |
| 新しい11台目へ移る | 9.08% | 9.09% |
| もとの10台のあいだで移る | 81.8% | 81.82% |
| **置く台が変わる（合計）** | **90.88%**（10〜90%：90.47〜91.28%） | 90.91% |

- **1台足しただけで、全体の90.88%のデータの置き場所が変わった**。式どおりの10÷11＝90.91%に近い値
- 新しい台に入る9.08%だけ動かせば台数は11台にそろうので、**動いた量は必要な最小の10.009倍**（式どおりなら10倍）だった。動いた分の大半（81.8%）は、もとの10台どうしの入れかえだった（図1）
- 番号を1〜1万の連番にすると、動いた割合は90.91%、新しい台へ9.09%、もとの台どうしで81.82%と、式どおりの値にそのまま一致した（作りどおり）
- 1組目の番号では、動いたのは90.4%で、台ごとの行き来は `results/set1_flow_10_to_11.csv` に置いた

### 確かめ：もとの台数を変えて1台足す・減らす（各200回、`results/by_servers.csv`）
| もとの台数 | 1台足す：動いた割合 | 必要な最小の何倍 | 1台減らす：動いた割合 | 必要な最小の何倍 |
|---|---|---|---|---|
| 2台 | 66.65% | 1.999倍 | － | － |
| 3台 | 74.99% | 2.999倍 | 66.65% | 1.999倍 |
| 5台 | 83.34% | 4.988倍 | 80.0% | 3.998倍 |
| 10台 | 90.88% | 10.009倍 | 90.01% | 8.996倍 |
| 20台 | 95.23% | 20.012倍 | 95.03% | 19.002倍 |
| 50台 | 98.05% | 49.931倍 | 98.02% | 49.437倍 |
| 100台 | 99.0% | 100.827倍 | 98.99% | 99.565倍 |

- **1台足すと、もとの台数2〜100台で66.65〜99.0%が動いた**。必要な最小の量に比べると1.999〜100.827倍で、ほぼもとの台数の倍数（式どおり）。1台減らす場合も、もとの台数−1倍に近かった
- 13通りすべてで、数えた割合と式の値の差は0.03ポイント以内だった

### 確かめ：10台から何台か足す（各200回、`results/by_added.csv`）
| 台数 | 動いた割合 | 必要な最小の割合 | 何倍 |
|---|---|---|---|
| 10→11台 | 90.88% | 9.08% | 10.009倍 |
| 10→12台 | 83.34% | 16.67% | 4.999倍 |
| 10→15台 | 66.67% | 33.32% | 2.001倍 |
| 10→20台 | 49.97% | 49.97% | 1.0倍 |
| 10→30台 | 66.67% | 66.67% | 1.0倍 |

- 5通りのうち、20台・30台のようにもとの台数の何倍かにしたときは、動いた割合が必要な最小と同じになった（作りどおり：番号を20で割った余りが10未満なら、10で割った余りと同じになる）（図3）

### 確かめ：10台から1台ずつ20台まで足す（各200回、`results/one_by_one_10_to_20.csv`・`results/a1307_main.json` の one_by_one_10_to_20）
- **1台ずつ10回足すと、動いた量は延べで全体の933.01%（式どおりなら933.12%）だった**。10回とも新しい台へ移す分だけなら延べ66.89%で済み、一度に20台にすれば49.97%だった

## 注意（言えないこと）
- 架空のデータです。番号はでたらめな整数と置きました。主な値は、割った余りで決める決まりからの式どおりで、でたらめな番号と連番でほぼ同じでした。番号が特定の数の倍数ばかりのような癖のある付け方は試していません
- 1件の大きさはどれも同じと置き、動く「件数」を数えました。動かすのにかかる時間や手間は数えていません
- 動く量を少なくする別の振り分け方（輪の上に並べる振り分け）は、この記事では扱っていません（1308 で扱っています）
- 実在のデータベース・機械を表すものではなく、どの振り分け方を使うべきか、台数をどう増やすべきかの助言でもありません
