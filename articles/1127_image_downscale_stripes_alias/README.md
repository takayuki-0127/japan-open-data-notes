# 1127 画素を間引いて縮小すると、細い縞はどんな模様に化けるのか？（画像と色）

画像を小さくするいちばん簡単な方法は、何画素かおきに1画素だけを取る「間引き」です。けれども、縮めた画像の画素の数の半分より細かい縞は、縮めた画像では描けません。間引くと、そうした細い縞は消えずに、元にはなかった粗い縞や無地に化けます。布の細かい縞やすだれの写真を縮めたときに出る、波のような模様がこれです。**ここでは、作成者が式で描いた架空の縞の画像（布の縞に見立てた、横2,000画素の白黒の縞）を、①間引く、②4×4画素ずつ平均する、③ぼかしてから間引く、の3つで1/4（横500画素）に縮め、縮めた画像に見える縞の細かさとくっきり度を、縞の細かさ10〜1,000組で数えました。縮める割合（1/2・1/3・1/4・1/8）とぼかしの強さを変えた20通りでも確かめました。**

例の縞は作成者が式と乱数で作ったもので、実在の写真・商品・画像ソフトを表すものではありません。くっきり度10%を「縞が見える」目安としたのは作成者が置いたもので、人に見せて確かめた実験ではありません。

関連する記事：同じ企画の 1125「画素の数を縦横2倍にすると、細かさは何倍になったと言えるのか？」は、写す側で、見分けられる縞が画素の数の半分までになることを数えています。1126「色の値をそのまま平均して混ぜた色は、なぜ暗く濁って見えるのか？」は、縮めるときの平均を色の値で取るか光の量で取るかで明るさが変わることを扱っています。40冊目の 1063「一定の間隔でのぞく測り方で、遅い場所の順位は入れかわるのか？」は、のぞく間隔が処理の周期と合うと同じ場所ばかりをのぞく話で、一定の間隔で取り出すと周期が化けるという同じ仕組みを、処理の時間で扱っています。20冊目の 819「移動平均の幅で、山と谷はどれだけ動くのか？」は、平均する幅で細かい山と谷が消えたり動いたりする話を、毎日の数字で扱っています。1135「小さい画像を拡大して画素の数を増やすと、失われた細かさは戻るのか？」は、こうして縮めた画像を拡大して戻したとき、消えた縞や化けた縞がどうなるかを数えています。この記事は縮める側で何が起きるかに絞ります。

## 主な結果

### 1/4に縮めたときの、縮め方ごとの結果（`results/by_method.csv`）
| 縮め方 | 偽の縞（くっきり度10%以上）が出た割合 | 偽の縞のくっきり度（平均／最大） | 残すべき縞のくっきり度（100組／200組／240組） |
|---|---|---|---|
| 間引く | **97.33%** | 0.969／1 | 1／1／1 |
| まとめて平均 | 78.67% | 0.2185／0.6282 | 0.9393／0.7694／0.6778 |
| ぼかしてから間引く | **12%** | 0.0289／0.2633 | 0.8209／**0.454**／0.3208 |

- **間引くと、250組より細かい縞は、ほぼすべて（97.33%）くっきり度を保ったまま粗い縞に化けた**。化けなかった2つ（500組・1,000組）は、縞が消えて無地になった
- 化けた縞の細かさは、式（500で割った余り r の min(r, 500−r)）と、無地になった2つを除いてすべて合った（式どおり）
- まとめて平均すると偽の縞は弱まったが、78.67%でくっきり度10%以上が残り、最大0.6282だった。ぼかしてから間引くと、偽の縞は12%まで減った
- **その代わり、残すべき縞も薄くなった**。200組の縞のくっきり度は、間引くと1、まとめて平均で0.7694、ぼかしてから間引くと0.454だった

### 細い縞が化けた例（`results/a1127_main.json` の examples）
| 元の縞 | 縮めた画像に見える縞 | くっきり度（間引く／まとめて平均／ぼかしてから間引く） |
|---|---|---|
| 300組 | 200組 | 1／0.5237／0.1692 |
| 480組 | 20組 | 1／0.0458／0.0106 |
| 700組 | 200組 | 1／0.2668／0.0001 |
| 900組 | 100組 | 1／0.1488／0 |

- 900組の細い縞は、間引くと100組の粗い縞になった。480組の縞は20組という、とても粗い波の模様になった
- **ちょうど500組（縮めた画素の数と同じ）の縞は、間引くと完全な無地（画像の中の明るさの散らばり0）になり、その明るさは、はじまりの位置と取る画素で0（真っ黒）〜1（真っ白）まで変わった**。2,000回のうち65.95%は、明るさが0.25未満か0.75より上だった。まとめて平均すると、いつも0.5だった

### 斜めの縞（`results/a1127_main.json` の slanted）
- 向き30度・170組の縞（400×400画素）を1/4に間引くと、向き−17.7度（右下がり）・49.34組の縞になった。細かさだけでなく、縞の向きも変わった

### 確かめ：縮める割合とぼかしの強さを変えると（20通り、`results/grid.csv`）
| 縮め方 | 偽の縞が出た割合（1/2・1/3・1/4・1/8） | 残すべき縞（限界の8割の細かさ）のくっきり度 |
|---|---|---|
| 間引く | 95.45〜100% | 1 |
| まとめて平均 | 59.09〜86% | 0.7599〜0.809 |
| ぼかし（幅は縮める割合の0.25倍） | 23.86〜98% | 0.8165〜0.8209 |
| ぼかし（0.5倍、基本） | 5.68〜36% | 0.4444〜0.454 |
| ぼかし（0.75倍） | 0% | 0.1612〜0.1692 |

- **どの縮める割合でも、間引くと、縮めた画像の限界より細かい縞の95.45%以上で偽の縞が出た**
- ぼかしを強くするほど偽の縞は減り、0.75倍では0%になったが、残すべき縞のくっきり度も0.1612〜0.1692まで下がった。偽の縞を消すことと、残すべき縞を残すことは、ぼかしの強さで入れかわった
- 偽の縞が出た割合は、同じぼかしでも縮める割合で動いた（0.5倍のぼかしで、1/2が36%、1/8が5.68%）。元の画像で描ける縞の細かさは、縮めた画像の限界の2倍（1/2）から8倍（1/8）までと幅が違い、偽の縞が残りやすい限界のすぐ上の縞の占める割合が違うため

## 注意（言えないこと）
- 架空のデータです。縞の形（白黒の波）、縮め方、ぼかしの形と幅、「見える」とみなす目安（10%）は作成者が置いたもので、結果はこれで決まります
- 間引いたあとの縞の細かさは、置いた式どおりの値です
- 実際の写真には、縞のほかにいろいろな細かさの模様がまざり、元の画像を写すときにも縞が化けることがあります（1125）。ここでは式で描いた縞だけを数えました
- 実在の画像ソフトの縮小の処理を表すものではなく、どの縮め方・ぼかしの強さを使うべきかも言えません。この記事は、縮め方で縞がどう化けるかを数えただけです
