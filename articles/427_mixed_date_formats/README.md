# 427 「2025/1/5」「R7.1.5」「20250105」が混ざった日付の列は、機械に読ませると何件が別の日になるのか（実務の型）

架空の入力2万件（日付の書き方10種類）を、3つの読み方で読み、正しい日付・エラー・黙って別の日になった行を数えたフォルダです。372（CSV を Excel で開く）・373（pandas の型の判定）は列全体の型を扱いました。ここでは、日付の書き方だけを扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A427 | 書き方の混ざった日付の列を読むと、何件がエラーになり、何件が黙って別の日になるか | ①そのまま読む（pandas の to_datetime、format="mixed"）②書式を1つに決めて読む ③書き方ごとに判定して読む（決まりを8段階で足す）。②は DuckDB の TRY_STRPTIME でも実行して一致を確かめる | `src/a427_dates.py`、`src/01_parse_dates_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
| 読み方 | 正しい | エラー | 黙って別の日 |
|---|---|---|---|
| ①そのまま読む | 13,739（68.7%） | 4,819（24.1%） | 1,442（7.2%） |
| ②書式を1つに決めて読む（年/月/日） | 6,080（30.4%） | 13,920（69.6%） | 0 |
| ③書き方ごとに判定して読む | 20,000（100%） | 0 | 0 |

- **①で別の日になった書き方**：「5/1/2025」（日/月/年）797件中283件（35.5%）、「25/1/5」（年が2桁）1,198件中1,159件（96.7%）。ほかの書き方は0件
- **ずれの大きさ**：日/月/年は中央値116日（すべて同じ年の中）、年が2桁は中央値2,914日（約8年）
- **①でエラーになった書き方**：「2025年1月5日」1,621件、「R7.1.5」1,399件、「令和7年1月5日」973件、表計算ソフトの通し番号826件（すべてエラー）
- **範囲の検査（2016〜2025年の外は怪しい）**：別の日になった1,442件のうち814件が見つかる（すべて年が2桁の行）。日/月/年の283件は0件
- **決まりを足したとき（読めない行／別の日になる行）**：年/月/日だけ 9,959／0 → ＋8桁の数字 7,992／0 → ＋漢字の年月日 6,371／0 → ＋和暦 3,999／0 → ＋年が後ろの書き方を数字だけで判定 2,024／283 → 入力元で月と日の順を決める 2,024／0 → ＋年が2桁 826／0 → ＋表計算ソフトの通し番号 0／0
- **DuckDB**：西暦の4つの書式を COALESCE で順に試すと、正しい13,629件・エラー6,371件・別の日0件
