# 474 Excel の表の空いている見出しを、下に埋めてよいのか（実務の型）

人が見るために作られた Excel の表には、結合セルや「上と同じなら省略」の見出しがあります。公開されている公的統計の Excel 24枚で、そういう行と列がどれくらいあるかを数え、正解の分かる架空の集計表で、読み方（そのまま／全部の列を下に埋める／列ごとに決める）による違いを測ったフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A474-1 | 公開されている Excel では、行の見出しを上の行に頼っている行、上の段の見出しが空の列がどれくらいあるか | 14ファイル・24枚のシートから「骨組み」（セルが数字・文字・空のどれか、左の8列と上の30行の文字、結合セルの範囲）だけを取り出し、機械的に数える | `src/a474_public.py`、`src/00_extract_skeleton.py` |
| A474-2 | そのまま読む／全部の列を下に埋める／列ごとに決める、で分類と合計はどれだけ違うか | 架空の集計表を openpyxl で Excel に書き出し、pandas で読んで正解と比べる。部門の中だけで埋める SQL を DuckDB で実行し、pandas と一致を確かめる | `src/a474_fictional.py`、`src/01_filldown_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
**公開されている Excel（24枚、数字の入っている行は合わせて2,210行）**
- その行にある文字だけでは、どの行か決まらない行（見出しが空、または同じ見出しが表の中に2回以上ある）：432行（19.5%）。24枚のうち12枚にあり、9枚では半分以上の行がそうだった
- 見出しの列に、上の行を見ないと埋まらない空きがある行：418行（18.9%）、11枚
- 下に埋めると、関係のない上の行の文字が入る行（左の列に自分の見出しがあり、右の列が空）：57行、5枚
- 列の見出しが2段以上あるシート：19枚（中央値3段、最大7段）。上の段の見出しが空になっている数字の列は、403列のうち197列（48.9%）、16枚
- 結合セルがあるシートは16枚（合わせて207か所）。表の途中に空行があるシートは6枚
- 行も列も、そのまま読んで困らないシートは4枚

**架空の集計表（明細167行、12部門。部門は縦に結合、商品区分は上と同じなら省略、地域は1割が本当に空、部門ごとに小計と空行、最後に合計、見出しは2段）**

| 読み方 | 部門が正しい | 商品区分が正しい | 地域が正しい | 売上の総合計（正解=100） | 部門別に集計した売上（正解=100） |
|---|---|---|---|---|---|
| ①そのまま読む | 7.2% | 30.5% | 100% | 300 | 7 |
| ②全部の列を下に埋める | 100% | 98.2% | 89.8% | 400 | 300 |
| ②' 空行を落としてから全部埋める | 100% | 98.2% | 89.8% | 300 | 200 |
| ②'' 空行と小計・合計も落としてから全部埋める | 100% | 98.2% | 89.8% | 100 | 100 |
| ③列ごとに決める | 100% | 100% | 100% | 100 | 100 |

- ①：部門が空の行が155行、商品区分が空の行が116行。部門別に集計すると、売上の7%しか部門に付かない。列の名前は「4月、5月、6月、4月.1、5月.1、6月.1」になり、売上と数量の区別が消える
- ②：全部の列を下に埋めると、本当に空だった地域17行（10.2%）に上の行の地域が入り、商品区分のない部門の3行に、前の部門の商品区分が入る。空行は小計の写しになる
- ②''：小計・合計を落としても、地域別の売上は東日本が+9.5%、西日本が+13.9%多く出る
- ③：部門は結合セルの範囲で埋める、商品区分は部門の中だけで埋める、地域は埋めない、小計・合計・空行は落とす
- 本当に空の割合を変えると（300回ずつ）、違う地域が入る行は、2%なら2.2%、10%なら10.0%、30%なら30.0%

## 動かし方
```
pip install -r requirements.txt
cd src && python a474_public.py && python a474_fictional.py     # 合わせて20秒ほど
```
`00_extract_skeleton.py` は、元の Excel から骨組みを取り出すときに使ったもの。取り出したあとの `data/public_excel_skeletons.json` を置いてあるので、動かす必要はない。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- 部門の中だけで埋める SQL（DuckDB）の結果が、pandas の結果と167行すべて一致する（コード内の assert）
- ③の読み方で、部門・商品区分・地域が正解と100%一致する

## データ
- `data/public_excel_skeletons.json`：公開されている Excel 24枚の骨組み。数値は入っていない
- `data/fictional_truth.csv`：架空の正解の表（seed 474）／`data/fictional_report.xlsx`：それを人が見る形にした Excel

## 注意（言えないこと）
- 24枚は、手元にあった公開の Excel から選んだもので、公的統計の全体を表す標本ではない。「公的統計の何%がこうだ」とは言えない
- 数え方は機械的。年が数字で書かれた見出しの行は数字の行として数えている、1枚あたり400行・60列までしか見ていない、など粗いところがある
- 元の表は人が読むための表として作られている。読みにくさを責めるものではない
- 架空の表での数字（7%、300 など）は、表の作り方で決まる。小計や空行のない表なら、合計のずれは出ない
- Excel の画面での操作（ジャンプ→空白セル→上のセルを参照、Power Query の「下方向へコピー」など）は試していない（未検証）。openpyxl で書き、pandas で読んだ結果
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
