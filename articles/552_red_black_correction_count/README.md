# 552 訂正を「取消（赤）＋再登録（黒）」で入れる伝票では、件数と金額をどう数えればよいのか（実務の型・訂正行の数え方）

伝票の訂正を、もとの伝票を打ち消す「赤」（金額はマイナス）と、正しい内容で入れ直す「黒」の2行で入れる作りでは、行をそのまま数えると件数も金額も多く出ます。**ここでは、架空の売上伝票（2025年、はじめの登録20,000件、そのうち1,600件を赤で取り消し、1,296件を黒で入れ直し、109件は黒をもう一度訂正）を作り、件数と金額を4通りで数えて、最後に有効な伝票だけを数えた値と比べました。** 訂正の起きやすさは作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A552 | 数え方で件数と金額がどれだけ多く出るか、月の金額を入力日で数えるともとの取引日とどれだけ違うか | N1 すべての行（金額はプラスの行）、N2 赤を除く（通常＋黒）、N3 全行を足す（件数は 通常＋黒−赤）、N4 最後に有効な伝票だけ（取り消されていない通常と黒）。月別は入力日の月ともとの取引日の月の比較。N4 を Python と SQL（DuckDB、1スレッド）で突き合わせ。seed 552 | `src/a552_red_black.py`、`src/02_red_black_duckdb.sql`、`src/01_red_black_tsql.sql`（未検証） |

## 主な結果
- **行の内訳**：22,896行（通常 20,000・赤 1,600・黒 1,296）。最後に有効なのは 19,696件、402,206,230円
- **すべての行を数える（N1）**：件数 +16.25%（+3,200件）、金額（プラスの行）+8.16%（+32,839,920円）
- **赤を除く（N2）**：件数 +8.12%（+1,600件）、金額 +8.16%。取り消された伝票の金額がそのまま残る
- **全行を足す（N3）**：件数（黒−赤も足す）も金額も正しい値と一致した。赤がもとの伝票のちょうど逆の金額で入っているときに限る
- **月別**：赤黒の 552行は、もとの取引と違う月に入力された。月の売上を入力日の月で数えると、もとの取引日の月で数えた値との差は −0.85%（12月）〜 +0.90%（7月）。2026年に入力された赤黒が 134行あり、2025年の合計は入力日で数えると 214 千円多い

## 動かし方
```
pip install -r requirements.txt
cd src && python a552_red_black.py
```
数秒で終わります。`data/slips.csv` に伝票を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 最後に有効な伝票の件数と金額（N4）が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_red_black_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/slips.csv`：row_id・slip_no（伝票番号）・kind（通常／赤／黒）・ref_slip_no（赤は取り消す伝票、黒は取り消した伝票）・entry_date（入力日）・orig_date（もとの取引日）・amount
- 仮定：金額の訂正 6%（黒で入れ直す。0.5〜2倍）、取引の取消 1.5%（赤だけ）、訂正の35%は翌月以降に入る、黒の10%をもう一度訂正する

## 注意（言えないこと）
- 架空のデータ。実際の会社の数字ではない
- 赤の金額がもとの伝票と合わない（一部だけ取り消す、など）作りでは、N3 の件数は合わなくなる
- どの月に入れるべきか、という会計処理の判断は扱っていない（数え方の違いで値がどれだけ変わるかだけ）
- 会計・税務についての助言ではない
