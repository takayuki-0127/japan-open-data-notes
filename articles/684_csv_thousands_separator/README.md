# 684 桁区切りのカンマが入った数字を CSV に書き出すと、読み込みで何列がずれるのか（実務の型）

表の金額を「1,234」のような桁区切りつきの文字にしてから CSV に書き出すと、金額の中のカンマと、列の区切りのカンマが区別できなくなります。引用符で囲まずに書き出した行は、読み込むときに列の数が増え、後ろの列がずれます。**ここでは、作成者が乱数で作った架空の売上表2,000行を、引用符なし・引用符あり・数字のままの3通りで書き出し、読み込みでずれた行と、読めた金額の合計を比べました。** 数字は置いた金額の分布で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A684 | 桁区切りのカンマで、何列がずれるか | 売上表2,000行（列：date・store・item・amount・qty）。金額は1,000円未満から100万円以上まで。引用符なし・引用符あり・数字のままで書き出す。引用符なしは「列の数が合わない行を飛ばす」（pandas の on_bad_lines="skip"）と「先頭から5列を取る」（csv モジュール）で読む。引用符ありは pandas の thousands="," と、DuckDB の REPLACE で読む。seed 684 | `src/a684_csv.py`、`src/02_read_duckdb.sql`、`src/01_read_tsql.sql` |

## 主な結果
- **引用符なしでは、金額が1,000円以上の1,775行（88.8%）で列の数が狂った**。1,000円〜99万円台の1,766行は6列、100万円以上の9行は7列になった（本来は5列）
- 列の数が合わない行を飛ばして読むと、残ったのは225行で、金額の合計は13万円（本当の4,884万円の0.3%）
- 先頭から5列を取ると、amount にはカンマの前の数字（「36,140」なら36）、qty には金額の下3桁（140）が入る。金額の合計は16万円（−99.7%）、数量の合計は本当の19倍（+1,842%）
- **引用符で囲んで書き出し、thousands="," を付けて読むと、金額の合計は本当の値と一致**。thousands を付けないと、金額は文字のまま読まれ、数として足せない
- DuckDB でも、引用符ありのファイルは REPLACE で「,」を除けば、数字のままのファイルと同じ合計になった

## 動かし方
```
pip install -r requirements.txt
cd src && python a684_csv.py
```
数秒で終わります。`data/` の3つの CSV もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- 引用符なしの各行の列の数が、5＋金額の中のカンマの数になっていること
- 引用符あり（pandas の thousands・DuckDB の REPLACE）と数字のまま（pandas・DuckDB）の金額の合計が、本当の値と一致すること

## データ
- `data/sales_unquoted.csv`：金額を桁区切りつきで、引用符なしで書き出したもの（列の数が狂う）
- `data/sales_quoted.csv`：金額を桁区切りつきで、引用符で囲んで書き出したもの
- `data/sales_plain.csv`：金額を数字のまま書き出したもの
- いずれも架空の売上表（date・store・item・amount・qty）。店・品目は番号だけ

## 注意（言えないこと）
- 架空のデータ。ずれる行の割合は、1,000円以上の金額がどれだけあるかで決まる
- 読み込みの道具ごとの細かい振る舞い（列の数が合わない行で止まるか、飛ばすか、空の列で埋めるか）は、ここで試した pandas と csv モジュール、DuckDB の一部の読み方だけ
- 表計算ソフトで開いたときの振る舞いは扱っていない
- 区切りがタブの形式や、小数点にカンマを使う地域の形式は扱っていない
- T-SQL 版（BULK INSERT で読む書き方）は未検証
