# 1188 よくある質問のページを増やして問い合わせが減ったとき、減ったのは解決した人か、あきらめた人か？（問い合わせ対応）

問い合わせ窓口では、よくある質問のページを増やしたあとに問い合わせの件数が減ると、「ページで解決する人が増えた」と読みたくなります。けれども、問い合わせが減る道は2つあります。ページを読んで解決した人と、探しても見つからずに問い合わせるのもやめた人（あきらめた人）です。窓口の記録には、問い合わせてこなかった人の中身は残りません。**ここでは、作成者が置いた架空の会社の窓口（1か月に困りごとを持つ人2万人、困りごとの種類200種類、ページを見る確率・ページにたどり着く確率・あきらめる確率を作成者が置いたもの）で、ページの数を10から320まで倍々に増やし、問い合わせの減りを「解決した人の増え」と「あきらめた人の増え」に分けました。ページが増えるほど探しにくく、探す手間が増えるほどあきらめやすいと置いています。窓口から見える数（ページを見て問い合わせなかった人、「解決しましたか」の答え）が、本当に解決した人とどれだけ離れるかも数え、置き方を変えた144通りで確かめました。**

例の窓口は架空のもので、実在の会社・窓口・問い合わせの管理の仕組みを表すものではありません。ページを増やすべきか、どう作るとよいかを勧める記事ではありません。

関連する記事：1089「見つかったバグが減ったのは、品質が上がったからか、テストが減ったからか？」は、減った数が2つの掛け算で決まり、数だけでは理由を見分けられない場面を、テストとバグで扱っています。同じ企画の 1185「1回で解決した割合は、何日以内に同じ人から再び来なければ解決と数えるかで、どれだけ変わるのか？」は、また来なかったことを解決の代わりに数える窓の幅を扱っています。この記事のあきらめた人は窓口にまた来ないので、その数え方では解決と同じに見えます。この記事は、問い合わせてこなかった人の中身を、解決とあきらめに分けて数えることに絞ります。

- **10→320ページで問い合わせは3,211.8件（22.69%）減った。そのうち解決した人の増えは1,807.3件、あきらめた人の増えは1,404.5件で、減りの43.73%はあきらめた人だった**
- 10→160ページまでは、どの段でも減りの3割ほど（10→20ページで32.12%、80→160ページで34.93%）があきらめた人だった。**160→320ページでは、解決した人が188.6人減り、あきらめた人が436.5人増えて、問い合わせは247.9件減った**。本当に解決した人がいちばん多かったのは160ページだった。ページが増えるほど探しにくく、あきらめやすいと置いたので、向きは置き方どおり
- 問い合わせの減りは、解決した人の増えとあきらめた人の増えの足し算にちょうど分かれる（困りごとを持つ人の数は変わらないので、作りどおり）
- ②「ページを見て問い合わせなかった人」は、ページを見る人の数を変えない置き方では、問い合わせの減りと同じだけ増える（作りどおり）。320ページで本当に解決した人の1.4815倍だった
- ③「はいの割合×見た人」は、320ページで本当に解決した人の1.319倍だった。160→320ページでは②が増え続け、③は8,174.2から8,064.1へ少し下がった
- 1か月分の例（80ページ、`data/people_example.csv`）：ページを見た人11,988人、ページにたどり着いた人7,451人、解決5,963人、あきらめた2,287人、問い合わせ11,750件

### 確かめ：144通り（各30回、`results/grid.csv`）
- **探しにくくもならず、あきらめやすくもならない置き方（b=0・g1=0、9通り）では、問い合わせの減りより解決した人の増えのほうが大きく、あきらめた人は減った**（あきらめた人の増え÷問い合わせの減りは−0.2535〜−0.247）。解決しない人が減るので、あきらめる人も減る（作りどおり）
- 10→320ページで問い合わせが減ったのは129通り。そのうち**23通りでは、本当に解決した人は10ページのときより減っていた**（探しにくさの増えが b=0.2・0.3 で、あきらめやすさも増える置き方）。問い合わせが減った129通りのうち、あきらめた人が増えていたのは91通り
- 160→320ページの段で問い合わせが減ったのは102通りで、そのうち54通りでは解決した人がこの段で減っていた。b>0 かつ g1>0 の81通りでは、この段で問い合わせが減った63通りのうち54通り。b=0・g1=0 の9通りでは0通り
- 本当に解決した人がいちばん多かったページの数は、10ページが36通り、40が3通り、80が21通り、160が36通り、320が48通りだった
- 問い合わせの減りは、10→320ページで−31.21%（増えた）〜60.6%と置き方で大きく動いた。どの段でも問い合わせが減り続けたのは99通り
- ②÷本当に解決した人（320ページ）は1.0768〜2.9117倍。b=0・g1=0 でも1.0768〜1.0782倍あるのは、ページの数によらずあきらめる人（確率0.2）を置いたため。③は1.0688〜1.8496倍

## 動かし方

```
pip install -r requirements.txt
cd src && python a1188_faq_solved_or_gave_up.py
```

## 確かめたこと
- 空のフォルダ（/tmp に `src` と `requirements.txt` だけを写したもの）で流し直し、results・figures・data の8ファイルがバイト単位で一致した（cmp、約43秒）
- 問い合わせの減りが、解決した人の増えとあきらめた人の増えの足し算にちょうど分かれることを、段ごとに確かめた
- b=0・g1=0 の置き方では、あきらめた人が増えず（減り）、解決した人の増えが問い合わせの減りを上回ることを確かめた（作りどおり）
- 図3枚を開き、日本語・重なり・軸（棒グラフの軸は0をまたぐ）を確かめた

## 注意（言えないこと）
- 架空のデータと、作成者が置いた探しにくさ・あきらめやすさです。どちらもページの数で増えると置いたので、あきらめた人が増える向きは置き方どおりです。結果の大きさは b と g1 の置き方で大きく変わり、実在の窓口でどれくらいかは分かりません
- ページは多い種類から順に作り、どの種類にも1ページと置きました。1ページで複数の種類に答える場合、検索で探せる場合、ページの質が違う場合は入れていません
- あきらめた人が後日また問い合わせてくる場合や、ほかの窓口に移る場合は入れていません
- ページを見ない人は必ず問い合わせると置きました。ページの数で見る人の割合が変わる場合は入れていません
- 「解決しましたか」に答える割合は作成者が置いたものです。答える割合が変われば③のずれも変わります
- ページを増やすべきか、どう作るとよいかは扱っていません
