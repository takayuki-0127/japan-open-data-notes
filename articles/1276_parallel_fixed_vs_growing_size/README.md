# 1276 量を変えずに数を増やす試し方と、数に合わせて量も増やす試し方では、速さの伸び方はどう違って見えるのか？（並列処理）

同時に動かす数を増やしたときの速さの伸び方を試すには、2つのやり方があります。① 仕事の量を変えずに、同時に動かす数だけを増やし、全体の時間がどれだけ縮むかを見るやり方。② 1つあたりの量をそろえ、数に合わせて全体の量も増やし、時間がどれだけ伸びずに済むかを見るやり方です。②では「1つのときの何倍の速さで仕事を片づけたか」を、数×（1つのときの時間÷今の時間）で出します。同じ処理を試しても、2つのやり方の「何倍」は同じになりません。**ここでは、作成者が置いた架空のアプリの処理（1つの仕事の時間の分布、量によらない分けられない部分、量に比例する分けられない部分、最後に結果をまとめる手間を作成者が決め、乱数でシミュレーションしたもの）で、同時に動かす数を1〜64に変え、2つの試し方の「何倍」を比べました。分けられない部分の置き方と1つあたりの量を変えた81通りでも確かめました。**

実機での計測はしていません。すべて作成者が置いた決まりでのシミュレーションです。実在のアプリ・道具の動きを表すものではありません。台数や費用の見込みの助言をする記事でもありません。

## 主な結果

### 同時に64で動かしたとき（`results/base_two_cases.csv`）
| 置き方 | ① 量を変えない「何倍」 | ② 量も増やす「何倍」 | ② で同時に64のときの時間は1つのときの何倍 |
|---|---|---|---|
| A 分けられない部分が量によらない | **32.7717倍** | **54.071倍** | 1.1836倍 |
| B 分けられない部分が量に比例して増える | **12.9723倍** | **21.1364倍** | 3.028倍 |

- **同じ処理を試したのに、同時に64での「何倍」は、② の試し方のほうが大きく見えた**（A で54.071倍と32.7717倍、B で21.1364倍と12.9723倍）
- 同時に64で動かすとき、①と②は同じ4,096個を処理する（時間は A で1.2848秒と1.2814秒、違いは回ごとの振れ）。違うのは割る相手だけ。① は1つで4,096個を処理した時間（A で42.1055秒）で割る。② は、1つで64個を処理した時間の64倍（A で69.2864秒）を、1つで4,096個にかかる時間とみなして割る形になる。1つで64個の時間には動かし始めの0.5秒が入っており、64倍するとそれを64回分数えるため、②が大きく出る（式どおり）
- 8つまでは2つの試し方の差は小さかった（8つで A 7.3802倍と7.5228倍、B 5.6295倍と6.3876倍）
- A では、② で同時に64にしても時間は1つのときの1.1836倍にしか伸びず、「数どおりにほぼ伸びる」ように見えた。B では3.028倍に伸び、② でも伸び方が鈍った

### 確かめ：81通り（同時に64、回ごとの振れなし、`results/grid.csv`）
- **81通りすべてで、② の「何倍」は ① を上回った**（②÷① は1.0165〜11.3854倍）。②÷① は、64×（1つで1つあたりの量を処理した時間）÷（1つで全部を処理した時間）と一致した（81通りで差0、式どおり）
- ① は3.4448〜61.0261倍、② は8.7724〜63.6193倍
- 量に比例する分けられない部分がない27通りでは、② は18.8238〜63.6193倍、① は4.3355〜61.0261倍。量に比例する部分がある54通りでは、② は8.7724〜57.0137倍、① は3.4448〜24.7838倍だった
- まとめる手間10ms・1つあたり16個の9通りでは、① の「何倍」は同時に32のときがいちばん大きく、同時に64では下がった。そのうち、動かし始め2秒・量に比例する部分なしの置き方では、① は同時に64で4.3355倍（同時に32で4.6002倍）、② は49.3613倍だった
- ②÷① が最小（1.0165倍）になったのは、動かし始め0.1秒・量に比例する部分1ms・1つあたり256個の置き方。量によらない部分が小さく、1つあたりの量が多いほど、2つの試し方は近づいた（`results/grid_ratio_by_start_size.csv`：動かし始め2秒・1つあたり16個では②÷①が10.5399〜11.3854倍、0.1秒・256個では1.0165〜1.0219倍）

## 注意（言えないこと）
- 架空のデータです。分けられない部分の長さと形、まとめる手間、1つの仕事の時間の分布は作成者が置いたもので、2つの試し方の差はこれで決まります。② が ① を上回るのは、② が動かし始めとまとめる手間を64回分数える物差しだからです（式どおり）。新しく数えたのは、置き方を変えたときにその差がどれだけの幅になるかです
- 同時に動かす所どうしは、置き場所の取り合いなどで互いに遅くし合わないと置きました。量を増やすと1つの仕事が遅くなる場合（置き場所に入りきらないなど）は入れていません
- どちらの試し方が正しいということではありません。① は決まった量を早く終えたいとき、② は量が増えても時間を保ちたいときの問いに当たります（推測）
- 実機の計測ではありません。実在のアプリや道具での伸び方を表すものではありません
