# 322 書いた記事は、何か月で「古い数字」になるのか（④ 振り返り R102）

記事が使った統計の「次の公表の目安」と、記事を作った日・公開の予定日を並べたフォルダです。2026年11月12日に「データが古くならないうちに出す」と決めて予定表を並べ替えたので、その前と後で、公開のときに次の数字がもう出ている記事が何本あったかを数えました。

## 問い

- 記事を作ってから、使った統計の次の数字が出るまで、何か月あるか
- 予定表のとおりに公開すると、公開のときに次の数字がもう出ている記事は何本か。並べ替えで何本減ったか

## 手法

| 手順 | 中身 |
|---|---|
| 材料（`src/a322_prepare.py`） | 手元の計画メモ「定点観測の候補一覧」（記事ごとの主な統計・公表の頻度・次の公表の目安）、リポジトリの履歴（記事フォルダが最初に入った日）、予定表（2026-11-12 の並べ替えの前と後）、公開ログから、記事ごとの表を作る |
| 1000本計画の記事 | 候補一覧にない227〜300の①の記事は、使った統計ごとに次の公表の目安を足した（`data/new_articles_release.csv`） |
| 次の公表の日付 | 「2027年2月」は2月1日、「1月末」「3月下旬」は25日、「春ごろ」は4月1日と置いた。気象の年の値は1月15日。「2027年ごろ」のように月が分からないものは、月数の計算から外した |
| 公表の頻度 | 毎月・毎週・毎日／四半期・年2回／年に1回／数年ごと の4つに分けた。月ごとの統計でも、記事が年の値を使っていれば「年に1回」 |
| 作ってからの月数（`src/a322.py`） | 記事フォルダが GitHub に最初に入った日から、次の公表の日付まで。毎月・毎週・毎日の統計は1か月以内とした |
| 公開の予定日との比較 | 未公開の記事について、予定表の公開予定日が次の公表の日付より後かどうか。毎月・毎週・毎日の統計は比べない（いつ出しても、すぐ次の月が出る） |

## 主な結果（`results/summary.json`）

| 公表の頻度 | 記事 | 作ってから次の数字まで（中央値） | 6か月以内に出る | 12か月以内に出る |
|---|---|---|---|---|
| 毎月・毎週・毎日 | 51 | 1か月以内 | — | — |
| 四半期・年2回 | 14 | 2.3か月 | 100% | 100% |
| 年に1回 | 274 | 5.0か月 | 62% | 100% |
| 数年ごと | 55 | 28.6か月（月が分かる17本） | 12% | 12% |

- 次の公表の目安を並べた394本のうち、月まで分かるのは327本。作ってから次の数字が出るまでの中央値は3.3か月で、67%は6か月以内、95%は12か月以内だった（図1）
- 年に1回の統計を使った記事（274本）は、中央値で5.0か月。作ったのが2026年10〜11月で、年の値の多くが翌年1〜8月に出るため
- 並べ替えの前の予定表では、比べられる未公開の254本のうち118本（46%）が、公開の予定日の時点で次の数字がもう出ている並びだった。年に1回の統計の記事では225本中106本（47%）
- 並べ替えのあと、予定表に残した146本では17本（12%）。前後の両方にある145本で見ると、61本 → 17本（図2）
- 118本のうち57本は、予定表から外して保留にした記事（保留にしたのは、比べた254本のうち109本）

## まだ後になる17本（`results/still_after_release.csv`）

- 学校基本調査を使った7本（049・F131・235〜239）：公開は12月12〜18日。確定値は12月に出る（日は未確認。月の初めに出ると置いたので後になった）
- 候補一覧で主な統計が「気象観測データ」になっている看板記事7本（F126・F134・F135・F150・F157・F167・F190）：年の値が1月に出る。朝の枠が1日1本になったぶん、公開が1月下旬〜2月に下がった
- 141（賃上げの調査。2026年分は11月に出た。更新の記事 T001 を続けて出す）、F83（国民経済計算）、F112（救急・救助の現況）

## 確かめたこと

- 次の公表の目安に「推測」とあるのは49%。日付は月の初めに寄せて置いたので、月の後半に出る統計では「後になる」を多めに数えている
- 候補一覧の「主な統計」は、README に出てくる統計名から機械で拾ったもの。上の気象の7本には、電力需要や再生可能エネルギーの記事が入っていて、気象の年の値が変わっても中身がほとんど変わらないものがある（推測）
- `src/a322_prepare.py`（手元のファイルが要る）と `src/a322.py` を空のフォルダで流し直し、data・results・figures が一致することを確かめた

## 動かし方

```
python src/a322.py     # data/ の表から集計と図を作る
```

`src/a322_prepare.py` は、手元の計画メモ・予定表・公開ログと git log の出力から data/ の表を作るスクリプト（手元のファイルがあるときだけ動く）。data/ には題名や本文を入れていない。

## 言えないこと

- 「古い数字になる」は、使った統計の次の年・次の回の数字が出る、という意味。新しい数字で記事の結論が変わるかどうかは分からない（変わらない記事も多いはず：推測）
- 次の公表の目安の半分は、例年の時期からの見込み。実際の公表日とずれる
- 作った日は、記事フォルダが GitHub に最初に入った日。リポジトリを作った2026年10月23〜24日に入った194本には、前のリポジトリから移した記事があり、実際に書いた日はもう少し早い
- 候補一覧で別に分けた記事（手法を見せる記事・振り返りの記事44本など）と、候補一覧を作ったあとの記事の一部は入っていない
- 並べ替えの前の数字は、2026年11月12日朝の予定表の日付で数えた。その予定表どおりに公開したとは限らない
