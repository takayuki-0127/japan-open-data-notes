# 742 LEFT JOIN のあと COUNT(*) で注文数を数えると、注文0件の顧客は何件と数えられるのか（実務の型）

顧客表に注文表を LEFT JOIN すると、注文のない顧客も1行残ります（注文の列は NULL）。この行を `COUNT(*)` で数えると、注文0件の顧客が「1件」になります。`COUNT(order_id)` のように注文の列を数えれば、NULL は数えられず0になります。**ここでは、作成者が乱数で作った架空の顧客6,000人と注文9,669件で、2つの数え方の違いを、1人あたりの注文数・「1回だけ買った人」の割合・登録月ごとに比べました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A742 | COUNT(*) と COUNT(列) で、注文数はどれだけ違うか | 架空の顧客6,000人（2025年1〜12月に登録、新しいほど注文が少ない）と注文9,669件。LEFT JOIN のあと COUNT(*)・COUNT(order_id) を DuckDB（1スレッド）で実行し、pandas の数えた値と一致を確認。seed 742 | `src/a742_count_star.py`、`src/02_count_duckdb.sql`、`src/01_count_tsql.sql` |

## 主な結果

| | COUNT(order_id)（正しい） | COUNT(*) |
|---|---|---|
| 注文0件の顧客（2,556人） | 0件 | **1件** |
| 1人あたりの注文数 | 1.61 | **2.04**（1.26倍） |
| 「1回だけ買った人」 | 1,355人（22.6%） | **3,911人（65.2%）** |
| 12月に登録した人の平均（81%が0件） | 0.22 | 1.03 |

- 注文0件の2,556人（43%）が、COUNT(*) ではみな1件と数えられた
- 1人あたりの注文数は1.61が2.04に、「1回だけ買った人」は22.6%が65.2%になった
- 登録の新しい月ほど0件の人が多く、ずれが大きい。12月登録の人では0.22が1.03と、4.6倍になった
- 注文のある人だけの平均は2.81。どの人を分母にするかを決めてから数える

## 動かし方
```
pip install -r requirements.txt
cd src && python a742_count_star.py
```
数秒で終わります。`data/customers.csv`・`data/orders.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- DuckDB の COUNT(order_id) が pandas で数えた注文数と、COUNT(*) が「注文数と1の大きい方」と全員で一致すること（assert）

## データ
- `data/customers.csv`：架空の顧客（customer_id・signup_month）
- `data/orders.csv`：架空の注文（order_id・customer_id・amount）

## 注意（言えないこと）
- 架空のデータです。ずれの大きさは、注文0件の顧客の割合で決まります
- T-SQL 版は未検証です（COUNT(*) と COUNT(列) の違いは SQL の決まりとして同じはず、と考えています。推測）
- 注文表の側に条件（期間など）をつけるときは、WHERE ではなく ON に書かないと、0件の顧客自体が消えます（601 の記事の話題、ここでは扱っていない）
