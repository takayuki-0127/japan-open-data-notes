# 445 順番に動かすはずの集計を、順番を違えて流すと、何枚の表が古い数字のままになるのか（実務の型）

架空の20枚の表（取り込み5枚・中間8枚・レポート用7枚、依存23本、5段）で、流す順番や開始時刻を変えたときに、古い数字のまま残る表の枚数と、検査で見つかる割合を数えたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A445 | 順番を違えると何枚が古い数字になり、どの検査で見つかるか | 8通りの流し方（順に1枚ずつ4通り、並行4通り）を、所要時間を毎回ばらつかせて1,000回ずつ試す。読みはじめた時点で元の表ができていなければ前の日の版を読む、として古い数字の表を数える。3つの検査（できあがりの時刻、読みはじめの時刻、元データの日付）で見つかる割合を出す。依存の定義から段を作る SQL を DuckDB で実行 | `src/a445_order.py`、`src/01_run_order_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（1,000回ずつ）
| 流し方 | 古い数字が残った回 | 残った回の平均の枚数（最大） | 2日以上前の数字があった回 | できあがりの時刻の検査で見つかった回 |
|---|---|---|---|---|
| 正しい順に1枚ずつ | 0% | — | 0% | — |
| となりの2枚が入れ替わる | 57.7% | 3.6枚（7枚） | 0% | 100% |
| はなれた2枚が入れ替わる | 91.5% | 5.1枚（12枚） | 20.9% | 100% |
| でたらめな順 | 100% | 12.1枚（15枚） | 99.8% | 100% |
| 並行（開始時刻を決め打ち、余裕なし） | 100% | 12.1枚（15枚） | 96.8% | 0% |
| 並行（余裕3割） | 87.4% | 7.2枚（15枚） | 33.1% | 1.1% |
| 並行（余裕6割） | 32.3% | 4.9枚（13枚） | 1.9% | 1.6% |
| 並行（元の表のできあがりを待つ） | 0% | — | 0% | — |

- 読みはじめの時刻を使う検査、元データの日付を比べる検査は、どの流し方でも100%（この設定での結果）
- **かかった時間**：1枚ずつ順に 平均246分、元の表を待つ並行 平均66分
- **となりの入れ替え19通り**（所要時間はふだんどおり、`results/adjacent_swaps.csv`）：読む・読まれるの関係にある2枚は11通りで、古くなる表は1〜7枚（s1⇄m1 が7枚）。残り8通りは0枚
- **1枚だけ遅れる**（余裕3割の並行、`results/one_table_late.csv`）：所要が1.5倍で20枚中13の場合に古い数字が残り、できあがりの時刻の検査で見つかったのは0。2倍で13のうち7、3倍で15のうち13
- **下流の枚数**：s1 は8枚、s2・s3 は7枚、s4 は6枚から読まれる（直接・間接）

## 動かし方

```
pip install -r requirements.txt

```

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- 依存の定義から段を作る SQL（再帰 CTE、DuckDB）の結果が、Python で作った段・順と一致する（コード内の assert）
- 正しい順（段ごとの順、手で書いた順）では、古い数字の表が0枚になる（コード内の assert）

## 注意（言えないこと）
- 架空の20枚の表での結果。割合や枚数は、関係の形、所要時間のばらつき、開始時刻の決め方で変わる
- 「元の表ができていなければ前の日の版を読む」という単純な決まり。作り直しの途中の表を読む、ロックで待つ、失敗とやり直し、は入れていない
