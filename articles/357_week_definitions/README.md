# 357 「週」の決め方で、週次の売上はどれだけ変わるのか（実務の型）

同じ日次の売上を、3つの「週」（ISO 週／日曜始まりで1月1日の週を第1週とする週／月で切る週）でまとめ、週の数、7日そろわない週、前年の同じ番号の週との比べやすさを数えたフォルダです。架空の日次売上5年分（2021〜2025年）を使いました。SQL は DuckDB で動かしました。T-SQL 版は `src/01_weekly_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A357 | 週の決め方で、週次の合計と前年同週比はどれだけ変わるか | 年3%で伸びる架空の日次売上（曜日の型・年末年始の山あり）を3通りの週でまとめる。前年の同じ番号の週と比べ、本当の伸び（+3%）からのずれを数える。YEAR(日付) と ISO 週を組み合わせる取り違えも試す | `src/a357_weeks.py`、`src/*.sql` |

## 主な結果
- **週の数（5年間）**：ISO 週は260週で、すべて7日。日曜始まり（1月1日の週が第1週）は265週で、うち8週が7日未満（いちばん短い週は1日）。月で切る週は311個で、うち100個が7日未満
- 同じ日でも、ISO 週と日曜始まりの週で**週の番号が違う日が49%**あった
- **前年の同じ番号の週と比べる（2022〜2025年、本当の伸びは+3%）**
  - ISO 週：208週のうち、5ポイント以上ずれたのは6週（最大17.5ポイント）。6週とも年末年始で、年末の山や元日が入る週が年によって違うため
  - 日曜始まり：212週のうち、日数が前年と違う週が8週、5ポイント以上ずれたのは12週。2023年の第1週（7日）と2022年の第1週（1日）の比は+1,602%
  - 月で切る週：250個のうち、前年に相手がないのが8個、日数が違うのが89個、5ポイント以上ずれたのは93個
- **年と ISO 週の取り違え**：`YEAR(日付)` と ISO 週でまとめると、5年間で6つのグループがおかしくなった。「2024年の第1週」は9日分（1月1〜7日と12月30・31日）で、正しい第1週より40%多い。「2025年の第1週」は8日分で19%多い。「2021年の第52週」は5日分で22%少なく、ISO では2020年に入る1月1〜3日が「2021年の第53週」として現れた
- ISO の年が暦の年と違う日は、5年間で11日

## 動かし方
```
pip install -r requirements.txt
cd src && python a357_weeks.py
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL（DuckDB）で出した3通りの週の数・日数・合計は、pandas で別に計算した値と一致した（コード内の assert）
- T-SQL に書いた「ISO の年」の式 `YEAR(DATEADD(day, 26 - DATEPART(iso_week, d), d))` は、5年分の全部の日で pandas の ISO の年と一致することを Python で確かめた（SQL Server では動かしていない）

## 注意（言えないこと）
- 売上は架空です。ずれの大きさは、置いた曜日の型と年末年始の山（12月26〜31日は1.6倍、元日は0.3倍など）で決まります
- 2021〜2025年の ISO の年はどれも52週でした。53週ある年（2026年など）では、第53週に前年の相手がありません。この記事のデータには入っていません
- 「日曜始まりで1月1日の週が第1週」は、SQL Server の `DATEPART(week, …)`（DATEFIRST 7）の数え方を式で書いたものです。SQL Server 本体では動かしていません
- 祝日は入れていません。祝日の数の違いによるずれは 356 で扱いました
- 週次の数字をいつ送るかは 280 で扱いました
