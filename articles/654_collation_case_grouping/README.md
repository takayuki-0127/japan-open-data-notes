# 654 大文字と小文字を区別するかしないかで、GROUP BY の件数とつながる行はどれだけ変わるのか（実務の型・照合順序）

文字の比べ方（照合順序）は、データベースによって既定が違います。DuckDB や PostgreSQL は大文字と小文字を区別し、SQL Server の日本語の既定（CI）は区別しません。メールアドレスのように本来は区別しない値を区別して集計すると、同じ人が別の人に分かれます。逆に、大文字小文字に意味のある番号を区別せずに集計すると、別の番号が1つにまとまります。**ここでは、架空の顧客8,000人・注文4万件（注文の2割でメールの書き方が違う）と、クーポンの番号4万個で、両方の場面を数えました。** 書き方の違いの割合は作成者が置いたもので、数字はその仮定で決まります。

## 主な結果
- **メールアドレスを区別して数えると**：本当の購入者 7,948人が **14,582人（+83.5%）** に。62.8%の人が2つ以上に分かれた
- **1人あたりの注文数とリピート**：本当は1人5.03回・2回以上買った人96.6%が、2.74回・**57.9%** に見える
- **顧客表とのつながり**：区別すると注文の **20.2%（金額の20.2%）** が顧客表とつながらない。区別しなければ0件
- **クーポンの番号（大文字小文字に意味がある）**：区別しないと、4けたの番号2万個のうち163個（0.81%）が別の番号と1つにまとまる。6けたでは0個

## 動かし方
```
pip install -r requirements.txt
cd src && python a654_collation.py
```
数秒で終わります。`data/` に customers・orders・coupons_used を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 区別する・しない・LOWER の件数と、つながらない注文の数が DuckDB と pandas で一致した
- T-SQL 版（`01_collation_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。照合順序の名前（Japanese_CI_AS など）は環境で違う

## データ
- `data/customers.csv`（customer_id・email）、`data/orders.csv`（order_id・email・amount）、`data/coupons_used.csv`（code・length）
- 仮定：注文の80%は登録どおり、10%は先頭だけ大文字、5%はドメインの先頭が大文字、5%は全部大文字

## 注意（言えないこと）
- 架空のデータ。実在のメールアドレスではない（example ドメインを使った）
- メールアドレスの「@」より前は、決まりの上では大文字小文字を区別してよいことになっている。実際の多くのサービスは区別しないので、ここでは区別しない値として扱った
- 照合順序はデータベース・列・クエリで指定できる。どこで決まっているかを確かめてから集計するのが安全
