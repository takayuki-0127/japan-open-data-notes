# 1270 分けた仕事の大きさがばらつくと、全体の時間はいちばん遅い1つでどれだけ延びるのか？（並列処理）

決まった量の処理を8つに分けて同時に動かすと、全体が終わるのは、分けた8つの組のうちいちばん遅い1つが終わったときです。組の大きさがそろっていれば合計÷8で終わりますが、店ごと・利用者ごとのように切れ目を動かせない単位で分けると、組の大きさがばらつき、ほかの7つは先に終わって待つことになります。**ここでは、作成者が置いた架空のアプリの毎晩の集計（記録10万件が2,000の店に分かれ、店ごとの件数のばらつきと1件の処理時間を作成者が置き、乱数で作ったもの）で、①件数で8等分（店をまたいでよいとき）、②店の番号順に件数がほぼ8等分になる所で切る、③店をでたらめに8組に分ける（店の数をそろえる）、④店の件数を見て大きい店から順に、件数の合計がいちばん少ない組に入れる、⑤④を見込みの件数（外れあり）で行う、の5つの分け方で、全体の時間が理想（合計÷8）よりどれだけ延びるかを数えました。店の件数のばらつき・店の数・分ける数を変えた27通りでも確かめました。実機での計測はしていません。**

例のアプリ・店・数は架空のもので、実在のアプリや部品の分け方を表すものではありません。機械の台数や費用の見込みの助言はしていません。

関連する記事：851「並行する作業が増えると、全体の遅れはどれだけ増えるのか？」は、1本ごとの長さが決まっていない作業を何本も同時に進め、全部そろうのを待つと、本数が増えるほど合流が遅れることを扱っています。1269「処理を8つに分けて同時に動かしても8倍速くならないのは、分けられない部分がどれだけあるときか？」は、分けられない部分の割合で、8つで何倍になるかが頭打ちになることを扱っています。1271「仕事を初めに同じ数ずつ割り当てるか、終わった所が次を取りにいくかで、全体が終わる時刻はどれだけ違うのか？」は、初めに分けずに、終わった所が次を取りにいく割り当て方を扱っています。1277「遅れた仕事の写しを別の所でも動かすと、全体の時間はどれだけ縮み、使う手間はどれだけ増えるのか？」は、最後まで長引いた仕事の写しを手のあいた所で動かし、いちばん遅い1つを縮める決まりを扱っています。この記事は、量が決まった1つの処理を初めに分けるとき、組の大きさのばらつきと分け方で、いちばん遅い1つがどれだけ延びるかに絞ります。

## 主な結果

### 分け方ごとの延びた割合（店2,000・件数のばらつき1.0・8つに分ける、200回、`results/base_by_method.csv`）
| 分け方 | 理想より延びた割合（平均） | 10〜90% | ほかの組が待っていた時間の割合（平均） |
|---|---|---|---|
| ①件数で8等分 | 0.62% | 0.21〜1.07% | 0.63% |
| ②店の番号順に切る | 1.25% | 0.49〜2.34% | 1.22% |
| ③店をでたらめに8組 | **12.45%** | 7.1〜18.55% | 10.91% |
| ④大きい店から、合計の少ない組へ | **0.61%** | 0.36〜0.87% | 0.61% |
| ⑤大きい店から（見込みの件数） | 4.36% | 2.42〜6.6% | 4.16% |

- 全体の処理は平均で99.999秒（理想は8つで12.5秒）。**店の数をそろえてでたらめに分けると、いちばん遅い組を待つ分で全体は12.45%延びた**。1回分のデータでは、理想12.5073秒に対し③のいちばん遅い組は15.7202秒だった（`results/one_set_part_times_sec.csv`）
- ③の延びは、組の時間のばらつき（標準偏差÷平均）に、8つの正規の乱数のいちばん大きい値の平均（1.4236）を掛けた目安の11.99%に近かった。①は1組1.25万件の散らばりだけなので、同じ目安（式）の0.64%どおりの0.62%だった
- 店をまたがない②でも、店の数が2,000あれば延びは1.25%だった。件数を見て大きい店から詰める④は0.61%で、店をまたいで切る①と同じくらいになった
- 件数の見込みが外れる（対数で標準偏差0.3）と、④の詰め方でも延びは4.36%になった
- この置き方では、いちばん大きい店1つ（平均で全体の1.04%）は理想の12.5%に届かず、下限にはならなかった（1回分では0.7992秒）

### 確かめ：27通り（各200回、`results/grid.csv`）
| 分け方 | 延びた割合の範囲（27通り） |
|---|---|
| ①件数で等分 | 0.28〜1.14% |
| ②店の番号順に切る | 0.34〜109.04% |
| ③店をでたらめに | **1.02〜190.01%** |
| ④大きい店から | 0.31〜100.03% |
| ⑤大きい店から（見込みの件数） | 0.58〜107.68% |

- ③は、店が少ないほど（店200で8.46〜190.01%、2,000で2.64〜55.06%、20,000で1.02〜15.97%）、分ける数が多いほど（4つで1.02〜41.2%、8つで2.05〜91.57%、16個で3.74〜190.01%）延びた
- 27通りすべてで、②と④は③より延びが小さく、⑤は④以上だった
- いちばん大きい店1つで決まる下限が10%を超えたのは、件数のばらつき1.5・店200の8つ（下限21.6%、④は22.03%）と16個（下限99.88%、④は100.03%）の2通りだけだった。このとき、どの分け方でも店をまたがない限り下限より短くできない。④は27通りすべてで、下限より高くても1.89ポイント以内だった
- ①は店をまたいで切るので下限に縛られず、27通りすべてで1.14%以下だった（店ごとにまとめて処理する必要がある集計では使えない）

## 注意（言えないこと）
- 架空の集計と、作成者が置いた件数・時間の作りです。延びの大きさは、置いた店の件数のばらつき・店の数・分ける数でほぼ決まります。③の延びが大きいのは、店の数をそろえても件数がそろわないと置いたからです
- 1件の処理時間は店によらず同じ分布と置きました。店ごとに1件の重さが違う場合、件数で詰める④・⑤でも延びは大きくなります（推測）
- 分けた8つの組は同じ速さで、同時に始まると置きました。組どうしの取り合い、終わった組がほかを手伝うことは入れていません（終わった所が取りにいく形は 1271 で扱っています）
- 実在のアプリ・機械の速さを表すものではなく、どの分け方を使うべきかは、処理の決まり（店をまたいでよいか）で変わります
