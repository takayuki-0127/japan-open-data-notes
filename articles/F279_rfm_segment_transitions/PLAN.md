# F279 計画（事前登録）：RFM で分けた顧客は、その後どう動くのか？

この計画は、購入データの中身（顧客ごとの値・その後の動き）を見る前に書いた。データの入手先・ライセンス・列の名前だけを確かめた段階で書いている。

## 問い
顧客を RFM（最終購入からの日数 R・購入回数 F・購入額 M）で分ける方法は、CRM やマーケティングの実務でいちばん使われる顧客の分け方の一つ。ただ「分けた後、その顧客がどう動くか」を、分けた時点より後のデータで確かめることは少ない。
- ある時点 t で RFM の区分に入った顧客は、次の6か月にもう一度買うのか、どの区分に移るのか
- RFM の区分は、過去の購入額だけで並べるより、次の6か月の売上をよく当てるのか

## データ
- UCI Machine Learning Repository「Online Retail II」（Chen, D. 2012。CC BY 4.0）。英国のオンライン小売（ギフト用品、卸売の顧客を多く含む）の 2009-12-01〜2011-12-09 の取引明細。
- 使う列：Invoice、Quantity、InvoiceDate、Price、Customer ID、Country。
- 顧客 ID のない行は使わない。Invoice が "C" で始まる行（取消）は、購入額から差し引く（純額）。数量か価格が0以下の取消以外の行は除く。

## 設計
- 時点 t：2010-12-01 から 2011-06-01 までの毎月1日（7時点）。
- 見る期間（過去）：t の直前12か月。R＝t から最終購入日までの日数、F＝請求書（Invoice）の数、M＝純購入額。過去12か月に1回以上買った顧客が対象。
- 結果（未来）：t から6か月。もう一度買ったか（請求書が1つ以上）、純購入額、6か月後の時点 t+6 での区分。
- RFM の点数：各時点の対象顧客の中で R・F・M をそれぞれ5段階（五分位、R は日数が短いほど高い点）。
- 区分：R と F の点（M は F と相関が強いため、区分には R・F を使い M は確かめで使う）でよく使われる10区分の表を使う：Champions(R4-5,F4-5)、Loyal(R3-5,F3-5 のうち Champions 以外)、Potential loyalist(R4-5,F2-3)、New(R5,F1)、Promising(R4,F1)、Need attention(R3,F2-3)、About to sleep(R3,F1)、At risk(R1-2,F3-4)、Can't lose(R1-2,F5)、Hibernating(R1-2,F1-2)。区分の表は README に載せる。
- 予測の比べ方：次の6か月の売上の合計のうち、各方法で上位20%に選んだ顧客が占める割合（捕捉率）。
  - 方法A：過去12か月の購入額 M で上位20%
  - 方法B：RFM の合計点（R+F+M）で上位20%（同点は M で並べる）
  - 方法C：区分ごとの「次の6か月の平均購入額」を、前の時点（6か月前より古い時点）の結果から計算し、それで並べる（時点をずらした検証。2011-06-01 の時点だけで使える：2010-12-01 の結果で学ぶ）

## 仮説と「外れ」の基準
- H1：Champions のうち、6か月後も Champions にいる顧客は 60% 未満。7時点の平均が 60% 以上なら外れ。
- H2：次の6か月にもう一度買う割合は、R の点が上がるほど高い（単調）。7時点のうち1時点でも単調でなければ外れ。
- H3：RFM の合計点（方法B）の捕捉率は、過去の購入額だけ（方法A）と3ポイント以上違わない。7時点の平均の差が3ポイント以上なら外れ。
- H4：区分ごとのもう一度買う割合は時点が違っても安定している：2010-12-01 の時点の値と 2011-06-01 の時点の値の差が、10区分のうち7区分以上で ±10ポイント以内。満たさなければ外れ。

## 頑健性（少なくとも3つ）
1. 過去の期間を6か月にする
2. 結果の期間を3か月にする（12か月は 2010-12-01 の時点だけ）
3. 英国の顧客だけにする
4. 購入額の上位1%の顧客（大口の卸）を除く
5. 五分位ではなく、固定の境目（R：30/90/180/270日、F：1/2/4/8回）で点をつける
6. 取消を差し引かない（総額）

## もう一度問う（結果を見た後で1つ足す）
結果を見てから、区分の動きについて新たに出た問いを1つ足す。足したことは記事と README に書く。

## 出さないもの
- 個人や特定の会社が分かる情報は扱わない（顧客 ID は匿名の番号）。
- 個別の顧客の名前や住所はデータにない。国は集計にだけ使う。
