# 1045 区分に分けて足し合わせると、重なりと抜けで合計はどれだけずれるのか？（概算）

「車を持たない世帯」「在宅で働く人がいる世帯」のように、使いそうな人を区分に分けて、区分ごとに「区分の世帯数 × 区分の中で使う割合」を出して足す概算はよく使われます。ところが、1つの世帯が2つ以上の区分に入っていればその世帯は2回以上数えられ（重なり）、どの区分にも入らない世帯で使う人は数えられません（抜け）。**ここでは、作成者が乱数で作った架空のA町（10,000世帯）の架空の「まとめ買いの定期便」を使う世帯の数（正しい件数を作成者が置いたもの）で、4つの区分ごとに足した合計が正しい件数の何倍になるか、そのうち重なりと抜けがそれぞれどれだけかを数えました。区分の数、区分どうしの重なりやすさ、区分の外で使う割合を変えた27通りでも確かめました。**

区分の合計÷正しい件数は、「使う世帯1つが入っている区分の数の平均」とちょうど同じになります（式どおり）。重なりで2回目以降に数えた分を足し、抜けた分を引いた値です。この記事では、その大きさが置き方でどれだけ動くかと、合計が合って見えても中身が合っていない場合を数えます。

全体から割合で割っていく概算と店ごとに積み上げる概算の食い違いは同じ企画の関連する記事 1044、掛け算でつなぐ要素の数と外れやすさは 1041、何人かの概算のまとめ方は 1046 で扱っています。地図の上で店の商圏の円が重なって数えすぎる話は 950、同じ時間に複数の場所にいる人の数え方は 1002、延べの来場者と実際の人数の違いは 993 で扱っています。この記事は、世帯の区分（属性ではなく暮らし方の区分）が重なったり抜けたりするときの合計のずれに絞ります。

## 主な結果

### 4つの区分の合計（基本、200町の平均）
| | 値 |
|---|---|
| 正しい件数（使う世帯） | 1,795.1世帯（17.95%） |
| **4つの区分の合計 ÷ 正しい件数** | **1.84倍** |
| 重なりで2回目以降に数えた分 | 正しい件数の95.13% |
| どの区分にも入らず抜けた分 | 正しい件数の10.77% |
| 使う世帯1つが入っている区分の数の平均 | 1.84 |
| 区分の世帯数の合計 ÷ 町の世帯数 | 1.1倍 |

- 4つの区分の合計は、正しい件数の1.84倍になった。1＋重なり0.9513−抜け0.1077＝1.8435で、使う世帯1つが入っている区分の数の平均と同じ（式どおり）
- **区分の世帯数を足すと町の世帯数の1.1倍で、重なりは小さく見えた**。けれども、使う世帯ほど複数の区分に入っている（区分に入るほど使いやすいと置いた）ので、使う世帯で見ると平均1.84個の区分に入っていた。27通りでは、使う世帯の区分の数の平均は、区分の世帯数の合計÷町の世帯数より0.2〜1.72大きかった
- 町の37.07%の世帯はどの区分にも入らず、31.75%の世帯は2つ以上の区分に入っていた

### やり方ごと（`results/methods.csv`、200町）
| やり方 | 正しい件数の何倍（平均） | 10〜90%の範囲 |
|---|---|---|
| ①区分ごとに足す（割合は正しく分かっている） | 1.84倍 | 1.81〜1.88倍 |
| ②区分ごとに足す（割合は200世帯に聞いて出す） | 1.84倍 | 1.72〜1.97倍 |
| ③②に「どの区分にも入らない」区分を足す | 1.94倍 | 1.8〜2.1倍 |
| **④1世帯を1つの区分にだけ入れる＋どの区分にも入らない区分** | **1.0倍** | **0.92〜1.08倍** |

- 区分の中で使う割合を聞き取りで出す誤差（②の幅）は、重なりによるずれ（0.84倍分）よりずっと小さかった
- 抜けだけを直すと（③）、1.94倍とかえって離れた。重なりが大きいときに抜けを埋めると、打ち消していた分がなくなるため
- 1世帯を1つの区分にだけ入れ、どの区分にも入らない世帯の区分も作る（④）と、1.0倍に戻った。区分が町の世帯をちょうど1回ずつ覆うので、残るのは聞き取りの誤差だけになる（作りどおり）。27通りでも④は0.99〜1.02倍

### 区分の数を変えると（`results/by_n_segments.csv`、各60町）
| 区分の数 | 合計 ÷ 正しい件数 | 重なり（%） | 抜け（%） | 区分の世帯数の合計 ÷ 町の世帯数 |
|---|---|---|---|---|
| 1 | 0.5205倍 | 0 | 47.95 | 0.2992倍 |
| 2 | 0.9465倍 | 23.88 | 29.23 | 0.5495倍 |
| 3 | 1.4727倍 | 63.03 | 15.76 | 0.9009倍 |
| 4 | 1.8471倍 | 95.36 | 10.65 | 1.0973倍 |
| 5 | 2.1634倍 | 124.92 | 8.57 | 1.3001倍 |
| 6 | 2.4318倍 | 150.09 | 6.91 | 1.4485倍 |

- 区分を増やすと、抜けは減るが重なりがそれ以上に増え、合計は大きくなり続けた
- 区分2つでは合計が0.9465倍とほぼ合ったが、中身は重なり23.88%と抜け29.23%の打ち消しだった

### 置き方を変えた27通り（`results/grid.csv`、各60町）
- ①の合計は正しい件数の0.75〜3.17倍。重なりは正しい件数の12.64〜222.2%、抜けは2.25〜37.35%
- **合計が正しい件数の±10%に入った3通りは、どれも重なりと抜けがそれぞれ15%を超えていて、打ち消し合っていた**（3通りとも区分2つ）
- 区分の世帯数の合計÷町の世帯数（0.55〜1.45倍）と、①の合計÷正しい件数の相関は0.896だった。区分の世帯数の合計は重なりの手がかりにはなるが、使う世帯が区分にどう偏るかで大きさは変わる
- ③は1.13〜3.2倍で、27通りすべてで正しい件数より大きかった

## 注意（言えないこと）
- 架空のデータです。区分の割合、区分どうしの重なりやすさ、区分ごとの使いやすさの上乗せ、区分の外で使う割合は作成者が置いたもので、結果はこれで決まります。合計は置き方で0.75〜3.17倍と動きました。実在の町の世帯や商品の数字ではありません
- 合計÷正しい件数が「使う世帯の区分の数の平均」になるのは式どおりで、新しく分かったことではありません。この記事で数えたのは、その大きさが置き方でどれだけ動くかと、合って見える合計の中身です
- 使う世帯ほど複数の区分に入りやすいと置きました（区分は使いそうな世帯を選んで作ると考えたため）。区分が使うかどうかと関係なく切られていれば、重なりは区分の世帯数の合計から読めるはずです（推測）
- 区分は世帯の暮らし方で切り、人の属性で比べることはしていません。どの区分を狙うべきかの助言でもありません
