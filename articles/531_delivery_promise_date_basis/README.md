# 531 納期の遵守率は、納期を「当初の約束日」と「変更後の日」のどちらで数えるかで何ポイント違うのか？（実務の型）

架空の受注20,000件（2025年の1年分）と納期変更の記録を作り、同じ記録の遵守率（約束日までに出荷した割合）を、(A) 当初の約束日、(B) 最後に変えた日、(C) 出荷の3日前以内の変更を除いた最後の日、の3通りで数えて比べたフォルダです。直前の変更の起きやすさを変えたシミュレーションで、差の大きさがどう動くかも見ました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A531 | 約束日の取り方で遵守率は何ポイント変わるか。差は直前の変更の割合とどう関係するか | 受注ごとに3通りの約束日を出し、出荷日と比べる。同じ判定を SQL（DuckDB）でも行い、Python と一致するか確かめる。直前の変更の起きやすさだけを変えて9通り作り直す | `src/a531_promise_basis.py`、`src/02_promise_basis_duckdb.sql`、`src/01_promise_basis_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（20,000件、納期を1回以上変えた受注38.0%、出荷の3日前以内に変えた受注12.2%）
- **遵守率**：A 当初の約束日 60.0%、B 最後に変えた日 72.8%、C 直前の変更を除く 64.7%
- **差**：B − A = +12.8ポイント、C − A = +4.7ポイント、B − C = +8.1ポイント
- **区分別**：変更なし（12,410件）はどの数え方でも66.6%。早めの変更だけ（5,149件）は A 65.1% → B・C 74.9%。直前の変更あり（2,441件）は A 15.9%、B 100.0%、C 33.3%
- 直前の変更は「出荷日以降へ約束日を動かす」ものとして作ったので、B で数えるとその受注は必ず遵守になる
- **直前の変更の割合を変えたシミュレーション**：0% → 23.8% で、B − A は 4.7 → 20.5ポイント、B − C は 0.0 → 15.8ポイント。直前の変更の割合が1ポイント増えると、B − C はおよそ0.67ポイント広がる
- 受注月別の遵守率の幅は、A 58.6〜62.2%、B 70.9〜75.3%、C 62.8〜66.8%。月による違いより、数え方による違いのほうがずっと大きい
- SQL（DuckDB）の判定は、Python と全件一致

## データ
- `data/fictional_orders.csv`：架空の受注（seed 531）。列は order_id・ordered（受注日）・promise_initial（当初の約束日）・shipped（出荷日）
- `data/fictional_promise_changes.csv`：架空の納期変更。列は order_id・seq・changed_on（変更した日）・new_promise（変更後の約束日）・kind（早め／直前）

## 注意（言えないこと）
- 架空のデータ。変更の起きやすさ、遅れの分布、直前の変更が遅れそうな受注に偏ることは作成者が置いたもので、実際の会社の値ではない
- 「直前」を出荷の3日前以内とした。境目を変えれば C の値も変わる
- どの数え方が正しいかは、約束（契約や社内の決まり）で決まる。この記事は差の大きさを見ただけ。変更の理由（客先の都合か、自社の都合か）は区別していない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
