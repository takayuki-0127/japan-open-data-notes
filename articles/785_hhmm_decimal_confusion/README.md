# 785 「1時間30分」を「1.30」と書いて合計すると、月の作業時間はどれだけ少なく出るのか（実務の型）

作業時間を「1.30」のように書くと、人によって「1時間30分」（時.分）の意味にも、「1.3時間」の意味にもなります。時.分で書かれた値をそのまま数として足すと、30分は0.30時間（18分）、45分は0.45時間（27分）と数えられ、合計が少なく出ます。**ここでは、作成者が乱数で作った架空の作業記録（40人×22日）で、半分の人が時.分で書いた場合に、月の合計がどれだけ少なく出るかを数えました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A785 | 時.分の値を数として足すと、月の合計はどれだけずれるか | 架空の40人×22日（1日0.5〜8時間、15分きざみ）。20人は時.分、20人は時間の小数で書く。数のまま足す合計と、分に直して足す合計を DuckDB（1スレッド）で出し、Python の本当の合計と一致を確認。seed 785 | `src/a785_hhmm.py`、`src/02_hours_duckdb.sql`、`src/01_hours_tsql.sql` |

## 主な結果

| | 本当の合計 | 数として足した合計 | ずれ |
|---|---|---|---|
| 時.分で書く20人 | 1,824.25時間 | 1,761.35時間 | **−62.9時間（−3.4%）** |
| 時間の小数で書く20人 | 1,825.75時間 | 1,825.75時間 | 0 |
| 40人の合計 | 3,650.0時間 | 3,587.1時間 | −1.7% |

| 書いた値 | 数として読むと | 本当は | ずれ |
|---|---|---|---|
| ○.15 | 0.15時間（9分） | 15分 | −6分 |
| ○.30 | 0.30時間（18分） | 30分 | −12分 |
| ○.45 | 0.45時間（27分） | 45分 | **−18分** |

- 時.分で書く人は、1人平均3.1時間（最大4.1時間）、月の合計が少なく出た。ずれは人によって1.6%〜6.5%
- ずれは「分」の部分だけで決まる。○.00 の日はずれない
- 時.分で書いた値には、小数が .60 以上のものが1つもない（時間の小数で書く人は23%）。これが見分ける手がかりになる

## 動かし方
```
pip install -r requirements.txt
cd src && python a785_hhmm.py
```
数秒で終わります。`data/staff.csv`・`data/work_log.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- DuckDB で分に直した合計と数のままの合計が、Python で数えた値と全員で一致すること（assert）

## データ
- `data/staff.csv`：架空の担当者（staff_id・style。hmm＝時.分、dec＝時間の小数）
- `data/work_log.csv`：架空の作業記録（staff_id・work_date・hours_text）

## 注意（言えないこと）
- 架空のデータです。ずれの大きさは、時.分で書く人の割合と、分の部分（15分きざみ）の出方で決まります
- 実際の表では、だれがどちらの書き方をしたかが分かっていないことが多いです。ここでは書き方の列（style）がある前提で直しています。小数が .60 以上の値があるかどうかは手がかりになりますが、それだけでは見分けきれません（.15 や .30 はどちらの書き方にも出る）
- T-SQL 版は未検証です
