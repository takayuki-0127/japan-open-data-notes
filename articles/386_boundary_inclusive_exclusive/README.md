# 386 「以上」と「超」、「以下」と「未満」を取り違えると、何件が別の区分に入るのか（実務の型）

年齢の区分（20歳以上30歳未満…）や金額の区分（3,000円以上5,000円未満…）を SQL で付けるとき、`>=` と `>`、`<` と `<=` を取り違えると、境目ちょうどの値の行だけが別の区分に入ります。架空の会員10万人（年齢）と架空のチャージ10万件（金額）で、何行が変わるか、境目のテストを何個置けば見つかるかを数えたフォルダです。SQL は DuckDB で動かしました。T-SQL 版は `src/01_bands_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A386 | 取り違えで何行が変わるか。きりのよい値に集まるほど増えるか。テストは何個で全部見つけるか | 正しい書き方（以上・未満）と、3つの取り違え（①下を「超」に ②上を「以下」に ③両方）、④1か所だけの取り違えで、区分の付き方を比べる。チャージ額は、きりのよい金額を選ぶ人の割合を0〜90%に変える。境目ごとに5種類の誤り（①②③と、境目の値が+1・−1）を1つずつ入れた50個を、8つのテストの組み方で見つけられるか数える | `src/a386_boundaries.py`、`src/01_bands_tsql.sql` |

## 主な結果
- **変わるのは、境目ちょうどの値の行だけ**。年齢（6つの境目）では10万人のうち9,335人（9.3%）、チャージ額（4つの境目、きりのよい金額を選ぶ人が70%）では43,566件（43.6%）
- **取り違えの種類で、起きることが違う**（チャージ額）：①下を「超」にすると、43,566件がどの区分にも入らない（INNER JOIN なら行が消える）。②上を「以下」にすると、同じ43,566件が2つの区分に入り、つないだ後の行は143,566行に増える。③両方だと行数は変わらず、43,566件が1つ下の区分に入る
- ③では、区分ごとの件数が「3万円以上」で−58.8%、「1万〜3万円未満」で−44.3%、「3,000円未満」で+47.6%。区分ごとの率（0〜5%）で付けるボーナスの合計は−20.4%
- **1か所だけの取り違え**：年齢は境目によって0.9〜2.2%、チャージ額は2.8〜15.5%（3,000円ちょうどが15.5%）
- **きりのよい値に集まるほど増える**：きりのよい金額を選ぶ人が0%なら0%、30%で18.5%、50%で31.0%、70%で43.6%、90%で55.5%
- **テスト（誤り50個のうち見つけた数）**：区分の真ん中の値だけ（12個）0、境目ちょうどの値だけ（10個）40、境目とその1つ下（20個）50、境目とその上下（30個）50。本番のデータからでたらめに選ぶと、20件で14.6、100件で31.2、1,000件で45.9、10,000件で46.4（300回の平均。50個すべて見つけた回は0%）
- 境目ちょうどの値だけでは、「境目の値が1小さい」誤り10個を見つけられない。本番のデータで見つからずに残ったのは、チャージ額の「境目の値が1小さい」誤り（2,999円などの行が10万件のうち0〜5件しかない）

## 動かし方
```
pip install -r requirements.txt

```
乱数の種を固定してあるので、実行のたびに同じ `data/`・`results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB で区分表につないだ行数（区分のついた行、どの区分にも入らない行）は、NumPy で数えた値と4つの書き方すべてで一致した（コード内の assert、`results/sql_check_duckdb.csv`）

## データ
- すべて架空（作成者が乱数で作成、seed 386）。`data/members_age.csv`（会員ID・年齢）、`data/charges_amount.csv`（チャージID・金額）
- 年齢は18〜89歳の整数。チャージ額は、70%の人がきりのよい金額（1,000円〜50,000円の8通り）を選び、残りは自由に入力する（100円単位にならない値）と置いた

## 注意（言えないこと）
- 架空のデータです。変わる行の割合は、境目ちょうどの値がどれだけあるかで決まります。チャージ額の43.6%は「きりのよい金額を選ぶ人が70%、うち6割が境目の金額」と置いた結果です
- 小数のある値（体重、率など）では、境目ちょうどの値はほとんどなく、取り違えで変わる行もほぼ0になります。その場合は、見つけにくい誤りになります
- 誤りは境目に1つずつ入れた50個です。条件の順番の誤り（CASE の上から順に当てはまる）や、単位の取り違えは入れていません
- テストの「見つけた」は、テストの値の区分の付き方が正しい書き方と1つでも違う、という意味です。期待する区分を人が正しく書けていることを前提にしています
- どちらの書き方（以上・未満か、超・以下か）が正しいかは、決まり（規約や仕様）で決まります。この記事はそれを決めるものではありません
- T-SQL 版は SQL Server 本体では動かしていません
