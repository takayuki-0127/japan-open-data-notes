# 1003 数取りの人による数え間違いは、どれだけ出るのか？（来場者と集客）

施設やイベントの入口では、係の人が手で持つ数取り器（カウンター）で、通った人を1人ずつ数えることがあります。人の手で数えると、何人かまとめて通ったときに押し漏れたり、2回押したりします。**ここでは、作成者が乱数で作った架空の展示施設（入口2つ、9:00〜17:00。1分ごとに本当に通った人数と、係8人の数え漏れのしやすさを作成者が置いたもの）で、混むほど数え漏れが増えると置いたときに、1日の合計・15分ごとの数・ピーク・入口どうしの比べがどれだけずれるか、2人で数える・録画で数え直して直す、でどこまで分かるかを数えました。**

施設・入口・係はすべて架空のもので、実在の施設の数字は使っていません。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A1003 | 手で数えた人数は、本当に通った人数からどれだけずれるか。ずれは1日の合計・15分ごと・ピーク・入口どうしの比べでどう違うか。2人で数えた差や、録画で数え直した一部で、ずれをどこまで知り、直せるか | 架空の展示施設の入口2つ（東口・西口）、9:00〜17:00の480分。1分あたりの平均人数は 3＋22×exp(−((分−210)÷70)²)（12:30ごろがピークで約25人）。人は組で通り、組の数はポアソン分布、組の人数は1＋ポアソン分布（平均0.8、組の平均1.8人）。両方の入口で同じ平均人数。係は8人。1人の数え漏れのしやすさ（基本の割合）は、平均2%・対数で標準偏差0.5のばらつき（基本の置き方の8人は0.866〜3.712%、`data/staff.csv`。500日とも同じ8人）。係は1時間ずつ交代し、1日の中で東口・西口を1時間ずつ受け持つ（順番は日ごとに乱数）。1人を数え漏らす確率＝基本の割合×（1＋1.0×その1分に通った人数÷10）×（1＋0.15×（組の人数−1））（上限0.9）。数えた1人ごとに0.5%の確率で2回押す。数えた数の期待値（置いた確率から出る値）も1日ごとに出した。2人で数える：東口では、受け持ちの係と別に、ほかの係がもう1人同じ人たちを数える。録画で直す：東口の15分の区切り4つを録画で数え直し、本当÷数えた数の比を1日の合計に掛ける。区切りは (a) でたらめな4つ、(b) 開館直後の1時間（9:00〜10:00）の4つ。基本の置き方で500日。確かめとして、基本の割合（1・2・4%）×混むほど増える強さ（0・1.0・2.0）×2回押す確率（0・0.5・2%）の27通り（各100日、係8人の比は基本と同じ）、係どうしのばらつき（対数の標準偏差0・0.5・1.0、係を5回作り直して各40日）。seed 1003 | `src/a1003_clicker.py` |

## 主な結果

### 1日の合計（基本の置き方、500日、`results/days_base_500.csv`）
- 2つの入口を合わせた1日の合計は、本当の人数より平均**−6.295%**（500日の5〜95%で−7.587〜−5.068%）少なかった。東口だけでは平均−6.285%（5〜95%で−8.863〜−4.075%）だった
- この平均は、置いた数え漏れと2回押しの確率から出る期待値（−6.305%）と0.0104ポイントの差で合い、**式どおり**です（27通りでは−22.168〜+0.742%と動く）。新しく数えたのは、そのずれがどこから来て、どんな比べ方に効くかです
- 1日の合計のずれのうち、1人ずつの押し漏れのたまたまの分（期待値との差）の標準偏差は0.267ポイントで、その日にどの係が混む時間を受け持ったかと人の流れで決まる分（期待値の振れ）の0.732ポイントより小さかった。数える人数が多いほど、たまたまの押し漏れは打ち消し合いますが、混むほど漏れやすい分と係の癖の分は打ち消し合いません

### 15分ごと・ピーク（東口、`results/slot_error_by_flow.csv`）
| その15分の1分あたりの人数 | 区切りの数 | ずれの平均 | 5〜95% |
|---|---|---|---|
| 5人未満 | 8,626 | −3.333% | −10.169〜+1.581% |
| 5〜10人 | 2,364 | −4.145% | −10.576〜0% |
| 10〜15人 | 1,371 | −5.388% | −12.359〜−0.635% |
| 15〜20人 | 1,317 | −6.815% | −14.708〜−1.729% |
| 20人以上 | 2,322 | **−8.388%** | −17.175〜−2.604% |

- 混むほど数え漏れが増えると置いたので、ずれが混む時間ほど大きくなる向きは作りどおりです。15分ごとの数は、空いている時間でも5〜95%で−10.169〜+1.581%と振れた
- いちばん多い15分（ピーク）の数えた人数は、本当のピークより平均−8.918%少なかった。本当のピークの区切りでのずれは平均−9.173%だった
- 数えたピークの区切りが本当のピークの区切りと違ったのは、500日のうち14.8%だった
- ピークの数÷15分の平均は、本当は2.989倍、数えた数では2.904倍で、山の形が少し平らに見えた

### 入口どうしの比べ（基本の置き方、500日）
- 東口と西口は同じ平均人数で置いたので、本当の差は人の流れのたまたまの分だけ（差の絶対値の平均2.678%）だった。数えた数では、差の絶対値の平均は3.542%だった
- 「数えた差−本当の差」が2ポイントを超えた日は**50.4%**（5〜95%で−4.485〜+4.869ポイント）だった。その日にどちらの入口の混む時間を、数え漏れの多い係が受け持ったかで決まる分です
- 係どうしのばらつきを0にすると2ポイントを超えた日は1.0%、0.5では52.0%、1.0では51.5%だった（`results/by_staff_spread.csv`）

### 2人で数える（東口、基本の置き方、500日）
- 同じ人たちを2人で数えると、2人の数の差は平均1.915%（本当の人数に対して）だった。一方、2人の数の平均は本当より−6.265%少なく、本当のずれ（絶対値の平均6.265%）は2人の差より大きかった。500日すべて（100.0%）で、2人の差は2人の平均の本当のずれより小さかった
- 2人とも混む時間に同じように漏らすので、2人の数がそろっていることは、数が正しいことを意味しません。係どうしのばらつきを0にすると、2人の差は平均0.463%まで小さくなったが、2人の平均のずれは6.057%のままだった

### 録画で数え直して直す（東口、基本の置き方、500日）
| 直し方 | 1日の合計のずれの平均 | 5〜95% |
|---|---|---|
| 直さない | −6.285% | −8.863〜−4.075% |
| でたらめな15分×4を録画で数え直す | −0.546% | −5.427〜+4.598% |
| 開館直後の15分×4を録画で数え直す | **−3.024%** | −7.413〜+3.103% |

- でたらめな区切りで直すと、平均ではほぼ本当に戻った（−0.546%）が、どの区切りを選ぶかで1日ごとの振れは広がった
- 空いている開館直後の1時間で直すと、平均−3.024%が残った。空いている時間の数え漏れの割合しか分からず、混む時間の多い漏れは直らないためです

### 確かめ：数え漏れの割合×混むほど増える強さ×2回押し（27通り、各100日、`results/grid_miss_slope_double.csv`）
- 1日の合計のずれの平均は、27通りで−22.168〜+0.742%と動いた。基本の割合1%・混むほど増える強さ0・2回押し2%の1通りでは、本当より多く出た（+0.742%）
- ピークのずれの平均は−26.44〜+0.863%。混むほど増える強さを0にすると、−4.656〜+0.863%で、1日の合計のずれ（−4.824〜+0.742%）とほぼ同じだった
- 開館直後の1時間で直したあとのずれの平均は、混むほど増える強さが0なら−0.327〜+0.544%でほぼ戻り、強さ1.0・2.0では−13.461〜−1.405%が残った。空いている時間で直してよいかは、混むほど漏れが増えるかどうかで決まります

## 動かし方
```
pip install -r requirements.txt
cd src && python a1003_clicker.py
```
10秒ほどで終わります。`data/day1_minutes.csv`・`data/staff.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダ（/tmp）に src と requirements.txt を写して流し直し、results・figures・data の10ファイルがバイト単位で一致した（cmp、約6秒）
- 1日の合計のずれの平均が、置いた確率から出る期待値と0.0104ポイントの差で合うことを確かめた（作りの確かめ）
- 15分ごとの区切りの数の合計（16,000＝500日×32区切り）が表の区切りの数の合計と合うことを確かめた

## データ
- `data/day1_minutes.csv`：基本の置き方の1日目、2つの入口の1分ごとの人数（minute（9:00からの分）・entrance・true（本当に通った人数）・count（係が数えた人数）・staff（受け持った係の番号））
- `data/staff.csv`：係8人の数え漏れのしやすさ（基本の割合）

## 注意（言えないこと）
- 架空のデータです。人の流れ、組の人数、係の数え漏れのしやすさ、混むほど漏れが増える強さ、2回押しの確率は作成者が置いたもので、ずれの大きさはこれで決まります。表のとおり、1日の合計のずれは置き方で−22.168〜+0.742%まで動くので、−6.295%という値そのものに重みはありません。言えるのは「混むほど漏れが増えるなら、ピークと混む時間ほど少なく出て、空いている時間の数え直しでは直らない」という向きと、その動き方です
- 係が時間とともに数え漏れやすくなる、入口の形で見落としやすい、といった形は入れていません
- 本当の人数は、録画で数え直すと正しく分かると置きました。録画の数え直しにも数え間違いはあると推測します（数えていません）
- 機械（センサー）で数える場合は扱っていません（入口のゲートのセンサーとチケットの読み取りの違いは 994 で扱っています）
- 実際の施設の数え方や数え間違いの大きさを表すものではありません
- 関連する記事：915（検査員によって合否が違うとき、何を数えればよいか）は、2人の判定がそろっていても同じ癖で同じ不良を見逃すことを、工場の検査で扱っています。この記事の「2人の数がそろっても数は正しくない」は同じ仕組みを、人を数える場面で数えたものです。1002（同じ時間に複数の場所にいる人を、どう数えるか）は、数え間違いのない数え方で、エリアを足すと二重に数える話を扱っています。994（入口のゲートで数えるか、チケットで数えるか）は、機械と券で数えたときのずれを扱っています
