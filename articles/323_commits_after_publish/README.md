# 323 公開したあとの手直しは、どれくらいあったか（④ 振り返り R103）

このリポジトリのコミットの履歴から、記事フォルダごとに「アップロードしたあとでファイルを書き換えたコミット」を数えたフォルダです。見直しで結論をどう直したかは [251](https://github.com/takayuki-0127/japan-open-data-notes/tree/main/articles/251_conclusion_reversals) で数えたので、ここでは履歴から、いつ・どのファイルを直したかだけを見ます。

## 問い

- 記事フォルダは、アップロードしたあとにどれくらい書き換えられたか
- 書き換えは、最初のコミットの何分後・何日後だったか。どの種類のファイルだったか
- note に公開したあとに、GitHub のフォルダを直した記事はあるか

## 手法

| 手順 | 中身 |
|---|---|
| 履歴を表にする（`src/a323_prepare.py`） | `git log --name-status` の出力を、「コミット × 記事フォルダ」が1行の表にする。追加（A）と変更（M）を分け、ファイルの種類（README・PLAN・src・results・data・figures・その他）ごとに数える |
| 手直しの定義（`src/a323.py`） | すでにあるファイルを書き換えた（M の）コミットを「手直し」とする。ファイルを足しただけのコミットは別に数える |
| 何分後か | その記事フォルダの最初のコミットからの時間 |
| note の公開日 | 手元の公開ログの日付（34本）。その日より後の日付のコミットがあるか |

GitHub の画面からアップロードすると、src・data・figures などのフォルダごとに1コミットになります。コミットの数は、作業の回数より多くなります。

## 主な結果（`results/summary.json`、2026年10月23日〜11月12日の4,049コミット）

- 記事フォルダは577本、フォルダに入ったコミットは3,467（1本あたり中央値5）。足したファイルは11,575、書き換えたファイルはのべ259
- 手直しのコミットは148（記事フォルダのコミットの4.3%）で、69本の記事（12%）にあった
- 148のうち121は最初のコミットから1時間以内、147は6時間以内。1日より後は1つだけ（F09、3.5日後）
- 書き換えたファイルは、図87、results 71、README 67、src 18、data 13。README だけを直したコミットは64（43%）
- note に公開した記事のうちフォルダのある34本で、公開日より後にフォルダへのコミットがあった記事は0本
- あとからファイルを足しただけのコミット（1時間より後）は11（6本）

| グループ | 記事 | コミット（中央値） | 書き換えがあった記事 | 最後の書き換えまで（中央値） |
|---|---|---|---|---|
| 000–099 | 92 | 5 | 0本（0%） | — |
| 100–226 | 127 | 5 | 2本（2%） | 0.1時間 |
| F01–F99 | 97 | 6 | 15本（15%） | 0.2時間 |
| F100–F199 | 100 | 5 | 4本（4%） | 0.1時間 |
| F200–F255 | 36 | 6 | 3本（8%） | 0.2時間 |
| 精選 F256–F295 | 40 | 10 | 40本（100%） | 0.5時間 |

- 精選の40本は、すべてに書き換えがあった（公開前の見直しで出た指摘を、アップロードのあとに反映したため）。ほかのグループは0〜15%
- 直しは、アップロードした日のうちに済んでいた。日をおいて戻って直すことは、ほとんどなかった

## 確かめたこと

- 「60分以上あけて、同じフォルダにもう一度コミットした」記事で数えても13本（2%）。区切りを30分にすると3%、180分にすると2%、日付が変わったかで数えると1%
- `src/a323_prepare.py`（git log の出力を渡す）と `src/a323.py` を空のフォルダで流し直し、data・results・figures が一致することを確かめた

## 動かし方

```
git log --name-status --format='C|%H|%ad|%s' --date=iso-strict > log.txt
python src/a323_prepare.py log.txt     # data/commit_folder.csv と data/commits.csv
python src/a323.py                     # 集計と図
```

## データ

| ファイル | 中身 |
|---|---|
| data/commit_folder.csv | コミット × 記事フォルダ（3,467行）。日時、触ったファイルの種類と数、追加・変更の数 |
| data/commits.csv | コミットごと（4,049行）。ルートの README だけのコミットか、など |

## 言えないこと

- 数えたのは GitHub に上げたあとの書き換えだけ。上げる前に手元で直した分は、履歴に残らない。直しが少ないのではなく、上げる前に済ませていた分が見えていないだけかもしれない
- このリポジトリの履歴は2026年10月23日から。それより前に別のリポジトリで作った記事の履歴は入っていない
- 期間は3週間。公開から時間がたってからの直し（新しい年の数字での更新など）は、まだ起きる時期になっていない
- 「書き換えた」はファイルが変わったという意味で、中身がどれだけ変わったかは見ていない。1文字の直しも、図の描き直しも1つに数えている
- note の本文を直したかどうかは、この履歴では分からない
