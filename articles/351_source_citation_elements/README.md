# 351 出典には、統計の名前・表の番号・取得日がそろっているか（④ 振り返り R106）

GitHub に置いた記事の README を1本ずつ読み、「出典」の節に、統計の名前・公表元・URL・表の番号・取得した日・年や期間が書いてあるかを数えた

## 問い

- 出典の節だけを見て、同じ表にたどり着けるか（統計の名前、表の番号、取得した日がそろっているか）
- 出典の節になくても、README のどこかに書いてあるか
- 記事のグループ（作った時期）で違うか

## 手法

| 手順 | 中身 |
|---|---|
| 拾う（`src/a351_extract.py`） | `articles/*/README.md` 607本のうち、初期の記事で同じ本文を共有しているものを1本にまとめた542本（2026年11月12日、コミット 0ee78ff）。見出しに「出典」がある節を取り出す |
| 要素 | 統計・資料の名前（かぎかっこ）、公表元（省・庁・統計局・日本銀行・協会など）、URL、使い方の決まり（「加工して作成」・利用規約・ライセンス）、年・期間、表の番号・ID（第○表・表○・statInfId・統計表ID・系列コード・URL の外の9〜12桁の番号）、取得した日（「取得」「ダウンロード」「アクセス」「閲覧」のすぐ前後の日付） |
| 対象 | 出典の節に、公表元と、かぎかっこの名前の両方がある README を「公的な統計などを出典にした記事」とした（464本）。自分の記事の記録や架空のデータだけを使った記事（78本）は外れる |
| まとめ方（`src/a351.py`） | 要素ごとに、出典の節にある割合と、README のどこかにある割合。記事のグループごと |

241（公的データで困ったこと）は README の「困ったこと」を、269（代わりのデータ）は代わりのデータの使い方を数えた。ここでは出典の書き方だけを数える

## 主な結果（`results/by_group.csv`、`results/n_elements.csv`）

公的な統計などを出典にした README 464本のうち

| 要素 | 出典の節にある | README のどこかにある |
|---|---|---|
| 統計・資料の名前、公表元 | 100%（対象の決め方による） | ― |
| 使い方の決まり（加工して作成など） | 87% | ― |
| URL | 72% | ― |
| 年・期間 | 28% | ― |
| 表の番号・ID | 9%（44本） | 47%（219本） |
| 取得した日 | 1%（6本） | 10%（47本） |
| 名前・表の番号・取得した日の3つ | 0本 | 6%（27本） |

グループごと（README のどこかにある割合）

| グループ | README | URL（出典の節） | 表の番号・ID | 取得した日 | 3つそろう |
|---|---|---|---|---|---|
| 000–099 | 33 | 100% | 27% | 15% | 0% |
| 100–226 | 113 | 92% | 65% | 0% | 0% |
| F01–F99 | 95 | 66% | 39% | 8% | 5% |
| F100–F199 | 93 | 58% | 39% | 11% | 3% |
| F200–F255 | 34 | 24% | 15% | 0% | 0% |
| 精選 F256–F295 | 33 | 55% | 61% | 15% | 15% |
| 1000本計画（227〜・T） | 63 | 83% | 60% | 30% | 22% |

- 出典の節は542本のうち536本（99%）にある。名前と公表元は、ほぼ必ず書いてある
- 表の番号は、出典の節には9%しかない。README の「データ」の節などまで広げると47%
- 取得した日は、出典の節に1%、README 全体でも10%。通常の記事の後半（100–226）と F200–F255 は0%
- 名前・表の番号・取得した日の3つが README にそろうのは27本（6%）。1000本計画が14本、精選が5本
- URL は、初期の記事ほど書いてある（100% → 24%）。README の31%は、URL が e-Stat の統計の一覧のページ（`toukei=`）で、表までは決まらない
- F200–F255 は URL も表の番号も少ない。前の記事で取ったデータを使い回した記事が多く、「F231 の取得データを使用」のように書いている

## 確かめたこと

- 機械が「表の番号あり」とした README を2回に分けて45本読んだ。誤りは3本で、URL の中の数字と「表1つ」を拾っていた。この2つの型は拾わないように直した
- 機械が「取得した日あり」とした README を、直したあとに20本読み、20本とも取得した日だった
- 「取得した日なし」で、本文に2026年10〜11月の日付がある README を15本読むと、2本は別の言い方で取得した日を書いていた（「今回の実行は 2026-10-26 時点」「ブラウザで保存し（2026-11-11）」）。10%は少なめに出ている
- `src/a351.py` を空のフォルダで流し直し、results と figures が一致することを確かめた

## 言えないこと

- 見たのは README の文だけ。取得した日がコードやデータのファイル名、コミットの日付から分かる場合は数えていない
- 「表の番号」は言葉の形で拾った。番号があっても、その表が本当に使った表かどうかは確かめていない
- 「公的な統計などを出典にした記事」は、公表元と、かぎかっこの名前の両方がある README とした。かぎかっこを使わずに書いた出典は外れる
- 出典の要素がそろっていることと、実際に同じデータを取り直せることは別。取り直せるかは F165（再現できる形）で確かめた
- グループは番号のまとまりで、作った順とは少しずれる
