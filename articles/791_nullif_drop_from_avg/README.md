# 791 0で割るのを NULLIF で避けると、その店は平均から黙って消え、全体の率はどれだけ変わるのか（実務の型）

SQL で率を出すとき、分母が0の行でエラーにならないよう `x / NULLIF(分母, 0)` と書くことがよくあります。分母が0の行は NULL になり、そのあと `AVG` をとると、NULL の行は数えられずに黙って外れます。分母がずっと0の店は、店ごと平均から消えます。逆に `COALESCE(…, 0)` で0にすると、来店がなかった日を「申込み率0%」と数えることになります。**ここでは、作成者が乱数で作った架空の60店×30日の来店数と申込み数で、3通りの出し方の違いを数えました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A791 | NULLIF・0として・合計から、で申込み率はどれだけ違うか | 架空の60店×30日。1日の来店の平均は店ごとに0.6〜40人、申込み率は店ごとに3〜25%。2店は月の間ずっと改装で来店0。日ごとの率の AVG（NULLIF のまま・COALESCE で0）と、合計どうしの割り算を DuckDB（1スレッド）で出し、pandas の結果と一致を確認。seed 791 | `src/a791_nullif.py`、`src/02_rate_duckdb.sql`、`src/01_rate_tsql.sql` |

## 主な結果

| 全体の申込み率の出し方 | 値 |
|---|---|
| 日ごとの率の平均（NULLIF のまま） | 11.6% |
| 日ごとの率の平均（来店0の日を0とする） | **9.9%** |
| 合計から率（申込みの合計÷来店の合計） | 11.8% |

- 来店0の日は1,800行のうち263行（15%）。NULLIF のまま平均すると、この263行はエラーも警告もなく平均から外れた
- 月の間ずっと来店0だった改装中の2店は、店ごとの平均の表で値が NULL になり、店の平均を出すと58店だけで計算された
- 来店0の日を0として数えると、全体の率は11.6%から9.9%に下がった。来店の少ない21店（1日2人未満）では平均10.0%が6.6%になった
- 来店の少ない店は、NULLIF のままだと日の3分の1が外れ（使われたのは66%）、残った日も「1人来て1人申込み＝100%」のような日が入って大きく振れた

## 注意（言えないこと）
- 架空のデータです。違いの大きさは、来店0の日の割合と、来店の少ない店の数で決まります
- どの出し方が正しいかは、何を知りたいかで決まります。「来店した人のうち何%が申し込んだか」なら合計から率、「店をそれぞれ1票として比べる」なら店ごとの率の平均です。来店0の日を率0%とするのは、ふつうは意図と違います
- T-SQL 版は未検証です（AVG が NULL を飛ばすのは SQL の決まりなので同じはず、と考えています。推測）
