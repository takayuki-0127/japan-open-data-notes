# 1190 自動の受付返信を「初めの返事」に数えると、初めの返事までの時間はどれだけ縮んで見えるのか？（問い合わせ対応）

問い合わせ窓口の「初めの返事までの時間」は、記録の中でいちばん早く送られた返信の時刻から数えることがあります。フォームから届いた問い合わせには、すぐに「受け付けました」という自動の受付返信が出るので、それも返信に数えると、担当が実際に返事をするまでの時間とは別のものを数えることになります。**ここでは、作成者が置いた架空の会社の窓口（平日9〜18時だけ開く。問い合わせはフォームとメールの2つの入口から来て、フォームにだけ自動の受付返信が出る。担当の返事までの時間を作成者が置いたもの）で、初めの返事までの時間を、(a) 担当の返事だけで数えた場合と、(b) 自動の受付返信も数えた場合で比べました。フォームの割合が増え、担当の返事は遅くなる6か月の動きも数え、置き方を変えた45通りと54通りで確かめました。**

例の窓口は架空のもので、実在の会社・窓口・問い合わせの管理の仕組みを表すものではありません。自動の受付返信を出すべきか、目標をどう置くとよいかを勧める記事ではありません。

関連する記事：525「メールの開封率は、画像の自動読み込みによる「見かけの開封」を除くと何ポイント下がるのか？」は、人の動きではない自動の記録が数に混ざる場面を、メールの開封で扱っています。521「問い合わせの対応時間を「営業時間」で数えるか「暦の時間」で数えるかで、期限内に返せた割合は何ポイント変わるのか？」は、同じ返信の記録を時間の数え方で比べています（この記事は暦の時間で数えます）。同じ企画の 1191「「24時間以内に返事」の目標を置くと、返事までの時間の分布はどう形を変えるのか？」は目標を置いたときの担当の動き、1194「夜と休みの日に来た分を翌朝まとめて受けると、朝の返事までの時間はどう見えるのか？」は閉まっている間に届いた分の待ちを扱っています。この記事は、何を「初めの返事」に数えるかに絞ります。

## 主な結果

### 基本：フォーム60%（20,000件、`results/base.csv`）
| 数え方 | 平均 | 中央値 | 90%点 | 1時間以内 | 24時間以内 |
|---|---|---|---|---|---|
| (a) 担当の返事だけ | 15.6466時間 | 8.3963時間 | 46.2921時間 | 11.69% | 82.52% |
| (b) 自動の受付返信も数える | 6.392時間 | **0.0436時間（2.62分）** | 19.9807時間 | 63.92% | 92.91% |
| (b)÷(a) | **0.4085倍** | 0.0052倍 | 0.4316倍 | | |

- **自動の受付返信も数えると、平均は0.4085倍、90%点は0.4316倍に縮み、中央値は8.3963時間から2.62分になった**。担当の返事の速さは同じ記録のまま
- 平均の縮み方は、ほぼ「1−フォームの割合」（0.4）の式どおり。フォームの分が数分になり、メールの分だけが残るため
- 中央値は、フォームの割合が半分を超えると、自動の受付返信の時間そのものになる（作りどおり）
- 届いた時刻が窓口の閉まっている時間だった問い合わせは37.55%。担当の返事までの時間は入口で変えないと置いたので、フォームとメールの (a) はほぼ同じ（中央値 8.1425時間と8.5536時間、作りどおり）

### 6か月の動き：フォーム40→80%、担当は1.15倍遅く（50回の平均、`results/six_months.csv`）
| | 1か月目 | 6か月目 |
|---|---|---|
| フォームの割合 | 40% | 80% |
| (a) の中央値 | 8.5654時間 | 12.0119時間 |
| (b) の中央値 | 1.348時間 | **0.0345時間（2.07分）** |
| (a) の平均 | 15.709時間 | 17.1145時間 |
| (b) の平均 | 9.4102時間 | 3.467時間 |
| (a) の24時間以内 | 82.5% | 80.24% |
| (b) の24時間以内 | 89.58% | 96.02% |

- **担当の返事は遅くなったのに、(b) で数えると、中央値・平均・24時間以内の割合のどれもが良くなって見えた**。50回すべてで、(a) の中央値は上がり、(b) の中央値と平均は下がった

### 確かめ1：45通り（各20,000件、`results/grid_static.csv`）
- (b)÷(a) の平均は0.1995〜0.8098倍で、「1−フォームの割合」との差は最大0.0175だった（式どおり）
- 中央値の (b)÷(a)：フォーム20%で0.3693〜0.8214倍、40%で0.1363〜0.3158倍、50%で0.0022〜0.0411倍、60%で0.0019〜0.0368倍、80%で0.0015〜0.0288倍。50%を超えると、担当の返事の速さによらず数分になった
- 90%点の (b)÷(a)：フォーム20%で0.6252〜0.9512倍、80%で0.0449〜0.3044倍
- 24時間以内の割合の上がり方は、担当の返事が遅い置き方ほど大きかった：W の平均60分で1.49〜13.3ポイント、180分で2.68〜17.12ポイント、480分で8.67〜38.92ポイント
- 閉まっている時間に届いた割合は、m=0.5で22.98%、1で37.36%、2で54.38%（45通りの (a) の中央値は1.1497〜23.3764時間）

### 確かめ2：54通り（1か月目と6か月目の差、各20回、`results/grid_trend.csv`）
- 担当が遅くなる36通りのうち、(a) の中央値が上がり (b) の中央値が下がったのは**36通りすべて**、平均では33通り、90%点では28通り、24時間以内の割合（(a) が下がり (b) が上がった）では32通りだった
- 担当が遅くならない18通りでは、(a) の平均の動きは最大0.1777時間だったが、(b) の平均は0.9591〜13.2102時間短くなった

## 注意（言えないこと）
- 架空のデータと、作成者が置いた届く時刻・入口・担当の返事までの時間です。平均の縮み方と、フォームが半分を超えたときの中央値は、置いた仕組みからの式どおり・作りどおりです
- 担当の返事までの時間は、入口で変えず、窓口の混み具合でも変わらないと置きました。フォームとメールで担当の速さが違う場合や、件数が増えると遅くなる場合は入れていません
- 自動の受付返信は、フォームのすべてに数分以内に出ると置きました。出ない場合や、担当が手で送る「受け付けました」の短い返信は扱っていません
- 祝日・長い休みは入れていません。時間は暦の時間で数えました
- 自動の受付返信を出すべきか、目標をどう置くとよいかは扱っていません
