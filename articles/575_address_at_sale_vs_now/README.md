# 575 顧客が引っ越したとき、売上を「売った時点の住所」で数えるか「今の住所」で数えるかで、地域別の売上はどれだけ動くのか（実務の型・属性をどの時点で取るか）

地域別の売上を出すとき、顧客マスタの住所をそのまま結合すると、引っ越した顧客の過去の売上も今の住所の地域に入ります。売った時点の地域で数えるには、住所の履歴（有効期間つき）と注文日で結合する必要があります。**ここでは、架空の顧客4万人（5年間で31.6%が引っ越し）と注文399,575件で、地域別・年別の売上を、売った時点の住所・今の住所・登録時の住所の3通りで数えて比べました。** 地域は架空の8地域（地域A〜H）で、引っ越しの向き（A・B に向かいやすい）は作成者が置いたものです。数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A575 | 住所をどの時点で取るかで、地域別の売上と伸び率がどれだけ変わるか | 住所の履歴（valid_from・valid_to）と注文日で結合（売った時点）、最後の履歴で結合（今の住所）、最初の履歴で結合（登録時の住所）。地域別・年別の売上、2021年→2025年の伸び率、今の住所だと別の地域に入る売上の割合（年別）を比べる。SQL は DuckDB（1スレッド）で実行し、売った時点の集計を Python と突き合わせ。seed 575 | `src/a575_address.py`、`src/02_region_duckdb.sql`、`src/01_region_tsql.sql`（未検証） |

## 主な結果
- **今の住所だと別の地域に入る売上**：2021年の注文は27.8%、2023年は16.9%、2025年は3.7%。古い年ほど大きい
- **2021年の地域別売上**：今の住所で数えると、売った時点の住所と比べて、地域Aが +16.0%、地域Bが +13.3%、地域Gが −17.1%、地域Hが −21.1%。地域C〜Fは ±3%以内
- **2021年→2025年の伸び率**：売った時点の住所では、地域A +14.8%、地域B +10.6%、地域G −17.6%、地域H −17.9%。今の住所で数えると、すべての地域が −4.7%〜+1.9%に収まり、人の動きによる伸び減りがほぼ消える
- **登録時の住所で数えると**：2025年の売上が、地域G・H で +24%台、地域A・B で −12〜−15%ずれる。住所を更新していない顧客マスタでは、こちらのずれが出る
- **売上の大きい順**：2021年は、今の住所で数えると8地域のうち4地域の順位が入れ替わる（隣どうしの入れ替わり）

## 動かし方
```
pip install -r requirements.txt
cd src && python a575_address.py
```
数秒で終わります。`data/address_history.csv`（customer_id・region・valid_from・valid_to）と `data/orders_2021_2023.csv`・`data/orders_2024_2025.csv`（order_id・customer_id・ordered_on・amount。1ファイル10MB未満にするため年で分けた）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 売った時点の住所で数えた地域別・年別の売上が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_region_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 顧客4万人。2021年1月1日時点の地域の割合は 地域A 16%〜地域H 10%
- 引っ越しは1年あたり7%（地域G・H は10%）。引っ越し先は地域A・B が選ばれやすい
- 注文は1人あたり5年で平均10件、日付は一様、金額は対数正規（中央値 約6,000円）
- valid_to は次の住所の開始日。最後の住所は 9999-12-31

## 注意（言えないこと）
- 架空のデータ・架空の地域。実際の地域の数字ではない
- ずれの大きさは、引っ越しの多さと向きで決まる
- どちらの数え方が正しいかは目的による。「その地域でどれだけ売れたか」なら売った時点の住所、「今の顧客がどこにいるか」なら今の住所
