# 591 欠品していた日の売上を0と見るか欠測と見るかで、平均の需要はどれだけ少なく見えるのか（実務の型・欠品と需要）

売上の記録は、在庫があった分しか残りません。欠品した日は、売れるはずだった数（需要）が売上より大きいのに、記録されるのは在庫が尽きるまでの数です。**ここでは、架空の200品目・1年分（2025年）の日次の需要と在庫で、欠品日の扱いを4通り（欠品日を0とみなす／そのまま平均／欠品日を除く／打ち切りとして推定）に変え、本当の平均需要とのずれを比べました。** 需要の分布・在庫の持ち方・発注のルールは作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A591 | 欠品日の扱いで、品目ごとの平均需要はどれだけ少なく見えるか | 本当の需要（負の二項分布）を在庫で打ち切った売上から、①欠品日を0、②そのまま平均、③欠品日を除いて平均、④欠品日を「需要 ≥ 売上」として扱う最尤法（負の二項分布）の4通りで平均需要を出し、本当の平均と比べる。欠品日の割合ごとの中央値。①〜③を DuckDB（1スレッド）の SQL と Python で突き合わせ。seed 591 | `src/a591_stockout_demand.py`、`src/02_stockout_duckdb.sql`、`src/01_stockout_tsql.sql`（未検証） |

## 主な結果
- 欠品した日（その日の終わりに在庫0）は全体の 8.5%。品目別では中央値 7.1%、最大 28.2%。売れなかった需要は全体の 5.6%
- **200品目の合計で見た平均需要のずれ**：欠品日を0 **−10.3%**、そのまま平均 −5.6%、欠品日を除く **−2.7%**、打ち切りとして推定 **+0.1%**
- **品目別（中央値・下位10%）**：欠品日を0 −10.1%・−23.0%、そのまま −4.8%・−14.5%、除く −2.9%・−6.6%、打ち切り 0.0%・−1.3%
- **欠品日の割合ごと（中央値）**：20%を超える11品目では、欠品日を0 −29.1%、そのまま −19.1%、除く −6.9%、打ち切り +0.3%
- 5%以上少なく見えた品目：欠品日を0 140品目、そのまま 96、除く 48、打ち切り 0
- 欠品日を除いても少なく出るのは、欠品した日の需要が品目の平均の 1.35倍と大きく（欠品しなかった日は 0.97倍）、需要の大きい日ばかりが抜けるため

## 動かし方
```
pip install -r requirements.txt
cd src && python a591_stockout_demand.py
```
数秒で終わります。`data/daily.csv`（date・item・sales・end_stock・stockout）と、答え合わせ用の `data/true_demand.csv`（date・item・demand）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 欠品日の割合と①〜③の平均が、Python と DuckDB の SQL（`02_stockout_duckdb.sql`）で200品目すべて一致した
- T-SQL 版（`01_stockout_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 品目200。平均需要は対数正規（中央値8個/日前後）、日々の需要は負の二項分布（サイズ4）
- 在庫は、発注点を割ったら目標まで発注し、3日後に入荷する。発注点の安全在庫の係数を品目ごとに −2.0〜1.6 で変え、欠品のしやすさに差をつけた
- 欠品日は「その日の終わりに在庫が0」の日。需要がちょうど在庫と同じだった日も欠品日に入る（実際のデータでも区別できないため）

## 注意（言えないこと）
- 架空のデータ。実際の店の売上・需要ではない
- 打ち切りとして推定する方法は、需要の分布の形（ここでは負の二項分布）を正しく置けた場合の結果。形が違うと、ずれが残る
- 曜日や季節の動き、欠品中に別の商品に流れた需要（代わりの購入）は入れていない
- 発注量・在庫の持ち方の助言ではない
