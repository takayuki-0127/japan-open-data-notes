# 1098 直したあとに別の所が壊れる率は、何で割るかでどう変わるのか？（テストとバグ）

アプリの開発では、バグを直した修正が、別の所を壊すことがあります（ここでは「壊れ」と呼びます）。チームどうしで「壊れの率」を比べるとき、割る数（分母）には、修正の件数・変更の登録の回数・変更した行数・リリースの回数などがあり、どれを使うかで値も順位も変わります。修正を大きくまとめるか小さく分けるかはチームの進め方で違うので、同じ壊れやすさでも、割る数によって高くも低くも見えます。**ここでは、作成者が乱数で作った架空のアプリの開発チーム3つ（壊れやすさ・修正の大きさ・登録とリリースの回数を作成者が置いたもの）の3か月の修正の記録で、6つの割り方の値と順位を比べ、作成者が置いた壊れやすさの順（B＞C＞A）をどれだけ当てるかを数えました。置き方を変えた36通りと、期間の長さ（1・3・12か月）も確かめました。**

例のアプリとチームは架空のもので、実在の会社・開発の道具の名前は使っていません。比べているのは作成者が置いたチームの進め方と壊れやすさで、人や属性の比べではありません。

関連する記事：分母を「全体」にするか「対象者」にするかの一般の話は 902「分母を「全体」にするか「対象者」にするかで、割合はどう変わるのか？」、台帳からキャンセル率を出すときの分母と分子の決め方は 1018「キャンセル率は、何を分母にするかでどう変わるのか？」、反応率の分母で良い投稿が入れかわる話は 837「反応率の分母（フォロワー・表示・再生）で、良い投稿は入れ替わるのか？」で扱っています。同じ企画の1095「リリースを細かく分けると、1回あたりの障害は減って見えるのか？」は、この記事の④（リリース1回あたり）と同じしくみで、同じ量の変更を何回に分けて届けるかだけで1回あたりの障害が動く話です。1092「千行あたりのバグ数で、チームどうしを比べてよいのか？」は、③と同じ千行あたりの物差しが、行数の書き方やテストの厚さでずれる話です。この記事は、開発の記録に固有の分母（修正の件数・登録の回数・行数・リリースの回数）と、あとから見つかる壊れの数え方に絞ります。

## 主な結果

### 6つの率の値（2,000回の3か月を合わせた、合計÷合計。⑥は2,000回の平均。`results/rates_by_team.csv`）
| | A（大きくまとめて直す） | B（小さく分けて直す） | C（その間） |
|---|---|---|---|
| 置いた壊れやすさ k（60行の修正1件あたり） | 0.05 | **0.075** | 0.06 |
| 3か月の修正の件数（平均） | 119.95件 | 269.79件 | 179.71件 |
| 修正1件の行数（平均） | 165.38行 | 41.23行 | 82.48行 |
| 3か月の壊れの件数（平均） | 11.377件 | 14.526件 | 12.681件 |
| ①修正1件あたり | **0.0949** | 0.0538 | 0.0706 |
| ②変更の登録1回あたり | **0.0519** | 0.0144 | 0.0297 |
| ③変更した千行あたり | 0.5736 | **1.3059** | 0.8555 |
| ④リリース1回あたり | **1.8962** | 0.6052 | 1.0568 |
| ⑤期間内に見つかった分÷修正の件数 | **0.0728** | 0.0454 | 0.0596 |
| ⑥大きさの帯をそろえた修正1件あたり | 0.0604 | **0.0756** | 0.066 |

- **壊れやすさを最も高く置いた B が、①修正1件あたりでは3チームで最も低く（0.0538）、③千行あたりでは最も高く（1.3059）出た**。①②④⑤の順は A＞C＞B で、置いた順（B＞C＞A）の逆だった
- ①〜④の値は、置いた分布からの式どおり（式は A 0.095・B 0.054・C 0.0702 など。行数を整数に丸める前の式との差は最大0.72%）。B は1件の修正が小さく、小さい修正は1件あたりの壊れが少ないので、①では低く出る。B は1件を多くの登録に分け（1件あたり3.75回）、リリースも多いので、②④ではさらに低く出る
- ③が置いた順と合ったのは、大きさの効き方を β＝0.7（行数が2倍でも壊れは2倍より少ない）と置いたため。β＝1 なら③は k に比例し（式どおり）、β＝1.3 では A が上がる（下の確かめ）
- ⑤：期間の終わりまでに見つかった壊れの割合は、B・C で 84.34%・84.5%（修正の日がでたらめなときの式 84.47%）、修正が月末に寄る A で 76.7% と、A だけ多く欠けた。それでも⑤の順は①と同じだった

### 3か月ごとに、置いた順をどれだけ当てたか（2,000回、`results/rank_accuracy.csv`・`results/top_team_share.csv`）
| 率 | B を1位にした割合 | 順をすべて当てた割合 | A を1位にした割合 |
|---|---|---|---|
| ①修正1件あたり | 4.6% | 2.1% | 72.8% |
| ②変更の登録1回あたり | 0.1% | 0.05% | 89.35% |
| ③変更した千行あたり | **84.4%** | 68.25% | 1.4% |
| ④リリース1回あたり | 0.4% | 0.2% | 88.25% |
| ⑤期間内に見つかった分÷修正の件数 | 7.6% | 3.6% | 62.65% |
| ⑥大きさの帯をそろえた修正1件あたり | 48.8% | 32.7% | 22.3% |

- 3か月の壊れは1チーム平均11.377〜14.526件しかなく、どの率も3か月ごとに振れた。③でも A や C が1位になる3か月があった（A 1.4%・C 14.2%）
- ⑥は値の平均では置いた順に近い（A 0.0604・B 0.0756・C 0.066）が、帯ごとの件数が少なく振れるため、3か月ごとの当たりは48.8%にとどまった

### 期間の長さ（各1,000回、`results/by_period.csv`）
| 率 | 1か月 | 3か月 | 12か月 |
|---|---|---|---|
| ①修正1件あたり：B を1位 | 13% | 4.9% | 0% |
| ③変更した千行あたり：B を1位 | 69.2% | 86.4% | **98.8%** |
| ⑥大きさの帯をそろえる：B を1位 | 39.9% | 48.1% | 58.8% |

- 期間を長くすると、③は置いた順に近づき、①②④⑤は置いた順の逆（A が1位）に固まった（12か月で B を1位にした割合は①②④⑤すべて0%）。長く数えても、割り方が持つ片寄りは消えない
- 主な結果の3か月（84.4%）と、この表の3か月（86.4%）は、別の乱数で作ったので少し違う

### 確かめ：置き方を変えると（36通り、各300回、`results/grid.csv`）
| 大きさの効き方 β | ①修正1件あたり：B を1位 | ③千行あたり：B を1位 | ⑥帯をそろえる：B を1位 | ③の式の順 |
|---|---|---|---|---|
| 0.4 | 17.67〜74% | 92.67〜99.67% | 39.67〜95.33% | B＞C＞A |
| 0.7（基本） | 4〜36% | 84〜100% | 31〜91.33% | B＞C＞A |
| 1.0 | 0〜7% | 64.67〜99% | 22.67〜87% | B＞C＞A |
| 1.3 | 0〜1% | 32〜94% | 16.67〜82% | A＞B＞C または B＞A＞C |

- 各行は、B の k（0.075・0.09・0.12）と行数の散らばり（0.5・0.8・1.1）の9通りの範囲
- **③千行あたりで3か月ごとに B が1位になったのは、36通りで32〜100%と、置き方で大きく動いた**。式の上で③が B を1位にするのは36通り中33通りで、β＝1.3・B の k＝0.075 の3通りでは A が1位になった
- 式の上で B を1位にする通りは、①で36通り中6通り（β＝0.4 で B の k が0.09以上）、②④では0通りだった
- 36通りのうち35通りで、3か月ごとの当たりは③が⑥より高かった。⑥は片寄りが小さいかわりに、3か月では振れが大きい
- 見つかるまでの日数の平均を7・14・28日にすると、期間内に見つかった割合は B で 92.36%・84.43%・70.28%（式 92.22%・84.47%・70.14%）、A で 85.21%・76.19%・62.02% と、どの日数でも A のほうが多く欠けた（`results/by_delay.csv`）

## 注意（言えないこと）
- 架空のデータです。チームごとの壊れやすさ、修正の大きさ、登録とリリースの回数、大きさの効き方は作成者が置いたもので、結果はこれで決まります。①〜④の値は置いた分布からの式どおりで、③で B が1位になる割合も置き方で32〜100%と動きました
- 「本当の壊れやすさ」は、作成者が60行の修正1件あたりで置いたものです。どの割り方が正しいかは、何を比べたいか（修正1件の危うさか、変更の量あたりか、リリースのたびの障害か）で決まり、この記事では決められません
- 壊れはどれも1件として数え、重さの違い、どの修正が起こした壊れかの取りちがえ、同じ壊れを2回数えることは入れていません
- 実在の会社・チームの開発を表すものではなく、チームの進め方の良し悪しも言えません
