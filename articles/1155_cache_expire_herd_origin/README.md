# 1155 同じものを大勢が同時に取りに来ると、置き場所から消えた瞬間に、元のデータへ何件の問い合わせが流れるのか？（キャッシュの当たり率）

よく使うデータを手元に置いておく置き場所（キャッシュ）は、決めた時間がたつとデータを消し、次の問い合わせで元のデータを取りに行き直します。とても人気のあるデータだと、消えてから元のデータが戻るまでのわずかな間にも問い合わせが次々に来て、そのどれもが置き場所で外れ、元のデータへ取りに行きます。当たり率で見ると99.9%を超えていても、消えた瞬間だけは元のデータに問い合わせがまとまって流れこみます。**ここでは、作成者が置いた架空のアプリの人気のデータ1件（問い合わせは1秒に平均1,000件、置き場所に60秒置く）で、消えた1回あたり元のデータへ何件流れるかを2,000回数えました。元のデータが同時にさばける数を置き、それを超えると1件ずつ遅くなるときに何件に増えるかも数えました。問い合わせの多さ×取りに行く時間×さばける数の27通りでも確かめました。問い合わせと時間はすべて作成者が置いた分布からの乱数で、実機の計測はしていません。**

関連する記事：同じ企画の 1149「当たり率90%と99%の差は、平均の応答時間で何倍の差になるのか？」は、当たり率と平均の応答時間の関係を、外れがでたらめに起きると置いて扱っています。874「利用が8割を超えると、待ち時間はなぜ急に伸びるのか？」は、さばける量に近づくと急に悪くなる形を窓口の待ち時間で、883「開店直後の行列は、何分で解消するのか？」は、一度にまとまって来た人の行列を扱っています。同じ企画の 1154「置いておく時間を長くすると、当たり率が上がる分と、古いデータを返す割合が増える分はどう釣り合うのか？」は、置いておく時間の長さで当たり率と古いデータの割合がどう動くかを扱っています。この記事は、置いておく時間（60秒）を決めたまま、置き場所から消えた瞬間に外れがまとまって起きる件数に絞ります。

## 主な結果

### 基本（遅くならないとき、2,000回、`results/by_capacity.csv` の1行目）
| 物差し | 値 |
|---|---|
| 消えた1回あたり、元のデータへ流れた件数の平均 | **40.92件** |
| 中央値・90%点・99%点・最大 | 40.0件・55.0件・64.0件・79件 |
| 置き場所が埋まるまでの時間の平均 | 40.02ms |
| 60秒の当たり率（6万件のうち） | **99.932%** |
| 元のデータへの問い合わせ（60秒を通した1秒あたり） | 0.682件 |
| 元のデータへの問い合わせ（消えた直後の0.1秒を1秒あたりに直す） | 409.2件（**600.0倍**） |

- **当たり率は99.932%なのに、消えた1回ごとに平均40.92件が、40ms ほどのあいだに元のデータへ流れた**。60秒を通した平均で見ると元のデータへの問い合わせは1秒に0.682件だが、消えた直後の0.1秒だけを1秒あたりに直すと409.2件で、600.0倍だった
- 目安の式「1＋来る速さ×取りに行く時間の平均」は91.65件だが、乱数では40.92件と半分ほどだった。取りに行く時間がばらつくと、あとから取りに行った速い1件が先に戻って置き場所を埋めるため。取りに行く時間を毎回同じ（90.65ms）にすると91.36件で、目安の式（91.65件）とほぼ同じだった（式どおり）
- 比べる値として、待っている問い合わせを1件にまとめて取りに行く場合は、元のデータへの問い合わせは1件（作りどおり）。そのかわり、戻るまでに来た平均90.69件が、平均45.23ms 待つことになった

### 元のデータが同時にさばける数を置くと（各500回、`results/by_capacity.csv`）
| 同時にさばける数 | 同時に取りに来る件数の目安 ÷ さばける数 | 消えた1回あたりの平均 | 90%点 | 無制限との比 | 60秒の当たり率 |
|---|---|---|---|---|---|
| 無制限 | － | 40.92件 | 55.0件 | 1.0倍 | 99.932% |
| 60件 | 1.51 | 41.16件 | 53.0件 | 1.006倍 | 99.931% |
| 40件 | 2.27 | 42.21件 | 57.0件 | 1.032倍 | 99.93% |
| 20件 | 4.53 | 59.19件 | 94.1件 | 1.446倍 | 99.901% |
| 15件 | 6.04 | 98.38件 | 181.1件 | 2.404倍 | 99.836% |
| 10件 | 9.07 | **245.34件** | 489.1件 | 5.996倍 | 99.591% |
| 7件 | 12.95 | 824.0件 | 1805.3件 | 20.137倍 | 98.627% |
| 5件 | 18.13 | **3533.56件** | 7727.0件 | 86.353倍 | 94.111% |

- 同時に取りに来る件数の目安（来る速さ×取りに行く時間の平均＝90.65件）がさばける数の数倍までは、流れる件数はほとんど増えなかった（60件・40件で1.006〜1.032倍）
- **さばける数を10件・7件・5件と減らすと、245.34件・824.0件・3533.56件と急に膨らんだ**。取りに来る件数が増えるほど1件ずつが遅くなり、置き場所が埋まるのが遅れ、そのあいだにさらに問い合わせが来るため。この膨らみ方は、作成者が置いた「超えると c÷n に落ちる」という遅くなり方の決まりから出たもの
- 5件では500回のうち3回が2万件の打ち切りに届いたので、3533.56件は少なめに出ている
- 60秒の当たり率は、5件のときでも94.111%だった。当たり率だけを見ると、元のデータに数千件がまとまって流れていることは読めない

### 置き方を変えた27通り（各40回、`results/grid.csv`）
- 遅くならない9通りでは、消えた1回あたり4.35〜464.48件で、目安の式の0.273〜0.786倍だった。取りに行く時間が長く、問い合わせが多いほど、目安の式との差が大きかった
- さばける数を置いた18通りのうち、同時に取りに来る件数の目安がさばける数の10倍以下の14通りは、目安の式の0.433〜0.899倍で、打ち切りはなかった
- 10倍を超えた4通り（17.0〜84.99倍）では、平均が2173.15件以上になり、40回のうち19〜40回が3,000件の打ち切りに届いた
- つまり、流れる件数の大きさは「来る速さ×取りに行く時間」でおおよそ決まり、元のデータのさばける数がそれを大きく下回ると、置いた遅くなり方の決まりのもとで一気に膨らんだ

## 注意（言えないこと）
- 架空のデータです。問い合わせの来かた、取りに行く時間の分布、さばける数と遅くなり方の決まりは作成者が置いたもので、結果はこれで決まります。とくに、さばける数が少ないときの膨らみ方は、置いた「c÷n に落ちる」決まりの写しです。実在のソフトやサーバーの動きを表すものではありません
- 人気のデータ1件だけを見ています。ほかのデータへの問い合わせや、同じ時刻に多くのデータが一度に消える場合は入れていません
- 取りに行って失敗する・やり直す、時間切れで打ち切る、といった動きは入れていません。実際には、元のデータが混むとやり直しでさらに問い合わせが増えることがあります（推測）
- まとめて取りに行く場合の待ち時間は、比べる値として出しただけです。どの置き方を選ぶべきかの助言ではありません。費用の見込みも扱っていません
