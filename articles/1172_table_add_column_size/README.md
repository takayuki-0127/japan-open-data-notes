# 1172 1行に項目を1つ足すと、表全体の量は足した項目の大きさの分だけ増えるのか？（データ量の見込み）

表に項目（列）を1つ足すとき、増える量を「足した項目の大きさ×行数」と見込むことがあります。4Bの数を100万行に足せば4MB、という見込みです。けれども、表を保存するときには、項目をその大きさの倍数の位置にそろえる詰め物、行の大きさを8の倍数に切り上げる決まり、決まった大きさのページに行を詰める決まりなどがあります。そのため、実際の増え方は、足した項目の大きさだけでなく、今の行の大きさと足す場所で決まります。**ここでは、作成者が置いた架空の表の保存の決まり（行の見出し・そろえる位置・行の切り上げ・ページの大きさを置いたもの）と、乱数で作った架空の表（文章の項目の長さや空の行を乱数で作ったもの）で、項目を1つ足したときの表全体の増え（ページの数×ページの大きさの差）を、「足した項目の大きさ×行数」で割って数えました。基本の表と、決まった大きさの項目だけの表で足し方を変えた11通り、行の数を変えた5通り、でたらめに作った表500個で確かめました。**

決まった大きさの項目だけの表では、どの行も同じ大きさなので、行の増えは「切り上げたあとの差」でちょうど決まります（作りどおり）。たとえば56Bの行に1Bを足すと64Bになり、8B増えます。この記事で数えて新しく分かったのは、文章の項目があって行の大きさがばらつく表での増え方、行の数による違い、でたらめに作った表での散らばりです。

関連する記事：同じ企画の 1161「1件あたりの大きさの平均に件数を掛けた見込みは、とても大きい件が少しまざるとどれだけ外れるのか？」は、1件の大きさの平均×件数の見込みが、分布の形で外れる場面を扱っています。同じ企画の 1168「小さなファイルがたくさんあると、大きさの合計と実際に使う量はどれだけ違うのか？」は、ファイルを決まった大きさの区画に切り上げるために、大きさの合計と使う量が合わない場面を扱っています。この記事は同じ「切り上げ」の仕組みを表の行に当て、項目を1つ足したときに、今の行の大きさと足す場所で増え方が0倍から数倍まで変わる点に絞ります。

- 同じ表で、印1Bのすぐ後に1Bを足すと、もともとの詰め物に収まり、行の大きさもページの数も変わらなかった（0倍）
- **文章のある表では、末尾に4Bを足すと1.3455倍、1Bで3.1293倍だった**。行の長さがばらつくので、切り上げで8B増える行と増えない行がまざる（4Bでは66.52%の行が大きくなった）
- 同じ2Bでも、末尾なら1.9333倍、印1Bのすぐ後なら2.6911倍だった。印のすぐ後に入れると、そのあとの金額4Bがそろえる位置の都合で4B後ろにずれ、メモも4Bずれる

- 行の大きさの差だけで割った値（`row_increase_ratio`）と、ページの数の差で割った値は、100万行ではどれも近かった（文章ありの末尾4Bで1.3304倍と1.3455倍）。ページに詰めるときの余りの分は、100万行ではわずかだった

## 注意（言えないこと）
- 架空のデータと、作成者が置いた架空の保存の決まりです。見出しの大きさ、そろえる位置、行の切り上げ、ページの大きさを変えれば、倍率は変わります。実在のデータベースの保存のしかたを表すものではありません
- 項目を足したときに、すでにある行をすべて書き直して詰め直すと置きました。足す前の行を書き直さずに残すやり方や、空いた所をあとで詰め直すやり方は入れていません
- ページは隙間なく前から詰めると置きました。あとで行を書きかえるために空きを残す決まりや、消した行の跡は入れていません
- 表を探すための別の仕組み（索引など）の量は数えていません
- ページの大きさ8,192Bは2を掛け合わせた数で置きましたが、表の量をMBで書くときは1MB＝100万Bで数えました（この企画のほかの記事と同じ数え方）
- 容量をどれだけ用意するかや、その費用、表の作り方の良し悪しは扱っていません
