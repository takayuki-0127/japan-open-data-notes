# 244 毎月のレポートは、どんな順番で書くと伝わるか（実務の型）

月次レポートの最初の3段を「① 結論の1文 → ② 要因（大きい順に2つまで）→ ③ 次に確かめること」の順にそろえ、その文を数字から自動で作る型を、架空の小売チェーン（5部門、2024〜2025年の24か月、予算つき）で試したフォルダです。要因の選び方（金額で選ぶか、率で選ぶか）で、レポートに書く「いちばん大きな要因」がどれだけ入れ替わるかも数えました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A244 | 月次レポートを結論→要因→次に確かめることの順に、数字からどう書くか。要因は金額と率のどちらで選ぶか | 予算との差の部門別の分解（SQL のウィンドウ関数と `RANK()`）、文のテンプレート、金額と率の順位の比較 | `sql/02_contrib.sql`、`src/a244_make_data.py`・`a244_report.py` |

## 主な結果
- 部門ごとの予算との差を足すと、どの月も全体の差と一致した（差の最大0）。この足し算が合うことを確かめてから文を作る
- 例（2025年9月）：「9月の売上は10.2億円で、予算比-1.1%（-12百万円）、前年同月比+1.6%。」「予算との差の主な要因は日用品（-10百万円）・その他（+5百万円）で、部門の動きの69%。」「次に確かめること：日用品の不足が来月も続くか（客数か客単価か）。」
- いちばん大きな要因を**率**（予算比の%）で選ぶと、12か月中7か月で、**金額**で選んだ部門と違う部門になった。率で1位になったのは「その他」が6か月で、売上の4.4%しかない部門。率は小さい部門ほど大きく振れるので、要因の段は金額の大きい順に並べ、率は横に添えるのがよい（推測）
- 上位2部門で、部門の動き（差の絶対値の合計）の56〜85%（中央値66%）を説明できた。12か月中4か月は、プラスの部門とマイナスの部門が打ち消し合い、部門の差の大きさの合計が全体の差の2倍を超えた。この月は「全体の差は小さいが、中では大きく動いている」と1文足す

## 動かし方
```
pip install -r requirements.txt
cd src && python a244_make_data.py && python a244_report.py
```

## データ
- `data/monthly_dept.csv`：架空の小売チェーンの部門別の月次の実績と予算（百万円）。作成者が乱数で作成（seed 244）。実在の会社の数字ではありません
- `results/auto_headlines.csv`：月ごとに自動で作った3つの文と、金額・率の1位の部門
- `results/checks.json`：照合と集計の結果

## 注意
- 架空のデータなので、「率で選ぶと7か月で入れ替わる」という数は、部門の大きさや振れ方の置き方で変わります。言えるのは「小さい部門が率の1位に来やすい」という向きまでです
- 「次に確かめること」は、金額1位の部門を機械的に入れたひな形です。実際には、担当者が理由（客数か客単価か、一時的か）を書き足す前提です
- `sql/02_contrib.sql` は T-SQL と DuckDB で同じ文が動く書き方にし、DuckDB で動かしました（`CAST(… AS FLOAT)` だけ DOUBLE に置き換え）。SQL Server そのものでは動かしていません
