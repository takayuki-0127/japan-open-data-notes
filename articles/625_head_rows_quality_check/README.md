# 625 データの先頭1,000行だけで中身を確かめると、後ろにある異常は何%見つかるのか（実務の型）

大きなファイルを受け取ったとき、先頭の数百〜数千行だけを開いて中身を確かめることがあります。ファイルが日付順なら、先頭は最も古い部分です。**ここでは、架空の100万行のファイル（日付順に1年分）に異常な行を1,000行（0.1%）入れ、入り方3通り（全体にばらばら、最後の1日に固まる、200日目の1日に固まる）について、先頭 n 行・無作為に n 行・等間隔に n 行・100の区間から同じ数ずつの4通りで確かめたとき、異常を1行でも見つける確率を出しました。** 無作為は超幾何分布で正確に、等間隔と区間ごとは2,000回のくり返しで出しています。SQL（DuckDB）でも3通りの取り方を書きました。数字は置いた異常の入り方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A625 | 確かめる行の取り方で、異常の見つかる確率はどう変わるか | 100万行・異常1,000行の位置を3通り、確かめる行数 1,000〜20,000、超幾何分布（無作為）と2,000回のシミュレーション（等間隔・区間ごと）、seed 625 | `src/a625_head_check.py` |
| SQL | 先頭・無作為（SAMPLE）・区間ごと | DuckDB 版（1スレッドで実行）、T-SQL 版（未検証） | `src/02_sample_check_duckdb.sql`・`src/01_sample_check_tsql.sql` |

## 主な結果
- **先頭の行だけで確かめる**：異常が最後の1日や200日目に固まっていると、2万行（2%）を見ても見つかる確率は 0%。全体にばらばらの場合は、このファイルでは先頭1,000行に異常がなく、2,000行で見つかった（確率ではなく、その位置しだい）
- **1,000行（0.1%）を確かめる**：無作為で 63.2%（どの入り方でも同じ）、等間隔で 66〜70%、区間ごとで 64〜66%
- **95% の確率で見つけるのに要る行数**：無作為で 2,995行（異常が全体の 0.1% のとき）。5,000行で 99.3%、1万行で 99.996%
- 異常が1日分に固まっていても、全体から散らして取れば、その日の行に当たる回が出るので、確率はばらばらの場合とほぼ同じになった
- SQL（最後の1日に固まる場合、5,000行）：先頭 0行、SAMPLE 9行、区間ごと 6行の異常が見つかった


## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- 無作為に取る場合の確率が、1 − (1 − 0.001)^n とほぼ一致すること
- 先頭5,000行の異常の数が、SQL（DuckDB）と Python で一致すること

## データ
- データファイルは置いていない。データはコードの中で乱数から作る（seed 625）

## 注意（言えないこと）
- 架空のデータ。異常の割合と位置は作成者が置いたもので、結果はこれで決まる
- 「1行でも見つける」確率だけを数えた。異常の割合を見積もる精度は扱っていない
- 異常の割合が 0.1% より小さいと、要る行数は反比例して増える（0.01% なら約3万行）
