# 594 日をまたぐ夜のシフトを、開始日で数えるか日ごとに分けるかで、日ごとの労働時間はどれだけ違うのか（実務の型・日をまたぐ時間の集計）

22時〜翌6時のように0時をまたぐ勤務は、「どの日の時間」として数えるかで日ごとの合計が変わります。勤務の記録を開始日でまとめれば1行で済みますが、0時で分ければ2つの日に分かれます。**ここでは、架空の勤務記録（2025年の1年分、10,780回のうち4,016回が0時をまたぐ）で、①開始日に全部つける、②0時で日ごとに分ける、の2通りで日ごと・月ごとの時間を比べました。** あわせて、日付を開始日だけ持ち、開始と終了を「時刻だけ」で持つ表で、終了から開始をそのまま引いたときの誤りも数えました。シフトの型と人数は作成者が置いたもので、数字はその仮定で決まります。休憩の差し引きは扱っていません。

## 主な結果
- 勤務10,780回（2024年12月31日〜2025年12月31日に開始）。0時をまたぐのは4,016回（37.3%）。合計97,819.8時間（どちらの数え方でも同じ）
- **日ごとの差**（2025年の365日）：開始日につけた値と日ごとに分けた値の差は、平均21.4時間（その日の合計の8.2%）、最大45.4%（1月19日：260.25時間 対 179.0時間）。5%を超えて違う日は225日。2つの日ごとの値の相関は0.88
- **月ごとの差**：−0.32%〜+0.68%。差の大きさは、その月の最終日と前の月の最終日に始まった夜勤の、0時以降の時間の差で決まる（11月は+53.5時間）
- **時刻だけで持つ表**：終了から開始をそのまま引くと、0時をまたぐ4,016回すべてがマイナス（22時〜6時の夜勤は−16時間）。1年の合計は1,435.8時間になり、本当の97,819.8時間より98.5%少ない。終了が開始より前なら24時間を足すと、すべて一致した

## 動かし方
```
pip install -r requirements.txt
cd src && python a594_shift_split.py
```
数秒で終わります。`data/shifts.csv`（shift_id・staff_id・shift_type・start_at・end_at）と、時刻だけの形にした `data/shifts_time_only.csv`（shift_id・work_date・start_time・end_time）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 日ごとに分けた時間（2026年1月1日にはみ出す69.5時間を含む）が、Python と DuckDB の SQL（`02_split_duckdb.sql`）ですべての日で一致した
- 時刻だけの表で24時間を足した値は、日時から出した時間と全件で一致した
- T-SQL 版（`01_split_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 職員80人（架空のID）。シフトの型は、日勤（9時〜・9時間）、遅番（14時〜・8時間）、準夜（17時〜・8時間）、夜勤（22時〜・8時間）、長い夜勤（20時〜・12時間）
- 1日に入る人数はポアソン分布で、土日は日勤・遅番を少なめにした。開始は±15〜30分、終了は0〜60分ずらした
- 1回の勤務は24時間未満

## 注意（言えないこと）
- 架空のデータ。実際の職場の勤務記録ではない
- どちらの数え方を使うべきかは、何に使う集計か（人員の配置、日ごとの作業量、勤務の記録など）と、職場のルールによる。どちらかが正しいという主張ではない
- 休憩の差し引き、深夜の時間帯の区分、労務・法令上の扱いは扱っていない。労務や法令についての助言ではない
