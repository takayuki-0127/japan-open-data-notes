# 341 月次の数字は、締めてから何日たてば「確定」と言えるのか（実務の型）

架空の取引36か月分（約41万件）に、区分ごとの「計上の遅れ」を入れて、締め後の営業日数ごとに月の合計が最終値の何%まで入っているかを数えたフォルダです。早く出す代わりに、過去の入り方から見込みで補ったときのずれも出しました。SQL は DuckDB で動かしました。T-SQL 版は `src/01_completeness_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A341 | 月の数字は、締め後の何営業日目で最終値にそろうか。見込みで補うとずれはどれだけ縮むか | 4区分（店頭の売上・請求書の売上・返品・経費精算）の取引に遅れの分布を置く。締め後 k 営業日の時点の合計÷最終値を36か月で比べる。過去12か月の割合で割り戻す見込み（全体で／区分ごとに）を24か月で試す | `src/a341_close.py`、`src/01_completeness_tsql.sql` |

## 主な結果
- 月の利益（売上−返品−経費）が最終値に対して入っている割合（36か月の中央値）：0営業日目 83%、1営業日目 89%、3営業日目 94%、5営業日目 97%、10営業日目 99.7%
- 月ごとの幅は大きい：5営業日目は 89%〜99.8%。最終値の1%以内に入った月は、5営業日目 1/36、10営業日目 28/36、15営業日目 33/36。**36か月すべてが1%以内にそろったのは20営業日目**、0.1%以内は60営業日目
- 区分ごと（金額の割合）：店頭の売上は1営業日目で99.7%。請求書の売上は1営業日目 79%・5営業日目 92%・10営業日目 98%。返品・値引きは5営業日目 81%、経費精算は5営業日目 73%・10営業日目 88%
- 引く側（返品・経費）が遅れて入るので、10営業日目を過ぎると最終値を上回る月がある（最大101.2%）
- **見込みで補う**（最終値とのずれ、24か月の平均）：入っている分だけ 1営業日目 12.5%／3営業日目 7.1%／5営業日目 3.8%／10営業日目 0.9% → 全体の割合で割り戻す 2.8%／2.4%／2.2%／0.9%。区分ごとに割り戻す形はほぼ同じ（5営業日目 2.3%）で、良くはならなかった。補っても最大7〜8%ずれた月がある

## 動かし方
```
pip install -r requirements.txt
cd src && python a341_close.py
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL で出した「k営業日目の割合」は、pandas で別に計算した値と一致した（コード内の assert）

## 注意（言えないこと）
- すべて架空のデータです。「何営業日目で何%」は、置いた遅れの分布で決まります。実際の会社の締めの早さを表すものではありません
- 営業日は土日だけを除いて数えました（祝日は入れていません）
- 金額の訂正や取消は入れていません（それは 342 で扱いました）。遅れて入る取引だけです
- 見込みは「過去12か月の割合で割り戻す」形だけを試しました
- T-SQL 版は SQL Server 本体では動かしていません
- 週次の数字をいつ送るかは 280 で扱いました。この記事は、月次の数字が固まる時点に絞っています
