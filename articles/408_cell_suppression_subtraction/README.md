# 408 件数の小さいセルを隠した集計表は、引き算で何セル分かってしまうのか（実務の型）

件数の小さいセルを「x」で隠した集計表（行・列の合計つき）で、隠したセルのうち何セルが合計からの引き算で分かるかを、架空の表で数えたフォルダです。F146（ノイズで置き換える方法）とは別の方法（セルを隠す）を扱います。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A408 | 隠したセルのうち、行・列の合計からの引き算で分かるのは何%か。追加で隠すとどう減るか | 架空の40地域×8区分の表を1,000枚（seed 408）。1以上10未満を隠す。引き算のくり返しで分かるセルを数える。線形計画で、合計と矛盾しない値の範囲も出す（100枚）。隠す境目・地域の数・地域の大きさを変える | `src/a408_suppression.py`、`src/01_suppression_check_tsql.sql`（未検証） |

## 主な結果
- **基本の設定（40地域×8区分、10未満を隠す、1,000枚）**：1枚あたり48.0個（全セルの15.0%）を隠す。隠したセルの13.5%が引き算で分かる。1セル以上分かる表は100%。隠したセルに入る件数は全体の1.33%
- **合計と矛盾しない範囲（100枚・4,959セル）**：値が1つに決まる13.9%、3つ以内に絞れる19.4%、範囲の幅の平均5.7
- **追加で隠す**（隠したセルが1つだけの行・列で、いちばん小さい出ているセルを隠す）：引き算で分かる0%、値が1つに決まる0%、3つ以内0%。「10未満である」と分かるセルは6.3%、範囲の幅の平均20.3。追加で隠したセルは1枚あたり6.5個（最初に隠した数の13.5%）、件数では全体の0.42%
- **隠す境目**（引き算で分かる割合／追加で隠す数の割合）：3未満 78.3%／60.2%、5未満 38.5%／35.0%、10未満 14.2%／14.2%、20未満 4.5%／4.5%
- **地域の数**：5地域 51.0%、10地域 30.7%、20地域 20.2%、40地域 13.8%、100地域 11.9%、200地域 11.7%
- **地域の大きさ**：中央100人（42.1%を隠す）3.2%、中央300人 13.8%、中央1,000人（2.1%を隠す）53.4%、中央3,000人（0.2%を隠す）96.9%

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の SQL で数えた「隠したセルが1つだけの行・列」の数が、NumPy の値と一致する（コード内の assert）

## データ
- `data/example_table_true.csv`・`data/example_table_published.csv`：例の表（隠す前と、隠した後）。作成者が乱数で作成（seed 408）

## 注意（言えないこと）
- 架空の表。割合は、地域の人数の置き方と表の大きさで変わる
- 行と列が1つずつの表だけ。複数の表（別の切り口、年ごと）の間の引き算は扱っていない
- 追加で隠す決まりは簡単なもの1つだけ。隠す件数を最小にする方法は試していない
- 「分かる」は、値がぴったり決まること・3つ以内に絞れることで数えた
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
