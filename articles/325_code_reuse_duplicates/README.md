# 325 同じ処理を、何回書き直していたか（④ 振り返り R105）

このリポジトリの記事フォルダにある Python のコード（src/）を関数ごとに取り出し、別の記事に「まったく同じ関数」「ほぼ同じ関数」がどれだけあるかを数えたフォルダです。[F275](https://github.com/takayuki-0127/japan-open-data-notes/tree/main/articles/F275_sql_change_requests)（SQL は共通にまとめると直す所が1か所になる）の見方を、自分のコードに当てました。データの使い回しは [F124](https://github.com/takayuki-0127/japan-open-data-notes/tree/main/articles/F124_data_lineage_network) で数えたので、ここではコードだけを見ます。

## 問い

- 同じ関数は、いくつの記事に写されていたか。写したあとで書き方が分かれたものはいくつあるか
- 記事ごとに置いた共通ファイル（common.py）は、何通りあったか
- フォントの設定のような決まった処理は、何本の記事に、何通りの書き方で出てくるか

## 手法

| 手順 | 中身 |
|---|---|
| 関数を取り出す（`src/a325_extract.py`） | articles/*/src/ の .py（2,050ファイル、17.8万行）を構文解析し、関数（def）を5,065個取り出す。30トークン未満の小さな関数は除く（残り4,622個） |
| まったく同じ | 書式・コメント・docstring を除いた中身（ast.dump）が同じ関数 |
| ほぼ同じ | トークン4つの並びの集合どうしの重なり（Jaccard）が0.8以上。64個の MinHash で見積もる。文字列の中身（ファイル名や図の題）は同じとみなす |
| まとまり | 同じか、ほぼ同じ関数をつないだまとまりのうち、2本以上の記事にまたがるものを「同じ処理」と数える。その中に中身の違う版が2つ以上あれば「書き方が分かれた」 |
| 決まった処理の行 | フォントの設定、乱数の種、JSON への書き出しなどの行を正規表現で拾い、空白を除いた行が何通りあるかを数える |
| 集計（`src/a325.py`） | 記事のグループ別、処理のまとまり別に数える。同じ記事フォルダの中の重なりは数えない |

## 主な結果（`results/summary.json`）

- 4,622個の関数のうち、同じか、ほぼ同じ関数が別の記事にもあるのは1,354個（29%）。まったく同じものがあるのは1,312個（28%）
- 2本以上の記事にまたがる「同じ処理」は401組。うち369組は写しただけ（1通り）で、書き方が分かれていたのは32組（中央値2通り）
- いちばん多くの記事に出てくるのは、図を保存する `save`（99本・6通り）。次が `note`（36本・1通り）、フォントを設定する `setup_font`（23本・5通り）
- 関数の行数で数えると、2回目からの写しにあたる行は8,272行で、関数の行（49,528行）の17%
- common.py は453本の記事にあり、中身は313通り。いちばん多く使われた版でも15本で、247通りは1本でしか使われていなかった
- 日本語フォントの設定は577本すべての記事にあり、行の書き方は75通り。乱数の種を決める行は235本に217通り

| グループ | 記事 | py ファイル | 行 | 関数 | まったく同じ関数が別の記事にある | 同じか、ほぼ同じ関数が別の記事にある |
|---|---|---|---|---|---|---|
| 000–099 | 92 | 200 | 15,591 | 513 | 88% | 89% |
| 100–226 | 127 | 260 | 18,873 | 455 | 61% | 62% |
| F01–F99 | 97 | 512 | 42,528 | 1,035 | 7% | 9% |
| F100–F199 | 100 | 450 | 44,351 | 1,083 | 6% | 7% |
| F200–F255 | 36 | 183 | 19,083 | 451 | 2% | 2% |
| 精選 F256–F295 | 40 | 201 | 19,110 | 491 | 2% | 3% |
| 1000本計画 | 85 | 244 | 18,158 | 594 | 70% | 71% |

- 通常の記事（000〜226）と1000本計画は、同じデータから2〜5本を続けて作ったので、取得や整形のコードをそのまま写している（6〜9割）
- 看板記事（F）は、1本ごとにコードを書き起こしていて、別の記事と同じ関数は2〜9%しかない。同じ種類の処理（データを読む・図を保存する）を毎回違う形で書いていた、ということになる
- 「写したあとで別々に直した」ものは少ない（32組、関数の5%）。重なりのほとんどは、直さずに写したもの

## 確かめたこと

- 重なりのしきい値を0.7にすると30%、0.9にすると29%。60トークン以上の関数に限ると25%
- `save` や `setup_font` は数行の小さな関数で、何を「同じ処理」とみなすかは、しきい値より関数の切り方に左右される
- `src/a325_extract.py`（リポジトリのルートを渡す）と `src/a325.py` を空のフォルダで流し直し、data・results・figures が一致することを確かめた

## 動かし方

```
python src/a325_extract.py <japan-open-data-notes のルート>   # data/functions.csv.gz・files.csv・idioms.csv
python src/a325.py                                            # 集計と図
```

## 言えないこと

- 見つけられるのは、ほぼそのまま写した関数だけ。同じ目的の処理を違う書き方で書いたもの（看板記事に多いはず：推測）は、この方法では「別の関数」になる。「書き直した回数」は、ここで数えたより多い
- 記事ごとにフォルダを分け、そのフォルダだけで動くようにしたので、コードを写すのは決めた作り方の結果でもある。写しが多いこと自体が悪いとは言えない
- 関数の外に直接書いたコード（スクリプトの本体）は比べていない。関数の行は全体（17.8万行）の3割ほど
- SQL・R・ノートブックは見ていない。Python の .py だけ
