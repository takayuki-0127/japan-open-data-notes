# 705 リピート率を「30日以内」で数えるか「90日以内」で数えるかで、月ごとの比べ方はどれだけ変わるのか（実務の型・顧客の集計）

リピート率を「初回購入から W 日以内に2回目を買った人の割合」で出すとき、W の長さで値そのものが変わるうえ、データの最終日に近い月の顧客は W 日分の観察期間がないので、低く出ます。**ここでは、架空の顧客2.4万人（初回購入 2024年1月〜2025年6月、データの最終日 2025-06-30）で、W=30・60・90日と、観察期間の足りない月を出すか出さないかを比べました。** 2025年1月以降の顧客だけ「すぐ買い直す人」を40%→46%に増やしてあり（本当の変化）、それが見えるかも確かめます。数字は作成者が置いた買い直しの形で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A705 | 窓の長さと観察期間の足りなさで、月別のリピート率はどう見えるか | W=30・60・90日、全員を分母に入れる／月の最後の日から W 日たった月だけ出す。窓を1〜120日で動かした曲線も。DuckDB（1スレッド）と pandas で一致を確認。seed 705 | `src/a705_repeat.py`、`src/02_repeat_duckdb.sql`、`src/01_repeat_tsql.sql`（未検証） |

## 主な結果
- **窓の長さで値が変わる**：2024年7〜12月の初回の顧客で、30日以内47.0%、60日以内57.2%、90日以内62.1%
- **直近の月が落ちて見える**：全員を分母に入れると、2025年6月の初回は3つの窓とも33.9%。90日の窓では、2025年1〜6月の平均（60.4%）が2024年後半（62.1%）より **低く** 見える
- **本当は上がっている**：観察期間の足りない月を出さないと、2025年の月の平均は90日で68.1%（2024年後半62.1%）、30日で52.4%（47.0%）。置いた変化（すぐ買い直す人の増加）が見える
- **その代わり**：90日の窓では最後に出せる月は2025年3月で、最後の3か月は出せない。30日なら2025年5月まで出せる

## 動かし方
```
pip install -r requirements.txt
cd src && python a705_repeat.py
```
数秒で終わります。`data/purchases.csv` に購入（初回と2回目）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- DuckDB の SQL（ROW_NUMBER で1回目・2回目を取り、窓で数える）と、pandas の結果が一致した
- T-SQL 版（`01_repeat_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/purchases.csv`：customer_id・purchase_date（1人あたり1〜2行。3回目以降は作っていない）
- 仮定：初回購入日は一様。2回目までの日数は「すぐ（平均12日）40%・ゆっくり（平均70日）30%・買い直さない30%」。2025年1月以降の初回は「すぐ」を46%にした

## 注意（言えないこと）
- 架空のデータ。どの窓が正しいということはない。商品の買い直しの間隔に合わせて決め、窓の長さを数字と一緒に書く
- 月の途中の人だけ除く（初回から W 日たった人だけ）やり方は、月の前半の人だけが残るので、月の中で客層が違うと偏る。ここでは月ごと出す・出さないにした
- 実在の店の数字ではない
