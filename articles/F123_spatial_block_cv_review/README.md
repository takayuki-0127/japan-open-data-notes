# F123 「場所で分けて確かめる」と、記事の結論は変わったか？（空間ブロック交差検証の横並び）

看板記事 F123。note の記事：（公開後に記入）

## 問い

これまでの記事のうち、地図の上のデータで予測をしたもの（F03 地価・F37 地価の予測区間・F75 地価のガウス過程・F74 気温・F107 出生率のグラフニューラルネット）は、検証の分け方を2通り以上で試していました。地点をランダムに分ける検証と、場所（ブロック・都道府県）でまとめて外す検証です。

- 場所で分けると、どの記事の、どの数字が、どれだけ変わったか
- 同じ条件（同じ分け方・同じモデル・ブロックの大きさを変える）でやり直すと、何が言えるか
- 「どのモデルが一番か」という結論は、分け方で変わるか

## データ

新しいデータは取らず、これまでの記事のデータを再利用しました（`src/01_取得.py` で兄弟フォルダからコピーし、MD5 で同じものか確認）。

| データ | 元の記事 | 行数 | 目的変数 | 特徴量 |
|---|---|---|---|---|
| 地価公示 2026年 | F03 `data/features.csv` | 25,565 地点 | log(価格) | 地点の属性・駅の乗降客数・市区町村の人口など28 |
| 市区町村の合計特殊出生率（2018〜22年） | F107 `data/nodes.csv` | 1,841 区域 | 合計特殊出生率 | 若い女性の割合・所得・通勤・保育所・未婚割合など11 |
| アメダスの年平均気温（平年値） | F74 `data/normals_mean_temp.csv` | 915 地点 | 年平均気温（℃） | 標高 |

座標は緯度経度を日本付近の平面（km）に近似で直しました（`common.to_km`）。出生率の持ち家率・床面積の欠け（646区域）と地価の人口増減率の欠け（8地点）は、線形回帰のときだけ学習側の中央値で埋めています（LightGBM はそのまま扱える）。

## 手法

- **モデル4つ**：LightGBM（特徴量＋座標）、LightGBM（特徴量だけ）、線形回帰（リッジ、気温は標高＋座標）、近くの10地点の距離加重平均（座標だけ）
- **分け方**（5分割）：
  - ランダム（地点ごと）
  - ブロック：x km 四方のマスごと（地価 5・10・20・50・100km、出生率 10・20・50・100・200km、気温 20・50・100・200km）。地点数がそろうよう、大きいマスから順に一番少ない分割へ入れる
  - 都道府県ごと（気温は予報区ごと、63）
  - ブロック＋緩衝帯：テストの地点から一定距離以内の学習地点も外す
- ランダムとブロックは乱数の種を3通り（2026〜2028）で回して平均。都道府県と緩衝帯は1回
- 誤差：地価は「予測÷実際 −1」の絶対値の中央値（%）、出生率と気温は RMSE
- あわせて、テストの地点から一番近い学習地点までの距離（中央値）を記録

- **一番のモデルは、3つのデータとも分け方で変わらなかった**（地価・出生率は LightGBM（特徴量＋座標）、気温は標高＋座標の線形回帰）
- **入れ替わったのは下の順位**：地価では、ランダムなら「近くの地点の平均」（21.5%）が線形回帰（31.2%）より良く見えるが、20km ブロックで逆転（43.6% 対 32.0%）。出生率の都道府県ごとでは、線形回帰が LightGBM（特徴量だけ）を上回った
- **差の大きさは分け方で変わる**：地価の LightGBM と線形回帰の差は、ランダムで16.2ポイント、都道府県ごとで8.9ポイント。ランダムの検証だけでは「機械学習でどれだけ良くなるか」を約2倍に見積もる
- **ブロックが大きいほど誤差は増え、その増え方は一番近い学習地点までの距離でほぼ決まる**（図3）。地価で20km ブロックにすると、一番近い学習地点は0.6km → 5.5km に遠ざかる。座標だけのモデルが最も敏感で、地価の100km ブロックでは外れが99.6%（ランダムの4.6倍）
- 座標を足した LightGBM は、場所で分けても「特徴量だけ」より良いまま（地価の都道府県ごと 24.4% 対 26.0%、出生率 0.116 対 0.166）。座標は「近くの答えを覚える」だけでなく、地方ごとの水準の違いも持っている（推測）

### どの記事の結論が変わったか

- **F03**：「LightGBM で外れの中央値13.7%」は、まだ見ていない地域では18.7〜25.0%。順位（LightGBM が一番）は変わらない
- **F107**：「隣の出生率を使うと R² 0.74」は、都道府県ごとに外すと0.08。結論そのものが分け方しだいで、記事でもそう書いた
- **F37**：予測区間は、較正もブロックで取らないと90%区間に82%しか入らない。記事の結論（較正も場所で取る）は今回の結果と合う
- **F75・F74**：「地図だけの補間は、近くの平均とほぼ同じ」「特徴量（標高）を入れるほうが強い」は、場所で分けるとさらにはっきりする
- **F91**（手法の解釈）はランダムな80%／20%の分け方だけで、場所で分けた検証はしていない。ただし解釈の比較が主で、精度の主張は小さい

## 頑健性

1. **ブロックの大きさ**：地価5〜100km、出生率10〜200km、気温20〜200km で、どのモデルも大きくするほど誤差が増え、一番のモデルはどの大きさでも同じ（図2）
2. **都道府県・予報区ごと**：ブロックと同じ向き。地価・出生率ではブロック（20km・50km）より厳しい
3. **緩衝帯**（図5、`results/buffer.csv`）：テストの周りの学習地点を外すと、さらに悪くなる。地価の LightGBM（特徴量＋座標）は20km ブロックで19.9% → 緩衝帯20kmで26.7%、座標だけのモデルは44.0% → 84.6%。気温の LightGBM は0.92 → 2.05℃（緩衝帯100km）、標高＋座標の線形回帰は0.755 → 0.876℃
4. **乱数の種**（3通り）：誤差の標準偏差は、地価の log 価格 RMSE で0.009以下、出生率で0.0024以下、気温で0.027℃以下。分け方による差よりずっと小さい
5. **モデルの種類**：木・線形・近傍の3系統で、悪くなり方の順（座標だけ＞木＞線形）は3つのデータで同じ

## 言えないこと

- **どの分け方が「正しい」かは、使い道しだい**です。同じ地域の空き地点を埋めるならランダムに近く、まだデータのない地域に広げるならブロックや都道府県に近い
- ブロックの大きさの決め方（空間の相関が消える距離など）は今回は決めていません。大きさを変えた結果を並べただけです
- これまでの記事の数字（図1）は、記事ごとにモデルの設定・指標・分け方が少しずつ違い、厳密には同じ物差しではありません
- 気温の「LightGBM（特徴量だけ）」は標高しか使えず位置の情報がないため（R² がマイナス）、図からは外しました（表 `results/cv_summary.csv` には残しています）
- 3つのデータ・4つのモデルでの結果で、ほかのデータやモデル（グラフニューラルネットなど）に同じことが言えるかは、確かめていません

```

cd src
python 01_取得.py      # 兄弟フォルダ（F03・F107・F74）からデータをコピー（なければ同梱の data/ を使う）

```
