# 721 2つの列を区切りなしでつないでキーにすると、別の組み合わせが同じキーになる行は何件あるのか（実務の型）

店コードと商品コードのように、2つの列を文字としてつないで1つのキーにすることがあります。コードの桁数がそろっていないと、店「10」の商品「13」と店「101」の商品「3」が、どちらも「1013」になります。**ここでは、架空の120店×各60品（7,200組）の売上と目標の表で、区切りなし・区切りあり・2列のままの3通りでキーを作って目標をつなぎ、同じキーになった組の数、つないだあとの行数、目標の合計のずれを数えました。** DuckDB の SQL と Python で同じ結果になることを確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A721 | 区切りなしでつないだキーは、どれだけ別の組と重なるか | 架空の店コード1〜120・商品コード1〜300（どちらも0で桁をそろえない文字）、1店60品、店×商品ごとに売上と目標。区切りなし・区切り「-」・2列のままの3通りで目標の表をつなぐ。店の数を9〜999に変えた場合も各5回。seed 721 | `src/a721_concat_key.py`、`src/02_concat_key_duckdb.sql`、`src/01_concat_key_tsql.sql`（T-SQL：未検証） |

## 主な結果（7,200組）
| キーの作り方 | キーの数 | つないだあとの行数 | 目標の合計 | 本当の目標の合計とのずれ |
|---|---|---|---|---|
| 区切りなし（店コード＋商品コード） | 7,089 | **7,422** | 73,575,800円 | **＋3.21%** |
| 区切りあり（店コード＋'-'＋商品コード） | 7,200 | 7,200 | 71,289,600円 | 0 |
| 2列のまま結合 | — | 7,200 | 71,289,600円 | 0 |

- 区切りなしでは、111のキーに2組ずつ、計222組（3.08%）が同じキーになった。例：店10の商品13と店101の商品3がどちらも「1013」。111キーのうち88キーは1桁と2桁の店、22キーは2桁と3桁の店の組み合わせだった
- 同じキーの組は互いの目標も拾うので、つないだあとの行は222行ふえ、目標の合計は3.21%、売上の合計も3.14%多くなった
- 店が9店（1桁）だけなら重なりは0%、99店で3.18%、120店と999店で3.56%（各5回の平均）。桁数のまちまちなコードが混ざると起きる

## データ

- `data/targets.csv`：同じ店×商品の目標（円）

## 注意（言えないこと）
- 架空のデータです。店と商品の数、扱う品数は作成者が置いたもので、重なる組の割合はこれで決まります
- 区切り文字を入れる方法は、コードの中にその文字が出てこないことが前提です。2列のまま結合するのがいちばん確実です
- 0で桁をそろえたコード（「010」「003」など）なら、区切りなしでも重なりません。ただし途中で桁数を変えると同じことが起きます
- T-SQL の書き方は SQL Server では試していません（未検証）
