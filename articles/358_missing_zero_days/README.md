# 358 売上が0の日が表にないと、1日あたりの平均はどれだけ高く出るのか（実務の型）

売上の表には「売上のあった日」しか行がありません。その表でそのまま平均を取ると、売上0の日が分母から抜けます。どれだけ高く出るかを、架空の120店・2年分の日次売上で数えたフォルダです。0で埋めるときに定休日まで入れてしまう逆のずれと、7日の移動平均への影響も出しました。SQL は DuckDB で動かしました。T-SQL 版は `src/01_avg_daily_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A358 | 0の日が抜けると、1日あたりの売上はどれだけ高く出るか | 大20店・中40店・小60店の日次売上を、1日の会計の件数（ポアソン分布）から作る。売上のあった日だけの表で、A：そのまま平均、B：全部の日を0で埋めて平均、C：開いていた日だけを0で埋めて平均（正しい値）を比べる。会計の件数の平均を変えた比べと、7日の移動平均も見る | `src/a358_zero_days.py`、`src/*.sql` |

## 主な結果
- 全部の日は87,720行ぶん、開いていた日は79,474、売上の表にあるのは73,951行
- **A：売上の表だけで平均**。小さい店60店では、開いていた日の15%が売上0で、1日あたりの売上は平均21%高く出た（中央値12%、最大130%）。10%以上高く出た店は120店中32店。大きい店・中くらいの店は0%
- **B：全部の日を0で埋める**。定休日のある店では、休みの日が0として入り、小さい店で14%、中くらいの店で平均7%低く出た
- **全体の平均では見えない**：120店の「店ごとの平均」を平均すると、Aのずれは+0.2%、Bは−1.6%。小さい店60店だけなら+13%と−14%
- **会計の件数の平均（λ）ごと**：1日0.5件の店は+154%、1件で+58%、2件で+16%、3件で+5%、4件で+2%。理屈の値（1÷(1−e^−λ)−1）と合った
- **7日の移動平均**：小さい店では、行で7つ取る枠（ROWS）が8営業日以上にまたがった日が46%で、開いていた7日の平均より平均19%高い。1日の会計が2件未満の24店では平均43%高かった。前の行（LAG）が前の営業日でなかったのは13%

## 動かし方
```
pip install -r requirements.txt
cd src && python a358_zero_days.py
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL（DuckDB）で出した3通りの平均は、pandas で別に計算した値と一致した（コード内の assert）

## 注意（言えないこと）
- すべて架空のデータです。高く出る幅は、置いた客の少なさ（小さい店は1日0.4〜4件）で決まります。実際の店の数字ではありません
- 「開いていた日」の表があることを前提にしています。店が開いていたかどうかの記録がない場合は、売上0の日と休みの日を見分けられません
- 臨時休業、開店・閉店による途中からの営業は入れていません
- 月が1つ抜けると LAG がずれる話は 232 で扱いました。この記事は、0の日の欠けと平均に絞っています
- T-SQL 版は SQL Server 本体では動かしていません
