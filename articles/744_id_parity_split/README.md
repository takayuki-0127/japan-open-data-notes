# 744 会員番号の偶数と奇数で2群に分けると、番号の振り方によって群の間にどれだけ差が出るのか（実務の型）

A/B テストで会員を2群に分けるとき、「番号の偶数と奇数」は手軽です。ところが番号の振り方によっては、偶数と奇数が会員の性質とつながっています。たとえば受付の仕組みが2台あり、1台目が奇数、2台目が偶数を振っていて、2台が受け持つ受付の経路が違う場合です。**ここでは、作成者が乱数で作った架空の会員（1か月20,000人）で、施策をしないまま2群に分け、偶数と奇数・ハッシュ・無作為の3つの分け方で、「差あり」になる割合を1,000か月分数えました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A744 | 偶数と奇数で分けると、施策なしでどれだけ差が出るか | 1か月20,000人。店頭とWebが半々。受付2台：1台目は奇数（店頭の80%・Webの20%）、2台目は偶数。月の購入額の平均は店頭5,000円・Web4,200円、標準偏差3,000円。分け方3つ（番号 % 2・番号のハッシュ・無作為）、Welch の t 検定。1,000か月。比べとして1台で連番を振る場合。1か月分を DuckDB（1スレッド）で集計し、偶奇の平均の一致を確認。seed 744 | `src/a744_parity.py`、`src/02_split_duckdb.sql`、`src/01_split_tsql.sql` |

## 主な結果

| 分け方 | 受付2台で交互に番号：平均の差（奇数−偶数） | 「差あり」の割合 | 1台で連番：「差あり」の割合 |
|---|---|---|---|
| 偶数と奇数 | **+480円** | **100%** | 4.2% |
| ハッシュ | +3円 | 4.9% | 4.7% |
| 無作為 | +0円 | 5.2% | 3.9% |

（施策はしていない。1,000か月）

- 受付2台で交互に番号を振ると、奇数の会員の80%が店頭、偶数の会員の19%が店頭だった（1か月分）。偶数と奇数の差は平均480円で、1,000か月すべてで「差あり」になった
- ハッシュや無作為で分けると、「差あり」は5%前後だった
- 1台で連番を振る場合は、偶数と奇数でも5%前後だった。偶奇で分けてよいかは、番号の振り方で決まる

## データ

## 注意（言えないこと）
- 架空のデータです。受付2台の受け持ちや購入額の差は作成者が置いたもので、差の大きさはこれで決まります
- Python で使ったハッシュ（splitmix64 の混ぜ方）と、SQL の DuckDB の hash()・SQL Server の HASHBYTES は別のものです。SQL のハッシュの分け方は1か月分の集計を出しただけで、1,000か月の割合は Python のハッシュで数えた。T-SQL 版は未検証
- 実際の仕組みで番号がどう振られているか（台数・受け持ち・振り直し）は、このデータからは分かりません。分ける前に、群ごとの属性（経路・登録日など）がそろっているかを確かめるのが安全です
