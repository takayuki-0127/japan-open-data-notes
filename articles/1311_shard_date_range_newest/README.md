# 1311 データを日付の範囲で台に分けると、新しい日付を受け持つ1台に、書き込みはどれだけ集まるのか？（データの振り分け）

記録を何台かに分けて置くとき、「1月分はこの台、2月分はあの台」のように日付の範囲で分けると、期間を決めた読み出しや古い分の片付けがしやすくなります。けれども、新しい記録はどれも「今日」の日付で入ってくるので、今日の日付を受け持つ1台に書き込みが集まります。台数を増やしても、今日の書き込みは1台のままです。**ここでは、作成者が置いた架空のアプリの記録（台は10台。1日10万回の書き込みのうち8割がその日の新しい記録、2割が前からある記録の書き直しと置き、乱数で作ったもの）で、①日付の範囲（新しい日付は最後の範囲の台）、②日付の範囲（先の日付も36日ずつ台に順に割り当て）、③日付の番号を台数で割った余り（1日ごとに台が替わる）、④記録の番号を台数で割った余り（日付を見ない）、⑤日付の範囲を2台ずつで受け持つ、の5つで、その日の書き込みのうちいちばん多い1台の割合を360日数えました。新しい記録の割合・書き直す記録の古さ・台数を変えた27通りでも確かめました。実機での計測はしていません。**

例のアプリ・数は架空のもので、実在のデータベースや振り分けの仕組みを表すものではありません。台数や費用の見込みの助言はしていません。

関連する記事：1269「処理を8つに分けて同時に動かしても8倍速くならないのは、分けられない部分がどれだけあるときか？」は、分けられない部分があると、数を増やしても速さが頭打ちになることを扱っています。1312「値の種類が台数の数倍しかない項目（店の番号など）で振り分けると、いちばん多い1台は平均の何倍になるのか？」は、振り分けに使う項目の値の種類が少ないときの偏りを扱っています。1313「置く台を乱数で2つ選んで、空いている方へ入れる決まりにすると、いちばん多い1台は1つだけ選ぶときよりどれだけ減るのか？」は、置く台を選ぶ決まりで件数の偏りを減らすことを扱っています。1310「一部のデータに読み書きの1割が集まると、台数を増やしても、いちばん忙しい1台の負荷はどこから下がらなくなるのか？」は、人気の1件に読み書きが集まると、台を増やしてもいちばん忙しい1台の負荷が下がらなくなることを扱っています。この記事は、日付で台を決めたときに、新しい日付の書き込みが1台に集まる割合と、それが1日ごとに見るか合計で見るかで見え方が変わる点に絞ります。

## 主な結果

### 振り分け方ごとの、いちばん多い1台の割合（10台・360日、`results/base_by_method.csv`）
| 振り分け方 | 1日ごとに見たとき（360日の平均） | 1日ごとの最小〜最大 | 平均（10%）の何倍か | 360日の合計で見たとき |
|---|---|---|---|---|
| ①日付の範囲（新しい日付は最後の台） | **99.82%** | 97.04〜100.0% | **9.982倍** | 99.82% |
| ②日付の範囲（先の日付も順に割り当て） | **90.96%** | 80.88〜96.83% | 9.096倍 | **10.0%** |
| ③日付の番号の余り（1日ごとに替わる） | **82.49%** | 82.21〜82.83% | 8.249倍 | **10.0%** |
| ④記録の番号の余り（日付を見ない） | 10.16% | 10.04〜10.31% | 1.016倍 | 10.01% |
| ⑤日付の範囲を2台ずつで受け持つ | 50.11% | 49.77〜50.44% | 5.011倍 | 50.0% |

- **日付の範囲で分けると、10台あっても、その日の書き込みの99.82%（平均の9.982倍）が最後の範囲の1台に集まった**。新しい記録の8割はすべてこの台に入り（作りどおり）、書き直しも多くは最近の記録なので、ほとんどがこの台に来た。初日は97.04%で、式の目安（新しい記録0.8＋書き直しのうち最後の36日に入る分）の96.69%に近かった
- ③の82.49%は、新しい記録の8割に、書き直しのうち日付の差が10の倍数になる分を足した式の値（82.48%）どおりだった。**1日ごとに台を替えても、その日の新しい記録は1台に入るので、新しい記録の割合より下にはならない**
- ②は、範囲に入った1日目は81.05%、36日目は96.71%だった。範囲が替わった直後は、書き直しの多くが前の台へ行くので少し下がる
- **②と③は、360日の合計で見ると、どの台も10.0%で均等に見えた**。合計では均等でも、1日ごとには8〜9割が1台に集まっていた
- ⑤のように1つの範囲を2台で受け持つと、50.11%（平均の5.011倍）になった。受け持つ台数を変えると、1台で98.97%、2台で50.19%、5台で20.37%、10台で10.38%と、ほぼ「1÷受け持つ台数」になった（60日・1日2万回、`results/by_machines_per_range.csv`。作りどおり）
- 置いてある記録の数で見ると、①は359日目に最後の台が全体の55.0%を持っていた（運用前36日分＋運用の360日分。作りどおり）。⑤は30.0%、②③④は10.0%

### 確かめ：27通り（60日・1日2万回、`results/grid.csv`）
- ①のいちばん多い1台の割合は73.02〜100%（平均の8.285〜39.976倍）、③は51.72〜96.05%（5.55〜38.363倍）、⑤は38.63〜50.3%、④は2.74〜10.36%（台数で決まる平均2.5〜10%の近く）だった
- ①と③は27通りすべてで、新しい記録の割合（0.5・0.8・0.95）以上だった（作りどおり）
- ①がいちばん下がったのは、新しい記録が5割で、書き直す記録の古さが平均60日、40台のとき（73.02%）。書き直しが古い記録に散らばり、1台の範囲（9日）が短いほど、最後の台に来る書き直しが減った

## 注意（言えないこと）
- 架空の記録と、作成者が置いた書き込みの作りです。集まる割合は、置いた新しい記録の割合と書き直しの古さでほぼ決まります（①③は新しい記録の割合より下にならないのは作りどおり）
- 書き込みの回数だけを数えました。1回の重さの違い、読み出し、台の速さの違いは入れていません
- 範囲を途中で分け直したり、台を足したりする動きは入れていません。①で最後の台が大きくなったときに範囲を分け直すと、置いてある記録の割合は変わります
- 日付の範囲で分けると、期間を決めた読み出しや古い記録の片付けがしやすくなる良さがあります。この記事はその良さを数えていません。どの振り分け方を使うべきかは、読み出しの形や書き込みの量で変わります
- 実在のデータベース・アプリの振り分けの仕組みを表すものではありません
