# 567 支払備金の個別見積を途中から厚く積むようにすると、発生ベースのチェインラダーはどれだけ多く見込むのか（保険数理・正解の分かるデータで試す）

損害の見込み（最終損害）をチェインラダーで出すとき、「支払った額」の三角形を使う（支払ベース）か、「支払った額＋未払いの個別見積」の三角形を使う（発生ベース）かを選びます。発生ベースは個別見積の分だけ情報が早く入りますが、**見積の積み方が途中で変わると、過去の進展の仕方が今に当てはまらなくなります。** ここでは、本当の最終損害が分かる架空のデータで、個別見積を「本当の残りの8割」から厚く積むように変えたとき、チェインラダーの見込みがどれだけずれるかを数えました（各条件300回）。数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A567 | 個別見積の積み方が途中で変わると、支払ベース・発生ベースのチェインラダーはどれだけずれるか | 架空の10事故年（2016〜2025年、2025年末で評価）。各年の事故500件（ポアソン）、1件の損害は対数正規（平均100万円）、支払は1〜10年目のどこかで全額。未払いの事故の個別見積＝本当の額×ぶれ（平均1）×積み方の倍率。倍率を 0.8 から 0.9・1.0・1.1 に、2025・2023・2021年末から変えた。出来高で重み付けた進展係数のチェインラダー（テールなし）で、支払ベース・発生ベース・過去の見積を今の倍率に直した発生ベースを比べた。各300回、seed 567。進展係数の計算は DuckDB（1スレッド）の SQL でも行い Python と一致を確認 | `src/a567_case_strengthening.py`、`src/a567_chain_ladder.sql`、`src/a567_chain_ladder_tsql.sql` |

## 主な結果
- **積み方を変えなければ**、どの方法もほぼ正しい（未払い分の見込みのずれ：支払 +0.7%、発生 +0.1%）
- **2023年末から 0.8→1.0 に変えると**、発生ベースは**未払い分を +18.4%**（最終損害では +3.7%）多く見込む。支払ベースは +0.7% のまま
- **厚くする幅に比例**：0.8→0.9 で +9.3%、0.8→1.1 で +27.4%（2023年末から）
- **変えた時期**：直近1年だけ（2025年末から）だと 0.8→1.0 で +28.2%、直近5年（2021年末から）だと +10.6%。変えてからの年数が短いほど、過去の進展係数との食い違いが大きい
- **事故年ごと**（0.8→1.0、2023年末から）：最終損害のずれは 2020年 +0.8%、2023年 +5.7%、2024年 +9.8%、2025年 +15.8%。新しい年ほど、大きい進展係数が掛かるため
- **過去の見積を今の積み方に直して**から発生ベースで計算すると、ずれは +0.1% に戻る（このシミュレーションでは本当の倍率が分かっているので直せる）
- **支払ベースはずれないが、ぶれは大きい**：未払い分の見込みの標準偏差は、支払ベース 10.6%、発生ベース 2.4%（0.8→1.0、2023年末から）

## 確かめたこと
- 空のフォルダで流し直し、results がすべて一致した
- 1回分の発生ベースの三角形の進展係数9個が、Python と DuckDB の SQL で一致すること（T-SQL 版は SQL Server では動かしていない：**未検証**）

## データ
- データはコードの中で乱数から作る（seed 567）。1回分の発生ベースの三角形を `results/example_incurred_triangle_long.csv` に置いた

## 注意（言えないこと）
- 架空のデータ。事故の数・損害の大きさ・支払の時期・見積のぶれは作成者が置いたもので、結果はこれで決まる
- 事故はすべて発生した年に報告されるとし、テール（10年目より先の支払）はないとした
- 実際には積み方の変化の大きさは分からないので、「今の積み方に直す」には見積の平均の動きなどから推し量る必要がある。ここではその方法は試していない
- 支払備金の積み方や、どの方法を使うべきかの助言ではない
