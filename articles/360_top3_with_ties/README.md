# 360 「上位3件」を取る SQL は、同じ点数があると何件返すのか（実務の型）

店ごとに「販売数の上位3商品」を取る SQL を、ROW_NUMBER・RANK・DENSE_RANK（と TOP 3 WITH TIES）で書いたとき、同点があると何件返るか、顔ぶれが実行のたびに変わるかを、架空の300店×40商品の売上で数えたフォルダです。SQL は DuckDB で動かしました。T-SQL 版は `src/01_top3_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A360 | 同点があると、「上位3件」は何件返り、顔ぶれは安定するか | 店×商品の月の販売数（ポアソン分布、1商品あたり平均12個）で、4通りの書き方の返る件数を数える。ROW_NUMBER は表に入っている行の順だけを変えて20回実行し、顔ぶれが変わる店を数える。販売数の大きさと、並べる列（販売数／売上金額）を変えて同点の起きやすさを見る | `src/a360_top3.py`、`src/*.sql` |

## 主な結果
- **返る件数（300店）**：ROW_NUMBER は全部の店で3件（計900行）。RANK は265店で3件、32店で4件、3店で5件（計938行）。DENSE_RANK は228店で3件、56店で4件、12店で5件、4店で6件以上（最大7件、計993行）
- 3位と4位が同点だった店は12%で、RANK が3件より多く返した店と同じ。DENSE_RANK が3件より多く返した店は24%
- **ROW_NUMBER の顔ぶれ**：表に入っている行の順を変えて20回実行すると、12%の店（3位と4位が同点の35店すべて）で上位3件の顔ぶれが変わった。同点のときの決まり（商品番号の小さい順）を ORDER BY に足すと、変わった店は0
- 下流の集計にも出る：「上位3件に入った店の数」を商品ごとに数えると、40商品中12商品で実行によって数が変わり、いちばん動いた商品は94〜104店だった
- **数の大きさ**：1商品あたりの月の販売数の平均が3個だと、3位と4位が同点の店は32%。6個で19%、12個で12%、25個で6%、100個で2%、300個で1%。売上金額で並べると0.1〜2%

## 動かし方
```
pip install -r requirements.txt
cd src && python a360_top3.py
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します（ROW_NUMBER の20回は、同点の選ばれ方が環境によって変わる可能性があります。手元の2回の実行では同じでした）。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL（DuckDB）で出した RANK・DENSE_RANK の件数は、pandas で別に数えた値と全部の店で一致した（コード内の assert）

## 注意（言えないこと）
- すべて架空のデータです。同点の起きやすさは、販売数の大きさと商品の人気の差で決まります
- ROW_NUMBER の同点の選ばれ方は、データベースの製品・版・実行計画によります。DuckDB 1.5 で確かめた結果で、SQL Server での動きは試していません
- `TOP (3) WITH TIES` は T-SQL だけの書き方で、動かしていません。RANK で3以下を取るのと同じ件数になる、というのは SQL の決まりからの説明です
- どの関数が正しいかは、使い道で決まります。この記事は件数と安定性の違いを数えただけです
