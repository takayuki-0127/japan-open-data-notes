# F242 毎日の KPI の「いつもと違う」を、どう自動で知らせるか？

シリーズ「実務に近い分析」（F231〜F245）の12本目。毎日の数字（KPI）に「いつもと違う」動きが出たら自動で知らせる仕組みを、6つのルールで比べた。
異常の「正解」が分かっていないと良し悪しを測れないので、**架空の通販会社「あおばマート」（架空）**の毎日の注文数をシミュレーションで作り、わざと異常を入れた。そのうえで、**本物の毎日の数字**（東京・関西の電力需要、F22 のデータ）にも同じルールを当て、1年に何回鳴り、どんな日に鳴るかを見た。

## 問い
- 毎日の KPI の異常を知らせるルールは、どれを選ぶと「空振り（何もないのに鳴る）」と「見逃し」のつり合いがよいか
- 曜日・祝日・販促（予定どおりの山）を考えると、どれだけ変わるか
- 本物の数字に当てると、どんな日に鳴るのか

## データ
- **架空のあおばマートの注文数**（2021〜2025年、毎日、乱数の種20通り）：1日約1万件。曜日（土日に多い）、季節（12月に多い）、祝日（+10%）、お盆、年末（12/26〜30は多く、12/31〜1/2は少ない）、毎月11日の月例セール（+25%、予定どおりの山）、ゆるやかな伸び（年5%）、日々のばらつき（約4%、前日と少し連動）を入れた。
  - そこに**異常を40件**入れた（2021年4月以降、10日以上あける）。7割が下振れ・3割が上振れ、大きさは5・10・15・20・30%、長さは1日60%・2日25%・3日15%。
  - 祝日の印は、東京の電力データにある祝日の列をそのまま使った（実在の暦）。
- **東京の毎日の電力需要**（2016年4月〜2026年9月、3,835日）と**関西**（2024年4月〜2026年9月、913日）：F22 のフォルダの1時間ごとの需要（気温・祝日つき）を1日の合計にした。新しい取得はしていない。

## 6つ（＋α）のルール（どれも、その日の判定には前日までの値だけを使う）
| 名前 | 中身 |
|---|---|
| D1 前日比 | 前日より10%以上動いたら鳴らす |
| D2 28日平均±3σ | 前の28日の平均と標準偏差で z を出し、\|z\|>3 |
| D3 同じ曜日の中央値 | 前の同じ曜日4回の中央値と比べ、その差を前56日の差の MAD（外れに強いばらつきの尺度）で割る。\|z\|>3.5 |
| D4 STL の残差 | 前の84日を STL（傾向・曜日の形・残差に分ける方法）で分け、今日を予測。尺度は当てはめた残差の MAD。\|z\|>3.5 |
| D4b STL＋外れで尺度 | D4 と同じ予測で、尺度だけ「これまでの予測の外れ」の MAD にする |
| D5 D3＋暦 | D3 に暦を足す：比べる相手を「ふつうの日」の同じ曜日に限る。祝日は前の日曜4回と、販促の日は前の販促の日4回と比べる。年末年始・お盆は前年と比べ、\|z\|>6 のときだけ鳴らす |
| D6 D5＋2日確認 | D5 の z で、\|z\|>5 ならすぐ、3.5〜5 なら2日続いたら（2日目に）鳴らす |
| D7 暦＋気温の回帰（電力だけ） | 曜日・祝日・年末年始・お盆・気温（暑さ寒さの2次）・傾向で回帰し、毎月、前の730日で当てはめ直す |

採点：続けて鳴った日は1回の警報にまとめ、異常の期間（と翌1日）に重ならない警報を「空振り」として1年あたりで数えた。異常は、その期間（と翌1日）に1日でも鳴れば「見つけた」とした。主な数字は、ふつうの日に入れた異常（種1つあたり約34件）で数えた。

## 結果
### A. 架空のあおばマート（種20通りの平均、カッコは95%の幅）
| ルール | 空振り（1年あたり） | 見つけた割合 | 10%以上の下振れ |
|---|---|---|---|
| D1 前日比10% | 69.0（65.1〜71.8） | 90% | 97% |
| D2 28日平均±3σ | 6.0（4.8〜7.6） | 20% | 31% |
| D3 同じ曜日の中央値 | 10.1（9.0〜11.4） | 38% | 53% |
| D4 STL の残差 | 63.2（58.8〜66.9） | 86% | 96% |
| D4b STL＋外れで尺度 | 8.0（6.4〜9.9） | 24% | 34% |
| D5 D3＋暦 | **3.9（2.3〜5.7）** | **44%** | 59% |
| D6 D5＋2日確認 | 1.4（0.8〜2.2） | 27% | 36% |

- **よく見つけるルールは、鳴りすぎる**：D1 と D4 は9割前後を見つけるが、1年に60回以上（週1回以上）空振りする。D1 は曜日の差（日曜→月曜で約−13%）だけで鳴り、D4 は「当てはめた残差」の尺度が小さく出るため。
- **同じ空振りの回数で比べると（閾値を動かして合わせる）**：見つけた割合は次のとおり。暦を考えた D5 は、空振り年4回のとき44%で、ほかのルールの2倍以上（`results/A_recall_at_budget.csv`）。

| 空振りの上限（1年） | D1 | D2 | D3 | D4b | D5 |
|---|---|---|---|---|---|
| 2回 | 15% | 5% | 9% | 7% | **30%** |
| 4回 | 20% | 11% | 16% | 13% | **44%** |
| 12回 | 38% | 40% | 42% | 29% | **64%** |
| 52回 | 73% | 48% | 69% | 57% | 73% |

- **小さい異常は、どのルールでも見つけにくい**：D5 で下振れ5%は6%、10%は16%、15%は45%、20%は78%、30%は99%。ふだんの揺れ（1日約4%）の4倍あたりから見つかり始める。
- **2日確認（D6）は空振りを減らすが、閾値を上げるのとほぼ同じ**：D6（閾値3.5）は空振り1.4回・27%、D5 の閾値を5にすると1.4回・24%。
- **特別な日の異常は見つけにくい**：祝日・年末年始・お盆・販促の日に入れた異常は、D5 で35%（ふつうの日は44%）。

### B. 本物の毎日の数字（東京の電力需要、2018年4月〜2026年9月）
| ルール | 警報（回/年） | 鳴った日（日/年） | 特別な日 | その前後 | 気温が急に変わった日 | そのほか |
|---|---|---|---|---|---|---|
| D1 前日比10% | 78.2 | 90.3 | 5% | 9% | 25% | 61% |
| D3 同じ曜日の中央値 | 5.3 | 15.6 | 28% | 5% | 61% | 7% |
| D4 STL の残差 | 57.9 | 147.5 | 12% | 7% | 27% | 53% |
| D4b STL＋外れで尺度 | 6.6 | 11.3 | 23% | 3% | 25% | 49% |
| D5 D3＋暦 | 5.1 | 14.2 | 2% | 7% | **81%** | 10% |
| D6 D5＋2日確認 | 3.1 | 9.9 | 1% | 5% | 85% | 10% |
| D7 暦＋気温の回帰 | 7.2 | 12.5 | 38% | 31% | 10% | 21% |

- 「気温が急に変わった日」＝その日の平均気温が、前の同じ曜日4回の平均から4℃以上離れた日。
- 暦を考える（D5）と、特別な日の警報はほぼ消え、**残る警報の8割は気温が急に変わった日**だった。電力需要の「いつもと違う」の多くは天気で説明できる。
- 気温を回帰に入れる（D7）と気温の日は10%に減るが、今度は祝日・年末年始と**その前後（飛び石連休など）**が7割になった。暦の入れ方が粗いと、別の種類の空振りが出る。
- 関西（2024年8月〜）でも、D1 は年93回、D5 は年3.7回で、D5 の警報の79%が気温の急変の日だった。

### C. SQL
- `sql/alert_same_weekday.sql`：同じ曜日の前4回の平均と比べ、前56日の標準偏差で割る警報を T-SQL（SQL Server）で書いた。窓関数（`AVG() OVER (PARTITION BY 曜日 ... ROWS BETWEEN 4 PRECEDING AND 1 PRECEDING)`）だけで書ける。
- 照合：DuckDB で動くよう最小限（`LOG→LN` など4か所）を置き換えて流し、pandas で同じルールを書いたものと比べた。1,742日で z（小数2けた）の差は0、警報の一致は100%（`results/C_sql_check.json`）。SQL Server そのものでは動かしていない。

### D. ダッシュボード
- `dashboard/index.html`：架空のあおばマートの「見張り画面」の例。注文数の推移、印（|z|>3.5）と連絡（|z|>5 か2日続く）の日、直近の印の一覧と「どうするか」、空振りの目安（年4回）を1枚にした。数字はシミュレーション。

## 頑健性
1. **乱数の種**：20通りで、平均と95%の幅を出した（上の表）。
2. **閾値**：D1（5〜60%）、D2〜D5（z 2〜8）を細かく動かした（`results/A_frontier.csv`）。どの空振りの上限でも、D5 がいちばん多く見つけた（52回では D1 と同じ）。
3. **ばらつきの大きさ**（1日2%・4%・8%）と**比べる週の数**（4・8週）：ばらつき2%なら D5 は空振り9.6回・72%、8%なら1.3回・14%。D5 が D3 より空振りが少なく見つけた割合が高い関係は、ばらつき2〜4%では変わらなかった（8%ではどちらも見つけられない）。週を8にしても大きくは変わらない（`results/A_robustness_noise_window.csv`）。
4. **本物のデータを2つ**（東京・関西）。

## 言えないこと
- **架空のデータでの比べ方**：異常の種類（大きさ・長さ・上下の割合）や販促の入れ方を変えると、順位が変わりうる。実際の KPI では「本当の異常」の記録がないことが多く、空振りと見逃しを数えにくい。
- **電力需要は KPI の例**：電力需要の「いつもと違う」は、ほとんどが天気。売上・アクセス数などでは、天気以外（キャンペーン、障害、報道）の効き方が違う。
- **気温の扱い**：D7 は暦の入れ方が粗い（祝日の前後・飛び石連休を入れていない）。改善の余地がある。
- **月次のデータ品質のチェック（F293）や、予測のずれの見張り（F205）とは別**：ここは「毎日1つの数字」を見る話。
- **閾値の決め方**：空振りを年何回まで許せるかは、確かめる手間と見逃しの損で決まる。ここでは目安として年4回を置いた。

```
python src/03b_同じ空振りで比べる.py  # 閾値を動かした比較（約2分）
python src/04_図.py
python src/05_SQL照合.py

```
