# 343 損害率は、事故が起きた年で数えるか、支払った年で数えるかで、どれだけ違うのか（実務の型）

架空の保険の事故・支払データ（事故 約15万件）で、損害率を「支払った年」と「事故が起きた年」の2つの数え方で SQL から出し、保険料が伸びる時期・縮む時期の差を比べたフォルダです。本当の損害率は60%に固定しています。SQL は DuckDB で動かしました。T-SQL 版は `src/01_two_loss_ratios_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A343 | 2つの損害率は、契約が伸びる時期・縮む時期にどれだけ違うか | 件数ポアソン・金額対数正規の事故。支払いは事故の年から5年（40・30・15・10・5%、1件ごとにばらつく）。場面1：年+10%→横ばい→年−10%。場面2：伸び率を−20%〜+30%に変える（式と、20回のシミュレーション）。場面3：本当の損害率を60%→70%に上げる（200回） | `src/a343_lossratio.py`、`src/01_two_loss_ratios_tsql.sql` |

## 主な結果
- 場面1：支払った年で数えた損害率は、保険料が年10%伸びた2014〜16年に平均54.5%（本当の値より−5.8ポイント）、年10%縮んだ2020〜25年に平均66.9%（+6.7ポイント）。事故が起きた年で数えた損害率は57〜63%（偶然の揺れ）
- 場面2（同じ伸びが続いたときの差）：+5% −2.9、+10% −5.6、+20% −9.8、+30% −13.0、−5% +3.6、−10% +8.3、−20% +19.1 ポイント。式（本当の損害率×払う割合を伸び率で割り引いた和）とシミュレーションはほぼ一致
- 場面3：損害率が10ポイント上がったとき、支払った年の数字は 64.0%→66.9%→68.5%→69.5%→69.9%。最初の年に出たのは上がり幅の4割
- 事故が起きた年で数える方法の弱点：2025年末に払った分だけで数えると、2025年の事故は24%、2024年は42%、2023年は50%（払い終わると60%前後）。直近の年は支払備金の見積もりが要る

## 動かし方
```
pip install -r requirements.txt
cd src && python a343_lossratio.py
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL で出した「支払った年の保険金」は、pandas で別に計算した値と一致した（コード内の assert）
- 場面2は、式の値とシミュレーションの平均を並べた

## 注意（言えないこと）
- すべて架空のデータです。差の大きさは、置いた払い方と伸び率で決まります。実際の種目ごとの差を表すものではありません
- 支払備金を足した損害率は作っていません（備金の見積もりの外れ方は 316〜318 で扱いました）
- 保険料は、その年に対応する分がそのまま入るとしました（経過保険料の按分は 315）
- 事業費・再保険は入れていません
- T-SQL 版は SQL Server 本体では動かしていません
