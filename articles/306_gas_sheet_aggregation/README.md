# 306 Google スプレッドシートの申込集計を、GAS で自動にする（実務の型）

申込フォームの回答がたまるシートを、コースごとの申込件数と人数にまとめる作業を、Google Apps Script（GAS）で自動にする型です。**GAS 本体とスプレッドシートでは実行していません。** 集計の関数（スプレッドシートに触らない計算だけの部分）を Node.js で試験し、シートの読み書きは Node の小さな模型で確かめました。トリガーとメニューは未検証です。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A306 | 入力のゆれがあるとき、関数をそのまま当てた集計と、スクリプトの集計はどれだけずれるか | 架空の申込600件に、ゆれを11種類（1種類につき40行）入れ、1種類ずつと全部いっしょの13通りで正解と比べる | `gas/Code.gs`、`test/run_node.js`、`src/a306_run.py`・`a306_figs.py` |

## 主な結果
- ゆれを1種類ずつ入れたとき、**関数（COUNTIFS・SUMIFS をそのまま当てた場合を模した計算）は11種類中3種類、スクリプトは9種類でずれが0**
  - 関数でずれたもの：コース名の前後の空白（人数で49人のずれ）、全角・半角（53人）、人数が文字（54人）、人数が空欄（40人）、同じメールの二重申込（62人）、取消の書き方のゆれ（60人）、人数が「未定」（70人）、別のメールでの二重申込（59人）
  - スクリプトでずれたもの：人数が「未定」（40行を集計に入れず「確認が要る行」に出す。推し量らない）と、別のメールでの二重申込（59人。メールでは見分けられない）
- 11種類を全部入れた申込シート（正解 520件・804人）：関数は 565件・719人、スクリプトは 520件・793人
  - スクリプトの件数が正解と同じなのは、「未定」の40件を除いた分と、別メールの二重申込40件を数えた分が打ち消し合ったため。コースごとに見ると12件ずれている
- 計算だけの関数の試験は 18件すべて通過。模型での実行では、集計シートに5コース、確認が要る行に40行が書かれた

## 動かし方
```
pip install -r requirements.txt
cd src && python a306_run.py && python a306_figs.py   # 途中で node test/run_node.js を呼ぶ（Node.js 18 以上）
```
GAS で使うときは、`gas/Code.gs` をスプレッドシートの Apps Script に貼り、シート名「申込」（A〜F列：受付日時・氏名・メール・コース・人数・状態）を用意して `runAggregation` を実行します（この手順は未検証）。

## データ

- `results/errors_by_scenario.csv`：場面ごとのずれ、`results/all_by_course.csv`：全部入りのコース別、`results/node_output.json`：Node の試験と集計の出力

## 注意
- **関数の側は、スプレッドシートで動かした結果ではありません。** 「コース名は文字として一致する行だけ数える（大文字小文字は区別しない）」「数でないセルは足さない」「状態が『取消』と完全に一致する行だけ除く」という決まりを Python で模したものです。TRIM や ARRAYFORMULA を組み合わせれば、関数でも多くのゆれは直せます
- 同じメール×コースは「受付日時がいちばん新しい行だけ残す」という決まりにしました。別の決まり（先着を残す、合算する）のほうが合う場合もあります
- ゆれの種類と行数（各40行）は作成者の置き方です。ずれの人数そのものに意味はなく、言えるのは「どのゆれで、どちらがずれるか」までです
