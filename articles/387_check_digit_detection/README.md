# 387 チェックデジットは、打ち間違いの何割を止めるのか（実務の型）

会員番号などの末尾に付ける検査用の1桁（チェックデジット）が、打ち間違いをどれだけ止めるかを数えたフォルダです。架空の会員番号100万件（本体11桁＋検査用の1桁）に6種類の打ち間違いを入れ、4つの方式で比べました。あわせて、2回打って突き合わせる「二重入力」と比べました。検査の SQL は DuckDB で動かしました。T-SQL 版は `src/01_luhn_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A387 | 打ち間違いの種類ごとに、検査で止まる割合は何%か。100万件を入力したとき、誤った番号は何件通るか | 方式は、モジュラス10（ウェイト3・1）、モジュラス10（ルーン）、モジュラス11（ウェイト2〜7、検査用の値が10なら0に読み替え）、モジュラス11（10になる番号は使わない）。打ち間違いは、1桁の誤り、隣の2桁の入れ替え、1つ飛ばしの入れ替え、同じ数字2つの誤り（55→88）、2桁の誤り、まったく別の番号。100万件ずつ試す | `src/a387_check_digit.py`、`src/01_luhn_*.sql` |

## 主な結果
### 打ち間違いの種類ごとの、止まった割合（%）
| 打ち間違い | モジュラス10（3・1） | ルーン | モジュラス11（10→0） | モジュラス11（10は使わない） |
|---|---|---|---|---|
| 1桁の誤り | 100 | 100 | 98.3 | 100 |
| 隣の2桁の入れ替え | 88.9 | 97.9 | 98.1 | 100 |
| 1つ飛ばしの入れ替え | 0 | 0 | 98.2 | 100 |
| 同じ数字2つの誤り（55→88） | 88.9 | 93.2 | 80.4 | 81.9 |
| 2桁の誤り | 88.9 | 88.9 | 88.5 | 90.0 |
| まったく別の番号 | 90.1 | 90.0 | 90.0 | 90.9 |

- 1桁の誤りは、モジュラス10の2つとモジュラス11（10は使わない）で100%止まる。モジュラス11で「10を0に読み替える」と、1.7%が通る
- 隣の2桁の入れ替えで通る数字の組は、ウェイト3・1で90組のうち10組（差が5の組）、ルーンで2組（0と9）。モジュラス11（10→0）は、差が1の18組で、9%の割合で通る
- 1つ飛ばしの入れ替え（123→321）は、モジュラス10の2つでは1件も止まらない
- でたらめな番号は、どの方式でも約1割が通る（検査用の桁が1桁なので）

### 100万件を入力したとき、誤ったまま通る番号（入力の誤りを1%、内訳を仮定した場合）
- 検査なし 10,000件、ウェイト3・1 317件、ルーン 225件、モジュラス11（10→0）267件、モジュラス11（10は使わない）100件
- 二重入力（2回打って違えば打ち直す）：2回の誤りが別々に起きるなら0.5件。誤りの10%が「元の紙の読み違い」（2回とも同じ誤り）なら1,000件、30%なら3,000件
- 二重入力＋ルーン：読み違いが10%で22件、30%で68件

## 動かし方
```
pip install -r requirements.txt
cd src && python a387_check_digit.py     # 1分ほど
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- ルーンの「1桁の誤りは100%」「隣の入れ替えは90組のうち88組（97.8%）」、ウェイト3・1の「90組のうち80組（88.9%）」という理屈の値と、数えた値が合った（コード内の assert）
- ルーンの検査を SQL で書いたもの（DuckDB）は、2万件すべてで NumPy と同じ答えだった（`results/sql_check_duckdb.csv`）

## データ
- すべて架空（作成者が乱数で作成、seed 387）。番号そのものは置いていません（実行のたびに同じ番号を作ります）

## 注意（言えないこと）
- 打ち間違いの内訳（1桁の誤り79%、隣の入れ替え10%、1つ飛ばしの入れ替え1%、同じ数字2つ0.5%、2桁の誤り5%、まったく別の番号4.5%）と、入力の誤り1%は、置いた値（仮定）です。実際の内訳は、入力の方法（手入力、読み取り機、音声）で変わります
- 「通った件数」は、検査を通ったという意味です。通った番号が、たまたま別の会員の番号として存在するかどうかは数えていません
- モジュラス11のウェイト（2〜7）や、10の扱いは、決め方がいくつもあります。ここで試したのは2通りだけです
- 二重入力の「読み違い」の割合（10%、30%）は、説明のために置いた値です
- 数字だけの番号を扱いました。英字が入る番号や、桁数の誤り（1桁多い・少ない）は入れていません。桁数は、検査の前に長さで止められます
- T-SQL 版は SQL Server 本体では動かしていません
