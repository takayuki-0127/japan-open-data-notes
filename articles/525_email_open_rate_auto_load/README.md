# 525 メールの開封率は、画像の自動読み込みによる「見かけの開封」を除くと何ポイント下がるのか？（実務の型）

架空のメール配信（1回5万通、件名A・Bを2万5千通ずつ）の記録を作り、開封の数え方を5通りに変えて開封率を出し、本当の開封率（本人が読んだ割合。架空のデータなので分かる）と比べたフォルダです。受信者の40%は、届いた直後に画像を自動で読み込む端末を使っていると置きました。特定のメール配信サービスや端末の仕様は扱っていません。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A525 | 自動読み込みによる見かけの開封を除くと、開封率は何ポイント下がるか。除き方（5分以内を除く・クリックした人だけ・自動読み込みの端末を分母から除く）で本当にどこまで近づくか。A/B の勝ち負けはどれだけ入れ替わるか | 自動読み込みの端末では、届いて数分以内に開封が記録され、本人が後で読んでも2回目は記録されないと置く。5通りで開封率を出し、自動読み込みの割合を0〜80%に変えてくり返す。各2,000通のA/Bテストを2,000回くり返して、勝ち負けが本当と入れ替わる割合を数える。開封率は SQL（DuckDB）でも出し、Python と一致するか確かめる | `src/a525_open_rate.py`、`src/02_open_rates_duckdb.sql`、`src/01_open_rates_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（5万通、自動読み込みの端末40%、本当の開封率20.56%）
- **全部の開封**：52.45%（本当より+31.9ポイント）。自動読み込みの端末を分母から除くと20.54%で、全部の開封から31.9ポイント下がり本当とほぼ同じ
- **5分以内の開封を除く**：13.04%（−7.5ポイント）。自動読み込みの端末の人は、本人が読んでも開封が残らないので、下に出すぎる
- **クリックした人だけ**：2.52%（−18.0ポイント）。開封の下限にしかならない
- **5分以内を除く＋クリックした人**：14.07%（−6.5ポイント）
- **件名B−件名A**：本当 +1.93ポイント、全部の開封 +1.09、5分以内を除く +0.88、クリックだけ +0.30、自動読み込みを除く +1.70。見かけの開封が混ざると差が縮む
- **自動読み込みの割合を0→80%にすると**（本当21.06%）：全部の開封は21.06%→84.11%、5分以内を除くは20.85%→5.99%。自動読み込みの端末を分母から除くと21.06〜21.34%
- **A/B の勝ち負けが本当と入れ替わった割合**（各2,000通×2,000回）：全部の開封25.4%、5分以内を除く16.2%、クリックだけ35.1%、5分以内を除く＋クリック14.9%、自動読み込みを分母から除く12.8%。本当の差が2ポイント以上のときに限ると、それぞれ12.0%、2.0%、23.5%、1.3%、0.8%
- SQL（DuckDB）で出した5通りの開封率は、Python と一致

## 動かし方

```
pip install -r requirements.txt

```

## データ
- `data/fictional_send_log.csv`：架空の配信記録（seed 525）。列は id・variant（件名A/B）・auto_device（自動読み込みの端末か）・read_by_person（本人が読んだか。実際の記録にはない列）・first_open_min（配信から最初の開封の記録までの分。記録がなければ空）・clicked

## 注意（言えないこと）
- 架空のデータ。自動読み込みの端末の割合、自動読み込みが起きるまでの時間（数分以内）、本人が読むまでの時間（平均6時間）、クリックの割合は作成者が置いたもので、実際の配信の値ではない
- 特定のメール配信サービスや端末の仕様は調べていない。自動読み込みのしくみは「届いた直後に一度だけ読み込み、本人が読んでも再び記録されない」と単純に置いた
- 「自動読み込みの端末を分母から除く」が本当に近く出たのは、自動読み込みの端末を使う人と使わない人で、読む割合が同じと置いたから。読む割合が違えば、このやり方もずれる。また、実際の記録で自動読み込みの端末をどこまで見分けられるかは確かめていない
- 本人が5分以内に読んだ開封（このデータでは本人の開封の約1.5%）も「5分以内を除く」で落ちる
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
