# 553 売掛金の滞留を、請求日から数えるか支払期日から数えるかで、区分ごとの金額はどれだけ動くのか（実務の型・年齢区分の起算日）

売掛金の「滞留」を、請求日から何日たったかで分けるか、支払期日から何日過ぎたかで分けるかで、「90日超」などの区分に入る金額は変わります。**ここでは、架空の取引先200社への請求（2024年7月〜2025年12月、9,568件。支払条件は30・60・90日の3通り）と入金を作り、2025年12月末で未入金の1,123件・414,457,100円を、2つの起算日で区分に分けて比べました。** 支払条件と入金の遅れ方は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A553 | 起算日を変えると、区分ごとの金額・同じ請求の入る区分・月末ごとの「90日超」がどれだけ違うか | 請求日から（30日以内・31〜60日・61〜90日・90日超）と支払期日から（期日前・30日以内・31〜60日・61〜90日・90日超）。対応表（件数・金額）、支払条件別、2025年4月末〜12月末の月末ごと。Python と SQL（DuckDB、1スレッド）で対応表が一致することを確認。seed 553 | `src/a553_aging.py`、`src/02_aging_duckdb.sql`、`src/01_aging_tsql.sql`（未検証） |

## 主な結果
- **12月末の未入金**：1,123件・414.5百万円
- **請求日から**：30日以内 187.6・31〜60日 140.8・61〜90日 59.4・90日超 26.6（百万円）。30日を超えるものが 54.7%
- **支払期日から**：期日前 348.6・30日以内 37.3・31〜60日 11.0・61〜90日 3.5・90日超 14.1（百万円）。期日を過ぎたものは 15.9%
- **90日超**：請求日からは 26.6百万円、支払期日からは 14.1百万円で 1.89倍。支払条件90日の取引先では 8.0百万円 と 0.95百万円（8.4倍）、30日の取引先では 10.5 と 8.0百万円
- **同じ請求の移り先**：請求日から61〜90日の 59.4百万円のうち 31.7百万円（53.3%、101件）は、支払期日から見るとまだ期日前
- **月末ごと**：2025年4月末〜12月末の「90日超」は、請求日から 21.8〜35.6百万円、支払期日から 11.5〜14.1百万円。請求日からの値のほうが月ごとの振れが大きい

## 動かし方
```
pip install -r requirements.txt
cd src && python a553_aging.py
```
数秒で終わります。`data/invoices.csv` に請求と入金を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 12月末の対応表（金額）が、Python と DuckDB の SQL で一致した
- T-SQL 版（`01_aging_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/invoices.csv`：invoice_id・customer_id（架空）・invoice_date・due_date・amount・paid_date（空は入金なし）・terms_days
- 仮定：支払条件 30日 45%・60日 35%・90日 20%（取引先ごと）。入金の遅れ方は取引先ごとに3通り（期日どおり 70%・少し遅れる 22%・遅れがち 8%）。0.4% は入金がないまま

## 注意（言えないこと）
- 架空のデータ。実際の会社や取引先の数字ではない
- 差の大きさは、置いた支払条件の長さと入金の遅れ方で決まる。支払条件が長い取引先が多いほど差は大きくなる
- どちらの起算日を使うべきか、貸倒れの見込みをどう立てるかは扱っていない
- 会計・与信についての助言ではない
