# 570 進展の途中で打ち切ったチェインラダーは、テールファクターを省くと最終損害をどれだけ少なく見るのか（保険数理・正解の分かるデータで試す）

支払の三角形が10年分しかないのに、支払が10年より先まで続くと、チェインラダーの進展係数だけでは11年目以降の支払が入りません。その分を足すのがテールファクターです。ここでは、本当の最終損害が分かる架空の支払データで、**テールを省いた場合**と、進展係数を曲線で外挿してテールを作った場合（**指数**・**べき**）の最終損害の見込みを比べました（各条件300回）。数字は置いた支払の進み方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A570 | テールを省くと最終損害をどれだけ少なく見るか、曲線で外挿するとどれだけ戻るか | 架空の10事故年。各年の事故400件（ポアソン）、1件の損害は対数正規（平均100万円）、支払までの年数はワイブル分布（形0.8）で、10年目までに 95%・85%・75% を払う3通り（40年目までに全額）。10年分の三角形から出来高で重み付けた進展係数を出し、(1) テールなし、(2) 3〜9年目の ln(係数−1) を経過年数に直線で当てはめる（指数）、(3) ln(経過年数) に当てはめる（べき、逆べき曲線）で40年目まで外挿。各300回、seed 570。指数の当てはめは DuckDB（1スレッド）の SQL でも行い Python と一致を確認 | `src/a570_tail.py`、`src/a570_tail.sql`、`src/a570_tail_tsql.sql` |

## 主な結果（300回の中央値）
- **本当のテールファクター**：10年で95%払うなら 1.053、85%なら 1.176、75%なら 1.333
- **テールなし**：最終損害を 95%で −5.0%、85%で −14.6%、75%で −24.9% 少なく見る。ほぼ「1 − 1/テール」の分だけ足りない
- **指数で外挿**：−2.1%・−7.2%・−14.4%。足りなさは半分ほどに縮むが、残る。指数の曲線は先で早く0に近づくため、テールを小さく見る（85%で中央値 1.088）
- **べきで外挿**：+4.3%・+10.6%・+10.9% と逆に多く見る。テールの中央値は 85%で 1.297（本当は 1.176）。ぶれも大きく、85%の場合の10〜90%の範囲は −4.4%〜+32.1%
- **事故年ごと**：テールはどの事故年にも同じく掛かるので、テールなしの足りなさは古い事故年でも新しい事故年でも約 −15%（85%の場合）
- 見えている9個の進展係数だけでは、先の形（指数かべきか）を見分けにくい。どちらの曲線も見えている範囲ではよく合う

## 確かめたこと
- 空のフォルダで流し直し、results がすべて一致した
- 1回分の三角形で、指数の当てはめの傾きと切片が Python と DuckDB の SQL で一致すること（T-SQL 版は SQL Server では動かしていない：**未検証**）

## データ
- データはコードの中で乱数から作る（seed 570）。1回分の三角形を `results/example_triangle_long.csv` に置いた

## 注意（言えないこと）
- 架空のデータ。支払の進み方（ワイブル分布）は作成者が置いたもので、どちらの曲線が合うかはこれで決まる。別の進み方なら指数の方が合うこともある
- 外挿は40年目で打ち切った。どこまで外挿するかでもテールは変わる
- 事故はすべて発生した年に報告されるとした
- テールファクターの決め方や支払備金の積み方の助言ではない
