# 703 売上のない月が行ごと抜けた表で LAG を使って前月比を出すと、何行が2か月前と比べてしまうのか（実務の型・SQL のウィンドウ関数）

月別の売上表では、売上0の月に行そのものがないことがよくあります。そのまま `LAG(sales) OVER (PARTITION BY store_id ORDER BY ym)` で前月の値を取ると、LAG は「前の月」ではなく「前の行」を返すので、抜けた月の次の月は2か月以上前と比べてしまいます。**ここでは、架空の60店×24か月（小さい店ほど売上0の月が多い）で、そのまま LAG した場合と、店×月のカレンダーと結合して0で埋めてから LAG した場合を比べました。** 売上0になる割合は作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A703 | 行の抜けた表の LAG は、何行で前月でない月と比べるか | A そのまま LAG、B カレンダーと結合して0で埋めてから LAG、C 前の行との月の差が1でない行を数える SQL。DuckDB（1スレッド）と pandas で一致を確認。seed 703 | `src/a703_lag.py`、`src/02_lag_duckdb.sql`、`src/01_lag_tsql.sql`（未検証） |

## 主な結果
- **行の抜け**：1,440店月のうち200（13.9%）が売上0で行がない
- **前月と比べていない行**：LAG の値がある1,180行のうち **145行（12.3%）** が、2か月以上前と比べていた（2か月前121行、3か月前20行、4〜5か月前4行）。60店のうち53店に1行以上あった
- **値はふつうに見える**：その145行の「前月比」は絶対値の中央値14.2%で、36.6%は±10%以内。本当は前月が0なので前月比は出せない
- **小さい店ほど多い**：店を大きさで4つに分けると、前月でない行の割合は小さい店20.3%、大きい店4.2%

## 動かし方
```
pip install -r requirements.txt
cd src && python a703_lag.py
```
数秒で終わります。`data/monthly.csv` に売上（0の月は行なし）を、`results/wrong_rows.csv` に前月でない行を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- DuckDB の LAG（A・B）と前月でない行の数（C）が、pandas の shift・reindex の結果と一致した
- T-SQL 版（`01_lag_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。月のカレンダー表 `dbo.calendar_month` がある前提

## データ
- `data/monthly.csv`：store_id・ym（月初の日付）・sales
- 仮定：店の大きさは対数正規分布。売上0の月の確率は小さい店ほど高い（最大約30%）。季節の波±15%、店ごとの伸び

## 注意（言えないこと）
- 架空のデータ。ずれる行の割合は、0の月の多さで決まる
- 0で埋めると、0の翌月の前月比は計算できなくなる（割る数が0）。そこをどう表すか（空欄・「—」）は表の目的で決める
- 実在の店の数字ではない
