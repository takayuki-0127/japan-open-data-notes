# 572 同じ時刻の行が並ぶとき、ROW_NUMBERで「最新の1行」を選ぶと、実行のたびに何件入れ替わるのか（実務の型・同順位の決め方）

更新ログから会員ごとの「最新の状態」を取るとき、`ROW_NUMBER() OVER (PARTITION BY 会員 ORDER BY 更新時刻 DESC)` の1行目を使うことがよくあります。更新時刻が秒単位で、同じ秒に2行以上あると、その中のどれが1行目になるかは決まっていません。**ここでは、架空の会員2万人の状態の更新ログ（71,738行）で、行の物理的な並びだけを変えて同じ SQL を100回動かし、選ばれる行がどれだけ入れ替わるかを数えました。あわせて、ほかの書き方（時刻＋状態名、MAX(時刻) で結合、時刻＋連番）と比べました。** 同じ秒の行が入る割合は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A572 | 並びの決め方で、「最新の1行」がどれだけ変わるか | 正解は書き込み順の連番（seq）で決める。DuckDB（1スレッド）で、表に入れる行の順番だけを100通りに変え、時刻だけの ROW_NUMBER を実行。前回と違う行を選んだ会員数、正解と違う会員数、「解約」の人数と月額の合計の振れを数える。時刻＋状態名、MAX(時刻) で結合、時刻＋連番も同じデータで比べる。seed 572 | `src/a572_row_number_ties.py`、`src/02_latest_duckdb.sql`、`src/01_latest_tsql.sql`（未検証） |

## 主な結果
- **最新の時刻が同じ秒に2行以上ある会員**：1,606人（8.0%）。そのうち状態が違うのは771人
- **時刻だけで並べると**：100回の実行で、前回と違う行を選んだ会員が毎回 355〜419人（平均 384.7人）。正解と違う会員は 354〜415人（平均 383.4人）
- **集計値の振れ**：「解約」の人数は 4,202〜4,255人（正解 4,314人）、月額の合計は 2,273万〜2,282万円（正解 2,261万円）
- **時刻＋状態名で並べると**：毎回同じ結果になるが、正解と違う会員が313人。並びは決まっても、正しい順番ではない
- **MAX(時刻) で結合すると**：同じ会員が2行出て、行が1,631行増える（「解約」は4,640人に増える）
- **時刻＋連番で並べると**：100回とも正解と一致（0人）

## 動かし方
```
pip install -r requirements.txt
cd src && python a572_row_number_ties.py
```
十数秒で終わります。`data/status_log.csv`（member_id・updated_at・status・seq）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 実際のデータベースで同順位の並びが変わるのは、実行計画や並列処理、行の格納の順番による。ここでは1スレッドに固定したうえで、行の並びを変えることで「並びが決まらない」状態を再現した
- T-SQL 版（`01_latest_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 会員2万人。1人あたり1〜6回の更新（2025年の1年間、秒単位）。状態は 有効・休止・解約
- 最後の更新の6%に、同じ秒の「上書き」の1行を足した（夜間の一括処理を想定）。2%に、同じ秒・同じ状態の1行を足した（二重送信を想定）
- seq は書き込まれた順の連番。これを正しい順番とした
- 月額は 有効1,980円・休止300円・解約0円（集計値の振れを見るための仮の値）

## 注意（言えないこと）
- 架空のデータ。実際の会員の数字ではない
- 入れ替わる件数は、同じ秒の行の多さで決まる。時刻がミリ秒まであれば同順位は減るが、なくなるとは限らない
- 書き込み順の連番がない表では、正しい順番を後から決められない。その場合は、どの行を正とするかの決まりを先に作る必要がある
