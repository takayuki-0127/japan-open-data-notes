# 587 同じテスト用データでモデルの調整を何度もくり返すと、テストの成績はどれだけ楽観的になるのか（手法の解説・正解の分かるデータで試す）

モデルの成績は、学習に使っていないテスト用データで測ります。ところが、設定（使う特徴・正則化の強さ）を変えてはテストの成績を見て、良いものを選ぶ、をくり返すと、テスト用データにも合わせ込んだことになります。**ここでは、特徴40個のうち予測力のあるものが0個または4個の架空のデータで、設定を1〜200通り試して「テストの成績がいちばん良いもの」を選んだときのテストの成績を、2万件の新しいデータで測った本当の成績と比べました。比べる相手として、別の検証用データで選び、テストは最後に1回だけ使う方法も試しました。** 数字は置いた前提で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A587 | テストの使い回しで、成績はどれだけ上振れするか | 学習600件・検証用300件・テスト200件または1,000件・新しいデータ2万件。目的変数は0/1、特徴40個（予測力ありは0個または4個、係数0.35）。設定は「使う特徴2〜10個をランダムに選ぶ」×「正則化の強さ」をランダムに200通り。ロジスティック回帰、成績は AUC。各条件40回。例の1回の AUC を DuckDB（1スレッド）の SQL で順位から出し直した。seed 587 | `src/a587_reuse.py`、`src/a587_auc.sql`、`src/a587_auc_tsql.sql` |

## 主な結果（AUC、40回の平均）
| 条件 | 試した数 | テストで選んだ：テストの成績 | 本当の成績 | 上振れ | 検証用で選んだ：テストの成績 | 本当の成績 |
|---|---|---|---|---|---|---|
| 予測力なし・テスト200件 | 20 | 0.573 | 0.500 | +0.073 | 0.506 | 0.502 |
| 予測力なし・テスト200件 | 200 | 0.602 | 0.501 | +0.101 | 0.506 | 0.501 |
| 予測力なし・テスト1,000件 | 200 | 0.542 | 0.500 | +0.041 | 0.497 | 0.500 |
| 弱い予測力・テスト200件 | 20 | 0.635 | 0.591 | +0.044 | 0.590 | 0.599 |
| 弱い予測力・テスト200件 | 200 | 0.666 | 0.617 | +0.049 | 0.616 | 0.626 |
| 弱い予測力・テスト1,000件 | 200 | 0.653 | 0.643 | +0.010 | 0.631 | 0.634 |

- **予測力がまったくないのに**、200通り試してテストで選ぶと、テストの AUC は平均0.60になった（本当は0.50）。20通り以上では40回すべてで上振れ
- **弱い予測力があるとき**も、テスト200件では +0.04〜+0.05 上振れ。テストを1,000件にすると +0.01 前後
- **検証用で選んで手つかずのテストで測る**と、上振れは −0.010〜+0.009 の範囲に収まった。選んだモデルの本当の成績も、テストで選んだ場合と同じかやや高い（0.626 と 0.617）

## 注意（言えないこと）
- 架空のデータ。特徴の数・効き方・試す設定の範囲は作成者が置いたもので、結果はこれで決まる
- 上振れの大きさは、テストの件数・試した数・設定どうしの似かたで変わる。ここでは設定をランダムに選んだので、似た設定を少しずつ変える調整では、上振れはもっと小さいと考えられる（推測）
- 「答えの漏れた列」（記事460）のように、データそのものに問題がある場合の話ではない。ここではデータは正しく、使い方だけが問題になる
- 検証用データでくり返し選ぶと、検証用データの成績は上振れする。ここでも、検証用データの成績ではなく、最後に1回だけ使ったテストの成績を報告している
