# 1165 毎日の差分だけを残す控えと、毎回全部を残す控えでは、量と戻すときに読む量はどう入れかわるのか？（データ量の見込み）

保存データの控え（バックアップ）を毎日全部取ると、控えの量はデータの量×残す日数になります。そこで、ときどき全部を取り、その間の日は書きかわった分だけを取ることがよくあります。書きかわった分の取り方には、「前日の控えから書きかわった分」（増分）と、「最後の全部の控えから書きかわった分」（差分）の2つがあります。前日からの分は1つ1つが小さく、残す量は少なくなりますが、戻すときには全部の控えに、その後の前日からの分を全部重ねて読みます。全部の控えからの分は、戻すときに読むのが全部の控え＋1つだけで済みますが、日がたつほど1つが大きくなります。**ここでは、作成者が置いた架空のアプリの保存データ1,000GB（10MBの区切り10万個。毎日、区切りの一部が書きかわる確率を置き、乱数で作ったもの）で、過去28日のどの日の状態にも戻せるように控えを残すとき、全部を取る間隔（1・7・14・28日）と2つの取り方で、残している控えの量と、最新の日に戻すときに読む量を224日分数えました。書きかわり方の形と1日に書きかわる量を変えた9通りで確かめました。**

毎日全部取ると、残す量はデータの量×28日の28,000GB、戻すときに読む量はデータの量の1,000GBです（作りどおり）。前日からの分で残す量は、ほぼ「残している全部の控えの数×1,000GB＋前日からの分の合計」になります（作りどおり）。この記事で数えて新しく分かったのは、同じ区切りが何度も書きかわるときに、全部の控えからの分がどれだけ小さく収まるかと、2つの取り方の量と読む量の入れかわりの大きさです。

関連する記事：同じ企画の 1163「同じ中身をまとめて減る量は、試しに使った一部のデータから見込めるのか？」は、同じ中身の写しをまとめて減る量を扱っています。1162「ファイルごとの圧縮率を平均すると、全体の縮み方とどれだけ違うのか？」は圧縮で減る量です。この記事は、控えの取り方で残す量と戻すときに読む量がどう入れかわるかに絞ります。1164「1か月の増え方を12倍した1年の見込みは、月による増え方の偏りでどれだけ外れるのか？」は、データそのものが増える量の見込みを扱っています。1169「控えを何世代残すかで、控えの量は世代の数に比例して増えるのか？」は、同じ区切りが何度書きかわっても1回分しか残らないので「日数×1日に書きかわる量」が多く出る、という同じ仕組みを、残す世代の数の側から扱っています。この記事は、全部の控えの間に取る分の取り方（前日からか、全部の控えからか）で、残す量と戻すときに読む量が入れかわる点に絞ります。1166「古いものを消す決まりを入れると、量の伸びはどこで止まり、そこまで何日かかるのか？」は、古いものを消す決まりで量が止まる高さと日数を扱っています。

## 主な結果

### 基本の置き方（1日に書きかわる量は平均19.78GB＝1.978%、`results/base_schemes.csv`）
| 取り方 | 残す量（224日の平均） | 残す量（最大） | 戻すときに読む量（平均） | 戻すときに読む量（最大） |
|---|---|---|---|---|
| 毎日全部 | 28,000GB | 28,000GB | 1,000GB | 1,000GB |
| 7日ごとに全部＋前日からの分 | 5,374.3GB | 5,578.5GB | 1,059.4GB | 1,120.4GB |
| 7日ごとに全部＋全部の控えからの分 | 6,044.3GB | 6,198.9GB | 1,042.4GB | 1,073.8GB |
| 14日ごとに全部＋前日からの分 | 3,553GB | 3,757.1GB | 1,128.6GB | 1,259.2GB |
| 14日ごとに全部＋全部の控えからの分 | 4,848.4GB | 4,929.9GB | 1,068.6GB | 1,110.5GB |
| 28日ごとに全部＋前日からの分 | **2,746.5GB** | 3,053.7GB | 1,267.2GB | **1,537.8GB** |
| 28日ごとに全部＋全部の控えからの分 | 4,927.3GB | 4,977.3GB | 1,105.9GB | 1,171.6GB |

- **残す量がいちばん少ないのは28日ごとに全部＋前日からの分の2,746.5GB（毎日全部は28,000GB）。その代わり、戻すときに読む量は最大1,537.8GBで、データの量（1,000GB）の1.538倍になった**。前日からの分を27日分重ねて読み、同じ区切りを何度も読むため
- 全部の控えからの分で戻すときに読む量は最大1,171.6GB（28日ごと）。前日からの分より読む量は少なく、残す量は多かった
- 全部の控えからの分は、全部の控えの間隔を14日から28日に空けると、残す量が4,848.4GBから4,927.3GBに増えた。1つ1つの分が日を追って大きくなり、28日分残すため

### 全部の控えからの分の大きさ（基本の置き方、`results/base_diff_growth.csv`）
| 最後の全部の控えからの日数 | 全部の控えからの分 | 日数×1日に書きかわる量 | 比 |
|---|---|---|---|
| 1日 | 19.8GB | 19.8GB | 0.9999 |
| 6日 | 72.4GB | 118.7GB | **0.6103** |
| 14日 | 114.8GB | 276.9GB | 0.4145 |
| 27日 | 170.9GB | 534GB | **0.3201** |

- **全部の控えからの分は、日数×1日の量の見込みより小さかった（6日で0.6103倍、27日で0.3201倍）**。よく書きかわる5%の区切り（50GB）は何度書きかわっても1回分しか数えないため。日数×1日の量で見込むと、全部の控えからの分の大きさを高く見込む

- 全部の控えの間を空けた取り方（F＝7・14・28）の残す量は、データの量の2.354〜12.812倍だった（毎日全部は28倍）

## 注意（言えないこと）
- 架空のデータです。書きかわる区切りの割合と確率、区切りの大きさ、残す日数（28日）は作成者が置いたもので、量と読む量はこれで決まります。実在のアプリのデータや、実在の控えの仕組みを表すものではありません
- データの大きさは変わらないと置きました。データが増える場合、消した区切り、控えの圧縮や同じ中身のまとめは入れていません
- 「読む量」は最新の日に戻すときの量だけを数えました。古い日に戻すとき、読む速さ、控えを取るのにかかる時間、1つの控えが壊れたときに戻せなくなる範囲は数えていません
- 前日からの分を重ねて、新しい全部の控えを作る取り方は入れていません
- どの取り方を選ぶべきかや、容量の費用は扱っていません
