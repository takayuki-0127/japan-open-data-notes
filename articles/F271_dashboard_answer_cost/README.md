# F271 見られるダッシュボードと、見られないダッシュボードの違いは何か ― 同じ商業動態統計から3つの画面を作り、毎月の問いに答える手間を数える

精選モードの記事（D. 求人票の業務 Q34）。毎月のダッシュボードは、作っても開かれなくなることがある。ここでは「毎月出てくる問いに、どれだけ少ない手間で答えられるか」が分かれ目だと考えた。同じ公開データから、よくある形の画面を3つ作り、決めた問いに答えるまでの操作の数と時間を、人を使わずに数えて比べた。

## 結論
- **問いから作った画面（D3）は、主な8問に、見積もり時間の中央値0.85秒で答えられた。** 水準のグラフ型（D1）は33.95秒、表型（D2）は2.08秒。D3÷D1＝0.025（約40分の1）で、H1 支持。D1 の時間の7割は「自分で前年同月比を計算する」手間だった。計算と比べる手間を除いても、D1 は11.08秒（約13倍）。
- **最初の画面だけで答えられた割合は、D3 が100%、D1 が12.5%、D2 が75%**（パソコン 1366×768、H2 支持）。D2 は画面が1280×720だと12.5%、スマートフォンだと25%に下がった。
- **スマートフォンで、表型（D2）の時間は2.06倍になった。** D3 は0.88倍（H3 支持）。ただし、読む時間を0.6秒にすると D2 は1.67倍で、H3 は条件しだいだった。
- **水準の折れ線を位置で読むと、「前年同月より多いか」を間違える割合は平均9.7%。** 計画の基準10%にわずかに届かず、H4 は外れ。百貨店（17.7%）とホームセンター（14.1%）で高く、前年同月比の大きさが2%未満の43の月・業態では平均26%（3〜47%）になった。6業態を重ねた折れ線で読むと25.0%。
- **想定外の4問では、D3 は D1 より遅かった。** 中央値は D1 9.23秒、D2 8.43秒、D3 14.25秒。D3÷D1 は主な8問の0.025倍から1.54倍に変わり、H5 は支持。
- **問い直し：D3 の下に D1 の「水準」の部分（カード7枚と業態を選ぶ折れ線）を足した D4 は、主な8問の時間を変えずに（0.85秒、最初の画面で100%）、想定外の4問を11.25秒に縮めた。** ホームセンターの過去最高の月（X4）は244秒から15秒になった。

## データ
- 経済産業省「商業動態統計調査」業態別の月次販売額（6業態、2014-01〜2026-08）。F231 の `data/sales_monthly_6types.csv` を写した（新しい取得はしない）→ `data/raw/sales_monthly_6types.csv`（md5 081dc34b2191769ad3bc9c23774b6dba）。
- `data/processed/panel.csv`：業態×月の販売額（億円）、前年同月比、直近12か月の前年比、「いつもの揺れ」の帯と判定。

## 手法
### 3つの画面（`dashboard/`、外部ライブラリなしの HTML、`?m=YYYY-MM` で最新月を決める）
| 画面 | 形 | 中身 |
|---|---|---|
| D1 水準グラフ型 | 統計ダッシュボードのような形 | 最新月の販売額のカード7枚（億円）、業態を選ぶプルダウンと選んだ業態の販売額の折れ線（全期間、点にマウスを当てると値）、6業態を重ねた直近5年の折れ線 |
| D2 表型 | 公表資料の表のような形 | 行が月（直近25か月、新しい月が下）、列が業態ごとの販売額と前年同月比 |
| D3 問いから作る型 | 主な8問だけを見て作った | 最新月の表示、6業態合計の前年同月比と直近12か月の前年比のカード、業態ごとの前年同月比の並べ替えた棒（いつもの揺れの外は色）、業態ごとの前年同月比の直近24か月の小さな折れ線（揺れの帯、今月と先月の値） |
| D4 D3＋水準（問い直し） | 結果を見てから足した | D3 の下に、D1 のカード7枚と業態を選ぶ折れ線を足した |

- どの画面にも、同じ「元データの表」（`table.html`、全期間の販売額、新しい月が下）へのリンクを置いた。画面に答えがないときは、そこへ移って探す。
- いつもの揺れ：前年同月比の、その月の前36か月（2020-03〜2021-12 を除く）の平均±1.645×標準偏差。主な期間（24か月×6業態＝144）のうち16が帯の外だった。

### 問い
- 主な8問（D3 の設計に使った）：Q1 6業態合計の前年同月比、Q2 いちばん伸びた業態、Q3 マイナスの業態、Q4 スーパーの前年同月比は先月より上か、Q5 ドラッグストアは前年同月より多いか、Q6 いつもの揺れの外の業態、Q7 直近12か月は前の12か月より多いか、Q8 最新月。
- 想定外の4問（D3 の設計に使っていない）：X1 百貨店の今月の販売額、X2 コンビニは2019年同月より多いか、X3 今月の販売額がいちばん大きい業態、X4 ホームセンターの過去最高の月。
- 2024-09〜2026-08 の24か月を、それぞれ「最新月」とみなして数えた。

### 数え方（`src/zz_f271_04_測定.py`）
- Playwright で画面を開き、答えになる要素（`data-k`）の位置と、探すときに目に入る要素（`data-item`、まとまり `data-grp`）を集めた。D1 はプルダウンの7つの状態ごとに集めた。
- 問いごとに「読む人の手順」を決めた。値が画面にあれば読む。なければ、ほかの値から計算する（前年同月比は2つの販売額から）。それでもなければ元データの表へ移る。読む順は上から。見えていない要素へはスクロールする。
- 数えたもの：スクロール（画面の高さ・幅の何つ分か）、ポイント・クリック（プルダウン、リンク）、マウス当て、読む値の数、比べる回数、計算（電卓で割り算＝キー15回＋考える1回、足し算は1つの値あたりキー7回）、探す（見えているまとまりの数＋そのまとまりの中の要素の数）。
- 読んだ値で答えを出し、データから計算した正解と照らした。5,760件のうち5,756件が一致した。合わなかった4件は、D1 で丸めた販売額から計算した前年同月比が、丸めの境目で0.1ずれた同じ1問（2025-05 の Q1、画面の大きさ4つ）。
- 実際の操作も各画面の大きさで確かめた。点にマウスを当てるとツールチップに値が出ること、プルダウンで線が変わること（`results/interaction_checks.json`）。
- 時間はキーストローク・レベル・モデル（KLM：Card・Moran・Newell）で見積もった：ポイント1.1秒、クリック0.1秒、キー0.28秒、考える1.35秒、比べる1回1.35秒、読む1つ0.3秒、スクロール1画面1.1秒、探す（要素の数÷2）×0.05秒。
- 読み違い（H4）：D1 の折れ線を、マウスを当てずに位置で読むとする。今月と前年同月の2点の位置に、それぞれ標準偏差＝描画の高さの1.5%の誤差が入るとき、「前年同月より多いか」を間違える確率を正規分布で計算した（縦軸の範囲は画面と同じ、最小×0.9〜最大×1.05）。

## 問い直し：時間はどこから来ているか、そして D3 に何を足せばよいか（結果を見てから足した）
- **主な8問の平均時間の内訳**（パソコン）：
  - D1 は311.9秒のうち計算が73%、マウス当てが14%、探すが7%。
  - D2 は130.4秒のうち計算が86%。
  - D3 は1.1秒のうち探すが49%、読むが36%。
- **想定外の4問**：D3 は70.3秒のうち比べるが70%（X4 で元データの表の152か月を読み比べる）、スクロールが9%。
- **D4（D3＋水準）**：主な8問は中央値0.85秒・最初の画面100%のまま（足した部分は下にあり、最初の画面の探す手間が増えないため）。想定外の4問の中央値は D3 の14.25秒から11.25秒へ縮んだが、D1 の9.23秒には届かなかった。X1 は8.67秒→1.80秒、X4 は244秒→15秒。X2（2019年同月）は10.4秒で変わらず、X3 は17.1秒→12.1秒。

## 計画からのずれ
- 「比べる」1回の時間を、計画では書いていなかった。考える（M＝1.35秒）と同じにした（頑健性で0.5秒も試した）。
- 「探す」は、計画では「見えている要素1つあたり0.05秒×半分」だった。実際は2段にした。まず見えているまとまり（カード群・グラフ・表など）の数、次にそのまとまりの中の要素の数を数え、合計の半分×0.05秒とした。表の中のセルを1つずつ探すと数百になり、見出しから行と列を探す実際の読み方と合わないため。
- 読み違いは、計画の「1,000回の乱数」ではなく、正規分布から直接確率を計算した（同じものを乱数なしで求めた）。
- D3 の Q3・Q6 は、並べ替えた棒を下から読む・色のついた棒だけ読む、という手順にした。D1 の X4 は、ホームセンターを選んで、いちばん高い点とその両隣の3点にマウスを当てる手順にした（見て分かる山を確かめる）。どちらも計画には書いていなかった。
- H5 は、主な8問の比（0.025）が極端に小さかったため、「2倍以上」の基準は簡単に満たされた。意味のある比べ方は、想定外の4問で D3 が D1 の1.54倍遅かったこと。
- D4 と問い直しは計画になく、結果を見てから足した。
- 1問（2025-05 の Q1、D1）で、丸めた販売額から計算した答えが正解と0.1ずれた（上の「数え方」）。

## 再現手順
```
pip install -r requirements.txt   # Playwright は chromium を使う
python3 src/zz_f271_01_取得.py     # F231 のデータを写す（FROM_WEB=1 で GitHub から）
python3 src/zz_f271_02_整形.py
python3 src/zz_f271_03_画面.py     # dashboard/ に d1〜d4.html と table.html

```
- 乱数は使っていない。data/raw と src だけを別のフォルダに写して全工程を流し直し（Python の文字列のハッシュの種も変えた）、data/processed・dashboard・results・figures の24ファイルがバイト単位で一致した。
- 初めの版では、同じ行の値を読む順が Python の集合の順に依っていて、スマートフォンの元データの表で横スクロールの数が±1変わることがあった。読む順を「上→左→キー名」に固定し、文字の読み込みを待ってから位置を集めるようにして直した（結果の数字は小数2桁で変わらなかった）。

## 言えないこと
- 人に使ってもらってはいない。時間は KLM の見積もりで、実際の人の時間ではない。とくに「探す」「比べる」の値は仮定で、頑健性で幅を見た。
- 「見られるかどうか」そのもの（開かれた回数）は測っていない。答える手間が少ないと開かれやすい、というのは仮定。
- 主な8問で D3 が速いのは、D3 をその8問に合わせて作ったから。この記事が数えたのは、その差の大きさと、想定外の問いでどれだけ不利になるか。
- 3つの画面は筆者が作ったもので、ほかの作り方（D1 に前年同月比のグラフを足すなど）では結果が変わりうる。
- いつもの揺れの帯は、百貨店のように直近36か月に大きな動き（2022〜23年の回復）を含むと広くなる。帯の決め方を変えれば、どの業態が「外」かも変わる。
- 読み違いの誤差（描画の高さの1.5%）は仮定。
