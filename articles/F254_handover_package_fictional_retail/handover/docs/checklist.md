# 引き継ぎのチェックリスト

## 渡す側（前の担当）

- [ ] 入口が1つある（`run_all.py`）。手順が README に3行以内で書いてある
- [ ] 使うコードの版が1つに決まっている（`config.toml` のコミット）
- [ ] ライブラリの版を固定した（`requirements.lock`）。下限だけ（`>=`）にしていない
- [ ] 作り直した結果が元と同じことを、機械で確かめられる（`verify.csv`。数字のファイルの「違う」が 0）
- [ ] 比べ方を決めた：バイトで比べるもの／中身で比べるもの（.gz）／丸めの差を許すもの（DuckDB の小数）／見た目だけのもの（PNG・PDF）
- [ ] コードのコメントにだけ書いてある前提を、README か docs に出した（F248 が隣の F246・F247 のフォルダを読む、など）
- [ ] 決めごとを一覧にした（`docs/decisions.md`）。同じ決めごとが何か所に書かれているかも
- [ ] 同じ決めごとを書いた場所が複数あるなら、同じ答えになるテストがある（`tests/test_rules.py`）
- [ ] 手で書いたファイルと作られるファイルの区別がつく（F249 の `powerbi/`）
- [ ] 時間のかかる段と、かかる時間を書いた（README の「かかる時間」）
- [ ] 新しい人の役で、きれいなフォルダから README だけを見て試走した。止まったところを `docs/troubleshooting.md` に書いた
- [ ] ネットワーク・ブラウザ（Chromium）・フォント（Noto Sans CJK）など、Python の外に要るものを書いた

## 受け取る側（新しい担当）

- [ ] README の「前提」を満たした（Python 3.11 以上、git、ネットワーク）
- [ ] `python run_all.py` が最後まで流れ、照合で「違う」が 0 だった
- [ ] `python tests/test_rules.py` が OK だった
- [ ] `docs/decisions.md` を読み、自分で決め直すもの（D1 の月の途中の開店など）と、持ち主に聞くもの（D8 の計画）を分けた
- [ ] 毎月の手順（`docs/monthly_runbook.md`）を、前の担当と一緒に1回やった
- [ ] 分からなかったことを、この資料に書き足した（次の人のため）
