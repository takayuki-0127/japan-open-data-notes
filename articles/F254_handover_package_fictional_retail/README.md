# F254 分析を引き継げる形にする（業務の再現：架空の会社で）

シリーズ③「業務の再現：架空の会社で」の9本目（F246〜F255）。架空の食品スーパー **サンプルマート（架空）** で1年かけて作った分析（F246〜F251）を、次の担当が同じ数字で作り直せる形にまとめ、**新しい人の役で試走して**、どこで止まり、何をそろえれば戻るかを測った。F165（公開分析の再現）の実務版。

> **会社も数字もすべて架空（乱数で合成したデータ）。** 実在の会社・顧客のデータは使っていない。
> 引き継ぎ資料の本体は [`handover/`](handover)。読むのは `handover/README.md` から。

- note：（公開後に記入）
- 成果物：入口 `handover/run_all.py`、手順書 `handover/README.md`、版の固定 `handover/requirements.lock`、決めごとの一覧 `handover/docs/decisions.md`、チェックリスト `handover/docs/checklist.md`、つまずきと直し方 `handover/docs/troubleshooting.md`、テスト `handover/tests/test_rules.py`、基準の md5 `handover/expected/manifest.json`

## 問い
前の担当が残したコードと README だけで、新しい人は同じ数字を作り直せるか。止まるのはどこで、数字がずれるのはどこか。何をそろえれば「同じ数字に戻った」と機械で言えるか。

## 結論
- **コードを読むと（図2）**：6回で README の手順は33、スクリプト33本・5,275行。前の回の成果物に頼る回が5、GitHub から取りに行く回が5、ブラウザ（Chromium）が要る回が5。ライブラリの版を固定した行は **30行中 0**（すべて `>=` の下限だけ）。F248 は隣の F246・F247 のフォルダを、GitHub から取る逃げ道なしで直接読む。
- **同じ決めごとが4か所に書かれていた（図6）**：「既存店」の判定が F246・F247・F248・F250 にそれぞれあり、書き方は2通り（暦の月の差で数える3か所、日付で13か月後と比べる1か所）。実際の24店×48か月では5つとも同じ答え。ただし月の途中（2024-10-15）に開店する架空の店を足すと、**2025-11 を既存店に入れるかで答えが割れた**。
- **新しい人の役で、README だけを見て流すと（図3）**：
  - 同じ版のライブラリで **33手順中4で止まった**。どれも「書き出すフォルダが無い」（F247・F249。`results/`・`dashboard/` を作らずに書く）。生成物を消してから流したときに起きる。
  - その日の最新版（pandas 3.1.1・DuckDB 2.0.0 ほか）では **8で止まった**。増えた4つは「ブラウザが無い」。**版が変わったこと自体では、1つも止まらなかった**。
- **数字は元に戻ったか（図4）**：同じ版で作り直した数字のファイル165のうち、バイトまで同じは144。違って見えたものの多くは、`.csv.gz` の頭に入る時刻（10、中身は同じ）と丸めの差だった。
  - **同じ版・同じデータでも、mart の数字が実行ごとに変わった（図5）**。DuckDB が並列で足し算して足す順番が変わり、人時を 0.1 の単位で書くため、四捨五入の境目の値が 0.1 ずれる。5回流すと md5 が5通り、1回目と違うセルは 6〜17。DuckDB を1本で足すと、5回とも同じ md5 になった。
  - mart のずれは下流に伝わり、F248 の人時粗利が相対 1e-4 ほど動いた。レポートの表に出る数字（Markdown）は変わらなかった。
- **引き継ぎ資料で流すと**：きれいなフォルダで、README の4つのコマンド（venv・pip・run_all.py・テスト）が止まらずに最後まで流れ、**数字のファイル88個が基準の md5 とすべて一致**した。かかった時間は約4分（pip 31秒、run_all.py 194秒。うち145秒は偶然の幅を測る20通りの作り直し）。
  - 版を固定せずに最新版で同じことをすると、88個のうち **32個の md5 が基準と合わなかった**（差は小数の終わりの方。元のファイルとは許容の範囲で同じ）。

## やったこと
1. **監査**（`src/01_監査.py`）：F246〜F251 のコード・README・requirements.txt を読み、前の回への依存、ネットワーク・ブラウザの要否、版の固定、README に書いていない前提、同じ決めごとを書いた場所を数えた。
2. **引き継ぎ前の試走**（`src/02_試走_引き継ぎ前.py`）：git で取ったきれいな作業コピーから生成物を消し、6回の README の「再現手順」の python の行を上から流した（止まっても次へ進む）。ライブラリは2通り（同じ版／最新版）。流し終わったら、コミットに入っている元のファイルと比べた。
3. **引き継ぎ資料を作った**（`handover/`）：
   - **入口は1つ**：`run_all.py` が、決めたコミットの F246〜F251 を取り、段の表（`samplemart/stages.py`）のとおりに流し、照合までやる。
   - **元のコードは書き換えない**：先に「数字が同じか」を確かめる仕組みを置き、整理はその後にする。前の回の成果物は GitHub から取らず、作り直した隣のフォルダから写す（前の回の直しが後の回に流れる）。
   - **DuckDB は1本で足す**（`samplemart/launch.py`）：コードは書き換えず、起動のときに `SET threads TO 1` を差し込む。
   - **版の固定**（`requirements.lock`）と、ブラウザが要る段の分離（`requirements-browser.lock`、`--target all` のときだけ）。
   - **照合**（`samplemart/verify.py`）：基準（引き継ぎのときに1回作って固定した md5）で合否を決め、記事に載った元のファイルとの差も書く。`.gz` は中身で、`.csv` は「相対 1e-9 か、書いた桁の1単位」まで、JSON は最大の相対差で比べる。処理の速さを測った欄（F249）は除く。
   - **決めごとの一覧**（`docs/decisions.md`）とテスト（`tests/test_rules.py`）：既存店の判定を4か所のファイルから関数だけ取り出し（コードは流さない）、同じ店・同じ月で比べる。
   - 毎月の手順（`docs/monthly_runbook.md`）、チェックリスト（`docs/checklist.md`）、試走で止まったところ（`docs/troubleshooting.md`）。
4. **引き継ぎ後の試走**（`src/03_試走_引き継ぎ後.py`）：空のフォルダで、`handover/README.md` の「まず、これだけ」のコマンドだけを上から流した。
5. **確かめ**（`src/04_確かめ.py`）：DuckDB を並列のまま／1本で、それぞれ5回流して mart のずれを数えた。最新版の venv で run_all.py を流し、基準と比べた。

| 　丸めの差（相対 1e-9 か書いた桁の1単位） | 4 | 34 | 3 |
| 　JSON の数が少し違う | 2 | 9 | 1（相対 9.9e-6） |

- 引き継ぎ前の時間は、ほかの作業と並べて流したため長めに出ている（同じ版の回は特に重なった）。人が README を読んで順番を決める時間は測っていない。
- 「元とバイトまで同じ」の分母は、コミットに入っている数字のファイルのうち、手で書いた3つ（F249 の `powerbi/` の md）を除いたもの。

## 頑健性
- **同じ結果が何度でも出るか**：引き継ぎ資料で report を2回（基準を作った回・空のフォルダからの試走）、all を2回流し、数字のファイルの md5 が基準と一致することを確かめた（all の2回目は `results/G_all2.json`）。
- **DuckDB の並列**：並列のまま5回 → md5 が5通り（1回目と違うセル 0・12・17・14・6、元のファイルと 10〜14）。1本で5回 → md5 は1通り（元のファイルと 8 セル）。
- **版の固定**：最新版で run_all.py → 基準と一致 56／88。元のファイルとは、68 が許容の範囲で同じ、2 が JSON で少し違う（相対 1e-5 以下）。md5 で合否を決めるなら、版の固定は欠かせない。
- **既存店の判定**：実際の24店×48か月（1,152）で割れ 0。境目の架空の4店（月の途中の開店・閉店、月初の開店、月末の閉店）×48か月で割れ 1（2024-10-15 開店の店の 2025-11）。

## 言えないこと
- 試したのは Linux・Python 3.13 だけ。Windows・Mac では試していない（パスの書き方・フォント・改行で、別のつまずきがありうる。推測）。
- 「新しい人」は筆者が役として演じたもの。コードを書いた本人なので、README に書いていない前提に気づかずに済んでいる部分がある（推測）。本当に別の人に渡して試したわけではない。
- 時間はほかの作業と並べて測ったので、目安。人が読んで理解する時間は測っていない。
- 図や PDF（見た目のファイル）が同じかは、フォントやライブラリの版で変わるので、合否には入れていない。
- 最新版で止まらなかったのは、この日（2026-11-11）の版の組み合わせでの話。
- 会社も数字も架空なので、実在の会社の引き継ぎでよく起きること（権限・データの置き場所・担当者の暗黙の知識）は再現していない。

```
python src/01_監査.py <F246〜F251 を sparse checkout した作業コピー>

python src/02_試走_引き継ぎ前.py <別の作業コピー> <最新版の venv の python> latest
python src/03_試走_引き継ぎ後.py <空のフォルダ> local1 local
python src/04_確かめ.py <run_all.py で作った work/repo> <最新版の venv の python> <空きフォルダ>

```
