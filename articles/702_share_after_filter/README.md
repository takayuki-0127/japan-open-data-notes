# 702 構成比を WHERE で絞り込んだあとに出すと、全体に対する割合とどれだけ違って見えるのか（実務の型・SQL の集計）

構成比を `SUM(amount) / SUM(SUM(amount)) OVER ()` で出すとき、WHERE で絞ったあとに計算すると、分母は「絞った中の合計」になります。表の見出しに「構成比」とだけ書くと、全体に対する割合と読まれがちです。**ここでは、架空の60品目（6カテゴリ）・4万行の売上明細で、分母を絞った中の合計にした場合と全体の合計にした場合を比べました。** 品目の売れ方と単価は作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A702 | 絞ってから割るか、全体で割ってから絞るかで、構成比はどれだけ違うか | A 絞った中の合計で割る、B 全体で割ってから絞る、C 上位10品目で割る。絞り方はカテゴリ・上位10品目・1行1万円以上の明細。DuckDB（1スレッド）と pandas で一致を確認。seed 702 | `src/a702_share.py`、`src/02_share_duckdb.sql`、`src/01_share_tsql.sql`（未検証） |

## 主な結果
- **カテゴリで絞る**：食品（金額で全体の8.8%）で絞ってから割ると、どの品目も **11.4倍** に見える。食品05は「29.6%」と出るが、全体に対しては2.6%
- **上位10品目に絞る**：10品目で合計100%になる。本当は全体の73.2%なので、各品目は1.37倍に見える（衣料04は18.5%と出るが、全体の13.5%）
- **行を金額で絞る**：1行1万円以上の明細（2,537行、金額の43.3%）だけで構成比を出すと、家電は53.0%→**87.3%**、食品は8.8%→0.0%。分母だけでなく、入る行そのものが変わる

## 動かし方
```
pip install -r requirements.txt
cd src && python a702_share.py
```
数秒で終わります。`data/sales.csv` に明細を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- DuckDB の3つの SQL（A・B・C）の構成比が、pandas の結果と一致した
- T-SQL 版（`01_share_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/sales.csv`：line_id・item・category・amount
- 仮定：カテゴリごとの行数の割合、品目の売れ方（ディリクレ分布）、カテゴリの単価の目安は作成者が置いた。金額は対数正規分布

## 注意（言えないこと）
- 架空のデータ。何倍に見えるかは、絞った範囲が全体の何%かで決まる（1÷その割合）
- 絞った中の割合が正しい場面もある（「食品の中でどれが売れているか」）。ここで言いたいのは、分母を表に書かないと読み違えるということ
- 実在の店や品目の数字ではない
