# 411 「保険年齢」と「満年齢」では、同じ契約者の年齢区分はどれだけ変わるのか（実務の型）

架空の契約者10万人（生年月日と契約日）で、満年齢・保険年齢・年度末の満年齢・DATEDIFF(year) を出し、年齢と年齢区分が違う人を数えたフォルダです。386（「以上」と「超」の取り違え）は区分の境目を扱いました。ここでは、年齢の数え方そのものを比べます。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A411 | 年齢の数え方を変えると、年齢・5歳刻みの区分・条件に当てはまる人数はどれだけ変わるか | 4つの数え方を Python で計算し、同じ SQL を DuckDB で実行して一致を確かめる。境目の日（6か月ちょうど、誕生日の前の日、2/29生まれ）の人数を数える | `src/a411_ages.py`、`src/01_ages_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **満年齢と1歳違う人**：保険年齢49.5%、年度末の満年齢50.8%、DATEDIFF(year) 51.0%。3つの数え方（満年齢・保険年齢・年度末の満年齢）がすべて同じ人は37.4%
- **5歳刻みの区分が満年齢と違う人**：保険年齢9.8%、年度末の満年齢10.1%、DATEDIFF(year) 10.1%
- **平均**：満年齢44.18歳、保険年齢44.67歳
- **「65歳以下」に当てはまる人**：満年齢96,187人、保険年齢95,781人（−406）、年度末の満年齢95,737人（−450）、DATEDIFF(year) 95,768人（−419）
- **6か月ちょうどの日に契約した人**：279人（「超えたら」と「以上」の取り違えで保険年齢が変わる）
- **誕生日の前の日に契約した人**：282人（「前の日の終わりに年を取る」数え方で満年齢が変わる）
- **2/29生まれ**：73人。うるう年でない年の誕生日を 2/28 とするか 3/1 とするかで、満年齢が変わった人0人、保険年齢が変わった人2人。1人の契約日を4年分（1,461日）動かすと、満年齢が違う日3日、保険年齢が違う日12日
- **6か月後の日がその月にない人**（月末に切り詰め）：1,931人
- **日数÷365.25 を四捨五入する近似**：保険年齢と0.31%の人で違う


## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の SQL で出した満年齢・保険年齢・年だけの差が、Python の計算と10万人すべてで一致する（コード内の assert）

## データ
- `data/policyholders.csv`：架空の契約者10万人（契約者ID・生年月日・契約日）。作成者が乱数で作成（seed 411）

## 注意（言えないこと）
- 架空のデータ。割合は、契約日と誕生日の散らばり方で変わる
- 保険年齢の決まりは「6か月を超えたら切り上げ」の1通りだけ。商品や会社による違いは扱っていない
- 年齢が法律上いつ増えるかは、人数を数えただけで、どちらで数えるべきかは決めていない
- 2/29生まれで変わった人数（0人・2人）は、人数が少なく割合としては読めない
- 保険料や給付への影響は計算していない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
