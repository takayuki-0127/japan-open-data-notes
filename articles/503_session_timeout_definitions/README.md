# 503 ログの「セッション」を何分空いたら切るかで、セッション数と1回あたりの滞在はどれだけ変わるのか（実務の型）

本当の「訪問」が分かっている架空のアクセスログ（3,000人・28日・40,489ページ）を作り、前のページから何分空いたら次のセッションにするか（5〜120分）と、日付が変わったところで切るかどうかを変えて、セッション数・1回あたりのページ数・1ページだけの割合・本当の訪問との一致を比べたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A503 | 切る時間でセッションの数字はどれだけ変わるか | 架空の閲覧（ふつうの間隔は中央値45秒、3〜15分の読み込み15%、15〜45分の離席5%、10〜60分後にすぐ戻る別の訪問12%）を作り、5・10・15・20・30・45・60・90・120分で切ってセッションを作り直す | `src/a503_sessions.py`、`src/02_sessionize_duckdb.sql`、`src/01_sessionize_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **本当の訪問**：11,878回、1回あたり3.41ページ、1ページだけの訪問29.8%
- **5分で切る**：セッション16,994（本当の訪問の143%）、1回あたり2.38ページ、1ページだけ42.3%、本当の訪問とちょうど一致70.5%
- **15分**：13,109（110%）、3.09ページ、32.7%、一致87.3%（この中で最も高い）
- **30分**：12,019（101%）、3.37ページ、29.7%、一致85.5%。数はほぼ合うが、分かれた訪問とまとまった訪問が打ち消し合っている
- **120分**：10,520（88.6%）、3.85ページ、24.6%、一致77.3%
- **間隔の重なり**：同じ訪問の中の間隔の2.4%は30分より長く、訪問と訪問の間の6.4%は30分以内。どこで切っても混ざる
- **日付で切る**：日をまたぐ訪問は75回。30分で切るとき、日付でも切るとセッションは64ほど増えるだけ


## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB のウィンドウ関数（LAG と累積和）で30分のセッションを作ると12,019で、pandas と一致すること（コード内の assert）

## データ
- `data/fictional_pageviews.csv`：架空の閲覧記録（seed 503）。列は user, visit（本当の訪問の番号）, ts

## 注意（言えないこと）
- 架空のログ。どの時間が合うかは、置いた間隔の分布で決まる。15分がいつも良いという話ではない
- 特定のアクセス解析の製品の数え方（キャンペーンの切り替わりで切る等）は試していない
- 実際のログでは本当の訪問は分からないので、一致の割合は出せない。間隔の分布を見て決める手がかりにとどまる
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
