# 621 A/B テストの割り付けが 50:50 からずれていることに、何人集まれば気づけるのか（実務の型）

A/B テストでは、予定どおりの比（ここでは 50:50）で人が割り付けられているかを、本題の比較の前に確かめます（SRM＝sample ratio mismatch の確認）。**ここでは、B 側だけ記録の取りこぼしで一部の人が消える架空のテスト（消えるのは申込みをしない人、本当の効果は0、申込み率5%）で、割り付けの比の確認（カイ二乗の適合度検定、p<0.001）が何人で気づけるか、気づかずに比べると B がどれだけ良く見えるかを数えました。** 各条件2,000回。1日1万人・28日の例は SQL（DuckDB）でも人数とカイ二乗の値を出し、Python と一致することを確かめています。数字は置いた消え方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A621 | 割り付けのずれに何人で気づけるか、ずれたまま比べると効果はどう見えるか | 二項分布のシミュレーション（予定 1,000〜100万人、B から消える割合 0〜5%）、カイ二乗の適合度検定（p<0.001）、非心カイ二乗での必要人数、申込み率の z 検定。各2,000回、seed 621 | `src/a621_srm.py` |
| SQL | 人数とカイ二乗の値を出す | DuckDB 版（1スレッドで実行）、T-SQL 版（未検証） | `src/02_srm_check_duckdb.sql`・`src/01_srm_check_tsql.sql` |

## 主な結果
- **気づける人数（p<0.001 で 80% の回に気づく、計算上）**：B の 5% が消えるなら約2.7万人、2% なら約17万人、**1% なら約68万人**、0.5% なら約273万人
- **シミュレーションでの気づく割合**：B の 1% が消える場合、10万人で 5.0%、30万人で 31.2%、100万人で 96.4%。2% なら 10万人で 46.4%、30万人で 98.6%
- **ずれたまま比べると（各群10万人、本当の効果0）**：B の申込み率は、消える割合 1% で平均 +0.95%、2% で +1.99%、5% で +4.99% 高く見えた。「差あり」（p<0.05）と出た回は、ずれなし 5.3% に対し、1% で 8.1%、**2% で 17.6%**、5% で 69.7%
- **1日1万人・28日・B の 2% が消える例**：累計の B の割合は 49.5〜49.6% で動き、p<0.001 に初めて届いたのは10日目（約10万人）。11〜14日目はまた 0.001 を上回り、15日目からは下回ったまま。28日目は A 139,820人・B 137,575人（B 49.60%）、カイ二乗 18.17

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data が一致した
- ずれなしのとき、割り付けの確認で「ずれあり」と出る割合が 0.1% 前後、申込み率の比較で「差あり」と出る割合が 5% 前後になること
- 28日の例で、SQL（DuckDB）と Python の人数とカイ二乗の値が一致すること

## データ
- `data/assignments.csv`：28日の例の割り付けの記録（user_id・day・arm・converted、277,395行）。作成者が乱数で作った架空のもの

## 注意（言えないこと）
- 架空のデータ。消える割合と、消えるのが申込みをしない人だという前提は作成者が置いたもので、結果はこれで決まる
- 割り付けのずれの原因（記録の仕組み、表示の遅れなど）を探す方法は扱っていない
- p<0.001 という基準は、よく使われる目安の1つを使った
