# 521 問い合わせの対応時間を「営業時間」で数えるか「暦の時間」で数えるかで、期限内に返せた割合は何ポイント変わるのか？（実務の型）

架空の問い合わせ30,000件（2025年の1年分）を作り、窓口は平日9〜18時だけ動く（土日・祝日・12/29〜1/3は休み）として初回の返信時刻を置いたうえで、同じ記録の「受付から初回返信まで」を暦の時間と営業時間の2通りで数え、期限内（4・8・24時間）に返せた割合を比べたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A521 | 同じ記録を暦の時間と営業時間で数えると、期限内の割合は何ポイント変わるか。受付の時間帯・曜日でどう違うか | 営業日カレンダー（祝日は内閣府「国民の祝日」）から「その時刻までに過ぎた営業分」の累積を作り、返信時刻と受付時刻の差を取る。同じ計算を SQL（DuckDB）でも行い、Python と一致するか確かめる | `src/a521_sla_hours.py`、`src/02_business_minutes_duckdb.sql`、`src/01_business_minutes_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（30,000件、営業時間で数えた返信までの中央値2.5時間）
- **期限内に返せた割合（暦の時間 → 営業時間）**：4時間以内 30.9% → 70.4%（+39.5ポイント）、8時間以内 37.9% → 90.6%（+52.7ポイント）、24時間以内 71.9% → 99.4%（+27.5ポイント）
- **返信までの中央値**：暦の時間 15.5時間、営業時間 2.5時間
- **受付の時間帯別（8時間以内）**：平日の営業時間内 63.5% → 90.4%（+26.9）、平日の夜・朝 24.4% → 90.9%（+66.5）、週末（金曜夜〜日曜）0.0% → 91.0%、3連休以上の前・最中 0.0% → 90.2%
- 営業時間で数えると、受付の時間帯がどこでも期限内は約90%でそろう。暦の時間で数えると、窓口が閉まっていた時間がそのまま「遅れ」に入る
- **受付の曜日別（暦の24時間以内）**：月〜木 83〜91%、金 52%、土 0%、日 49%。営業時間の8時間以内はどの曜日も90〜91%
- 8時間の期限で「暦では期限切れ、営業時間では期限内」になったのは15,818件（全体の53%）
- SQL（DuckDB）で数えた営業時間の経過は、Python と全件一致

## データ
- `data/fictional_inquiries.csv`：架空の問い合わせ記録（seed 521）。列は id・received（受付）・replied（初回返信）
- `data/holidays_2025.csv`：内閣府「国民の祝日」の CSV から、2024年12月〜2026年2月の祝日を抜き出したもの

## 注意（言えないこと）
- 架空のデータ。返信の速さ（営業時間で中央値150分の対数正規分布）、受付の時間帯と曜日の偏りは作成者が置いたもので、実際の窓口の値ではない
- 担当者は営業時間だけ動き、営業時間の中の速さは受付の時間帯によらない、と置いている。そのため営業時間で数えた割合が時間帯によらずそろうのは、置いた前提の結果でもある
- どちらの数え方が正しいかは、約束（契約や窓口の案内）がどちらで書かれているかで決まる。この記事は差の大きさを見ただけ
- 昼休み・夜間当番・年末年始以外の特別休業は入れていない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
