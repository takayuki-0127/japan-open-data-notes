# 330 同じファイルを2回取り込んでも、数字が二重にならない形はどう作るか（実務の型）

架空の日次売上ファイル（10日分、1日約240行）を、5つの取り込み方で表に入れ、6つの場面（再送、途中で止まって流し直し、訂正版、行が減る訂正版、古い版があとから届く、遅れた行が翌日のファイルに入る）で、二重・欠け・残り・古い値の行が何行出るかを数えたフォルダです。DuckDB で動かしました。T-SQL 版（`MERGE`）は `sql/01_idempotent_load_tsql.sql`（**SQL Server 本体では未検証**）。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A330 | 取り込みをやり直しても同じ結果になるのは、どの形か | A＝追記だけ／B＝ファイルにある日付の行を消して入れ直す（1つのトランザクション）／C＝キー（日・店・商品）で上書き／D＝版の番号を確かめて、その日の分を洗い替え／E＝キーで上書き＋版が古ければ上書きしない＋新しい版に出てこなかった行を消す。場面ごとに最後の表を「あるべき姿」とキーで突き合わせる | `src/a330_idempotent.py`、`sql/01_idempotent_load_tsql.sql` |

## 主な結果（おかしい行の数。あるべき行は2,398行）
| 場面 | A 追記だけ | B 洗い替え | C キーで上書き | D 版を確かめて洗い替え | E 上書き＋版＋消す |
|---|---|---|---|---|---|
| S1 同じファイルの再送 | 二重240 | 0 | 0 | 0 | 0 |
| S2 途中で止まって流し直し | 二重120 | 0 | 0 | 0 | 0 |
| S3 訂正版（値が変わる） | 二重240 | 0 | 0 | 0 | 0 |
| S4 訂正版（行が減る） | 二重228・残り12 | 0 | 残り12 | 0 | 0 |
| S5 訂正版のあとに古い版 | 二重240 | 古い値24 | 古い値24 | 0 | 0 |
| S6 遅れた行が翌日のファイルに | 0 | 欠け216 | 0 | 欠け216 | 0 |

- ずれた場面の数：A 5、B 2、C 2、D 1、E 0
- 売上合計のずれ：A は再送で+10.3%、途中停止で+5.0%、古い版まで届くと+20.5%。B と D は S6 で−9.1%（翌日のファイルにまじった前日の行のせいで、前日の分が消える）。C は S4 で+0.6%（取り消された12行が残る）
- 「洗い替え」は、ファイルがその日の全部の行を持つときだけ正しい。「キーで上書き」は、消えた行を消せない。どちらも、版を比べなければ古いファイルで新しい値が戻る

## 動かし方
```
pip install -r requirements.txt
cd src && python a330_idempotent.py
```
ファイルは実行時に作ります（seed 330）。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- 「あるべき姿」は、取り込みの処理とは別に、場面ごとに正しいファイルを集めて作った

## 注意（言えないこと）
- T-SQL の `MERGE` は SQL Server 本体では動かしていません。DuckDB では `INSERT … ON CONFLICT … DO UPDATE` で同じ流れを試しました
- E がずれ0だったのは、この6つの場面でのことです。たとえば「遅れた行」と「行が減る訂正版」が同じ日に重なると、E の「古い版の行を消す」は遅れて届いた行まで消すおそれがあります（試していません）
- 版の番号は、ファイルに付いているものとしました。版が分からないファイルでは、届いた順や中身のハッシュで代える必要があります
- 行数や割合は、1日240行・訂正1割・取り消し5%・遅れ1割という置き方で決まります
- 301（CSV を毎月取り込む形）は速報と確報の入れ替わりを扱いました。この記事は「やり直しても同じ結果になるか」に絞っています
