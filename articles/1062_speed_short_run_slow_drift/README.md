# 1062 短い時間の計測で、動かすほどだんだん遅くなる処理は見つかるのか？（処理の速さ）

呼ぶたびに少しずつ遅くなる処理（たとえば、動かすほど片付けの手間が積み上がっていく処理）は、長く動かして初めて困ったことになります。けれども、速さの計測は数分・数千回で終えることが多く、その間の遅れはごくわずかです。**ここでは、作成者が置いた分布からの乱数で作った架空のサーバーの処理時間（実機の計測ではない）で、1万回ごとに+1%（100万回で2倍）遅くなる処理を、1,000〜10万回だけ測って「だんだん遅くなっている」と言えるかを、①1件ずつの傾き ②20区切りの平均の傾き の2つの確かめ方で数えました。さらに、サーバーの混み具合の波（1,000回ごとに変わる）があると、遅くならない処理でもどれだけ「遅くなっている」と出るかを数えました。置き方を変えた27通りでも確かめました。**

## 主な結果

### 波がないとき（1回ごとの振れだけ、各400回）
| 測った回数 | その間に遅くなる量 | ①で「遅くなっている」と出た割合 | 式の値 | ②で出た割合 | 遅くならない処理で①が出た割合 |
|---|---|---|---|---|---|
| 1,000回 | +0.1% | **5.75%** | 5.21% | 5.0% | 4.25% |
| 3,000回 | +0.3% | 8.5% | 6.15% | 8.75% | 3.5% |
| 10,000回 | +1% | 13.75% | 15.35% | 14.5% | 5.5% |
| 30,000回 | +3% | 94.0% | 94.46% | 91.0% | 4.0% |
| 100,000回 | +10% | 100.0% | 100.0% | 100.0% | 5.25% |

- **1,000回の計測では、100万回で2倍になる処理でも「遅くなっている」と出たのは5.75%で、遅くならない処理（4.25%）とほとんど変わらなかった**。1,000回の間に遅くなる量は0.1%で、1回ごとの振れ（標準偏差でおよそ25%）に埋もれる
- 見つかる割合は、波がなければ式どおりだった（27通りのうち波のない9通りで、式との差は最大4.33ポイント）。式から、8割の確率で見つけるのに要る回数は**約25,150回**。25,100回（その間に遅くなる量は+2.51%）で測り直すと、①で79.5%、②で78.0%だった
- 傾きの確かさは測る回数の1.5乗に比例して増すため、見つかる割合は、10,000回の13.75%から30,000回の94.0%へと急に上がる。27通りでは、8割に要る回数は14,900〜45,100回（式の値）だった

### 混み具合の波があるとき（基本、各400回）
| 測った回数 | 遅くならない処理で①が出た割合 | 遅くならない処理で②が出た割合 | 遅くなる処理を②で見つけた割合 |
|---|---|---|---|
| 1,000回 | **20.0%** | 18.25% | 18.75% |
| 3,000回 | 31.25% | 24.75% | 24.0% |
| 10,000回 | 33.25% | 14.75% | 17.75% |
| 30,000回 | 30.75% | **7.5%** | 22.5% |
| 100,000回 | 34.5% | 6.5% | 100.0% |

- **波があると、遅くならない処理でも、①1件ずつの傾きでは20.0〜34.5%の回で「遅くなっている」と出た**（本来は5%）。①は1件ずつの振れがばらばらだと見なして計算するが、波で近くの回どうしが似た値になるため、波の上下を「遅れ」と取り違える。27通りのうち波のある18通りでは26.67〜46.0%だった
- ②20区切りの平均の傾きは、区切り1つが波の長さ（1,000回）より長くなると本来の5%に近づいた（30,000回で7.5%、100,000回で6.5%。27通りの波のある18通りで4.0〜10.67%）。区切りが波より短い3,000回では24.75%だった
- その代わり、②で遅くなる処理を見つけられたのは、30,000回で22.5%にとどまった（波がなければ91.0%）。波の上下の大きさ（およそ±5%）が、30,000回で遅くなる量（+3%）と同じくらいあるため。100,000回（+10%）では100.0%だった

## 注意（言えないこと）
- 架空のデータです。処理時間の分布、遅くなる速さ（まっすぐ増える形）、引っかかりの頻度と大きさ、混み具合の波の大きさと長さは作成者が置いたもので、結果はこれで決まります。8割見つけるのに要る回数は、置き方で14,900〜45,100回と動きました。実在のソフトやサーバーの計測を表すものではありません
- 遅くなる形は「呼んだ回数にまっすぐ比例」と置きました。ある回数を超えると急に遅くなる形や、ときどき元に戻る形では、見つかりやすさが変わります（推測）
- 確かめ方は傾きの2つだけです。ほかの確かめ方（前半と後半の比べ、ほかの区切りの数など）や、メモリの使用量など処理時間以外の記録を見る方法は扱っていません
- 混み具合の波は、決まった長さで入れかわる単純な形と置きました。実際の波の長さが分からないときに、何区切りにすればよいかは、この記事では決められません
