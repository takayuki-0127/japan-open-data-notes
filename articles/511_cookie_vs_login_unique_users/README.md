# 511 ログの利用者IDが Cookie だと、ユニーク利用者は本当の人数の何倍に数えられるのか？（実務の型）

架空の利用者5,000人（訪問した4,996人）の2026年1年分のアクセスログ（訪問365,920件）を作り、同じログを「本当の人ID」「Cookie」「ログインID（ログインした訪問だけ）」「Cookie をログインでつなぎ合わせたID」の4通りで数えて、ユニーク利用者と1人あたりの訪問回数を比べたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A511 | Cookie で数えると、ユニーク利用者は本当の人数の何倍になるか。期間の長さと Cookie の寿命で、それはどう変わるか | 1人に端末1〜3台を持たせ、端末ごとに Cookie を発行。Cookie は平均寿命（指数分布）で消え、消えると新しい Cookie になる。日・週・月・年ごとにユニーク数を数え、Cookie の平均寿命を「消えない」〜7日に変えてくり返す | `src/a511_cookie_ids.py`、`src/02_monthly_uniques_duckdb.sql`、`src/01_monthly_uniques_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（Cookie の平均寿命60日、端末1〜3台、ログインは訪問の35%）
- **Cookie で数えたユニーク利用者は、本当の人数の**：日ごと1.06倍、週ごと1.25倍、月ごと1.75倍、年ごと8.66倍（4,996人に対して43,251）
- **ログインでつなぎ合わせると**：1.03倍、1.11倍、1.35倍、4.78倍。半分ほどに縮むが、ログインしない訪問の Cookie は残る
- **ログインIDだけで数えると**：0.38〜0.59倍。ログインしない人と訪問が抜けて、逆に少なく出る
- **1人あたりの訪問回数**：年では本当は73.2回、Cookie で割ると8.5回。月では6.9回と3.9回
- **Cookie の寿命を変えると（年ごとの倍率）**：消えない1.68倍（端末の違いの分だけ）、365日3.05倍、90日6.69倍、30日13.55倍、7日30.64倍。日ごとの倍率はどれも1.06倍で変わらない
- **端末1台の人だけ**：日1.00倍、月1.26倍、年5.78倍。短い期間の水増しは端末の違い、長い期間の水増しは Cookie の消去から来る
- SQL（DuckDB の COUNT(DISTINCT)）で数えた月ごとの人数は、pandas と全月一致

## データ
- `data/fictional_access_log.csv`：架空のアクセスログ（seed 511）。列は person（本当の人ID）・date・device・cookie・login。約10MB あるので GitHub には置いていない。`a511_cookie_ids.py` を動かすと同じものが作られる

## 注意（言えないこと）
- 架空のデータ。倍率は、置いた端末の台数・Cookie の寿命・訪問の多さの散らばりで決まる。実際のサイトの Cookie の寿命は調べていない
- 訪問の多い人ほど Cookie が多く消えるので、年の倍率は「平均の訪問回数」より「訪問の偏り」に左右される
- つなぎ合わせは「一度でもログインした Cookie をその人に結ぶ」だけの単純な方法。実際の計測ツールのやり方は試していない
- 1つの Cookie を家族で共有する場合（逆に人数が少なく出る）は入れていない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
