# 1279 同時に動かす数を増やして1秒あたりの件数が増えたとき、1件が終わるまでの時間はどう動いているのか？（並列処理）

アプリの処理を試すとき、同時に動かす流れの数を増やしながら「1秒あたりに何件終わったか」を数えることがあります。件数が増えていれば、速くなったように見えます。けれども、処理する所の数には限りがあり、件数が頭打ちに近づくころから、1件が送ってから終わるまでの時間は伸び始めます。**ここでは、作成者が置いた架空のアプリの処理（処理する所の数・1件の処理の量の分布・流れが次の1件を送るまでに休む時間・所の使い方を作成者が決め、乱数でシミュレーションしたもの）で、同時に動かす流れの数を1〜128本に変え、1秒あたりの件数と、1件が終わるまでの時間（平均・99%点）を数えました。所の使い方は「分け合う」と「順に待つ」の2つを比べ、所の数・処理の量の散らばり・休む時間を変えた27通り（×使い方2つ）で確かめました。**

実機での計測はしていません。すべて作成者が置いた決まりでのシミュレーションです。実在のアプリ・道具の動きを表すものではありません。

関連する記事：874「利用が8割を超えると、待ち時間はなぜ急に伸びるのか？」は、客が外からでたらめに来る窓口で、埋まり具合（利用率）が上がると平均の待ち時間がどう伸びるかを扱っています。857「同時に持つ案件を増やすと、1件あたりの日数は何倍になるのか？」は、1人が案件を同時に回すと1件あたりの日数が延びることを扱っています。1272「同時に動かす数を増やすと、1つしかない置き場所の取り合いで、速さはどこから伸びなくなり、下がることもあるのか？」は、同時に動かす数を増やすと、1か所の取り合いで速さが頭打ちになり、受け渡しの手間があると下がることを扱っています。1280「1つあたりの働いていた時間の割合が高いことは、全体が速いことを意味するのか？」は、働いていた時間の割合の高さを「速い」の印として読んだときのずれを扱っています。この記事は、外から来る量ではなく、試す側が同時に動かす流れの数を増やしたときに、数えた「1秒あたりの件数」と「1件の時間」がどう一緒に動くかに絞ります。

（4・8・24本は `base_by_k.csv` にある）

- 1〜24本では、件数は流れの数にほぼ比例して増え、1件の平均の時間は1本のときの0.9948〜1.0225倍（分け合う）でほとんど変わらなかった
- **分け合う使い方で流れを32本から64本にすると、件数は1.265倍、1件の平均の時間は3.6596倍、99%点は3.7664倍になった**
- 件数がまだ増えている区間でも、1件の時間は伸び始めていた。32→40本で件数は1.1852倍、平均の時間は1.2556倍。40→48本で件数1.0566倍、平均の時間1.4974倍（`results/step_ratios.csv`）
- 件数がいちばん多かったのは、分け合うで96本（80.2955件/秒）、順に待つで64本（80.2359件/秒）。分け合うで40本から96本にすると、件数は1.0822倍、平均の時間は5.6542倍だった。頭打ちのあとの件数の上下は、処理の量の乱数の振れによるもので、件数がいちばん多い流れの数を選ぶと、1件の時間の長いところを選ぶことになる
- 件数×(1件の平均の時間＋休む時間)は、どの流れの数でも流れの数とほぼ同じだった（差は最大0.1582本）。件数が頭打ちになると、1件の平均の時間は「流れの数÷件数−休む時間」で流れの数に比例して伸びる（式どおり）

### 分け合うと順に待つの違い（流れ64本）
- **1件の平均の時間は、分け合う409.4216ミリ秒・順に待つ397.1808ミリ秒とほぼ同じだったが、99%点は分け合うが順に待つの2.7327倍（2,621.0376ミリ秒と959.1514ミリ秒）だった**。中央値は分け合うが0.6621倍と短かった
- 分け合うと、小さい件はすぐ終わり、大きい件はほかの件と速さを分け合ったまま長く残る。順に待つと、どの件も列で同じくらい待つので、1件の時間は中央に寄る

### 確かめ：27通り×使い方2つ（`results/grid.csv`）
- **件数が頭打ちになり始める流れの数（K*）から2倍に増やすと、件数は0.9232〜1.1532倍、1件の平均の時間は1.9092〜12.0135倍**（54通り）。休む時間が長いほど、平均の時間の伸びは大きかった（休む時間0秒で1.9092〜2.1599倍、0.4秒で3.509〜4.8488倍、1.6秒で5.3799〜12.0135倍）。頭打ちのあとの平均の時間は「流れの数÷件数−休む時間」で決まり、K* の2倍ではおおよそ「1件の処理の量の平均×2＋休む時間」になるため（式どおり）
- K* の半分から K* に増やすと、件数は1.7402〜2.0399倍、平均の時間は0.9815〜3.0875倍。頭打ちの手前でも、1件の時間がすでに伸びている置き方があった
- K* での件数は、所が全部働いたときの式の値の0.8659〜1.027倍
- K* の4倍で、分け合うの99%点÷順に待つの99%点は、27通りすべてで1より大きく、1.385〜7.2843倍。平均どうしの比は0.716〜1.0598倍
- 平均どうしの比が0.716倍と小さかったのは、所16か所・散らばり1.5・休む1.6秒（K* の4倍＝1,088本）のとき。このとき分け合うの件数は式の上限の1.1117倍と、上限を超えて数えられた。数えた12,000件のあいだに終わらなかった大きい件が数から外れ、小さい件ばかりが数えられたため（分け合う使い方で、短い区間で数えたときのずれ）

## 注意（言えないこと）
- 架空のデータです。所の数、処理の量の分布、休む時間、所の使い方は作成者が置いたもので、結果はこれで決まります
- 所の取り合いで、流れを増やすほど1件の処理そのものが遅くなる場合（置き場所の取り合いなど）は入れていません。入れれば、件数は頭打ちのあと下がることもありえます（推測。この記事では数えていません）
- 流れは「終わるのを待ってから次を送る」と置きました。外から決まった速さで件が来る場合は、件数は来る量で決まり、1件の時間の伸び方も違います（874 の置き方に近い）
- 「頭打ちになり始める流れの数 K*」は式で出した目安で、実際の伸び方はその前後でなだらかに変わります
- 分け合う使い方で処理の量の散らばりが大きいと、短い区間で数えた件数と平均の時間がずれることがありました（確かめの一例）
- 使う台数や費用の見込み、どの流れの数を選ぶべきかの助言をする記事ではありません
