# 765 「NA」という区分名を pandas で読むと、何行が欠けた値になってしまうのか（実務の型・CSV の読み込み）

pandas の `read_csv` は、何も指定しないと「NA」「N/A」「null」「None」「NaN」などの文字を欠けた値（NaN）として読みます。地域コードの「NA」（北米）のように、これらの文字が本物の値として使われている列では、その行がまるごと欠けた値になります。**ここでは、架空の海外向けの受注明細1万2,000行（地域コードは NA・EU・AS・OC・SA・AF、本当に分からない行は空欄）を、読み方を変えて読み、欠けた値になった行と地域別の構成比のずれを数えました。** 地域の割合は作成者が置いたもので、数字はその置き方で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A765 | 既定の read_csv で「NA」はどれだけ欠けた値になり、集計はどれだけずれるか | A read_csv の既定、B dtype=str を指定、C keep_default_na=False と na_values=[""]（空欄だけを欠けにする）、D DuckDB の read_csv（1スレッド）。地域別の groupby で構成比を比べる。seed 765 | `src/a765_na_string.py`、`src/02_na_duckdb.sql`、`src/01_na_tsql.sql`（未検証） |

## 主な結果
- **北米がまるごと消える**：既定の読み方では、地域が欠けた値になった行が3,906行（32.6%）。本当に空欄なのは125行で、残りは北米（NA）の3,781行
- **dtype=str では直らない**：文字として読むよう指定しても、3,906行が欠けた値のまま
- **直し方**：`keep_default_na=False, na_values=[""]` で読むと、欠けた値は本当に空欄の125行だけになった。DuckDB の read_csv も既定で空欄だけを欠けにした
- **構成比のずれ**：地域別に groupby すると北米（本当は売上の32.0%）が消え、アジアは27.6%→40.6%、欧州は27.3%→40.1%に見えた。合計は32.0%少ない
- **自由記述の列も変わる**：メモの列に書かれた「N/A」「null」「None」「NA」も欠けた値になり、欠けた行は4,718行から9,569行に増えた

## 動かし方

```
pip install -r requirements.txt
cd src && python a765_na_string.py
```
数秒で終わります。`data/orders.csv` に受注明細を、`results/by_region.csv` に地域別の本当の売上と既定で読んだ売上を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- C の読み方と DuckDB で、地域が欠けた行の数が、書き出したときの空欄の行数と一致した
- pandas 2.3 で確かめた。T-SQL 版（`01_na_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/orders.csv`：order_id・order_date・region・memo・amount
- 仮定：地域は NA 32%・EU 27%・AS 28%・OC 6%・SA 4%・AF 3%、1%は空欄。メモは空欄が多く、「N/A」「null」「None」「NA」「急ぎ」「再送」がまざる
