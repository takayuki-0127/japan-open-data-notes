# 356 曜日の並びが違うだけで、前年同月比は何ポイント動くのか（実務の型）

売上の力は同じなのに、月の中の土日・祝日の数が前年と違うだけで動く「前年同月比」の幅を、架空の日次売上（曜日の型あり）と内閣府の祝日の一覧で数えたフォルダです。割り方（1日あたり・平日1日あたり・曜日の型で割る）ごとに、どこまで消えるかも比べました。SQL は DuckDB で動かしました。T-SQL 版は `src/01_adjusted_yoy_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A356 | 曜日の並びだけで前年同月比はどれだけ動くか。補正でどこまで消えるか | 3つの曜日の型（小売・週末型／法人向け・平日型／飲食・金土型）で、成長0・揺れ0の月次売上を作り、2016年1月〜2026年12月の132か月の前年同月比を出す。補正4通りを比べる。次に、本当の伸び（−2〜+6%）と1日6%の揺れを入れた売上を200回作り、補正後の値と本当の伸びのずれ（RMSE）を比べる | `src/a356_weekday_yoy.py`、`src/*.sql` |

## 主な結果
- **曜日の並びだけで動く幅（成長0・揺れ0）**：小売（週末型）−4.5〜+5.8%（幅10.3ポイント）、法人向け（平日型）−8.7〜+8.6%（幅17.3）、飲食（金土型）−5.6〜+6.2%（幅11.8）。1ポイント以上動いた月は58%・64%・61%
- 小売でいちばん動いたのは2月。うるう年の2月は平均+4.3%、その翌年の2月は−3.7%。うるう年がらみの2月を除いても最大2.9ポイント（2019年8月：土日祝が前年の8日から10日に）
- **割り方ごとの幅**：小売は 補正なし10.3 → 1日あたり5.7 → 平日1日あたり25.7 → 曜日の型で割る0.0。法人向けは 17.3 → 17.3 → 3.0 → 0.0。飲食は 11.8 → 10.6 → 26.4 → 0.0。「1日あたり」はうるう年にしか効かず、「平日1日あたり」は平日型にしか合わない
- **揺れと本当の伸びがある場合（200回の平均、本当の伸びとのずれの RMSE）**：小売 補正なし2.25 → 曜日の型で割る1.60ポイント、法人向け 4.51 → 1.84、飲食 2.59 → 1.61。重みを過去24か月の日次データから推定しても、本当の重みを使った場合と同じだった。伸びの向き（プラスかマイナスか）を取り違えた月は、小売で16.5% → 12.7%、法人向けで31.0% → 14.3%
- 補正後に残る1.6ポイントほどのずれは、1日ごとの揺れ（6%）そのものから来る分

## 動かし方
```
pip install -r requirements.txt
cd src && python a356_weekday_yoy.py     # 2分ほど
```
乱数の種を固定してあるので、実行のたびに同じ `results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- SQL（DuckDB）で出した補正後の前年同月比は、pandas で別に計算した値と一致した（コード内の assert）

## データ
- `data/syukujitsu_utf8.csv`：内閣府「国民の祝日」の一覧（syukujitsu.csv、2026-11-12 取得）を UTF-8 に直したもの。祝日・休日は曜日より優先して1つの種類（祝）として扱った
- 売上は架空（作成者が乱数で作成、seed 356）

## 注意（言えないこと）
- 売上は架空です。動く幅は、置いた曜日の重み（たとえば小売は土曜が月曜の1.5倍）で決まります。実際の店や会社の数字ではありません
- 祝日はどれも同じ重みにしました。連休・お盆・年末年始のように、祝日でなくても動く日は入れていません（それは F233 で扱いました）
- 曜日の型は期間を通して変わらないとしています。型そのものが変わる場合は試していません
- T-SQL 版は SQL Server 本体では動かしていません
- 月次の数字を前月比・前年同月比・季節調整のどれで読むかは 272 で扱いました。この記事は、前年同月比の曜日の補正だけに絞っています
