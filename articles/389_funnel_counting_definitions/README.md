# 389 申込みまでの通過率は、数え方でどれだけ変わるのか（実務の型）

「商品ページを見た人のうち、申込みまで進んだのは何%か」という通過率は、何を1と数えるか（回数・人・訪問）と、順番を問うかどうかで変わります。架空のアクセスログ（4万人・28日・約16.6万行）で、6つの数え方を比べたフォルダです。ログには、二重の記録、時刻のずれ、日またぎ、途中の段から入る訪問を入れてあります。SQL は DuckDB で動かしました。T-SQL 版は `src/01_funnel_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A389 | 数え方で通過率は何ポイント違うか。ログの汚れのうち、どれがどの数え方を動かすか | 段は 商品ページ→カート→入力フォーム→申込み完了。数え方は、回数（記録のまま）、回数（同じ時刻の写しを除く）、人（順番を問わない）、人（順番を問う）、訪問（順番を問う）、人×日（順番を問う、同じ日のうち）。人の動きは同じまま、記録のされ方（汚れ）だけを1つずつ入れた場面も比べる | `src/a389_funnel.py`、`src/01_funnel_*.sql` |

## 主な結果
- **商品ページ→申込み完了の通過率**：回数（記録のまま）6.0%、回数（同じ時刻の写しを除く）6.1%、人（順番を問わない）18.8%、人（順番を問う）15.2%、訪問（順番を問う）9.7%、人×日（同じ日のうち）9.5%。最大と最小の差は12.8ポイント
- 回数で数えると低いのは、1人が商品ページを何枚も見るため（商品ページの記録は12.6万行、人数は3.9万人）
- **段ごと**：商品ページ→カートは、回数で16%、人で40%、訪問で30%。カート→入力フォームは、人（順番を問わない）74%に対し、人（順番を問う）61%、訪問55%
- **どの汚れが効くか**（人の動きは同じ。汚れなしの通過率は、回数6.0%、人18.1%、訪問12.7%）
  - 二重の記録：回数だけが動く（6.0→5.7%。同じ時刻の写しを除いても5.9%）。人・訪問で数える値は変わらない
  - 時刻のずれ：順番を問う数え方だけが下がる（人18.1→17.9%、訪問12.7→12.5%）
  - 日またぎ：「同じ日のうち」だけが下がる（12.7→12.4%）
  - 途中の段から入る訪問（メールのリンクからカートへ、など）：順番を問う数え方が大きく下がる（人18.1→15.4%、訪問12.7→9.9%）。順番を問わない数え方は上がる（18.1→18.8%。商品ページの記録がない人が分母から抜けるため）
- 日ごとの通過率（28日）の幅は、回数で5.2〜7.0%、人×日で8.8〜10.6%

## 動かし方
```
pip install -r requirements.txt
cd src && python a389_funnel.py     # 1分ほど
```
乱数の種を固定してあるので、実行のたびに同じ `data/access_log.csv`・`results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、results・figures が一致した
- 「人（順番を問わない）」「人（順番を問う）」の4つの段の人数は、SQL（DuckDB）と pandas で一致した（コード内の assert、`results/sql_check_duckdb.csv`）

## データ
- すべて架空（作成者が乱数で作成、seed 389）。`data/access_log.csv`（user_id・session_id・ts・step_name）は約8MBあるので、GitHub には置いていません。コードを実行すると同じファイルができます
- 1人は28日のうち1〜3日に訪れる。次の段へ進む割合は、商品ページ→カート30%、カート→入力フォーム55%、入力フォーム→申込み完了60%。カートまで進んだ人の再訪の半分はカートから、訪問の4%は入力フォームから始まる
- 汚れ：記録の8%（申込み完了は3%）が二重（半分は同じ時刻の写し、半分は3〜60秒後）、3%の記録の時刻が前後に最大90秒ずれる、訪問の6%が日付の変わる直前に始まる

## 注意（言えないこと）
- 架空のデータです。数え方の間の差の大きさは、1人が何枚ページを見るか、何回訪れるか、途中から入る訪問がどれだけあるかで変わります
- どの数え方が正しいかは決めていません。知りたいこと（人の割合か、訪問の割合か）で決まります。同じ数字を2か所で出すときに、数え方をそろえる必要がある、というところまでです
- 人は user_id で分かるものとしました。実際のログでは、端末やブラウザが変わると別の人として数えられます。ここには入れていません
- 「同じ時刻の写しを除く」は、user_id・session_id・時刻・段がすべて同じ行を1つにしただけです。数秒後の再読み込みは残ります
- 訪問（session_id）の切り方は、道具ごとに違います（30分あくと切る、日付で切る、など）。ここでは、1回の来訪を1つの訪問としました
- T-SQL 版は SQL Server 本体では動かしていません
