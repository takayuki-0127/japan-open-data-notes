# 485 論理削除のフラグと履歴の期間を見落とすと、件数と売上はどれだけ多く出るのか（実務の型）

架空の顧客2万人（履歴の版を含め24,430行）と注文30万件を作り、削除フラグ（注文・顧客）と顧客の履歴の期間を見落としたとき、注文件数・売上・顧客数が正しい値より何%多く出るかを数えたフォルダです。注文の4%（2025年3月だけ15%）をキャンセルとして削除フラグを立て、顧客の5%（テスト用などの想定）を削除扱いにし、顧客の15%に区分の履歴（2〜3版）を持たせています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A485 | 削除フラグと履歴の期間を見落とすと、集計はどれだけずれるか | 7通りの集計を DuckDB の SQL で出し、pandas の集計と一致を assert。削除と期間をまとめて隠すビュー `v_orders` も作成 | `src/a485_softdelete.py`、`src/01_view_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **正しい集計**：注文272,184件／売上24億4,512万円／顧客18,967人
- **正しい値より多く出る割合（件数／売上／顧客数）**：
  - 注文の削除フラグを見落とす：+4.5%／+4.5%／±0
  - 顧客の削除フラグを見落とす：+5.5%／+5.6%／+5.4%
  - 両方を見落とす：+10.2%／+10.4%／+5.4%
  - 履歴の期間を見ずに customer_id だけでつなぐ：+22.2%／+22.2%／±0（履歴の版の数だけ注文が増える）
  - 削除も履歴も見落とす：+34.9%／+35.0%／+5.4%
  - 注文表だけで数える（顧客表を見ない）：+5.5%／+5.6%／+5.4%
- **月ごとの売上の上振れ（両方の削除フラグを見落とした場合）**：中央値9.8%、最小8.9%、最大24.4%（キャンセルの多い2025年3月）
- **2025年3月の前年同月比**：正しくは−9.2%、削除フラグを見落とすと+2.3%（減少が増加に見える）
- **区分別の売上を「注文日の区分」と「今の区分」で比べると**：一般 −1.9%、法人 +7.0%（今の区分でつなぐと、後から法人に変わった顧客の過去の注文が法人に入る）

## 注意（言えないこと）
- 架空のデータ。削除の割合（注文4%、顧客5%）や履歴の割合（15%）は置いた値で、ずれの大きさはこの値で決まる。実際の仕組みでのずれの大きさを表すものではない
- 削除された顧客の注文には、注文の削除フラグを立てていない前提。仕組みによっては顧客を消すと注文にもフラグが立つので、その場合は顧客側の見落としのずれは小さくなる
- 「正しい」はこのフォルダでの定義（削除を除き、注文日に有効だった版とつなぐ）。キャンセルを売上から除くか、どの時点の区分で集計するかは、目的と社内の決め方による
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
