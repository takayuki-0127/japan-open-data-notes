# 407 名前を消しただけの顧客データは、何%の人が1人に絞れてしまうのか（実務の型）

顧客のデータから名前を消して外に出すとき、残した項目（郵便番号・生年月日・性別）の組み合わせだけで、何%の人が1人に絞れるかを、架空の10万人で数えたフォルダです。F146・F147（公的統計の秘匿）に対し、ここでは業務のデータを外に出す前の確かめに絞っています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A407 | 残す項目の組み合わせごとに、同じ組み合わせが1人だけの人は何%か。項目を粗くするとどう下がるか | 架空の顧客10万人（seed 407）。組み合わせごとの人数 k を数える（k-匿名性）。顧客の数を1,000人〜100万人に変える。住民50万人の名簿との突き合わせ | `src/a407_k_anonymity.py`、`src/01_k_anonymity_tsql.sql`（未検証） |

## 主な結果
- **1人に絞れる割合（10万人）**：郵便番号7桁＋生年月日＋性別 99.95%、7桁＋生年＋性別 84.9%、7桁＋10歳きざみ＋性別 37.2%、3桁＋生年月日＋性別 97.5%、3桁＋生年月＋性別 47.5%、3桁＋生年＋性別 0.6%、3桁＋5歳きざみ＋性別 0.05%、生年月日＋性別 13.7%、郵便番号7桁だけ 1.2%
- **同じ組み合わせが5人未満の割合**：7桁＋生年＋性別 99.8%、3桁＋生年月＋性別 98.8%、3桁＋生年＋性別 9.4%、3桁＋5歳きざみ＋性別 0.2%
- **5人未満の行を出さないとき、出せる行**：3桁＋生年＋性別 90.6%、3桁＋5歳きざみ＋性別 99.8%、3桁＋生年月＋性別 1.2%
- **顧客の数を変える（3桁＋生年＋性別）**：1,000人 91.6%、1万人 40.3%、10万人 0.6%、100万人 0.0%。3桁＋5歳きざみ＋性別でも1,000人では64.9%
- **住民50万人の名簿の中でも1人だけ**：7桁＋生年月日＋性別 99.8%、7桁＋生年＋性別 54.3%、3桁＋生年月日＋性別 88.2%、3桁＋生年月＋性別 5.1%、3桁＋生年＋性別 0.01%

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- DuckDB の SQL で数えた「1人だけ」の割合が、pandas の値と一致する（コード内の assert）

## データ
- `data/customers.csv`：架空の顧客10万人（顧客ID・郵便番号7桁・郵便番号3桁・生年月日・性別）。作成者が乱数で作成（seed 407）。実在の人・地域ではない

## 注意（言えないこと）
- 架空のデータ。割合は、地域の数（7桁12,000個・上3桁90個）と人数の置き方で決まる
- 項目は3つだけ。ほかの項目（購入日・金額など）が残れば、1人に絞れる人は増える
- 名簿との突き合わせは、相手が同じ項目を正確に持っていると置いた場合
- 同じ組み合わせの人が全員同じ属性を持つ場合の問題（属性が分かる）は扱っていない
- どこまで粗くすれば外に出してよいかは、法令・契約・社内の決まりで決まる。この記事はその判断をしない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
