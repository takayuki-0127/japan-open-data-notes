# 612 住所を「LIKE '%桜ヶ丘%'」のような部分一致で探すと、何件を余分に拾い、何件を取りこぼすのか（実務の型・住所の文字列の一致）

「桜ヶ丘の顧客を出して」と言われて、住所に「桜ヶ丘」を含む行を部分一致で探すと、東桜ヶ丘・桜ヶ丘台のような別の町や、建物名に「桜ヶ丘」が入った住所まで拾います。逆に「桜ケ丘」と書いた行や、全角の数字の行は取りこぼします。**ここでは、架空の市（架空市）の顧客の住所2万件（町名・建物名はすべて架空、本当の桜ヶ丘は1,927件）で、探し方3通りの余分と取りこぼしを、作ったときの正解と比べて数えました。** 書き方のゆれの割合は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A612 | 探し方で、余分に拾う件数と取りこぼす件数がどれだけ違うか | A1 部分一致 `LIKE '%桜ヶ丘%'`、A2 前方一致 `LIKE '架空市桜ヶ丘%'`、A3 正規化（NFKC・ケ→ヶ・空白の除去）してから、町名のすぐあとが数字・漢数字・終わりであることを正規表現で確かめる。DuckDB（1スレッド）と Python で一致を確認。seed 612 | `src/a612_like_address.py`、`src/02_address_match_duckdb.sql`、`src/01_address_match_tsql.sql`（未検証） |

## 主な結果
- **部分一致（A1）**：4,360件を拾い、本当の桜ヶ丘は1,655件だけ。**余分が2,705件**（桜ヶ丘台868・東桜ヶ丘779・西桜ヶ丘607、建物名に「桜ヶ丘」が入った住所451）。さらに「桜ケ丘」と書いた272件を取りこぼした。拾ったうち正しいのは38.0%、本当の桜ヶ丘のうち拾えたのは85.9%
- **前方一致（A2）**：2,048件を拾い、正しいのは1,329件。余分は桜ヶ丘台の719件。取りこぼしは598件（市の名前を省いた行384件、「桜ケ丘」272件、空白・全角の数字159件。重なりあり）。正しい割合64.9%、拾えた割合69.0%
- **正規化して町名の区切りを確かめる（A3）**：1,927件をすべて拾い、余分も0。ただし、作った書き方のゆれをすべて知っているから0になった。実際の住所では、知らないゆれの分だけ漏れる
- 住所の19.4%が市の名前を省き、桜ヶ丘・東桜ヶ丘などの685件が「ケ」で書かれていた（作成者が置いた割合）

## 動かし方
```
pip install -r requirements.txt
cd src && python a612_like_address.py
```
数秒で終わります。`data/addresses.csv` に住所を書き出します（正解の町は入れていない）。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- A1〜A3 の結果が、DuckDB の SQL と Python の文字列の判定で一致した
- T-SQL 版（`01_address_match_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）。SQL Server には正規表現がないので、LIKE の文字の範囲で書いた

## データ
- `data/addresses.csv`：cust_id・address
- 仮定：町は12（桜ヶ丘に似た町を3つ含む）、番地の書き方は「1-2-3」60%・「一丁目2番3号」20%・全角20%、市の名前の省略20%、桜ヶ丘系の町で「ケ」15%、空白10%、桜ヶ丘以外の住所の3%に「桜ヶ丘ハイツ」

## 注意（言えないこと）
- 架空の住所。実在の地名ではない
- 実際の住所には、ここにない書き方のゆれ（旧字・略字・字（あざ）・番地の誤記など）がある。正規化の決まりは、データを見ながら足していく必要がある
- 住所の照合には、公的な住所のマスタや郵便番号を使う方法もある。この記事は文字列の一致の落とし穴だけを扱った
