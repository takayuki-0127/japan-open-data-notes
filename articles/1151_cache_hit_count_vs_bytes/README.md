# 1151 当たり率を件数で数えるかデータの量で数えるかで、良し悪しはどう入れかわるのか？（キャッシュの当たり率）

よく使うデータを手元に置いておく置き場所（キャッシュ）の当たり率は、ふつう「当たった件数÷問い合わせの件数」で数えます。けれども、データの大きさがまちまちだと、「当たったデータの量÷問い合わせたデータの量」で数えた当たり率とは一致しません。小さなデータをたくさん置く置き方は件数で数えると良く見え、大きなデータを置く置き方は量で数えると良く見えます。どちらの数え方をするかで、置き方の良し悪しの順が入れかわることがあります。**ここでは、作成者が置いた架空のアプリのデータ2万件（大きさは中央値50KBで、大きく散らばるもの）への問い合わせで、置き場所の量を全データの合計の3%にそろえ、①いちばん長く使われていないものから捨てる、②①と同じだが大きいデータ（大きさの上位10%）は置かない、③いちばん大きいものから捨てる、の3つの置き方を比べました。件数の当たり率と量の当たり率で順がどう変わるかを数え、大きさと人気の関係・置き場所の大きさ・大きさの散らばりを変えた18通りでも確かめました。問い合わせはすべて作成者が置いた確率からの乱数で、実機の計測はしていません。**

関連する記事：918「不良の原因の上位を、件数で並べるか損失で並べるかで変わるのか？」は、件数で並べるか1件あたりの重みを掛けた合計で並べるかで上位が変わることを、工場の不良で扱っています。この記事は同じ形を、データの大きさで重みを付けた当たり率に当てたものです。同じ企画の 1149「当たり率90%と99%の差は、平均の応答時間で何倍の差になるのか？」は当たり率の差が応答時間でどれだけになるか、1150「置き場所の大きさを2倍にすると、当たり率はどれだけ上がるのか？」はデータの大きさをすべて同じと置いたときの当たり率の上がり方を扱っています。1156「当たり率が上がったのに、平均の応答が遅くなるのはどんなときか？」は、当たり率と平均の応答時間で良し悪しが逆になることを、1159「問い合わせの一部を抜き出して当たり率を見積もると、置き場所を小さくして試した値はどれだけずれるのか？」は、記録の抜き出し方で当たり率の見積もりがずれることを扱っています。この記事は、大きさの違うデータで当たり率をどう数えるか（分母を件数にするか量にするか）に絞ります。

## 主な結果

### 基本の置き方（大きさと人気は関係なし、置き場所3%、`results/base_policies.csv`）
| 置き方 | 件数の当たり率 | 量の当たり率 |
|---|---|---|
| ①いちばん長く使われていないものから捨てる | 28.25% | **25.47%（1位）** |
| ②①と同じだが大きいデータは置かない | **33.08%（1位）** | 20.5% |
| ③いちばん大きいものから捨てる | 30.25% | 6.32% |

- **件数で数えると ②＞③＞①、量で数えると ①＞②＞③ で、件数では最下位の①が量では1位、件数では2位の③が量では最下位になった**（3つの順がそっくり逆になったわけではない）
- ③は件数では30.25%と①より上だが、量では6.32%で①の25.47%を大きく下回った。小さいデータばかりが置き場所に残り、大きいデータの問い合わせはほとんど外れるため
- 大きさの上位10%のデータは、問い合わせの件数では9.52%なのに、問い合わせたデータの量では44.72%を占めた（`results/a1151_main.json` の base_detail）。②はこの1割を置かないので、件数ではほとんど損をせず、量では大きく損をする

### 確かめ：置き方を変えた18通り（`results/grid_summary.csv`・`results/grid_policies.csv`）
| 大きさと人気の関係 | 件数と量で1位が分かれた通り（各6通り） |
|---|---|
| 人気ほど小さい | 6通り |
| 関係なし | 6通り |
| 人気ほど大きい | 3通り |

- **18通りのうち15通りで、件数で1位の置き方と量で1位の置き方が違った**。順がまるごと逆になったのは2通り（どちらも関係なし・散らばり1.6）
- 件数で1位になったのは③が12通り、②が3通り、①が3通り。量で1位になったのは①が11通り、②が7通りで、③は0通りだった
- ③と①の差は、件数の当たり率では−23.67〜+31.38ポイントと上にも下にも振れ、量の当たり率では−62.93〜+0.83ポイントだった。18通りのうち、③が件数で①を上回ったのは12通り、量で①を下回ったのは16通り
- 件数でも量でも1位がそろったのは、人気ほど大きく、大きさの散らばりが小さい（0.8）3通りだけで、3通りとも①が1位だった
- 人気ほど大きい・置き場所3%・散らばり1.6の通りでは、①は件数の当たり率14.64%と3つの中でいちばん低いのに、量の当たり率は67.79%といちばん高かった。人気の上位の大きなデータを置いているため
- つまり、どの置き方が上に見えるかは、どちらの数え方をするかと、作成者が置いた大きさと人気の関係・散らばりで決まる。この記事が示せるのは、件数の当たり率だけ・量の当たり率だけを見ると、同じ置き方の評価が逆になりうること

## 注意（言えないこと）
- 架空のデータです。人気の偏り、データの大きさの分布、大きさと人気の関係、置き場所の大きさは作成者が置いたもので、どちらの数え方でどの置き方が上になるかはこれで決まります。実在のアプリの使われ方を表すものではありません
- 人気は時間で変わらないと置きました。③のいちばん大きいものから捨てる決まりは、人気が移り変わると、使われなくなった小さなデータが残り続けて当たり率が下がります（推測）
- 件数の当たり率と量の当たり率のどちらを使うべきかは言えません。件数は問い合わせ1件ずつの待ち、量は元のデータから運ぶ量に近い物差しですが、どちらが大事かは使い方によります。費用（料金）の見込みは扱っていません
- 置き方は3つだけを比べました。実際の置き方の決まりは、ほかにも多くあります
