# 741 16桁以上の番号を Excel で開くと、何件の番号が別の値に変わり、何件が同じ番号になるのか（実務の型）

Excel は数を有効数字15桁で持つため、16桁以上の番号を数として開くと、16桁目から先が0に変わります。注文番号のような長い番号では、別々の番号が同じ値になり、件数や結合が狂います。**ここでは、作成者が乱数で作った架空の注文番号（16桁と18桁、各約5万件。カード番号ではない）で、Excel の動きを Python で再現し、値が変わった件数と、ほかの番号と重なった件数を数えました。** 小数（float64）で読んだ場合と、文字で読んだ場合も比べました。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A741 | 長い番号を数として開くと、何件が変わり、何件が重なるか | 架空の注文番号。16桁＝日付8桁＋店3桁＋連番5桁（47,492件）、18桁＝日付8桁＋店4桁＋連番6桁（49,718件）。Excel の15桁（16桁目から先を0にする）を Python で再現、float64 は Python の float、文字はそのまま。DuckDB（1スレッド）で VARCHAR・BIGINT・DOUBLE に読み、件数の一致を確認。seed 741 | `src/a741_long_ids.py`、`src/02_read_duckdb.sql`、`src/01_read_tsql.sql` |

## 主な結果

| | 16桁（47,492件） | 18桁（49,718件） |
|---|---|---|
| Excel（15桁）で値が変わった | 42,748件 | 49,718件（全部） |
| Excel で、ほかの番号と同じ値になった行 | **27,927件** | **20,826件** |
| Excel で読んだあとの番号の種類 | 31,629 | 38,390 |
| 1つの値に重なった元の番号（最大） | 6 | 6 |
| 小数（float64）で値が変わった | 0件 | 48,771件 |
| 文字で読んだとき | 変わらない | 変わらない |

- 16桁の番号は、末尾が0の番号を除く42,748件で値が変わり、27,927行がほかの番号と同じ値になった。番号の種類は47,492から31,629に減った
- 16桁の番号は float64 では変わらなかった（この番号の大きさでは、float64 で正確に表せる）。18桁では float64 でも48,771件が変わった
- DuckDB で BIGINT に読むと、番号は変わらなかった（19桁まで）。DOUBLE に読むと、Python の float64 と同じ件数が変わった

## 動かし方
```
pip install -r requirements.txt
cd src && python a741_long_ids.py
```
数秒で終わります。`data/orders_16.csv`・`data/orders_18.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- DuckDB の VARCHAR・BIGINT での番号の種類が、Python の文字での種類と一致すること。DOUBLE での種類と変わった件数が、Python の float64 と一致すること（assert）

## データ
- `data/orders_16.csv`・`data/orders_18.csv`：架空の注文番号（order_no、文字）と金額（amount）。実在の番号ではなく、カード番号の形でもない

## 注意（言えないこと）
- Excel の動きは、Python で「有効数字15桁で残し、16桁目から先を0にする」と置いて再現したもの。Excel では未検証。Excel の版や開き方（CSV をダブルクリックで開く・取り込みで型を指定する）で変わることがある
- T-SQL 版は未検証
- 重なる件数は、番号の作り方（連番の位置と桁数）で大きく変わる。ここでは連番が末尾にある形だけを見た
