# 562 「直近30日」に今日を含めるか、時刻で切るか日付で切るかで、数字はどれだけ変わるのか（実務の型・動く窓の定義）

毎日の報告で「直近30日の売上」を出すとき、今日を含めるか、日付で切るか時刻で切るかで、値が変わります。**ここでは、架空の店の時刻つき取引（2025年1〜12月、115,767件）で、毎朝9時に「直近30日」を出すとして、4つの定義（A 今日を含む30日・B 昨日までの30日・C 今から720時間・D 両端を含めて31日分になる書き方）の件数と売上を、2〜12月の334日分比べました。出す時刻を0〜23時に変えたときの差も見ました。** 件数の曜日・季節・時間帯の形は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A562 | 定義で、直近30日の件数・売上と日ごとの振れがどれだけ違うか | A：日付が today−29〜today（今日は実行時刻まで）。B：日付が today−30〜today−1。C：時刻が now−30日 より後で now 以下。D：日付が today−30〜today（今日は実行時刻まで）。B を基準に毎朝9時の差、前日からの変化率の標準偏差、出す時刻（0〜23時）ごとの差の平均（3〜11月）。36時点で Python と SQL（DuckDB、1スレッド）を突き合わせ。seed 562 | `src/a562_last30.py`、`src/02_last30_duckdb.sql`、`src/01_last30_tsql.sql`（未検証） |

## 主な結果
- **毎朝9時、B（昨日までの30日）との売上の差**
  - A 今日を含む30日：平均 **−3.16%**（−4.86〜−2.10%）。29日分と今日の9時までの分しか入らない
  - C 720時間：平均 0.00%（−0.25〜+0.22%）。窓が9時間ずれるだけ
  - D 31日分になる書き方：平均 +0.16%（+0.03〜+0.38%）
- **前日からの変化率の標準偏差**：A 0.81%、B 1.09%、C 1.06%、D 1.08%
- **出す時刻で差が変わる（3〜11月の平均）**：A は0時 −3.33%、12時 −2.69%、18時 −1.20%、23時 −0.03%。D は0時 0.00%、12時 +0.63%、18時 +2.13%、23時 +3.29%。C は時刻によらず ±0.01% 以内
- A と D は、出す時刻が変わると、同じ定義でも値が変わる。B と C は、出す時刻によらず「30日分」がそろう

## 動かし方
```
pip install -r requirements.txt
cd src && python a562_last30.py
```
数秒で終わります。`data/transactions.csv`（tx_id・ts・amount）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 2〜12月の12日 × 0時・9時・23時の36時点で、4つの定義の件数と売上が Python と DuckDB の SQL で一致した
- T-SQL 版（`01_last30_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 架空の店：1日平均およそ300件。曜日（土日が多い）・季節・12月下旬の増加を置いた。時間帯は10〜21時が中心。1件の金額は対数正規
- 「今日」は実行した日。A と D は今日の実行時刻までの取引を含む

## 注意（言えないこと）
- 架空のデータ。実際の店の数字ではない
- 差の大きさは、1日の中の売上の時間帯の形と、出す時刻で決まる。夜に売上が多い店ほど、朝に出す A の差は大きくなる
- どの定義が正しいということはない。報告の中で定義をそろえ、書いておくことが大事（推測）
