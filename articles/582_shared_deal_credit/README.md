# 582 複数の担当者で受けた案件の成果を、主担当に全部付けるか人数で割るかで、担当者別の実績の順位はどれだけ入れ替わるのか（実務の型・成果の割り振り）

1つの案件に複数の担当者が関わると、担当者別の売上をどう数えるかを決める必要があります。**ここでは、架空の案件1,200件と担当者30人（営業20人・専門10人）で、案件の売上を「主担当に全額」「人数で均等割り」「関与度（記録した工数）の比」の3通りで担当者に付け、担当者別の実績と順位がどれだけ入れ替わるかを比べました。** あわせて、関わった全員に全額を付けた場合の合計も出しました。担当の付き方・関与度・金額の分布は作成者が置いたもので、数字はその仮定で決まります。**人事評価の方法の助言ではありません。数え方を変えると数字がどう変わるかを見せるだけです。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A582 | 成果の付け方で、担当者別の実績と順位がどれだけ変わるか | 案件と担当（主・応援、関与度）の表から、3通りで担当者別の売上を集計。順位の変わった人数・最大の動き・順位相関・上位5人の重なり、営業と専門の取り分、全員に全額を付けた場合の合計。複数人の案件の割合を20〜85%に変えて各20回の平均。関与度の比の集計を Python と SQL（DuckDB、1スレッド）で突き合わせ。seed 582 | `src/a582_deal_credit.py`、`src/02_credit_duckdb.sql`、`src/01_credit_tsql.sql`（未検証） |

## 主な結果
- 案件の56.4%（売上の68.2%）が複数人で受けた案件
- **主担当に全額 → 均等割り**：30人中27人の順位が変わり、12人が5位以上動いた。最大の動きは22位分（専門の1人が25位から3位へ）。順位相関 0.60、上位5人の重なり 3人
- **主担当に全額 → 関与度の比**：27人の順位が変わり、7人が5位以上動いた。最大15位分。順位相関 0.82、上位5人の重なり 4人
- **均等割り → 関与度の比**：25人の順位が変わり、最大8位分。順位相関 0.92
- **営業と専門の取り分**：専門10人の取り分は、主担当に全額で 8.9%、均等割りで 30.2%、関与度の比で 24.8%
- **全員に全額**：担当者別の合計は売上の 2.22倍（222%）になる。担当者別の数字を足しても会社の売上に戻らない
- **複数人の案件の割合**：20%なら順位の動きの平均は 1.7位、40%で 3.2位、55%で 4.0位、70%で 5.1位、85%で 5.8位（主担当に全額 → 関与度の比、各20回の平均）

## 動かし方
```
pip install -r requirements.txt
cd src && python a582_deal_credit.py
```
十数秒で終わります。`data/deals.csv`（deal_id・amount・team_size）と `data/deal_members.csv`（deal_id・person_id・role・involvement）を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 3通りの担当者別の売上が、Python と DuckDB の SQL（`02_credit_duckdb.sql`）で30人すべて一致した
- T-SQL 版（`01_credit_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- 担当者30人（架空の ID：営業 S01〜S20、専門 T01〜T10）。営業は主担当に、専門は応援に選ばれやすくした（選ばれやすさは人ごとに対数正規分布でばらつかせた）
- 案件1,200件。担当者の人数は1人45%・2人30%・3人17%・4人8%。金額は対数正規分布（中央値 約80万円、人数が1人増えるごとに約1.4倍）
- 関与度は記録した工数の比を想定し、主担当が多めになるガンマ分布から作った（案件内で合計1）

## 注意（言えないこと）
- 架空のデータ。実在の人・会社の数字ではない
- どの付け方が「正しい」かは、何のために数えるか（売上の見通し、工数の配分、評価など）で決まる。ここでは決めない。人事評価や報酬の決め方の助言ではない
- 関与度の比は、工数の記録がそろっていることが前提。記録の付け方がばらつくと、それ自体が数字を動かす
- 入れ替わりの大きさは、複数人の案件の割合と、営業と専門の役割の分かれ方で決まる
