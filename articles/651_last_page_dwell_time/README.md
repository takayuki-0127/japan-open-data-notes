# 651 ページの滞在時間を「次のページを開いた時刻との差」で測ると、最後に見たページの分はどれだけ抜け落ちるのか（実務の型・ログの集計）

アクセスログには「ページを開いた時刻」しか残らないので、滞在時間は次のページを開いた時刻との差で測ります。最後に見たページ（離脱したページ）には次の時刻がないので、そのページの滞在時間は測れません。**ここでは、架空のサイト（8種類のページ）・2万セッション・5.3万ページビューの閲覧ログに、作成者が本当の滞在時間を置き、差で測った値と比べました。** 離脱するときの滞在の長さ（記事は読み切ってから閉じる、トップはすぐ閉じる）は作成者が置いたもので、数字はその仮定で決まります。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A651 | 差で測った滞在時間は、ページごと・セッションの合計でどれだけずれるか | D0 本当の値、D1 差で測り最後のページを除く、D2 最後のページを0秒、D3 最後のページに「最後でないとき」の平均を入れる。LEAD 関数（DuckDB・1スレッド）と pandas で一致を確認。seed 651 | `src/a651_dwell_time.py`、`src/02_dwell_duckdb.sql`、`src/01_dwell_tsql.sql`（未検証） |

## 主な結果
- **最後のページを0秒とみなす（D2）と、離脱の多いページほど短く出る**：記事（離脱65%）は本当の249.5秒が63.7秒（−74.5%）、よくある質問（59%）は −66.2%、完了（95%）は −96.5%
- **最後のページを除く（D1）・平均で補う（D3）でも戻らない**：離脱するときの滞在が長いページ（記事）は −27.6%、すぐ閉じるページ（トップ）は +21.7%。差で測れる「最後でないとき」だけを見ているため。D3 はページごとの平均では D1 と同じ値になる
- **セッションの合計時間**：0秒とみなすと、本当の合計の **58.2%** が抜け落ちる（平均244.8秒→102.4秒）。1ページだけのセッション（37%）は0秒になる。平均で補っても −16.1%
- **ページの順位**：0秒とみなすと、本当は1位の記事が2位に、商品詳細が1位に入れ替わる（順位相関0.79）

## 動かし方
```
pip install -r requirements.txt
cd src && python a651_dwell_time.py
```
十数秒で終わります。`data/pageviews.csv` にログ（時刻だけ）を、`results/true_dwell.csv` に作成者が置いた本当の滞在時間を書き出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures がバイト単位で一致した（DuckDB は `SET threads=1`）
- 差で測った値が、DuckDB の LEAD と pandas の shift で一致した。最後でないページでは、差が本当の滞在時間と一致した
- T-SQL 版（`01_dwell_tsql.sql`）は書いたが、SQL Server では動かしていない（**未検証**）

## データ
- `data/pageviews.csv`：session_id・seq・page・ts
- 仮定：ページごとの平均滞在時間と離脱の割合、離脱するときの滞在の倍率（記事1.6倍、トップ0.4倍など）は作成者が置いた。滞在時間は対数正規分布

## 注意（言えないこと）
- 架空のデータ。実際のサイトの数字ではない
- 実際のツールは、ページを閉じた時刻や画面に出ていた時間を別の方法で取っていることがある。ここは「開いた時刻だけ」の場合
- 離脱するときに長くいたか短くいたかは、ログからは分からない。補い方の良し悪しはこの仮定で決まる
