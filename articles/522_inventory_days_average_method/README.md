# 522 在庫回転日数を「期首と期末の平均在庫」で出すと、毎日の在庫から出した値と何日ずれるのか？（実務の型）

架空の商品1つの在庫を2025年1月1日〜12月31日の毎日で作り、入荷のしかた（毎日・月1回の月初／月中／月末）と売れ方の季節（山なし・12月に山）を変えて、在庫回転日数（平均在庫 ÷ 1日あたりの払出し）を3通りの平均在庫で出して比べたフォルダです。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A522 | 平均在庫を「期首と期末の2点」「月末の13点」で取ると、毎日の在庫の平均から出した回転日数と何日ずれるか。入荷日と季節の山でどう変わるか | 入荷日に「次の入荷まで＋7日分」まで補う架空の在庫を作り、3通りの平均在庫で回転日数を出す。入荷日（1〜28日・月末）と山の月（1〜12月）を動かしてくり返す。同じ計算を SQL（DuckDB）でも行い、Python と一致するか確かめる | `src/a522_inventory_days.py`、`src/02_turnover_days_duckdb.sql`、`src/01_turnover_days_tsql.sql`（T-SQL 版、未検証） |

## 主な結果（1日の払出しは平均約100個。基準は毎日の平均）
- **毎日入荷・山なし**：期首と期末 6.96日、月末 7.01日、毎日 7.03日。在庫がほぼ一定なら、どの取り方でもほとんど同じ
- **月1回・月初に入荷・山なし**：期首と期末 7.57日（−14.3日、−65%）、月末 7.22日（−14.7日、−67%）、毎日 21.89日。月末は入荷の直前で在庫がいちばん少ない日
- **月1回・月末に入荷・山なし**：期首と期末 22.03日（+0.2日）、月末 34.28日（+12.5日、+57%）、毎日 21.80日。月末は入荷の直後で在庫がいちばん多い日
- **月1回・月中（15日）に入荷・山なし**：期首と期末 14.14日（−7.1日、−33%）、月末 20.04日（−1.2日）、毎日 21.19日
- **12月に山（±50%）・毎日入荷**：期首と期末 10.33日（+3.3日、+47%）。期末の12月は売れる時期で在庫も多い
- **12月に山・月1回・月末に入荷**：期首と期末 31.83日（+10.0日、+46%）、月末 34.64日（+12.8日、+59%）、毎日 21.83日
- **入荷日を1日〜月末に動かすと（山なし）**：月末の平均のずれは −14.7日（1日）から +12.5日（月末）まで。16日前後でほぼ0
- **山の月を1〜12月に動かすと（月末入荷）**：期首と期末の平均のずれは −10.3日（山が7月）から +11.1日（山が1月）まで。毎日入荷では −1.0〜+3.3日
- SQL（DuckDB）で出した3通りの回転日数は、Python と一致

## データ
- `data/fictional_daily_inventory_peak12_monthend.csv`：架空の在庫（seed 522、12月に山・月末入荷の場合）。列は date・inbound（入荷）・shipped（払出し）・inv_end（日末の在庫）。ほかの場合はスクリプトを動かすと作られる

## 注意（言えないこと）
- 架空のデータ。入荷のしかた（入荷日に「次の入荷まで＋7日分」まで補う）、売れ方の振れ（±15%）、季節の振れ幅（±50%）は作成者が置いたもので、実際の会社の値ではない
- 在庫は個数で数え、単価は一定とした。金額で出す場合の単価の変動や評価の方法は扱っていない
- どの取り方を使うべきかの判断や、会計・税の取り扱いの助言はしない。この記事は、同じ在庫でも平均の取り方で数字がどれだけ違うかを見ただけ
- 期は1〜12月の1年だけ。複数年の平均や、期の途中の四半期の値は見ていない
- T-SQL 版は SQL Server 本体では動かしていない（未検証）
