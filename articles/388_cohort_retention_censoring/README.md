# 388 登録月ごとの継続率の表で、まだ観測できていない月を0と数えると、どれだけ低く出るのか（実務の型）

登録月ごとに「1か月後、2か月後…に何%が続いているか」を並べる表（コホート表）を SQL で作るとき、まだその月数がたっていない会員の扱いで、継続率が大きく変わります。架空の会員68,854人（2024年1月〜2025年12月に登録、2025年12月31日まで観測）で、数え方ごとの値を、本当の値（観測の終わりより後の退会日まで分かっている値）と比べたフォルダです。F241（顧客の離脱）が離脱の予測を扱ったのに対し、ここでは SQL の集計表と、観測が途中で切れる月の扱いに絞ります。SQL は DuckDB で動かしました。T-SQL 版は `src/01_cohort_tsql.sql` に置きましたが、**SQL Server 本体では動かしていません（未検証）**。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A388 | 観測できていない分を0と数えると、継続率は何ポイント低く出るか。新しい登録月ほど差が大きいか | 退会までの日数はワイブル分布（最初ほど辞めやすい、12か月後に45%が残る）。数え方は ①観測できていない分を0と数える ②退会日が空欄なら続いていると数える ③kか月後まで観測できた会員だけで割る ④月ごとの継続率を掛け合わせる。登録の増え方（毎月0%・3%・8%）と、2025年の登録者が1.5倍辞めやすい場合も試す | `src/a388_cohort.py`、`src/01_cohort_*.sql` |

## 主な結果
- **全体の継続率（登録が毎月3%ずつ増える場合）**

| 登録からの月数 | 本当の値 | ①0と数える | ②空欄は続いている | ③観測できた会員だけ | ④掛け合わせる |
|---|---|---|---|---|---|
| 3か月 | 70.8% | 59.2% | 72.4% | 70.8% | 70.7% |
| 6か月 | 59.2% | 40.6% | 63.5% | 59.1% | 59.2% |
| 12か月 | 45.2% | 18.8% | 55.6% | 45.0% | 45.1% |
| 18か月 | 36.2% | 7.2% | 52.9% | 36.3% | 36.2% |

- ①は6か月で18.6ポイント、12か月で26.4ポイント低い。12か月後まで観測できた会員は全体の41.9%しかいないため
- ②は逆に高く出る（12か月で+10.4ポイント）。まだ辞めていないだけの新しい会員を、12か月続いたと数えるため
- ③と④は、本当の値と0.3ポイント以内
- **登録月ごとの表**：0と数えると、2025年2月以降の登録月の12か月継続率は0%、2025年1月は7.2%（本当は45.9%）。6か月継続率は2025年8月以降が0%（本当は59〜61%）。新しい登録月ほど、表の右側から0になる
- **新しい会員が多いほど差は大きい**：①の12か月の差は、登録が増えない場合−22.5ポイント、毎月3%増で−26.4、毎月8%増で−32.4
- **2025年の登録者が1.5倍辞めやすい場合**：③は12か月で+8.2ポイント高く出る（12か月後まで観測できたのは、辞めにくい2024年の登録者だけのため）。④は+2.5ポイント

## 動かし方
```
pip install -r requirements.txt
cd src && python a388_cohort.py     # 30秒ほど
```
乱数の種を固定してあるので、実行のたびに同じ `data/`・`results/`・`figures/` を出します。

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- SQL（DuckDB）で作った登録月×経過月の表から出した①と③は、NumPy で数えた値と一致した（コード内の assert、`results/cohort_table_sql.csv`）

## データ
- すべて架空（作成者が乱数で作成、seed 388）。`data/members.csv`（会員ID・登録月・登録日・退会日）。退会日は、2025年12月31日までに退会していなければ空欄
- 登録は2024年1月の2,000人から毎月3%ずつ増える。1か月は30日として数えた

## 注意（言えないこと）
- 架空のデータです。差の大きさは、登録の増え方と、辞めやすさの形で変わります
- 「本当の値」は、作ったデータなので分かります。実際のデータでは、観測の終わりより後のことは分かりません
- ③と④が本当の値に近いのは、登録月が違っても辞めやすさが同じ、と置いたからです。新しい登録者の辞めやすさが違うと、③は古い登録者だけの数字になり、全体の値からずれます（+8.2ポイントの例）
- 再入会、休会、退会日の記録の遅れは入れていません
- 1か月を30日と数えました。暦の月で数えると、月の日数の違いで少し変わります
- T-SQL 版は SQL Server 本体では動かしていません
