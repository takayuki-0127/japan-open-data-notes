# 471 年初からの累計の前年比は、変化に気づくのが何か月遅れるのか（実務の型）

月次の売上の前年比を「単月」「年初からの累計」「直近12か月の合計」の3通りで出し、水準が変わったときに、それぞれ何か月遅れて数字に出るかを測ったフォルダです。架空の月次売上（正解が分かる）と、商業動態統計の百貨店の販売額で確かめています。

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A471 | 累計の前年比は、変化の半分が出るまで何か月かかるか。変化が起きた月で違うか。ぶれの小ささと引き換えに何を失うか | 水準が−10%変わる架空の系列を、変化の月を1〜12月に動かして作る／月ごとにぶれを足して2,000回くり返す／公的統計で同じ3つを並べる。SQL は DuckDB で実行し、numpy の値と一致を確かめる | `src/a471_ytd.py`、`src/01_ytd_tsql.sql`（T-SQL 版、未検証） |

## 主な結果
- **変化の半分が数字に出るまで**（水準が−10%、暦年の累計）：単月は0か月。直近12か月は5〜6か月。累計は変化の月によって違い、1月0、2月1、3月1、4月2、5月3、6月4、7月5、8月5、9月4、10月3、11月2、12月1か月（平均2.6、最大5）。変化の幅を−5%・−20%・+10%にしても同じ
- **12月の累計に出ている変化の割合**：1月に変わったなら100%、4月77%、7月52%、10月27%、12月10%。残りは翌年1月にまとめて出る（12月→翌1月の累計前年比の動き：7月の変化で−4.9pt、10月で−7.5pt、12月で−9.2pt）
- **戻るとき**：単月の前年比が元に戻ったあとも、累計は0〜6か月、直近12か月は6か月、変化が残る。10月に変わった場合、翌年12月の累計はまだ−5.7%（単月は+2%に戻っている）
- **累計に占める最新の月の重み**：1月100%、2月48%、6月17%、12月9.7%
- **ぶれ**（月ごとに標準偏差3%のぶれ、2,000回）：前年比の標準偏差は、単月が4.3pt、累計は1月4.4pt→12月1.2pt、直近12か月は1.2pt
- **「ふだんより5pt低い」で知らせる決まり**：年あたりの誤報は単月1.41回、累計0.20回、直近12か月0回。気づくまでの遅れ（中央値）は0か月、2.5か月、5か月
- **百貨店の販売額（商業動態統計）**：前年比が初めて−10%を下回った月は、単月2020年2月、累計2020年3月、直近12か月2020年4月。2020年12月の累計−25.5%が、2021年1月に−30.2%へ動く。2021年4月は単月+153%、累計+5.6%、直近12か月−16.1%。プラスに戻った月は単月2021年3月、累計2021年4月、直近12か月2021年11月

## 確かめたこと
- 空のフォルダで流し直し、data・results・figures が一致した
- SQL（DuckDB）で出した3つの前年比が、numpy で出した値と一致する（コード内の assert）

## データ
- `data/fictional_monthly_sales.csv`：架空の月次売上（seed 471）
- `data/meti_sales_monthly.csv`：商業動態統計の業態別の月次販売額（経済産業省。このリポジトリの 232 で使ったものと同じ）

## 注意（言えないこと）
- 架空の系列は「ある月から水準が一段変わる」形だけ。少しずつ変わる場合や、季節の形が変わる場合は扱っていない
- 累計が悪い指標だと言うものではない。年の着地を見るには合っている。ここで測ったのは、変化に気づく早さだけ
- 年度（4月始まり）の累計なら、遅れの大きい月がそのまま3か月ずれる
- 知らせる決まりの線（5pt）やぶれの大きさは置いた値。数字はこの置き方での結果
- T-SQL 版は SQL Server 本体では動かしていない（未検証）。SQL は DuckDB で実行した
