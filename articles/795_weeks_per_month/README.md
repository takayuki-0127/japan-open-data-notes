# 795 月の数字を週に直すとき4で割るか4.33で割るかで、週あたりの値はどれだけ違うのか（実務の型）

月の売上を「週あたり」に直すとき、「1か月は4週」として4で割る、「1年52週÷12か月」で4.33で割る、その月の日数÷7で割る、など決め方がいくつかあります。1か月は28〜31日なので、4で割るといつも大きく出ます。4.33で割ると平均は合いますが、日数の少ない2月は小さく出ます。**ここでは、作成者が乱数で作った架空の店の日次売上2年分で、3通りの週あたりの値を、本当の週の売上と月ごとに比べました。**

| # | 問い | 手法 | ファイル |
|---|---|---|---|
| A795 | 週あたりへの直し方で、値はどれだけずれるか | 架空の店の日次売上（2024〜2025年、土日が多い曜日の波あり、伸びなし）。月の売上を4・4.33（52÷12）・その月の日数÷7で割る値を DuckDB（1スレッド）で出し、pandas の値と一致を確認。本当の週の売上は、月〜日の週の合計を、週の木曜日が入る月で平均した値。seed 795 | `src/a795_weeks.py`、`src/02_weekly_duckdb.sql`、`src/01_weekly_tsql.sql` |

## 主な結果（24か月）

| 直し方 | ずれの平均 | 2月のずれ | ずれの最大（絶対値） |
|---|---|---|---|
| 4で割る | **＋8.7%** | ＋1.9% | 13.0% |
| 4.33で割る | ＋0.4% | **−5.9%** | 7.7% |
| 日数÷7で割る | −0.0% | ＋0.1% | 2.1% |

- 4で割ると、31日の月で平均＋10.6%、30日の月で＋7.2%と、いつも高く出た
- 4.33で割ると、平均はほぼ合うが、28〜29日の2月は−5.9%、31日の月は＋2%前後になった
- 日数÷7で割ると日数の違いは消えたが、土日の数のずれ（その月の土日が8日なら−1.0%、10日なら＋1.9%）は残った
- 逆向きに、週の目標を4倍して月の目標にすると、1か月の平均（30.4日）に対して8.0%足りない。4.33倍ならほぼ合う（0.3%）

## 動かし方
```
pip install -r requirements.txt
cd src && python a795_weeks.py
```
数秒で終わります。`data/daily_sales.csv` もこのとき作ります。

## 確かめたこと
- 空のフォルダで流し直し、results・figures・data がバイト単位で一致した
- DuckDB の月の合計と週あたりの値が、pandas で出した値と全月で一致すること（assert）

## データ
- `data/daily_sales.csv`：架空の店の日次売上（sale_date・sales）

## 注意（言えないこと）
- 架空のデータです。ずれの大きさは、曜日の波の強さで変わります。伸びのある系列では、月の中の伸びの分もずれに入ります
- 「本当の週の売上」は、週の木曜日が入る月に数える決め方で出しました。週の割り当て方を変えると、比べる相手の値も変わります
