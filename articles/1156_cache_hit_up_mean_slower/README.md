# 1156 当たり率が上がったのに、平均の応答が遅くなるのはどんなときか？（キャッシュの当たり率）

よく使うデータを手元に置いておく置き場所（キャッシュ）の良し悪しは、当たり率で比べることが多いです。けれども、当たり率は「何件当たったか」だけを数えるので、外れたものを取りに行くのに何msかかるか、当たったときに何msかかるかは入っていません。そのため、当たり率が上がったのに平均の応答時間が遅くなることがあります。**ここでは、作成者が置いた架空のアプリの1万種類のデータへの問い合わせ（よく使われるものへの偏りと、データごとに違う取りに行く時間を置いたもの）で、2つのしくみを数えました。1つ目は、置くものを「回数の多い順」に選ぶか「回数×取りに行く時間の順」に選ぶかで、外れるものの中身が入れかわるとき。2つ目は、当たり率を上げるかわりに当たったときの時間が延びるときで、平均が遅くなる境目を式で出しました。置き方を変えた54通りでも確かめました。問い合わせと時間はすべて作成者が置いた分布からの乱数で、実機の計測はしていません。**

関連する記事：同じ企画の 1149「当たり率90%と99%の差は、平均の応答時間で何倍の差になるのか？」は、当たったときと外れたときの時間を1つずつに置き、当たり率と平均の応答時間を式で結んでいます。この記事のしくみ2は、その式で当たったときの時間も動く場合です。1151「当たり率を件数で数えるかデータの量で数えるかで、良し悪しはどう入れかわるのか？」は、件数と量で良し悪しが入れかわることを扱っています。1060「平均が速くなっても、遅い側の数%は遅くなっていることはあるのか？」は、同じ変更で物差しどうしが逆に動くことを、応答時間の平均とパーセンタイルで扱っています。918「不良の原因の上位を、件数で並べるか損失で並べるかで変わるのか？」は、件数で並べるか1件の重みを掛けて並べるかで順が変わることを、工場の不良で扱っています。この記事は、当たり率と平均の応答時間が逆に動くしくみに絞ります。

## 主な結果

### しくみ1：外れるものの中身が入れかわる（置ける数500・100万件、`results/policy_compare.csv`）
| 物差し | A 回数の多い順 | B 回数×時間の順 |
|---|---|---|
| 当たり率 | **58.418%** | 38.1% |
| 平均の応答時間 | **49.446ms** | 43.46ms |
| 外れたときの平均 | 115.969ms | 68.921ms |
| 中央値 | 2.75ms | 7.286ms |
| 99%点 | 560.01ms | 450.14ms |
| 元のデータへの問い合わせ（1,000件あたり） | 415.82件 | 619.0件 |
| 置いたデータの取りに行く時間の平均 | 36.24ms | 412.05ms |

- **Aの当たり率はBより20.318ポイント高いのに、平均の応答時間はBより13.77%遅かった**（1.138倍）
- Aは、よく使われるが取りに行くのが速いデータで置き場所を埋めた。外れるのは使われにくく遅いデータになり、外れたときの平均はBの1.683倍だった。Bは取りに行くのが遅いデータを選んで置いた（置いたデータの取りに行く時間の平均412.05ms）
- Bが平均を短くするのは、回数×時間の大きい順に置けば外れの時間の合計が小さくなるという選び方の作りどおり。新しく分かるのは、その差の大きさと、物差しによって勝ち負けが分かれること。中央値はAが速く（2.75ms対7.286ms）、元のデータへの問い合わせはBが1.489倍多かった
- AとBで同じデータを置いていたのは、500種類のうち176種類だった

### しくみ2：当たったときが遅くなる（式、`results/break_even.csv`）
| 当たり率 | 平均が遅くなる、当たったときの平均の境目 | もとの2.09msの何倍か |
|---|---|---|
| 80% → 82% | 4.25ms | 2.03倍 |
| 80% → 85% | 7.3ms | 3.49倍 |
| 90% → 92% | **4.02ms** | 1.92倍 |
| 90% → 95% | 6.75ms | 3.23倍 |
| 95% → 97% | 3.92ms | 1.87倍 |

- 平均＝当たり率×当たったときの平均＋外れ率×外れたときの平均 の式どおり。たとえば当たり率を90%から92%に上げても、当たったときの平均が2.09msから4.02msを超えると、平均は遅くなる
- 100万件の乱数で照らすと、当たり率90%（当たったときの平均2.09ms）の平均10.981msに対し、95%に上げて当たったときを6msにすると10.251msで速く、7msにすると11.16msで遅くなった（`results/slow_hit_check.csv`）。式の境目6.75msと合う
- 置き場所を大きくするかわりに、当たったときの読み出しが遅くなる場合（推測：遅い置き場所に広げるときなど）がこれにあたる

### 置き方を変えた54通り（しくみ1、各30万件、`results/grid.csv`）
- 54通りすべてで、Aの当たり率がBより高く（0.373〜50.805ポイント）、Aの平均がBより遅かった（1.18〜79.21%）。向きは作りどおりで、変わったのは大きさ
- 遅い分の大きさは、データごとの取りに行く時間の散らばりでほぼ決まった。散らばり（対数の標準偏差）0.5で1.18〜5.75%、1.0で4.8〜27.55%、1.5で14.69〜79.21%
- 当たり率の差は相関で決まった。使われにくいほど遅い（相関0.5）と1.552〜50.805ポイント、使われにくいほど速い（相関−0.5）と0.373〜3.724ポイントで、相関−0.5では当たり率の差は小さいまま、平均はAで遅くなった（1.27〜69.9%）

## 注意（言えないこと）
- 架空のデータです。使われやすさの偏り、取りに行く時間の散らばりと相関、置ける数は作成者が置いたもので、結果はこれで決まります。とくに、Bが平均を短くする向きは選び方の作りどおりで、差の大きさは置いた時間の散らばりの写しです
- Bは、データごとの取りに行く時間の平均が分かっていると置きました。実際には時間も記録から見積もるので、Bの差は小さくなることがあります（推測）
- 置くものを途中で入れかえない（置きっぱなしの）比べです。データの大きさはすべて同じと置きました（大きさが違う場合は1151）
- 混み具合で外れたときの時間が延びる効果は入れていません。Bは元のデータへの問い合わせが1.489倍多いので、元のデータが混むとBの平均も延びることがあります（推測）
- 実在のソフトやサーバーの動きを表すものではありません。どの置き方を選ぶべきかの助言でも、費用の見込みでもありません
